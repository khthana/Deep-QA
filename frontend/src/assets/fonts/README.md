# ฟอนต์ที่ฝังลงไฟล์ PDF

สองไฟล์ในโฟลเดอร์นี้คือ **TH Sarabun** ในรูปแบบ base64 ของไฟล์ `.ttf`
แต่ละไฟล์ export สตริงก้อนเดียวออกมา ไม่มีผลข้างเคียงอื่นใด
ไม่ใช่ซอร์สที่เขียนขึ้นเอง และไม่ควรแก้ด้วยมือ

ผู้ที่ลงทะเบียนฟอนต์ทั้งสองคือ
[`components/ploMapping/exportPdf.js`](../../components/ploMapping/exportPdf.js)
ด้วย `addFileToVFS` + `addFont` ที่เดียว กับ `jsPDF` ตัวที่กำลังสร้างไฟล์นั้นเท่านั้น

## ทำไมต้องมี

jsPDF มีฟอนต์ base-14 มาให้สิบสี่ตัว และไม่มีตัวไหนมีอักขระไทยเลย
`doc.text('รายวิชา')` บนฟอนต์เริ่มต้นจึงได้กล่องสี่เหลี่ยมเรียงกัน
เกณฑ์ข้อ 5 ของ [#20](https://github.com/khthana/Deep-QA/issues/20)
คือคำว่า *rendering correctly* และคำนั้นแปลว่าต้องฝังฟอนต์ลงในไฟล์ PDF

## ที่มา

คัดลอกมาจาก `DEEP-QA-FRONTEND/src/assets/Fonts/` ซึ่งเป็นโค้ดที่นักศึกษาส่งมอบ
(ไดเรกทอรีนั้นเป็น read-only reference — คัดลอกได้ ห้ามแก้)
ชื่อไฟล์ตัวหนาถูกเปลี่ยนจาก `THSarabun Bold-normal.js` เป็น `THSarabun-bold-normal.js`
เพื่อไม่ให้มีช่องว่างในชื่อไฟล์

TH Sarabun เป็นฟอนต์ในชุดฟอนต์แห่งชาติที่กรมทรัพย์สินทางปัญญาและ SIPA
เผยแพร่ให้ใช้ได้โดยไม่มีค่าลิขสิทธิ์

## สามสิ่งที่แก้ไปจากต้นฉบับ — ถ้าคัดลอกมาใหม่ต้องทำซ้ำ

**หนึ่ง — ตัด BOM ออก** ต้นฉบับมี UTF-8 BOM นำหน้า ซึ่งกฎ `unicode-bom` ของ
`eslint-config-react-app` ปฏิเสธ และ `CI=true npm run build` ถือ warning เป็น error

**สอง — ตัดโค้ดลงทะเบียนตัวเองออก** ต้นฉบับลงท้ายไฟล์ด้วย

```js
jsPDF.API.events.push(['addFonts', callAddFont])
```

บรรทัดนี้ทำงานตอน *import* ไม่ใช่ตอนเรียก และผลของมันคือทุกเอกสาร
jsPDF ที่แอปสร้างหลังจากนั้น ไม่ว่าที่ไหน จะมี TH Sarabun ฝังมาด้วยเสมอ
โค้ดลงทะเบียนใน `exportPdf.js` จึงกลายเป็นโค้ดที่ลบทิ้งได้โดยไม่มีอะไรเสีย
— มิวเทนต์ตัวแรกที่เขียนขึ้นเพื่อทดสอบแถว PDF จึงฆ่าอะไรไม่ได้เลย
บรรทัดนี้ถูกตัดออกทั้งสองไฟล์ พร้อมกับบรรทัด `import { jsPDF }` ที่มีไว้เพื่อมัน

**สาม — ตัวหนาต้องลงทะเบียนซ้ำ** ต่อเนื่องจากข้อสอง ตอนที่ยังลงทะเบียนตัวเอง
ไฟล์ตัวหนาลงทะเบียนเป็น *ตระกูล* ชื่อ `THSarabun Bold` ไม่ใช่ *สไตล์* `bold`
ของตระกูล `THSarabun` ตอนนี้ `exportPdf.js` เป็นคนตั้งชื่อตระกูลทั้งสองหน้าเอง
จึงไม่มีปัญหานี้อีกต่อไป
