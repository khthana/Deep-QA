# mutation/

การกลายพันธุ์ที่ใช้พิสูจน์ชุดทดสอบก่อนติด ⚙ ให้แถวใน `docs/acceptance/`

## ทำไมต้องมี

`docs/06-implementation-plan.md` §Acceptance กำหนดว่าแถวหนึ่งจะติด **⚙** — ครอบคลุมด้วย browser
seam — ได้ก็ต่อเมื่อ mutation test แสดงว่า *assertion ใหม่ตัวนั้น* (ไม่ใช่ตัวก่อนหน้า) ตายจริง
เมื่อโค้ดที่มันพูดถึงถูกทำให้พัง

ถ้าไม่มีขั้นตอนนี้ ชุดทดสอบที่ผ่านทั้งหมดพิสูจน์ได้แค่ว่า *มันรันแล้ว* ไม่ได้พิสูจน์ว่ามันจะสังเกตเห็นอะไร
assertion ที่ยิงผิดที่ก็เขียวเหมือนกัน

รอบกวาดของ #57 เป็นตัวอย่างที่ดีว่าขั้นตอนนี้จับอะไรได้จริง — `nofloor` ควรไม่มีผลกับรายการที่ไม่ว่างเลย
แต่กลับฆ่าแถวหนึ่งทิ้ง สาเหตุคือแถวนั้นอ่านตารางระหว่างที่คำออกมากับตอนที่หน้าจอยังวาดไม่เสร็จ จึงอ่านได้แถว
*กำลังโหลด…* มาเป็นคำตอบ ซึ่งไม่ซ้ำกับอะไรเลย ข้ออ้าง "หน้าถัดไปคือคนละชุด" จึงเป็นจริงโดยบังเอิญ
แก้ที่ `e2e/support/pager.js` ด้วยการรอให้ตารางวาดเสร็จก่อนอ่าน — นี่คือสิ่งที่ mutation test มีไว้เพื่อ

ก่อนหน้านี้สคริปต์เหล่านี้อยู่ใน scratchpad ของแต่ละ session แล้วหายไปพร้อมกัน — เอกสารตรวจรับอ้างถึง
หลักฐานที่ไม่มีใครเปิดดูได้อีก โฟลเดอร์นี้คือการเก็บมันไว้ **ให้ทำซ้ำได้ แทนที่จะให้เชื่อ**

```
python mutation/18-program-subjects.py save        # เก็บไฟล์ต้นฉบับไว้ก่อน

python mutation/18-program-subjects.py restore     # คืนโค้ดเดิม
```

`save` คัดลอกไฟล์ที่ยังไม่ถูกแตะไปไว้ที่ `mutation/.backup/` (อยู่ใน `.gitignore`)
ทุกครั้งที่ apply จะ restore ก่อนเสมอ ตัวกลายพันธุ์จึงซ้อนกันไม่ได้

**`restore` ก่อน commit เสมอ แล้วดูว่า `git status` สะอาดจากไฟล์ใน `backend/` กับ `frontend/`** —
นั่นคือหลักฐานเดียวว่าต้นไม้กลับมาเป็นต้นไม้แล้ว

**และ `save` ใหม่ทุกครั้งก่อนเริ่มกวาด ไม่ว่าจะเคย save ไปแล้วหรือไม่** — `restore` เขียนทับ
*ทุกไฟล์ใน `FILES`* ด้วยสำเนาที่ backup ถืออยู่ ไม่ใช่เฉพาะไฟล์ที่มัตแตนต์ตัวนั้นแตะ ดังนั้นการแก้ไฟล์
ในชุดนั้นหลัง `save` ครั้งล่าสุด — แม้จะแก้คนละไฟล์กับที่กำลังกวาด — จะหายไปเงียบ ๆ ตอน restore
ครั้งถัดไป เรื่องนี้กินงานไปสองรอบใน #33 (ครั้งแรกคือการแก้ระหว่างกวาด ครั้งที่สองคือแก้หลังกวาด
แล้วกวาดซ้ำโดยไม่ save ใหม่) วิธีที่ปลอดภัยคือ **อย่าแก้ไฟล์ในชุดระหว่างที่กวาดค้างอยู่** และ
**`save` เป็นคำสั่งแรกของสคริปต์กวาดเสมอ**

**และห้ามกวาดใบที่ใช้ไฟล์ร่วมกันพร้อมกัน** ตอนนี้มีสี่คู่ กลุ่มสามใบสองกลุ่ม และกลุ่มสี่ใบหนึ่งกลุ่ม ทุกใบมี backup
ของตัวเอง และการ restore ของใบที่กวาดทีหลังจะเขียนทับสิ่งที่ใบแรกกำลังใช้อยู่

## เมื่อ MISS

ตัวกลายพันธุ์ที่ตอบ `MISS` **ไม่ได้แปลว่าโค้ดผิด** แปลว่าข้อความที่มันถูกเขียนไว้ไม่อยู่ตรงนั้นแล้ว —
ไฟล์ถูก refactor หลังจากที่ข้ออ้างนั้นถูกพิสูจน์ ต้องเขียนตัวกลายพันธุ์ใหม่ให้ตรงกับโค้ดวันนี้
แล้วรันใหม่ ก่อนจะเชื่อแถวที่มันค้ำอยู่

harness ปฏิเสธตัวที่ข้อความตรงกับโค้ด **มากกว่าหนึ่งที่** ด้วย เพราะ "แก้ที่แรกที่เจอ" คือการแก้จุดที่
ไม่มีใครตั้งใจ ตัวที่กำกวมต้องผูกกับข้อความที่ยาวพอจะชี้จุดเดียว

- `save` ต้องเป็นคำสั่งแรกของรอบ ไม่ใช่ของที่ค้างจากรอบก่อน
