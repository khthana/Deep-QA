## สิ่งที่วัดได้

**การวัดที่มาก่อนคำตอบของเจ้าของงานคือการวัดของที่ส่งมอบ** ตาม `docs/06` §Out of Scope ตัวเลือกที่
ขยับค่าที่ส่งมอบมาเป็นการเบี่ยง และที่ขยับค่าที่การรีบิลด์เลือกเองไม่ใช่ (#156) `DEEP-QA-FRONTEND`
**ไม่มีตัวควบคุมสถานะบนจอไหนเลย และไม่อ่าน `is_active` ที่ไหนเลย** ทั้งห้าช่องจึงเป็นของการรีบิลด์เอง
และคำถามเรื่องรูปทรงเป็นของเจ้าของงานโดยไม่มีอะไรขัด · อีกครึ่งของการวัดเดียวกันออกมาคนละทาง
`departmentModel.js` ของ backend ที่ส่งมอบเขียน `is_active` ตอนสร้าง การอ่านนั้นจึง **สืบทอดมา**
ไม่ได้เลือก และกลไกที่สืบทอดมาไม่ใช่การตัดสินใจ (#77) ซึ่งเป็นสิ่งที่ทำให้การเอามันออกเป็นการแก้
ไม่ใช่การเบี่ยง

**ความเห็นของตั๋วถูกด้วยเหตุผลที่ผิด** ตั๋วบันทึกไว้เมื่อ 1 ต.ค. ว่า *คำถามเรื่องรูปทรงคือของจริงข้อ
เดียวที่เหลือจาก #178* และข้อตั้งของ #178 คือไม่มีตัวควบคุมสถานะบนจอไหนเลย ซึ่งการวัดวันนั้นหักล้าง
ไปแล้ว ข้อสรุปที่ถูกด้วยเหตุผลที่ผิดหมดอายุในวันที่ผิด (#141) ความเห็นจึงถูกหามาใหม่จากห้าฟอร์ม
แทนที่จะสืบทอด — มันรอด ซึ่งควรเขียนไว้ เพราะย่อหน้าของตั๋วเองอ้างอิงไม่ได้

**ที่ตั๋วประเมินราคาไว้สี่แถว วัดได้เก้าแถวที่เก้าจุด** ตั๋วเขียนว่าสี่แถวใน `16a` กับ `18a` จะ
หมดอายุ ซึ่งจริงเมื่อ 1 ต.ค. #181 ลงหลังจากนั้นและพามาอีกห้าแถวผ่าน helper สองตัว · และใบ 14 เอง
ทำนายไว้ที่ §#181 ว่า *บรรทัดเดียวที่เปลี่ยนคือ `statusBox` ใน `e2e/support/` ของแต่ละจอ* —
เป็นบรรทัดเดียว**ในแฟ้มนั้น** แต่เป็นเก้าจุดในชุดทดสอบ และจุดหนึ่งไม่ได้อ่านสถานะเลย (#52)

**และ locator ตัวหนึ่งแตก** `departmentPicker` ใน `e2e/support/subjects-screen.js` เป็น
`getByRole('combobox')` เปล่า ๆ ซึ่งชี้ได้ตัวเดียวเพราะฟอร์มนั้นไม่มี `select` ตัวที่สอง การเพิ่ม
ช่องสถานะทำให้มันเป็น strict-mode violation — locator ชี้ได้ตัวเดียวเพราะอุบัติเหตุของสิ่งที่
กำลังจะเอาออก **หรือกำลังจะเพิ่ม** (#93) สำรวจทุก `getByRole('combobox'` และ
`getByRole('checkbox'` ใน `e2e/` แล้วมีตัวนี้ตัวเดียว ซึ่งเป็นตัวเลขที่วัดได้ ไม่ใช่การประมาณ

**สองแถวของใบ 16 มาร์กถอยหลัง และนั่นถูกต้อง** *ข้อมูลเดิมยังอ่านได้* เป็น ◐ (ครึ่งแรกเดินแล้วและ
ยังจริง ครึ่งที่อ่านช่องสถานะเดินผ่านตัวควบคุมที่ไม่มีอยู่แล้ว) และ *เปิดกลับมาได้* กลับเป็น ☐
ทั้งแถวเป็นการกดนั้นครั้งเดียว ส่วน *ฟอร์ม เพิ่ม ไม่มีช่องสถานะ* ยังเป็น ☑ เพราะข้ออ้างของมันคือ
**การไม่มี** ซึ่งไม่เปลี่ยน มีแต่คำว่า *checkbox* ในถ้อยคำที่หมดอายุ และนั่นลงวันที่ ไม่ได้ลบ (#54)

  ตาราง แล้วอ่านว่าการแก้ยังปิดได้ `statusatcreation` ตายที่ข้อแรก ฉะนั้นทุกบรรทัดใต้มันถูกเครดิต

  false แล้วรายงาน true* ตัวที่ห้าจึงเป็นประโยคนั้นทำให้รันได้ (#115 จากอีกด้าน) และมันตายที่
  `:673` · ข้ออ้างที่สามไม่มีตัวค้ำ**โดยเจตนา** มันเป็นข้ออ้างของเกณฑ์ 3 ซึ่ง `181a` ถืออยู่

## เรื่องที่จะกินเวลาถ้าไม่รู้ (gotchas)

- **`getByLabel` หาช่องของ `Field` ไม่เจอ** `<label>` คร่อมตัวควบคุมไว้ ข้อความของมันจึงพา
  `<option>` มาด้วย — ใช้ `getByRole('combobox', { name: ... })` และอ่าน snapshot ของรอบที่ล้ม
  ก่อนอ่าน stack ของการรอ (#160)
- **`16a` กับ `18a` ไม่ใช่ชื่อแฟ้มที่ชี้ได้ตัวเดียว** อาร์กิวเมนต์ของ Playwright แมตช์เป็น substring
  `16a` จึงรัน `116a` ด้วย และ `18a` รัน `118a` `180a` `181a` ด้วย — ใช้ชื่อฐานเต็ม
- **`181-the-status-switch.py` มีหกตัว ไม่ใช่สี่** สองตัวอยู่ใน `backend/auth/authorise.js`
  ถ้าจะอ้างจำนวน ให้เกรปแฟ้ม ไม่ใช่นับจากตัวที่เกี่ยวข้อง
- **`DepartmentForm` ยังส่ง `is_active` ตอนสร้าง ทั้งที่ route ไม่อ่าน** อย่าเอาออก มันเป็นบรรทัด
  ที่มัตแตนต์สี่ตัวของ #181 ยึดอยู่ และคอมเมนต์ที่จุดนั้นเขียนไว้แล้ว
- **บรรทัดสุดท้ายของ `180a` ยืนอยู่บนภาควิชา `05` ที่เปิดอยู่** ซึ่งเป็นเงื่อนไขของโลกที่แฟ้มนี้
  ถูกส่งมา ไม่ใช่สิ่งที่มันจัดเอง — แฟ้มที่ปิด `05` ก่อนหน้ามันจะทำให้บรรทัดนั้นแดง
- **clone อื่นยังมี `master` ที่ตายแล้ว** — `git branch -m master main && git fetch origin &&
  git branch -u origin/main main && git remote set-head origin -a`
- **พอร์ต 5100/3100 อยู่ในช่วงที่ Windows จองไว้บางเครื่อง** อ่าน
  `netsh int ipv4 show excludedportrange protocol=tcp` ก่อนเชื่อว่า "มีอะไรรันอยู่"
- **อย่า `git add` อะไรใต้ `DEEP-QA-BACKEND/` หรือ `_local/`** และ `git add -A` ถูกปฏิเสธที่นี่ —
  stage ทีละ path
- **Playwright ผ่าน Bash ถูกปฏิเสธที่เครื่องนี้** ใช้เครื่องมือ PowerShell รันคำสั่งเดียวกัน
- `python mutation/anchors.py` ต้องมี `PYTHONIOENCODING=utf-8`
- คอนโซลเป็น cp874 — **อย่าพิมพ์ไทยหรือ ☑⚙◐☐ ออกมาทาง Bash** อ่านด้วยเครื่องมือ Read
  (รวมถึงการ redirect ของ `print` ใน python ซึ่งก็ไปตาม codepage ของคอนโซล — เขียนด้วย
  `io.open(..., encoding='utf-8')`)
- **อย่า rewrap ย่อหน้าไทยด้วย `textwrap`** มันต่อบรรทัดด้วยช่องว่าง แล้วคำไทยที่ถูกตัดข้ามบรรทัด
  จะกลายเป็นสองคำ — ขึ้นบรรทัดใหม่ด้วยมือ
- **heredoc กิน backslash** สคริปต์แก้ไฟล์ที่มี `\n` อยู่ในสตริงต้องเขียนลงแฟ้ม ไม่ใช่ส่งผ่าน
  heredoc — ตัวบอกคือ count 0 ไม่ใช่ error
