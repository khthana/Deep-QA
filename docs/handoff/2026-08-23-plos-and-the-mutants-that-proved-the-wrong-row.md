## 3. เรื่องที่กินเวลา session นี้ไปมากที่สุด — หลักฐานผิด ไม่ใช่โค้ดผิด

มัตแตนต์สองตัวดูเหมือนฆ่าแถวของมันสำเร็จ ทั้งที่จริง ๆ มันฆ่าแถวก่อนหน้า
สามกลไกที่ทำให้หลักฐานผิดโดยดูน่าเชื่อ แต่ละอย่างกินเวลาไปหนึ่งรอบเต็ม ๆ

- **`19a-plos.spec.js` รันแบบ `serial`** แถวแรกที่ตายหยุดทุกแถวที่เหลือ
  มัตแตนต์ทุกตัวจึงรายงานว่า `1 failed` เหมือนกัน **ต้องอ่านจากชื่อเทสต์ที่ตาย ห้ามอ่านจากตัวเลข**
  สองมัตแตนต์ที่ดูเหมือนผ่านที่แท้จริงไปฆ่าแถวก่อนหน้า เขียนใหม่เป็น `childpath` กับ `ordernotsaved`
- **การฆ่า task ของ Playwright ทิ้ง webServer ไว้บนพอร์ต 3100/5100** ทุกรอบหลังจากนั้น
  ตายทันทีด้วย *is already used* และสคริปต์เดิมก็อาจยังวิ่งอยู่
  **ต้องดูว่า process ตายจริงก่อนสั่งรอบใหม่** ไม่งั้นสองรอบจะ `save`/`restore` ไฟล์ชุดเดียวกัน
  และ backup ของ harness จะเป็นสำเนาของไฟล์ที่ *ถูกมัตแตตไปแล้ว* — restore ทุกครั้งจะคืนความพังกลับมา
- **harness จับกรณีที่สตริงตรงหลายที่ได้ แต่การตรงแบบ substring ยังผ่านเงียบ ๆ**
  หลังจัดย่อหน้าใหม่ มัตแตนต์ที่เขียนด้วยย่อหน้าเก่ายัง “ตรง” อยู่ แต่แก้คนละบรรทัด

## 4. สิ่งที่ค้างอยู่ตรงหน้า

**เก้าแถว ☐ ของ #19 รอเดิน** คือ การซ้อนที่มองเห็น · ข้อย่อยของข้อย่อย ·
สี่ตัวเลือกประเภทในฟอร์ม · ป้ายประเภทในตาราง · ข้อความรหัสซ้ำที่มีคำว่า *ในหลักสูตรนี้* ·
ข้อความในกล่องยืนยัน · เมนูซ้ายของสามบัญชี · หัวเรื่องกับย่อหน้า (รวมช่องว่างกลางคำ) · breadcrumb
ฐานของเครื่องเดิน seed ใหม่แล้วใน session นี้

**สองแถวเรื่องการซ้อนถูกชี้มาที่ `PLO-12` แทน `PLO-14`** — `PLO-14` ไม่มีใน seed
มันถูกสร้างโดยแถว ⚙ ซึ่งเดินใน schema ของ e2e คนเดินด้วยมือจึงไม่มีทางเห็น
นี่คือสิ่งที่ต้องตรวจก่อนส่งใบเดินงานทุกครั้ง — แถวที่ seed รองรับไม่ได้คือการเสียเวลาของคนเดิน

**หน้า PLO ยิง `listPlos({})` รอบที่สองเมื่อมีตัวกรอง** เพื่อให้ช่อง *อยู่ใต้ข้อ*
เสนอข้อของหลักสูตรที่ฟอร์มอยู่ ไม่ใช่ที่ตารางกรองไว้ ชุดเต็มกับ baseline นิ่งทั้งคู่
แต่ `waitForList` มี response เพิ่มอีกหนึ่งตัวที่มัน resolve ได้ ถ้าวันหนึ่ง flake ที่นี่คือที่ที่ควรดูก่อน

**#96 ยังเปิดอยู่** ตั๋วนี้ปิดจุดบอดของมันใน seed ไปแล้ว แต่คำถามเรื่องการเรียงรหัสยังไม่ตอบ

**#95 ยังเปิดอยู่** และ **ใบเดินงานของ #94 ยังค้างอยู่เหมือนเดิม**

## 5. กับดักที่เพิ่มจากฉบับก่อน

- **อ่านผลมัตเตชันจากชื่อเทสต์ที่ตาย ห้ามอ่านจากจำนวน** โดยเฉพาะ spec ที่รัน `serial`
- **`Number(null)` คือ `0`** ช่องตัวเลขที่บังคับต้องเช็ค null แยกก่อน `Number.isInteger`
- **รูปร่างกับช่วงเป็นการตรวจสองอย่าง** `2147483648` เป็นจำนวนเต็มที่คอลัมน์ `integer` รับไม่ได้
- **`\d` ใน template literal ของ JS กลายเป็น `d`** ใช้ `[0-9]` หรือ `\\d`
- **`innerText` ไม่ใส่ช่องว่างให้ element ที่ห่างกันด้วย margin** (`PLO-2-1ข้อย่อย`)
- **Playwright `selectOption` ไม่รับ `{label: RegExp}`**
- **`eslint` มี config เฉพาะใต้ `frontend/`** ไฟล์ของ backend กับ e2e ตรวจด้วย `node -e "require(...)"`
- **อย่าตรวจว่า backend รู้จัก route ใหม่ด้วยการ `curl` แบบไม่เข้าระบบ** ทุก path ตอบ 401 เหมือนกันหมด
- **process ที่ค้างบนพอร์ตอาจเป็นของ agent ไม่ใช่ของคน** ดู PID กับเวลาเกิดก่อนสรุป
- **ในข้อความไทยบน JSX ห้ามขึ้นบรรทัดใหม่กลางคำ** JSX ต่อบรรทัดด้วยช่องว่างหนึ่งตัวเสมอ
- **A fresh clone lands on a dead `master`.** Run, verbatim:
  `git branch -m master main && git fetch origin --prune && git branch -u origin/main main`
