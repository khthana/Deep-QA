## 2. The browser seam (#65)

There are now two seams the rebuild tests at:

- **the backend HTTP surface** — `backend/test/*.test.js`, the original seam;
- **the browser** — `e2e/`, Playwright against the real screens and the real server.

The browser seam asserts **behaviour**. Anything a checklist row states in terms of **appearance**
— colours, wording, what is in a menu, a breadcrumb, "this is text and not a control" — stays a
hand-walked row. Where a row is half behaviour and half appearance, the row keeps its ☐ and gains
a note saying which half the spec already proves.

Acceptance documents therefore use a **four-valued legend**:

| Mark | Meaning |
|---|---|
| ☑ | hand-walked and passing |
| ◐ | half-walked |
| ☐ | not walked |
| **⚙** | covered by the browser seam; no hand-walk owed. The row names the spec file that covers it. |

### Mutation testing is the entry price for a ⚙

No row is marked ⚙ on the strength of a passing test. Every new assertion is proved by breaking the
code it is supposed to be about and watching that assertion — **that one, not an earlier one** —
fail. `16-subjects.md` records fourteen mutants and fourteen kills; the other documents record
theirs the same way.

Two things learned doing it, both of which cost time:

- **A serial spec file masks later kills.** With `test.describe.configure({ mode: 'serial' })`, a
  mutant that kills test 2 skips tests 3–8, so an assertion in test 6 looks unproved. Re-run the
  mutant with `-g` filtered to the later test.
- **`| tail -20` truncates the Playwright failure detail**, so the run proves only "1 failed" and
  not *where*. Redirect the whole log to a file and grep it for `Error: ` and `> <line> |`.

**The mutation scripts are in the repo, under `mutation/`.** Seventy-nine mutants across six
tickets, seventy-eight of which still apply to the code as it stands; `mutation/README.md` says how
to run one and what a `MISS` means. They used to live in the session scratchpad, which meant every
acceptance document cited evidence nobody could open again.

## 3. Running it

```
docker start deep-core-postgres
cd db       && npm run reset && npm run migrate && npm run seed
cd backend  && npm start          # :3000
cd frontend && npm start          # :5000
```

- Postgres on **port 5433** (machine-specific — `DB_PORT=5433`), database `deep_qa`, user `deep_core`,
  **schema `deep_core`**: any `psql` session needs `set search_path=deep_core`.
- Every seeded account's password is `deep-core-local`. The database is currently at a clean seed.
- **Restart the backend, do not merely check that something is listening.** A process started before
  a route existed answers 404 and reads as a frontend bug; this cost a false failure during #57.
- Backend tests: `cd backend && npm test` (`node --test "test/*.test.js"`) —
  **270 pass, 0 fail** at `HEAD`, about 40 seconds.
- Frontend has no typechecker (CRA JS). The compile check is `cd frontend && npx react-scripts build`.

### The e2e suite

```
cd e2e && npm test          # playwright test — 84 passed at HEAD, about 9 minutes
```

- It runs against **its own stack**: backend on **3100**, frontend on **5100**, schema
  **`deep_core_e2e`**. The dev stack on 3000/5000 and schema `deep_core` is untouched, so a run
  cannot damage whatever is on screen.
- `global-setup` **drops, migrates and seeds `deep_core_e2e` on every invocation**, and
  `reuseExistingServer: false` means the servers are started fresh too. There is no state to clean
  up between runs and no need to reset anything by hand.
- `workers: 1`. The specs share one schema and several write into the lists they then count.
- Spec files are named for the ticket they serve: `11a-users-refusals`, `11b-users-import`,
  `12a-role-grants`, `13a-user-history`, `14a-departments-refusals`, `14b-departments-import`,
  `16a-subjects`, `17a-students-refusals`, `17b-students-import`, `17c-students-register`,
  `18a-program-subjects`, `18b-program-subjects-import`, `18c-program-subjects-refusals`.
- Shared helpers are in `e2e/support/` — one module per screen, plus `accounts.js`, `auth.js`,
  `import-panel.js`, `env.js`. A new spec should reach for those before writing its own selectors.

## 6. Gotchas that cost time

- **A fresh clone lands on a dead `master`.** Run, verbatim:
  `git branch -m master main && git fetch origin --prune && git branch -u origin/main main`
- **Do not print Thai or box-drawing characters through the Bash tool.** The console is cp874 and
  `print()` raises `UnicodeEncodeError`. Verify edits with `grep -c`, `grep -o`, `cut -c1-N` or
  `git diff --numstat`. Python edits must use `io.open(..., encoding='utf-8', newline='\n')` and
  should assert the marker count before replacing. For long or backtick-bearing Thai, use the Write
  tool rather than a heredoc.
- **`rev` does not exist in Git Bash.** To read a checklist tick use `sed -n 'Np' | grep -o` on the
  box characters rather than reversing the line.
- **Write `gh` bodies to a file and pass `--body-file` with an absolute path**, run from inside the
  repo. Heredocs break on apostrophes. `$TMPDIR` is unset under the Bash tool — it expanded to `/`
  and the write was refused; use the session scratchpad path in full.
- **A literal U+FEFF written into source by a script is invisible and wrong.** Emit the six-character
  escape instead, as `backend/lib/csv.js:27` has it.
- **A backup/restore keyed by basename collides on Windows.** `mutate*.py` back files up by their
  `FILES` dict key, because two different paths can have the same file name and the filesystem is
  case-insensitive as well.
- **`17b-students-import.spec.js` row 15 flaked twice, on a slow run** - in the full suite and then again under `-g "row 15"`. After `page.reload()` the
  register's own pager read `ทั้งหมด 0 รายการ` where 173 was expected; the same file passed alone and
  the full suite passed twice around it. It looks like #68 - a list answer arriving after the one the
  screen should be showing - rather than anything about the import. If it recurs, that is the ticket
  to attach it to, not a new one.
- **`toBeDisabled()` reports a disabled `<option>` as enabled** — it checks the controls a person
  types into. Assert `toHaveAttribute('disabled', '')` instead.
