## 3. เรื่องที่กินเวลา session นี้มากที่สุด — มัตแตนต์ที่ทำให้ route ตอบ 500

`nopaging` ตั้งใจจะพิสูจน์แถวเรื่องการแบ่งหน้า แต่มันไปฆ่าแถวที่หนึ่ง เพราะมันเขียนว่า
`LIMIT 100 OFFSET 0` ซึ่งไม่ได้ใช้ `$3` กับ `$4` เลย route จึง bind สี่พารามิเตอร์เข้าคำสั่งที่ต้องการสอง
รายการตอบ **500** และแถวที่หนึ่งตายด้วย `expect(response.status()).toBe(200)`
นั่นคือ **การพัง ไม่ใช่หลักฐานเรื่องการแบ่งหน้า** เขียนใหม่เป็น
`LIMIT ($3 + 100) OFFSET ($4 * 0)` ทั้งสองพารามิเตอร์ยังถูกใช้ หน้ากว้างพอเสมอและเริ่มที่แถวบนเสมอ
แถว 1–3 จึงผ่าน และแถวเรื่องการแบ่งหน้าเป็นแถวแรกที่สังเกตว่าหน้าสองคือหน้าหนึ่งอีกครั้ง

บทเรียนที่กว้างกว่านั้น — **มัตแตนต์ที่ทำให้โปรแกรมพังไม่ใช่มัตแตนต์** มันต้องเปลี่ยน
*พฤติกรรมหนึ่งอย่าง* ไปเป็นอีกอย่างหนึ่ง ไม่ใช่ทำให้โปรแกรมหยุดทำงาน เพราะทุกแถวตายเมื่อหน้าจอพัง
และการตายของแถวแรกก็ไม่ได้พูดอะไรเลยเกี่ยวกับสิ่งที่มัตแตนต์อ้างว่าตัวเองพูดถึง

**แล้วก็เจอกับดักเดียวกันอีกตัวหนึ่ง ในรอบทบทวนโค้ด** — `editnotsaved` เดิมเขียนว่า `rubric_name_th = rubric_name_th,` ซึ่งทำให้ `$3` ไม่ถูกอ้างถึงที่ไหนเลย ขณะที่ยังส่งค่าครบหกตัว PostgreSQL ตอบ `42P18 could not determine data type of parameter $3` PUT จึงตอบ **500** แต่อาการที่เห็นในเบราว์เซอร์คือ "ชื่อไม่เปลี่ยน" สิ่งเดียวกับที่การฆ่าที่ถูกต้องควรเห็น มันจึงรอดการตรวจมาได้ วิธีแยกคือเอามัตแตนต์ไปรันที่ `backend/test/rubrics.test.js` ซึ่งเช็ค status ตรง ๆ ถ้าเห็น 500 ก็คือการพัง เขียนใหม่เป็นการเปลี่ยน *ค่าที่ผูก* แทนตัว SQL — `draft.values.rubric_name_th` เป็น `existing.rubric_name_th` `$3` ยังถูกใช้ PUT ตอบ 200 และชื่อเพียงแต่ไม่เปลี่ยน ตอนนี้มันฆ่าเทสต์ที่ `21a-rubrics.spec.js:153` โดยแถว 1–5 ยังผ่าน

มัตแตนต์อีกตัวที่เพิ่มทีหลังคือ `staleafterasave` เดิมมีสิบสองตัว แต่ครึ่งแรกของแถว
*เพิ่มแล้วเห็น* ยังไม่มีมัตแตนต์ของตัวเอง `editnotsaved` ฆ่าแถวเดียวกันด้วยการแก้ไข
ครึ่งแรกจึงไม่มีหลักฐาน ตอนนี้มีแล้ว และมันฆ่าแถว 6 โดยแถว 1–5 ยังผ่าน

## 5. กับดักที่เพิ่มจากฉบับก่อน

- **มัตแตนต์ต้องเปลี่ยนพฤติกรรม ไม่ใช่ทำให้โปรแกรมพัง** ถ้าแถวที่ตายคือแถวแรก
  และสาเหตุคือ 500 หรือหน้าจอขาว มัตแตนต์นั้นไม่ได้พิสูจน์อะไรเลย ต้องเขียนใหม่
- **SQL ที่มัตแตตต้องใช้พารามิเตอร์ครบเท่าเดิม** `node-postgres` นับจำนวนที่ส่งกับที่สเตตเมนต์ขอ
  เลขหนึ่งหายไปคือ error ไม่ใช่ค่า default — ใช้เลขคณิตศาสตร์กับพารามิเตอร์เดิมแทน
- **`display_order` เป็น `NOT NULL DEFAULT 0`** ลำดับซ้ำจึงเป็นสภาพตั้งต้น ไม่ใช่กรณีขอบ
  รายการที่แบ่งหน้าโดยไม่มีตัวตัดสินลำดับซ้ำ จะแสดงแถวหนึ่งสองหน้าและอีกแถวหายไปเลย
- **คอลัมน์แรกของตารางคือกุญแจที่ `e2e/support/pager.js` ใช้** ตารางที่เอาอย่างอื่น
  ขึ้นนำจะทำให้ helper แยกสองหน้าไม่ออก โดยเฉพาะคอลัมน์ที่มีค่าซ้ำกันได้
- **`getByText` ที่จับเศษของประโยคจะชนกับคำอธิบายในฟอร์ม** ที่นี่ต้อง assert
  ประโยคเต็ม ไม่ใช่เศษของมัน — เศษอย่างเดียวจะผ่านกับหน้าจอที่ปฏิเสธเงียบ ๆ ด้วย
- **หน้าที่แบ่งหน้าไม่พาคนไปหน้าที่แถวที่เพิ่งบันทึกไปอยู่** ทั้งระบบ
  spec จึงต้องสร้างแถวด้วยลำดับ `0` เพื่อให้แน่ใจว่าแถวนั้นอยู่หน้าที่กำลังดูอยู่
- **A fresh clone lands on a dead `master`.** Run, verbatim:
  `git branch -m master main && git fetch origin --prune && git branch -u origin/main main`
