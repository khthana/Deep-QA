## #190 — คำที่ไม่มีอะไรทำให้พังได้

ใบ `question` จากรอบรีวิวของ #185 — เกล็ดของ Rubric วาด `Rubric <รหัส>` ขณะที่อีกสองชนิด
วาดค่าเปล่า `docs/06` §Out of Scope บอกว่าใครตอบ งานจึงเป็นการวัดแล้วถาม และคำตอบคือ
**คงไว้**

ตัวเลขที่เอาไปเสนอ สี่ข้อ

- เกล็ดข้างเคียงเขียนคำนี้ **สามที่** ไม่ใช่สองที่อย่างที่ใบเขียน และที่สามคือเกล็ดถัดไป
  บนแถวเดียวกัน แถวจึงอ่านคำนี้สามครั้งในสี่ช่อง ซึ่งเป็นข้อโต้แย้งที่ใบไม่ได้เขียนเอง
- **จอปลายทางเองวาดหัวเรื่องว่า `เกณฑ์การให้คะแนนของ Rubric {rubric_code}`**
  (`RubricCriteria.js:222`) คือคำแล้วรหัสเปล่า ส่วนชื่ออยู่บรรทัดรอง เกล็ดไม่ได้ตั้งธรรมเนียม
  ขึ้นเอง มันทำตามจอ
- **ความกว้าง** วัดแล้วเล็กกว่าที่ใบกลัว ชื่อไทยของ Rubric ใน seed ยาว 13–27 ตัวอักษร
  ป้ายคงที่ในแผนที่เกล็ดยาวถึง 38 และเกล็ด**กิจกรรม** ซึ่งเป็นชนิดพี่น้องที่ยืนตำแหน่ง
  เดียวกัน วาดชื่อเปล่ายาว 44 ตัวอักษรอยู่แล้ววันนี้
- **`rubric_name` ไม่มีเป็นคอลัมน์** มีแต่ `rubric_name_th` กับ `rubric_name_en`
  (ส่งมาทั้งคู่แล้ว) ข้อเสนอข้อ 3 จึงพ่วงการเลือกภาษาที่อีกสองชนิดไม่มี

และราคาที่ใบประมาณไว้ยาวเกินจริงหนึ่งข้อ คือสำมะโนของ #93 ซึ่งมองตระกูลนี้ไม่เห็น
โดยโครงสร้าง — docstring ของมันเขียนเองว่า `rubric_code` ไม่ใช่ `_id` (รันไว้เป็นตาข่าย
อยู่ดี problems 0 ทั้งสองตัว)

### คำตอบว่า *คงไว้* ไม่ได้แปลว่าไม่มีงาน

*เมื่อข้อเสนอของตั๋วถูกปฏิเสธ มัตแตนต์ที่ต้องเขียนคือข้อเสนอนั้นเองที่ทำให้รันได้* (#48)
ข้อเสนอที่ถูกปฏิเสธคือ *วาดรหัสเปล่า* · แถว 3 ยืนยันคำนำหน้ามาตั้งแต่ #185 แล้ว
(`toEqual` ที่ `185a:161` เกิดมาพร้อมคำนั้นที่ `42be4bf`) สิ่งที่ไม่มีคือ**ตัวที่ทำให้
ข้ออ้างนั้นเสี่ยง** — `rubriccodeisid` ซึ่งยิงบรรทัดเดียวกันนั้น **เก็บคำไว้** แล้ว
เปลี่ยนรหัสเป็น id *มัตแตนต์สองตัวที่แปรคุณสมบัติเดียวกันมองคุณสมบัติที่สามไม่เห็น* (#96)

`rubricwordgone` คือตัวนั้น **ล้ม `185a` แถว 3 ตัวเดียว** ตายที่ `toEqual` อ่าน `RUB-02`
แทน `Rubric RUB-02` · รอบสะอาดหลัง restore ผ่าน **6 จาก 6** ที่ 25.7 วินาที (รอบที่ลง
มัตแตนต์ ล้ม 1 ผ่าน 5 ที่ 37.4 วินาที) · `anchors.py` รันสองรอบ รอบแรก
ทันทีที่เพิ่มมัตแตนต์ ซึ่งเป็นรอบที่จับได้ว่า
`mutation/README.md` ยังเขียน 9 ตัวกับ 869 ตัว (`catalogue … problems 1`) และรอบที่สอง
หลังแก้ตัวเลขเป็น 10 กับ 870 ได้ **problems 0 ทั้งสี่คำถาม**

ห้าตัวเดิมฝั่งเปลือก **ไม่ได้** กวาดซ้ำรอบนี้ ซึ่งเป็นฝาแฝดของเหตุผลที่ #191 ต้องกวาด:
สิ่งที่ทำให้จำนวนที่ฆ่าได้หมดอายุคือฟิกซ์เจอร์หรือไฟล์ spec ที่ขยับ (#48) รอบนี้ไม่มีอะไร
ขยับ การเพิ่มมัตแตนต์ไม่ได้ทำให้ของตัวอื่นหมดอายุ

ชุดเต็มเบราว์เซอร์ไม่ได้รันซ้ำรอบนี้ และเหตุผลอยู่ที่ว่าไม่มีไฟล์ใดใน `e2e/` `frontend/`
หรือ `backend/` เปลี่ยนเลย — ที่เปลี่ยนคือ `mutation/` กับเอกสาร ชุดทดสอบจึงเป็นตัวเดิม
ทุกตัวอักษร (ตัวเลขล่าสุดของมันคือ 693/693 ที่ 37.3 นาที ในหัวข้อของ #191)

## #189 — คำเดียว สองจอ และข้อสอบที่ตอบคนละทาง

ใบ `question` จากรอบรีวิวของ #185 และเป็นฝาแฝดของ #190 — เกล็ดสุดท้ายบนที่อยู่

ประโยคเดียวต่อคำ · คำตอบของเจ้าของข้อกำหนดคือ **ให้อ่านตามเส้นทาง และใช้คำว่า
*เกณฑ์การบรรลุผล***

สิ่งที่ใบเขียนถูกสามข้อ ส่วนที่ไม่ถูกเป็นของใบเองสองข้อ

- ชื่อจอที่ใบเขียนคือ *เกณฑ์การวัดและประเมินผลของ CLO* ซึ่งเป็น**ชื่อที่สี่** ไม่ตรงกับ
  หัวเรื่องของจอ (`AchievementCriteria.js:188`) ไม่ตรงกับใบ `29` และไม่ตรงกับอภิธานศัพท์
  — *ตัวระบุที่ใบยกมาเป็นข้ออ้างเหมือนตัวเลขของมัน* (#54) ซึ่งเป็นการมาถึงแบบเดียวกับ
  ที่ #190 เจอ ห่างกันหนึ่งใบ
- ใบอ้าง ADR-0004 ซึ่งตรึง `:sectionId` ไว้เป็นตัวพาบริบทตอนเรียน ส่วน `<screen>` ในนั้น
  เป็นที่ว่าง ADR ไม่ได้พูดถึงคำท้ายที่อยู่เลย และการสร้างใหม่เปลี่ยนคำท้ายมาแล้วหนึ่งคำ
  คือ `activityScores/AssessmentCriteria` เป็น `evidence`

และสำมะโนของใบนับด้วยสตริง ไม่ใช่ด้วยกลไก (#174) ชนิดของคำถามคือ *คำที่เป็น segment
สุดท้ายของที่อยู่มากกว่าหนึ่งที่* นับอย่างนั้นบนที่อยู่ 35 ที่ที่เสิร์ฟอยู่ มีคำท้ายต่างกัน 34 คำ
และ `criteria` เป็นคำเดียวที่สองจอเข้าถึง — หัวเรื่องของใบจึงถูก ด้วยสำมะโนที่ตอบอย่างอื่น
ก็ได้ และผลที่ตามมาคือคำตอบนี้ไม่ขยายไปกรณีที่สอง เพราะไม่มีกรณีที่สอง

### ข้อสอบเดียวกับที่ #190 ใช้ตัดสิน ตอบคนละทางที่นี่

#190 เก็บคำว่า *Rubric* ไว้ด้วยเหตุผลว่าเกล็ดทำตามจอ — จอปลายทางเขียนหัวเรื่องของตัวเอง

ตอบคำเดียวกัน และไม่มีแหล่งไหนตอบคำที่เกล็ดวาดอยู่วันนี้ คือ `CONTEXT.md:76`
(**Achievement Criteria (เกณฑ์การบรรลุผล)**) หัวเรื่องของจอที่ `AchievementCriteria.js:188`
ซึ่ง `29a:101` ยืนยันไว้ และลิงก์ขาเข้าที่ `CourseOutcomes.js:327` ซึ่งเขียนคำนี้ทั้งใน

## เรื่องที่ต้องรู้ก่อนเริ่ม (gotchas)

- **อย่ารัน `npm run format` และอย่ารัน `npx prettier --write` บนไฟล์ของ `frontend/`**
  prettier ที่ติดตั้งอยู่ใหม่กว่าสไตล์ที่คอมมิตไว้ มันจัดไฟล์ใหม่ทั้งไฟล์และเขียนทับบรรทัด
  ที่มัตแตนต์ยึดอยู่ โดย diff อ่านเหมือนช่องว่าง (#189 เจอกับ `Mainpage.js` ซึ่งมีมัตแตนต์
  ยึดอยู่ห้าตัว) ไฟล์ที่สะอาดอยู่แล้วก็ไม่ผ่านรุ่นนี้ คือ `Mainpage.js` กับ `CourseOutcomes.js`
  ถ้ารันไปแล้วให้ `git checkout --` ไฟล์นั้น ลงแก้ด้วยมือใหม่ แล้วรัน
  `python mutation/anchors.py`

- **clone บนเครื่องอื่นยังมี `master` ที่ตาย** `origin/master` ไม่มีแล้ว clone ไหนที่ยังไม่ได้ซ่อมต้องรันมือ:

  ```bash
  git branch -m master main && git fetch origin --prune && git branch -u origin/main main
  ```

- **รอบที่ถูกสั่งหยุดอาจยังไม่หยุด (#146) และวันนี้ตัวบอกคือพอร์ต** playwright ของการกวาดที่ถูกฆ่า
  ตอนครบเวลายังมีชีวิตอยู่สองชั่วโมงให้หลัง ถือพอร์ต 3400/5310 ไว้ รอบใหม่จึงล้มด้วยข้อความของ
  playwright เอง *http://localhost:3400/api/health is already used* **ให้ไล่ต้นไม้ของโปรเซส
  (`taskkill //PID <pid> //T //F`) ไม่ใช่ฆ่าตัวที่ฟังพอร์ตตัวเดียว** เพราะตัวแม่ตั้งตัวใหม่ขึ้นมาแทน ·
  **และห้ามแตะพอร์ต 3000/5000** — `grader-app-1` นั่งที่ 3000

  รันเบื้องหลังแบบไม่ต่อ `tail` แล้วค่อยอ่านไฟล์ และ **ขีดจำกัดของงานเบื้องหลังคือสองชั่วโมง**
