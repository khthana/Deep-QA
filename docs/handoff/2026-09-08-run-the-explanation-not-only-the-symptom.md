## สามตั๋วที่ปิดรอบนี้

### #102 — ทุกหลักสูตรใน seed อยู่ภาควิชาเดียว จึงไม่มี fixture ไหนพูดถึงข้อบกพร่องได้

หัวข้อของตั๋วบอกว่า `reachablePrograms` ลบทิ้งทั้งก้อนได้โดยไม่มีเทสต์ล้ม — แทนที่ตัวกรองด้วย
`TRUE` แล้ว **ล้มเจ็ดแถว** และย่อหน้าถัดไปของตั๋วเองก็บอกว่าทำไม นี่คือรูปแบบใหม่ของคำวินิจฉัยที่
ผิด: **ไม่ใช่เก่า แต่ไม่เคยจริง** — อ่านตั๋วให้จบก่อนเชื่อประโยคแรก สิ่งที่ไม่ได้ถูกพิสูจน์จริง ๆ แคบกว่า
ทั้งสองประโยค คือ *กิ่งภาควิชา* ของ `coveredScopes` และคำตอบคือ **fixture** — `0101` ของภาควิชา
`01` เข้า `db/seed.js` ทำให้มัตแตนต์จากฆ่า 2 แถวเป็น **7** แถวใน 5 suite

### #67 — convention เป็นคำกล่าวเรื่องพฤติกรรม ไม่ใช่เรื่องคอลัมน์

แถวตัวอย่างในเทมเพลตนำเข้านักศึกษาใช้รหัส `66010001` ซึ่งเป็นนักศึกษาจริงใน seed ดาวน์โหลด
เทมเพลตแล้วอัปโหลดกลับโดยไม่แก้ — สิ่งแรกที่ทุกคนทำกับเทมเพลต — จึง**เขียนทับคน** แล้วรายงานว่า
*นำเข้าสำเร็จ 1 รายการ* ตั๋วนี้ถูกตอบไปแล้วสามที่ (#25 #26 #34) ด้วย `66019999` *รหัสที่ไม่มี cohort
ไหนไปถึง* และคำตอบนั้นถูกที่นั่น เพราะสามที่นั้น **ปฏิเสธ** นักศึกษาที่ไม่รู้จัก ส่วนที่นี่ **สร้าง** —
`grep` ที่เหมือนกันไม่ใช่ยามตัวเดียวกัน อีกครั้ง เทมเพลตนี้จึงส่งหัวตารางอย่างเดียว

เทสต์ที่ผ่านเพราะข้อบกพร่อง มักอธิบายตัวเองไว้ในคอมเมนต์ของมันเอง: `students.test.js` เคยยืนยันว่า
จำนวนแถวเท่าเดิมหลังอัปโหลด ใต้คอมเมนต์ที่เขียนว่า *แถวตัวอย่างชื่อนักศึกษาที่ seed มีอยู่แล้ว จึงไม่
เพิ่มใคร* — มันเห็นการชนแล้ว เข้าใจแล้ว และบันทึกไว้เป็นข้อดี

### #101 — ตั๋วอธิบายกลไกที่ไม่มีอยู่จริง และของจริงแย่กว่า

หน้าผลการเรียนรู้มีตัวเลือก *ทุกหลักสูตร* ทำให้ผู้ดูแลภาควิชาเห็นรายการที่ปนสองหลักสูตรบนหน้าที่
**ลบข้อมูลได้** ขณะที่ `UNIQUE (program_id, outcome_code)` แปลว่าทั้งสองหลักสูตรมี `PLO-1` ของตัวเอง

ตั๋วเขียนว่า *ห้าหน้าของ `0501` มาก่อนแถวแรกของ `0503`* — `grep -c Pager` ตอบ **0** หน้านี้ไม่แบ่งหน้า
โดยตั้งใจ และ docstring ของไฟล์เขียนเหตุผลไว้เอง ของจริงคือ **56 แถวต่อกันในการเลื่อนเดียว** ไม่มี
*หน้า 1 จาก 6* บอกว่ายังมีต่อ นี่คือคำวินิจฉัยผิดชนิดที่สี่ ต่อจาก **เก่า** (#66 #111 #55) **ไม่เคยจริง**
(#102) และ **เหมารวม** (#122): **ตั๋วบรรยายกลไกที่ไม่มีอยู่** — ตั๋วที่อธิบาย *ทำไมมันดูเป็นแบบนั้น* ได้
เสนอสาเหตุไว้ และสาเหตุคือครึ่งที่ตรวจง่ายที่สุด **รันคำอธิบาย ไม่ใช่แค่รันอาการ**

*"Prefer required unless a caller turns up"* — **มี caller** คือช่อง *อยู่ใต้ข้อ* ของฟอร์ม ที่ดึงผล
การเรียนรู้ทุกข้อในสิทธิ์มาเติม คำตอบไม่ใช่ *คงไว้เป็น optional* แต่คือทำให้ required **แล้วแก้ caller
ให้ขอสิ่งที่มันต้องการจริง** ฟอร์มจึงอยู่ในตั๋วเดียวกัน — **ตั๋วที่พูดว่า *unless X* ได้บอกแล้วว่าให้ไปดูอะไร**

สี่หน้าพี่น้องที่ตั๋วสั่งให้อ่าน ถูกอ่านแล้วและไม่มีหน้าไหนเปลี่ยน: ทั้งสี่ยังมี *ทุกหลักสูตร* และทั้งสี่
**แบ่งหน้า** สิ่งที่ตัดสินอยู่ที่ schema ไม่ใช่รสนิยม — รหัส PLO เป็นตัวชี้แถวอันเดียวในห้าหน้าที่ซ้ำ
ข้ามหลักสูตรได้

เกณฑ์ข้อสี่ถูกย้ายเข้าไปอยู่ใน route: `REFUSALS.ploProgramRequired` — **เกณฑ์ที่หน้าจอถืออยู่ ย้ายเข้า
route ได้เกือบเสมอ และที่นั่นลืมไม่ได้** ส่วนตัวกันฝั่งหน้าจอยังอยู่ และบันทึกว่า **พิสูจน์ด้วยมัตแตนต์
ไม่ได้** เพราะเอาออกแล้ว `openPlos` ล้มสิบหกจากสิบเจ็ดแถว ซึ่งเป็นรูปทรง premise ของ #85

## /code-review ของ #101 เอง เจอห้าข้อ และข้อแรกคือเกณฑ์รั่ว

- **เกณฑ์ข้อ 4 รั่วที่คำขอที่มันตั้งชื่อตาม** — query string ซ้ำ key ได้ และ Express ส่งคู่นั้นมาเป็น
  array `blankToNull` เป็นเรื่องของ *ช่องว่าง* ไม่ใช่ *รูปทรง* จึงปล่อยผ่าน
  `?program_id=0501&program_id=0503` แล้วตอบ **200 พร้อมรายการว่าง** วัดด้วย suite ใช้แล้วทิ้ง
  ภายในชั่วโมงเดียว **ยามที่เขียนด้วย helper ของช่องกรอกฟอร์ม ถูกบอกเรื่องค่า ไม่ได้ถูกบอกเรื่องรูปทรง**
- **เกณฑ์ข้อ 3 ไม่มีแถวของตัวเอง** ถูกเขียนเป็นประโยคที่สองบนแถวของ #19 ขณะที่ตารางมัตแตนต์
  ข้างล่างอ้างว่าฆ่า *สองแถว* — คอลัมน์ *แถวที่ตาย* ชี้ไปยังแถวที่ตารางเกณฑ์ไม่มี ซึ่งเป็นรูปกลับด้าน
  ของ `10:nowrite` ใน #97 และ**การตรวจสองทิศทางที่คลังมีอยู่ มองไม่เห็นทั้งคู่** อ่านคอลัมน์ *แถวที่ตาย*
  เป็นคำกล่าวอ้างเกี่ยวกับตารางเกณฑ์ด้วย
- **มัตแตนต์ยึดกับคอมเมนต์ภาษาไทย** — บรรทัดที่ขยับง่ายที่สุดบนจอ **ยึดมัตแตนต์กับโค้ดที่มันทำพัง
  ไม่ใช่กับข้อความข้าง ๆ** ข้อความมีไว้ให้เขียนใหม่
- **สองคำที่ *ยังไม่มีเทสต์*** บันทึกบนแถวของมันเอง: *หลักสูตรแรกที่ยังใช้งานอยู่* (ทุกหลักสูตรใน seed
  ยังใช้งานอยู่) และประโยคของบัญชีที่ไม่มีหลักสูตรเลย (#102 ให้ `0101` กับภาควิชา `01` ไปแล้ว จึงไม่มี
  บัญชีไหนเดินไปถึง) — คำตอบที่สามของ #107 ไม่ใช่ความเงียบ
- **prop ที่ effect พึ่งอยู่ต้องเสถียร** เขียนไว้ใน docstring ของ `PloForm` แล้ว

สองข้อที่ **ไม่แก้** และเหตุผล: ประโยค 56 แถว ถูกเขียนด้วยมือใน 8 ไฟล์ (ตั้งใจ คนละคนอ่าน) และ
`programPicker` กับ `programFilter` เป็นฟังก์ชันเดียวกันสองชื่อ (เขียนอธิบายไว้ และไม่มีทางวาดพร้อมกัน)

## Gotchas ที่ยังต้องพก

ยกมาทั้งชุดจากใบก่อนหน้า ยังใช้ได้ทุกข้อ และเพิ่มสามข้อจากรอบนี้

- `git clone` ที่ทำไว้ก่อนเปลี่ยนชื่อ branch ยังชี้ `master` ที่ตายแล้ว แก้ด้วย
  `git remote set-head origin -a && git branch -m master main && git branch -u origin/main`
- e2e ใช้พอร์ต 5100 ซึ่ง Windows จองไว้เป็นช่วง ๆ ถ้าเจอ *already running* ทั้งที่ไม่มีอะไรฟัง
  ให้รันด้วย `E2E_FRONTEND_PORT=5300` ชุดเต็มใช้เวลาราว **18 นาที** (รอบนี้ 17.8 นาที 367 แถว)
- `node server.js` ไม่มี reload — บันซ์ backend ก่อนเดินทุกครั้ง
- TaskStop ปิด shell แต่ไม่ปิดลูกของมัน เซิร์ฟเวอร์ที่ค้างจะทำให้การกวาดรอบถัดไปรายงานว่า
  *ไม่มีอะไรล้ม*
- **อย่ากวาดมัตแตนต์ระหว่างที่ชุด e2e กำลังรัน** และ **เดินด้วยมือก่อนกวาดและก่อนรันชุดเต็ม**
- **การแก้ไฟล์ใน `frontend/src` ระหว่างที่ชุด e2e กำลังรัน ทำให้ CRA คอมไพล์ใหม่กลางคัน**
  เอกสารกับ `backend/` แก้ได้ปลอดภัย
- **docstring ในไฟล์มัตแตนต์ที่อ้าง regexp ต้องเป็น raw string** (`r"""`)
- **สคริปต์นับเครื่องหมายต้องรับตารางหกช่องด้วย** ไม่งั้นหายเจ็ดแถว ☑ เงียบ ๆ วิธีตรวจคือให้มันนับ
  ที่ commit ของใบส่งมอบก่อนหน้าแล้วเทียบกับตัวเลขที่ใบนั้นเขียนไว้
- **spec ที่รันแบบ `serial` รายงาน kill ต่ำกว่าจริง** แถวแรกที่ตายหยุดแถวที่เหลือ — วัดทีละแถวด้วย
  `--grep` ก่อนเขียนจำนวนลงใบตรวจรับ (รอบนี้ `alwaysallprograms` ต้องวัดสี่แถวที่ถูกข้ามแยกต่างหาก)
- **`npx eslint` ใน `backend/` และ `e2e/` ออก exit 2 เพราะไม่มี config ไม่ใช่เพราะ lint ไม่ผ่าน** ใช้
  `node --check` ที่นั่น ส่วน `frontend/` มี config และใช้ `npx eslint` ได้จริง
