### [#88](https://github.com/khthana/Deep-QA/issues/88) — ปลายทั้งสองของช่วงเวลาใช้งานถือกันเองเป็นขอบ

**การแก้เป็นสองบรรทัด** `max={draft.valid_until || undefined}` บนช่อง *เริ่มใช้งานได้* และ
`min={draft.valid_from || undefined}` บนช่อง *ใช้งานได้ถึง* ใน
`frontend/src/components/users/UserForm.js` · `|| undefined` ไม่ใช่ `''` เพราะกฎของเซิร์ฟเวอร์คือ
`from && until && from > until` — อีกฝั่งที่ว่างคือปลายเปิด ไม่ใช่ขอบที่ศูนย์ · ตั๋วเขียนไว้เองว่า
**นี่เป็นการเพิ่ม ไม่ใช่การแทนที่** ยามที่ `backend/routes/users.js` กับ CHECK constraint
จึงไม่ถูกแตะ (ADR-0002)

· **`88a` ห้าแถว รันกับโค้ดที่ยังไม่แก้ก่อนเขียนมัตแตนต์** (#203) — สามแถวที่มีตอนนั้นแดงทั้งสาม
ที่ assertion ของ `min`/`max` เอง ไม่ใช่ที่อื่น
· **หกมัตแตนต์ สามข้ออ้าง สองปลาย** — ขอบมีอยู่ (`nolowerbound` `noupperbound`) ขอบไม่มี
เมื่ออีกฝั่งว่าง (`lowerboundwhenthereisnone` `upperboundwhenthereisnone`) และขอบนับวันนั้นด้วย
(`thelowerboundexcludesit` `theupperboundexcludesit`) ตัวที่หกเกิดขึ้น**ระหว่างกวาด** เพราะ
off-by-one ฝั่งเดียวไม่แตะ `max` เลย
· **แถว 4 กับแถว 5 ถูกแยกออกมาระหว่างกวาด** ด้วยเหตุผลในประโยคแรกของใบนี้ — ข้ออ้าง
*ล้างปลายหนึ่งแล้วอีกฝั่งไม่มีขอบ* กับ *เบราว์เซอร์เป็นคนตัดสินช่วงหนึ่งวัน* เคยอยู่ใต้ assertion อื่น
· **แถว 5 เป็นคำตอบของเบราว์เซอร์เอง ไม่ใช่ของเรา** — ช่วงหนึ่งวันให้
`{under:false, over:false}` ทั้งสองช่อง และปลายที่ย้อนไปหนึ่งวันให้ `rangeUnderflow` ที่ช่องปลาย
กับ `rangeOverflow` ที่ช่องต้น พร้อมกัน
· **กวาดทีละตัวด้วยชื่อแฟ้มเต็ม** (#154/#158) · `grep -l UserForm.js mutation/*.py` พบแฟ้มนี้

  `git branch -m master main && git fetch origin && git branch -u origin/main main && git remote set-head origin -a`
- **`git add -A` ถูกปฏิเสธโดยตัวจัดประเภทของโหมดอัตโนมัติ** เพราะรีโปมี `DEEP-QA-BACKEND/` กับ

  `git push` ผ่านหมด — stage ร่างไว้ใน `_local/github/` แล้วส่งคำสั่งเดียวให้เจ้าของงานรันเอง
