## 3. #100 — อ่านก่อนหยิบงานต่อจาก #20

ตั๋วนี้คือการ **คืน** ความหมายเดิมของระบบนักศึกษา ไม่ใช่ของใหม่ หลักฐานอยู่ในตั๋ว:

และ `subjectPloMappingController:58` ยัง dedupe ด้วย `outcome_id` อีกชั้น

**เกณฑ์ข้อ 1 ของ #20 ต้องถูกแก้บน GitHub ตอน #100 ลง** — *every PLO* เป็น *every main PLO*
ตั๋วปิดไปแล้วก็จริง แต่เกณฑ์ที่เขียนค้างไว้จะขัดกับโค้ด และนั่นคือสิ่งที่คนอ่านรอบหน้าจะสะดุด

สิ่งที่จะหมดความหมายไปกับ #100 และต้องเขียนใหม่ ไม่ใช่ลบทิ้ง:

  คือ *ไม่มีคอลัมน์ของข้อย่อยถูกวาด*
- แถวหัวคอลัมน์ในใบตรวจ ซึ่งเดินผ่านมาแล้วในรอบนี้ และ token ที่แก้กลางการเดินนั้น
  (`text-slate-500` / `font-semibold text-gray-800`) จะไม่มีอะไรให้แยกอีกต่อไป

## 4. กับดัก

ของฉบับก่อนทั้งหมด บวกสี่ข้อนี้

- **assertion ที่ฆ่าอะไรไม่ได้ อาจไม่ได้อ่อน แต่เอื้อมไม่ถึง** มัตแตนต์แรกของ PDF
  เปลี่ยนชื่อ font family แล้วไม่มีอะไรตาย เพราะไฟล์ฟอนต์ที่ vendor มา register ตัวเอง
  ผ่าน `jsPDF.API.events` ตอน import — ทางแก้คือแก้ที่โค้ด ไม่ใช่ที่มัตแตนต์
- **แถวที่ขอสองอย่างในแถวเดียว ต้องถามทีละอย่าง** รอบนี้เจอสามครั้งที่คำตอบกลับมา
  ครึ่งเดียว — *กดไม่ได้* โดยไม่บอกสี · *ไม่มีเมนู* โดยไม่บอกเรื่องกลุ่ม · *อ่านครบห้า*
  โดยไม่บอกเรื่องช่องไฟ
- **ก่อนส่งขั้นตั้งค่าให้คนเดิน ต้องอ่านโค้ดของหน้าที่จะให้เขาไปกดก่อน** รอบนี้สั่งให้
  *ปิดใช้งาน PLO ที่หน้า #19* ทั้งที่หน้านั้นไม่มีปุ่มนั้น การปิดใช้งานเกิดเองตอนกด *ลบ*
  แล้วมีสิ่งอ้างอยู่
- **การเดินเขียนข้อมูลจริง และเขียนผิดที่ได้** นับจำนวนแถวก่อนและหลัง walk ที่มีการลบ
  รอบนี้ `0501` หายไปสองข้อจาก 52 เหลือ 50 โดยไม่มีใครสังเกต จนมาเทียบตัวเลขตอน reseed
- **จะอ่านค่าใน database ระหว่างที่คนกำลังกด ให้อ่านซ้ำก่อนสรุป** รอบนี้ผมอ่านค่าหนึ่งครั้ง
  แล้วบอกเจ้าของงานว่า *ยังไม่มีอะไรเปลี่ยน* ทั้งที่เขากำลังกดอยู่ขณะนั้น
- **สูตรนับ marker นับแถวที่เดินแล้วตกไม่ได้** ดูหัวข้อ 1
- **A fresh clone lands on a dead `master`.** Run, verbatim:
  `git branch -m master main && git fetch origin --prune && git branch -u origin/main main`
