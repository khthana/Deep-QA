## 3. #34 คืออะไร และตัดสินใจอะไรไว้บ้าง

`activity_scores.clo_id` เป็น NOT NULL และ unique อยู่ที่ (student_id, activity_id, clo_id)
**จึงไม่มีคะแนนที่ให้กับกิจกรรม มีแต่คะแนนที่ให้กับผลการเรียนรู้ของมัน** ทุกอย่างในตั๋วนี้ไหลมาจาก

ข้อเท็จจริงเกี่ยวกับคะแนน — เซิร์ฟเวอร์เป็นคนหารตามน้ำหนักและคูณให้สมาชิกทุกคน

**การหารต้องลงตัวเป๊ะ** เพราะหน้าจออ่านกลับด้วยการบวก เศษสตางค์จึงถูกยกไปไว้แถวแรก คนที่พิมพ์
61 แล้วอ่านกลับได้ 60.99 มีสิทธิ์ไม่เชื่อหน้าจอนั้นอีกเลย

**ผู้ใช้ตัดสินสองข้อระหว่างทาง** (ทั้งคู่เป็นส่วนหนึ่งของ spec ไม่ใช่ scope creep)

1. ไฟล์นำเข้าเป็น**รายคนเสมอ** — เกณฑ์ทั้งสี่ข้อของการตรวจไฟล์พูดถึงนักศึกษาทั้งหมด สวิตช์ต่อ-CLO
   จึงเปลี่ยน*คอลัมน์*ของไฟล์ ไม่ใช่*แถว* ส่วนการกรอกรายกลุ่มเป็นวิธีพิมพ์บนหน้าจอเท่านั้น
2. สวิตช์กลุ่ม**เปิดให้เลือกเสมอ** และตั้งต้นตาม `activity_type` — งานเป็นอะไรคือข้อเท็จจริง
   ส่วนผู้สอนจะกรอกยังไงเป็นความชอบ และงานกลุ่มที่ให้คะแนนรายคนเป็นเรื่องปกติ

**#108 ยังเปิดอยู่และงานนี้จงใจไม่แตะ** handoff ฉบับก่อนบอกว่า #34 คือ "ที่อยู่" ของมัน ซึ่งจริง —
แต่มันเป็นการตัดสินใจเชิงผลิตภัณฑ์ (แก้คะแนนเต็มหรือน้ำหนักของกิจกรรมที่มีคะแนนแล้ว จะปฏิเสธ
ปฏิเสธเฉพาะที่ทำให้คะแนนเดิมเป็นโมฆะ หรือ rescale) ที่ไม่มีอยู่ในเกณฑ์สิบเอ็ดข้อของ #34

## 4. สิ่งที่ review จับได้ และเป็นเหตุผลที่สองแกนมีอยู่

`/code-review` เจอสามอย่างที่ทั้ง 25 subtests และ 10 แถวเบราว์เซอร์ไม่เจอ **และทั้งสามเป็น
ความผิดเดียวกันคนละที่**

> ช่องว่างแปลว่า *ยังไม่ให้คะแนน* และหน้าจอนี้วาดช่องให้ว่างด้วยเหตุผลของตัวเองสองกรณี —
> กลุ่มที่สมาชิกถือคะแนนไม่ตรงกัน กับคนที่ได้คะแนนมาบางข้อ

การส่งทุกแถวขึ้นไปตอนบันทึกจึงเขียน NULL ทับคะแนนที่ทำให้ช่องนั้นว่างตั้งแต่แรก **ลบงานของทั้งกลุ่ม
ด้วยการกดปุ่มที่เล็งไปที่แถวอื่น** ไม่มีอะไรปฏิเสธ แถบแจ้งผลบอกว่าบันทึกแล้ว และไม่มี seam ไหนเห็น
เพราะทุกแถวทดสอบเรียก `setEntry` หลังโหลดใหม่เสมอ

แก้ทั้งสามแล้ว และแต่ละข้อได้แถวเบราว์เซอร์กับมัตแตนต์ของตัวเอง — `34a` แถว 11, 12, 13 กับ
`entryresetsonsave`, `savesendseveryrow`, `partialreadsastotal`

แกน Standards จับ**ทะเบียนมัตแตนต์ที่ผิดสองที่**: `26-work-groups.py` ยังเขียนว่า 14 ทั้งที่
commit ก่อนหน้าเพิ่มตัวที่ 15 ไปแล้ว และไฟล์ของ #34 ไม่ได้อยู่ในตารางเลย **นับใหม่ด้วย one-liner
ของ README เสมอ อย่าบวกมือ**

**สองสำเนาของด่านเพดานคะแนนถูกยุบเป็นหนึ่ง** และนั่นคือ smell ที่พิสูจน์ตัวเอง: สำเนาฝั่งไฟล์
ไม่เคยได้ด่านที่สำเนาฝั่งหน้าจอมี มัตแตนต์สองตัวที่เคยต้องมีเพราะมีสองสำเนาจึงเหลือตัวเดียวที่ฆ่า
ทั้งแถว 5 (จอ) และแถว 9 (ไฟล์)

**`refusedfilestillwrites` บังคับให้ต้องสลับลำดับ assertion ของแถว 8** ฉบับแรกของมันตายที่
*ประโยค* ไม่ใช่ที่ *คะแนนไม่ขยับ* เพราะทั้งสองครึ่งของ "ปฏิเสธทั้งไฟล์" เดินผ่านโค้ดเส้นเดียวกัน
มัตแตนต์ย่อมตายที่ assertion ที่อยู่ก่อน — แล้วเกณฑ์ข้อ 8 ก็จะติด ⚙ ด้วยหลักฐานของเกณฑ์ข้อ 7
ซึ่งเป็นความผิดชนิดเดียวกับที่ review ทักมาพอดี **ย้าย assertion ที่เป็นข้ออ้างจริงขึ้นก่อนเสมอ**

**สิ่งที่ review ทักแล้วตรวจสอบแล้วไม่แก้** — แกน Spec บอกว่าเพดานรายข้อ (`markOverClo`) เกิน

น้ำหนักครบร้อย ด่านที่เพิ่มเข้าไปจะยิงได้เฉพาะเศษหนึ่งสตางค์ตอนคะแนนเต็มไม่ใช่จำนวนเต็ม —
คือไปปฏิเสธคนที่พิมพ์เพดานของทุกช่องตามที่หน้าจอบอกเอง เขียนเหตุผลไว้ในโค้ดแทนการเพิ่มด่าน

## 7. กับดัก

**อย่าสรุปว่าเทสต์ที่ตกเป็นเพราะงานของตัวเองจากการรันครั้งเดียว** (ใหม่) — เทียบกับ tree ที่ย้อน
การแก้ออกแล้ว **หลายรอบ** ก่อน ไม่งั้นรอบเขียวรอบเดียวจะกลายเป็น control ที่ไม่ได้ควบคุมอะไรเลย

**`before` ระดับบนสุดสองอันของ `node --test` ไม่ได้รันเรียงกัน** — อันที่สองเริ่มโดยไม่รออันแรก
**ใช้ hook เดียว**

**route ที่ตอบข้างในทรานแซกชันคือ route ที่โกหก** — `res.send()` ก่อน `COMMIT` ทำให้ผู้เรียก
รู้ผลก่อนที่ผลจะจริง

**ล็อกละเอียดหลายตัวในทรานแซกชันที่แตะหลายแถวคือ deadlock ที่รอเวลา** — ใช้ล็อกเดียวที่หยาบพอ

**ตารางคิวเดินมือถูกก๊อปส่งต่อมาโดยไม่มีใครตรวจ** — นับจากใบตรวจรับเสมอ (คำสั่งอยู่หัวข้อ 5)

**`restore` ของ harness เขียนทับทุกไฟล์ใน `FILES`** — อย่าแก้ไฟล์ในชุดระหว่างที่กวาดค้างอยู่ และ
**`save` เป็นคำสั่งแรกของสคริปต์กวาดเสมอ**

**อย่าให้ assertion ของ e2e เทียบกับคำตอบของ API ที่เติม control นั้นเอง**

**อย่าฆ่า node ที่พอร์ต 3100/5100 โดยไม่ดูก่อนว่าอะไรรันอยู่** — เซสชันนี้ฆ่าไปสองตัวโดยคิดว่าเป็น
ของค้าง ที่จริงเป็นเซิร์ฟเวอร์ของชุด e2e ที่กำลังรันอยู่ รอบนั้นจึงจบแบบ *26 did not run*

**clone อื่นที่ยังชี้ `master`**

```bash
git branch -m master main && git fetch origin --prune && git branch -u origin/main main
```

**อย่า `git add` อะไรใน `DEEP-QA-BACKEND/` หรือ `_local/`** — `.env` มีคริเดนเชียลจริง `uploads/`
เป็นงานของนักศึกษาจริง และ repository นี้เป็น public

**อย่าพิมพ์ภาษาไทยผ่าน Bash** (cp874 `UnicodeEncodeError`) — ใช้ Write tool หรือสคริปต์ Python
`io.open(..., encoding='utf-8', newline='\n')` · และ `python mutation/<file>.py list` พิมพ์ `\r`
