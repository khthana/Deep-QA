### #89 (ปิด) — ข้อบกพร่องอยู่ในใบตรวจรับ ไม่ใช่ในโค้ด

ผู้ประเมินที่รอบยังไม่เปิด กับผู้ประเมินที่รอบปิดไปแล้ว ถูกปฏิเสธด้วยประโยคเดียวกันตามตัวอักษร —
เพราะแถว *ยังไม่ถึงวันเริ่ม ก็เข้าไม่ได้* ของ `11-user-accounts.md` เขียนไว้เองว่า *ข้อความเดียวกับแถวบน*
ใบถูกแก้ก่อนแล้วโค้ดตาม `outsideValidity` แยกเป็น `validityNotStarted` กับ `validityEnded` แกนที่แยกคือ
**คนต้องทำอะไรต่อ** — ปลายหนึ่งรอได้ อีกปลายรอไปก็ไม่เปลี่ยน ต้องติดต่อเจ้าหน้าที่

ประโยคไม่ระบุวันที่ และนั่นเป็นผลวัด ไม่ใช่การละ ทั้งสองคีย์เดินทางเป็น `/login?error=<reason>` ที่ไม่มี
body ให้ประตูที่มี body พูดมากกว่าประตูที่ไม่มี คือบัญชีเดียวตอบต่างกันตามทางเข้า — เลื่อนไปเป็น
[#128](https://github.com/khthana/Deep-QA/issues/128) พร้อมราคาที่ต้องจ่าย

การย้ายกฎเข้า helper ทำให้ *the list of reasons is the list the rules can actually produce* แดงทันที เพราะ
มันอ่าน source ของฟังก์ชัน **scan ที่อ่านข้อความของฟังก์ชัน หยุดที่ขอบของฟังก์ชันนั้น**
`validityRefusal` จึงคืนคำปฏิเสธทั้งก้อน และ sweep เจอเทสต์สองข้อที่แชร์ `U_EXT` แล้วคืนคอลัมน์เฉพาะ
ตอนผ่าน — `finally` คือการแก้

### #52 (ปิด) — บัญชีที่ไปต่อไม่ได้ ถูกพาไปหน้าเข้าระบบพร้อมเหตุผล

บัญชีที่ถูกระงับ หรือผู้ประเมินที่รอบปิดระหว่างที่ยังเข้าระบบอยู่ ถูกปฏิเสธถูกต้อง แล้วถูกทิ้งไว้บนจอที่ใช้
ไม่ได้ หรือพิมพ์ที่อยู่เองแล้วถูกส่งไป `/` โดยไม่มีคำอธิบาย

- **สัญญาณคือช่องที่ server ตั้งตรงจุดที่ตัดสิน** `endAccess` ใน `authorise.js` เป็นทางเดียวที่
  `attachRoles` ปฏิเสธคนที่ถือคุกกี้ดี และมันตอบ 403 พร้อม `accessEnded: true` ไม่มีการจับข้อความไทย
  และไม่มีรายการ reason ฝั่ง client `noRole` ไม่อยู่ในตั๋วแต่ได้ธงด้วย เพราะสำหรับคนหน้าจอเป็นสภาพเดียวกัน
- `client.js` → `AuthContext` ล้างสถานะ ลบคุกกี้ผ่าน `/api/auth/logout` แล้ว `Login` แสดงประโยคของ server
- รีวิวเจอว่าจอที่ขอสามอย่างพร้อมกันเขียน `LOGOUT` สามแถว ref แบบครั้งเดียวแก้ได้ และ `load()` ต้อง
  รีเซ็ตมัน ไม่งั้นเป็น *ครั้งเดียวต่อแท็บ* **ด่านที่บอกว่า *ครั้งเดียว* ต้องบอกว่าครั้งเดียวต่ออะไร**
- `52a` หกแถว · ห้า subtest ใน `authorise.test.js` · มัตแตนต์ 11 ตัวใน `mutation/52-access-ended.py`
  `everyrefusalends` — *ทุก 403 จบ session* — ผ่าน `52a` ทั้งหมด และพัง **13 แถวในเก้าไฟล์** ที่เขียนก่อนตั๋วนี้

## Gotchas ที่ยังต้องพก

ยกมาทั้งชุดจากใบก่อนหน้า ยังใช้ได้ทุกข้อ และเพิ่มจากรอบนี้

- `git clone` ที่ทำไว้ก่อนเปลี่ยนชื่อ branch ยังชี้ `master` ที่ตายแล้ว แก้ด้วย
  `git remote set-head origin -a && git branch -m master main && git branch -u origin/main`
- **`python mutation/<ใบ>.py save` ก่อนทุกมัตแตนต์ และอ่าน `git status` หลัง `apply` ไม่ใช่แค่หลัง
  `restore`** ตั้งแต่ #126 harness ปฏิเสธแทนที่จะเขียนทับไฟล์ที่มันอธิบายไม่ได้ แต่การถูกปฏิเสธ
  กลางการกวาด ก็ยังคือการกวาดที่ต้องเริ่มใหม่
- **รายการ *ห้ามกวาดคู่กับ* ต้องสร้างจาก `grep -l` บน `FILES` ไม่ใช่จากการอ่านว่าใบไหนพูดถึงอะไร**
- **อย่าพิมพ์ภาษาไทยหรือ ☑ ⚙ ◐ ☐ ผ่าน Bash ด้วย Python** console ที่นี่เป็น cp874 และจะได้
  `UnicodeEncodeError` — เขียนไฟล์ด้วย `io.open(..., encoding='utf-8')` แล้วอ่านด้วยเครื่องมืออ่านไฟล์
- **`.gitattributes` เป็น `* text=auto eol=lf` — ต้นไม้ต้องเป็น LF** สคริปต์แก้ไฟล์ที่เขียนด้วย
  `io.open(...)` ต้องส่ง `newline=''` ทั้งตอนอ่านและตอนเขียน ไม่งั้นไฟล์กลายเป็น CRLF เงียบ ๆ
  ตรวจด้วย `git ls-files --eol`
- e2e ใช้พอร์ต 5100 ซึ่ง Windows จองไว้เป็นช่วง ๆ ถ้าเจอ *already running* ทั้งที่ไม่มีอะไรฟัง
  ให้รันด้วย `E2E_FRONTEND_PORT=5300` ชุดเต็มใช้เวลาราว 18–19 นาที (369 แถวใช้ 18.7 นาทีเมื่อ 9 ก.ย.)
  **หัวข้อ *Two test seams* ใน `CLAUDE.md` ยังเขียนว่า 3100/5100** — ยังไม่ได้แก้
- `node server.js` ไม่มี reload — บันซ์ backend ก่อนเดินทุกครั้ง
- TaskStop ปิด shell แต่ไม่ปิดลูกของมัน เซิร์ฟเวอร์ที่ค้างจะทำให้การกวาดรอบถัดไปรายงานว่า
  *ไม่มีอะไรล้ม*
- **อย่ากวาดมัตแตนต์ระหว่างที่ชุด e2e กำลังรัน** และ **เดินด้วยมือก่อนกวาดและก่อนรันชุดเต็ม**
- **frontend ของ e2e คือ CRA dev server ที่ hot-reload — แก้ไฟล์ใน `frontend/src` ระหว่างที่ชุด e2e รัน
  ทำให้มันคอมไพล์ใหม่กลางคัน** รอบนี้เกิดจริงและรอบนั้นต้องรันใหม่ เอกสารกับ `backend/` แก้ได้ปลอดภัย
- **docstring ในไฟล์มัตแตนต์ที่อ้าง regexp ต้องเป็น raw string** (`r"""`)
- **สคริปต์นับเครื่องหมายต้องอ่านช่องสุดท้ายของแถว ไม่ใช่ช่องที่ห้า** วิธีตรวจคือให้มันนับที่ commit
  ของใบส่งมอบก่อนหน้าแล้วเทียบกับตัวเลขที่ใบนั้นเขียนไว้
- **spec ที่รันแบบ `serial` รายงาน kill ต่ำกว่าจริง** แถวแรกที่ตายหยุดแถวที่เหลือ — วัดทีละแถวด้วย
  `--grep` ก่อนเขียนจำนวนลงใบตรวจรับ
- **`node --test` นับ suite แม่ใน `# fail` และเทสต์ระดับบนสุดของไฟล์มี `not ok` ที่ไม่เยื้อง** — อ่านชื่อ
  จากการรันทั้งชุด อย่านับบรรทัด (#48)
- **ยอด kill ที่ดูเหมือนทั้งชุด ให้อ่านชื่อหา fixture ที่รั่วก่อน** ก่อนสรุปว่ามัตแตนต์หยุดทั้งแอป (171 ของ #52)
- **การรอที่เขียนเพื่อจังหวะเวลา ต้องมี timeout ที่ยอมให้หมดได้** ไม่งั้นมันกลายเป็น assertion และ
  `networkidle` ไม่มีความหมายหลังการนำทางภายใน SPA
- **ค้นบน tracker ก่อนเปิดตั๋ว** (`gh issue list --state all --search "<ชื่อ spec หรือไฟล์>"`) — รอบนี้เกือบเปิด
  ตั๋วซ้ำให้แถว `44a` ทั้งที่ #129 ถืออยู่แล้ว
- **`npx eslint` ใน `backend/` และ `e2e/` ออก exit 2 เพราะไม่มี config ไม่ใช่เพราะ lint ไม่ผ่าน** ใช้
  `node --check` ที่นั่น ส่วน `frontend/` มี config และใช้ `npx eslint` ได้จริง
