## สิ่งที่ตัดสิน

**#227 เป็นงาน ไม่ใช่คำถามของเจ้าของงาน** ตั๋วเขียนเงื่อนไขไว้เองว่าจะกลายเป็นคำถามถ้าการแก้

**แก้จุดเดียวจากห้าจุด** เพราะสำมะโนตามกลไก — *ใครเขียนสถานะที่ presence ใช้เป็นกุญแจ* —

**ไม่มีแถวและไม่มีมัตแตนต์ และเขียนไว้ว่าไม่มี** เพราะไม่มี seam ใดสร้างเงื่อนไขนี้ได้ —

`DialogPresence.js` และการรวมสามจุดเรียกมาอยู่ใต้ตัวห่อเดียวไม่ได้ทำให้ proof เสียอะไร

## สิ่งที่วัดได้ (#227)

**ห้าจุดที่ยัง mount `AnimatePresence` เอง และมีจุดเดียวที่มีทางเข้าไม่ต้องแข่งกับมือคน**

|---|---|---|
| `pages/Login.js` การสลับ `mode="wait"` | `LoadLogin` ลงใน `finally` หลัง `await` | **มี** |
| `pages/Login.js` แถบคำปฏิเสธ | การพิมพ์ หรือการส่งฟอร์มครั้งถัดไป | ไม่มี |
| `components/Navbar.js` เมนูผู้ใช้ | การกด | ไม่มี |

| `components/SidebarItem.js` เมนูย่อย | การกด | ไม่มี |

**ความเสียหายที่จุดเดียวนั้นเป็นคนละชนิดกับ #169 และหนักกว่า** `mode="wait"` ทำให้ลูกที่ถูกถือ
เป็นลูกที่กำลัง **ออก** ลูกที่รอเข้าจึงไม่ถูก mount เลย — วัดได้ว่า spinner ยังอยู่ที่ `opacity: 1`
ทั้งที่ 500 และ 2500 มิลลิวินาทีหลัง 401 ถึงแล้ว โดย**ฟอร์มกับแถบคำปฏิเสธไม่อยู่ในเอกสารเลย**
กล่องของ #169 ทิ้งของเกินไว้บนจอ ของจุดนี้ทำให้จอพูดสิ่งที่คนรออยู่ไม่ได้

**ราคาของสี่จุดที่ไม่แก้ เป็นตัวเลขบนตัวมันเอง** อยู่ที่ 0.5, 1 และ 3 วินาที · `opacity: 1` ·
`pointer-events: auto` · โฟกัสลงได้ 0/3/1/2 ตัว · 4/19/6/11 node ในแผนผังการเข้าถึง · หน้าต่าง
ที่ต้องยิงให้เข้าคือการจางเอง **198, 198, 183 และ 318 มิลลิวินาที** (ตัวสุดท้ายยาวกว่าเพราะ
tween `height` ด้วย) เครื่องมือไปถึงหน้าต่างพวกนี้ที่ 6–13 มิลลิวินาที ซึ่งเป็นความไวของเครื่องมือ
ไม่ใช่ของมือคน

**ตัวแก้รุ่นแรกตกโหมดที่สี่อีกครั้ง ด้วยเส้นทางที่ #169 ไม่มี** — คำตอบถึงที่ **79 มิลลิวินาที**
เมื่อไม่จำลองอะไร เร็วกว่า 180 มิลลิวินาทีที่ฟอร์มใช้ออก ขาออกจึงถูก**ย้อน** และขาออกที่ถูกย้อน
ไม่ยิง `onExitComplete` ธงจึงค้างขึ้นตลอดไป แล้วการสลับแท็บครั้งถัดไป mount หน้าลงชื่อเข้าใช้
ใหม่ทั้งจอใต้คนที่ไม่ได้ปิดอะไร: **0 เฟรมจาก 44** ที่ควรเป็น 13 · หลังเปลี่ยนให้ธงถือค่า `at`
ของลูกที่อาจยังออกอยู่: **13 จาก 44** จบที่ 195 มิลลิวินาที เท่ากับก่อนแก้

**และความล้มนั้นถูกรายงานว่าเป็นการหายไป ซึ่งจริง ๆ เป็นการถูกแทนที่** เครื่องมืออ่านผ่าน
attribute ที่มันแปะไว้ การ remount จึงให้ node ใหม่ที่ไม่มีมาร์ก และรายงานออกมาเป็นการหายไป
อย่างสะอาดโดยทุกตัวเลขเห็นด้วยกัน (`stillOpenOnReturn: 0` · `framesStillDrawingIt: 0` ·
`opacityCameDown: false`) — **ตัวอ่านที่สร้างบนมาร์กแยกการลบจากการแทนที่ไม่ได้** ครั้งนี้ไม่ได้
ตัดสินอะไร เพราะสองคำตอบแย่ด้วยเหตุเดียวกัน แต่เขียนไว้ใน docblock ของโพรบแล้ว

**เลขหลังกลับมาของสี่จุดที่เหลือเป็นสมบัติของ tween ที่ถูกปลุก** สองรอบบนโค้ดชุดเดียวกัน

กลับกันพอดี) เหตุผลบนทั้งสี่จุดจึงถือ **ทั้งสองการอ่าน** ไม่ใช่รอบที่เซสชันนี้ได้

## สิ่งที่จะกินเวลา

- **พอร์ตของ `e2e` วันนี้คือ 3600 กับ 5310** และตั้งด้วย `E2E_BACKEND_PORT` /
  `E2E_FRONTEND_PORT` — **อย่ายกพอร์ตจากใบเก่ามาใช้ รวมทั้งใบนี้** อ่าน
  `netsh int ipv4 show excludedportrange protocol=tcp` ก่อน · อาการของพอร์ตที่ถูกจองคือ
  *exited early* เงียบ ๆ ไม่ใช่ `EACCES`
- **โพรบของ #169/#227 ต้องมีเซิร์ฟเวอร์สองตัวขึ้นอยู่ก่อน** และมันเปิด Chrome ของตัวเองผ่าน CDP
  (`playwright.config.js` มี `reuseExistingServer: false` จึงต้องดับเซิร์ฟเวอร์ที่ยกมือรันก่อน
  จะรันชุดเต็ม) · วิธีรันอยู่ใน docblock ของโพรบ
- **ชุดเบราว์เซอร์กินเวลา ~47 นาที** และต้องเป็นรอบที่ไม่มีการแก้ไฟล์ระหว่างรัน
- **ห้ามแก้ไฟล์ใน `frontend/` `e2e/` หรือ `mutation/` ขณะชุดทดสอบหรือ harness กำลังรัน** ·
  `TaskStop` ไม่ได้ฆ่าเซิร์ฟเวอร์ลูก ต้องเคลียร์พอร์ตเอง
- **หน่วยความจำของเครื่องนี้ยังเป็นเรื่องที่ต้องระวัง** — อ่าน §หน่วยความจำของเครื่องนี้ ของ
  `2026-10-24-the-word-on-two-controls.md` และ **อย่ารัน `wsl --shutdown` เองโดยไม่ถาม**
- **การโคลนใหม่ต้องแก้ปลายทางของ `master` ที่ตายแล้ว** —
  `git remote set-head origin -a && git branch -u origin/main main`
