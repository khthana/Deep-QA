## เรื่องที่จะกินเวลาถ้าไม่รู้ (gotchas)

- **อ่านข้อความที่ใช้สร้างสมอจากโค้ดที่มัตแตนต์ไปแก้** ไม่ใช่จากไฟล์มัตแตนต์ที่ยกมันมาอ้าง — สำเนา
  ใน string literal พาเครื่องหมายคำพูดมาด้วย และ assert ที่นับจำนวนครั้งจับไม่ได้ เพราะทุกครั้ง
  ผิดเหมือนกัน · assert ว่าสตริงที่สร้าง**พูดอะไร** ไม่ใช่ว่าปรากฏกี่ครั้ง
- **มัตแตนต์ที่ลบโค้ดต้องไม่ทิ้งตัวแปรที่ไม่มีใครอ้าง** react-scripts เปลี่ยน warning นั้นเป็น
  คอมไพล์ตกเมื่อ `CI=true` ซึ่งจะเป็นมัตแตนต์ที่หยุดแอป ไม่ใช่ที่ล้มแถว · ฮาร์เนสรับ **ลิสต์ของการแก้**
  ไม่ใช่แค่ tuple เดียว (`harness.apply` อ่าน `isinstance(edits, tuple)`)
- **clone อื่นยังมี `master` ที่ตายแล้ว** ปลายทางเปลี่ยนเป็น `main` แล้ว clone เก่าต้องแก้มือ:
  `git branch -m master main && git fetch origin && git branch -u origin/main main && git remote set-head origin -a`
- **`git add -A` ถูกปฏิเสธ** เพราะรีโปมี `DEEP-QA-BACKEND/` กับ `_local/` อยู่ข้างใน
  **stage ด้วยพาธชัดเจนเสมอ** และห้าม `git add` อะไรใต้สองที่นั้น
- **เลขบรรทัดที่อ้างในเอกสารไม่มีเครื่องมือเฝ้า** `anchors.py` อ่านการอ้าง**ด้วยชื่อ** (16 จุด)
  ส่วนการอ้างด้วยเลขบรรทัดมันแค่นับ · การแก้ที่เพิ่มบรรทัดในสเปกต้อง grep `<ไฟล์>a:` เองเสมอ ·
  รอบนี้การอ้างโค้ดสามจุดถูกเปลี่ยนไปอ้างด้วย**ข้อความที่วาดมัน** แทน (#173, #130)
- **สมอของมัตแตนต์มีสองครึ่ง และเครื่องมือตรวจครึ่งเดียว** `anchors.py` อ่านครึ่งสมอ ไม่อ่าน
  ครึ่งแทนที่ — รู้ได้จากการกวาดเท่านั้น (รอบนี้มันตอบ problems 0 เหนือมัตแตนต์ที่ไม่ทำอะไรเลย)
- **ตัวนับมาร์กที่เขียนเองหยิบคอลัมน์ไม่ตรงกับ `anchors.py`** ให้ `import anchors` แล้วใช้

- **`grep -rn` ทั้ง `e2e/` ค้างได้** เพราะ `test-results/` โตมากหลังการกวาด · grep ไฟล์ที่ต้องการ
