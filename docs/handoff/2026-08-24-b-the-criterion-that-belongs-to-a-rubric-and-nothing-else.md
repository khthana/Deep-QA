`mutation/22-rubric-criteria.py` **14 ตัว**
ทุกตัวฆ่าแถวของตัวเอง อ่านจากชื่อเทสต์ที่ตาย ไม่ใช่จากจำนวน

**สิ่งที่ทำให้หน้านี้ต่างจากทุกหน้าก่อน — เกณฑ์ไม่มีหลักสูตรเป็นของตัวเอง**

- `rubric_details` ไม่มี `program_id` สิ่งที่อนุญาตการเขียนคือ **Rubric ที่อยู่ใน URL เท่านั้น**
  `reachableRubric` จึงถูกยกขึ้นมาที่ module scope ของ `rubrics.js` และใช้ร่วมกันสองตั๋ว
- **ทุกคำขอต้องตรวจสองชั้น** `WHERE d.id = $1 AND d.rubric_id = $2` เสมอ ไม่ใช่แค่ `id`
  ถ้าขาดครึ่งหลัง บัญชีที่เข้าถึง Rubric A จะแก้เกณฑ์ของ B ได้ผ่าน
  `/rubrics/A/criteria/<id ของ B>` — เทสต์ข้อนี้ใช้ **Rubric สองตัวของบัญชีเดียวกัน** สิทธิ์จึงไม่ช่วยอะไรเลย
- **route เข้มกว่า schema** `level_*_description` ทั้งสี่คอลัมน์เป็น nullable แต่ route บังคับครบทั้งสี่
- **`numeric` อ่านกลับมาเป็นสตริง** (`'1.00'`) จึงต้อง `d.weight::float8 AS weight`
  มิฉะนั้นหน้าจอจะอ่านว่า `12.50` ทั้งที่คนพิมพ์ `12.5`
- **ไม่มีการแบ่งหน้า และไม่มีตัวกรอง** เกณฑ์คือหน้ากระดาษที่คนอ่านขณะตรวจงาน
  การแบ่งหน้าจะแย่กว่าหน้ายาว จำนวนจึงบอกด้วยประโยคแทน และนั่นคือที่มาของมัตแตนต์ `countnotsaid`
- **`FACULTY_ADMIN` ไม่อยู่ใน `MAINTAINERS`** สวนทางเกณฑ์ข้อ 6 ของตั๋วโดยตั้งใจ ตาม #79

## 3. สองมัตแตนต์ที่ต้องเล็งใหม่ กับข้ออ้างที่ไม่มีหลักฐานอยู่หนึ่งข้อ

ทั้งสามเรื่องเป็นเรื่องเดียวกัน — **ชุดเทสต์ที่เขียวไม่ได้แปลว่าหลักฐานดี**

- **`editnotsaved` รอดมาได้เพราะ locator หยาบเกินไป** `criterionRow` กรองด้วยข้อความ
  ในเซลล์แรก ซึ่งถือทั้งชื่อไทยและชื่ออังกฤษ แถวที่ชื่อไทยไม่เคยเปลี่ยนจึงยังถูกจับได้ด้วยชื่ออังกฤษ
  แก้ด้วย `listedNames()` ที่อ่านเฉพาะบรรทัดแรกของเซลล์แรก แล้ว assert ทั้ง `toContain` และ `not.toContain`
- **`countignorestherubric` ฆ่าแถวที่หนึ่งแทนที่จะเป็นแถวที่ห้า** `WHERE d.rubric_id = d.rubric_id`
  นับทั้งตาราง ทำให้ Rubric ที่ยังว่างมีจำนวนเกินศูนย์ ซึ่งแถวที่หนึ่งอ่านอยู่ —
  **มัตแตนต์ที่แก้คอลัมน์ที่หลายแถวใช้ร่วมกัน จะตายที่แถวที่เพียงอ่านมันผ่าน ๆ ก็ได้** กับดักใหม่
  แก้เป็น `count(*)::int - 1` ซึ่ง Rubric ว่างยังอ่านว่าว่าง (ที่ -1 เงื่อนไข `count > 0` ยังเท็จ) และเปลี่ยนชื่อเป็น `countoffbyone`
- **`countnotsaid` เพิ่มทีหลัง ตอนทบทวน** แถว *เพิ่มเกณฑ์ได้* พูดสามเรื่อง
  คือน้ำหนัก คำอธิบายสี่ระดับ และจำนวนใต้หัวเรื่อง แต่มัตแตนต์ทั้งสิบสามตัวแรกไม่มีตัวไหนแตะ `total` เลย
  จำนวนจึงเป็นข้ออ้างที่ขี่หลักฐานของเรื่องอื่นอยู่ `total: 0` แก้เรื่องนี้ และมันฆ่าแถวที่สองจริง โดยแถวที่หนึ่งยังผ่าน
- **การตรวจทศนิยมสองตำแหน่งด้วย `Math.round(w*100) !== w*100` ผิด** มันปฏิเสธ 1.1, 8.2, 0.07
  เพราะหนึ่งในสิบไม่ลงตัวในฐานสอง ต้องเป็น `Math.abs(w*100 - Math.round(w*100)) > 1e-9`
  เจอหลังชุดเทสต์เขียวแล้ว ด้วยการยิงค่าที่เทสต์ไม่เคยยิงเข้าไป

## 5. กับดักที่เพิ่มจากฉบับก่อน

- **มัตแตนต์ที่แก้คอลัมน์ที่หลายแถวใช้ร่วมกัน อาจตายที่แถวที่เพียงอ่านมันผ่าน ๆ**
  ก่อนเขียนมัตแตนต์ต้องถามว่า *มีแถวไหนอ่านค่านี้ก่อนแถวที่ตั้งใจจะพิสูจน์* ถ้ามี ต้องเล็งมันใหม่
- **locator ที่กรองด้วยข้อความของเซลล์ที่มีสองค่า ไม่ได้พิสูจน์ค่าที่เปลี่ยน**
  แถวที่พูดเรื่องการแก้ไขต้องอ่านเฉพาะส่วนที่เปลี่ยน และ assert ทั้งขาออกและขาเข้า
- **แถวหนึ่งที่พูดสองสามเรื่อง ต้องมีมัตแตนต์ครบทุกเรื่อง** ไม่ใช่ตัวเดียวต่อแถว
  วิธีตรวจคืออ่านช่อง *ต้องเห็นอะไร* ของแถวนั้นแล้วนับประโยค แล้วดูว่ามีมัตแตนต์ตรงกันกี่ตัว
- **ตัวเลขในคำบรรยายของ checklist ให้นับด้วย regex เสมอ** อย่าบวกจากฉบับก่อน
  เพราะตัวเลขนั้นคือสิ่งที่ session ถัดไปใช้วางแผนการเดิน สูตรที่ใช้คือ
  `\|\s*(☑|⚙|◐|☐)\s*\|?\s*$` รันทับ `docs/acceptance/*.md`
- **A fresh clone lands on a dead `master`.** Run, verbatim:
  `git branch -m master main && git fetch origin --prune && git branch -u origin/main main`
