## สิ่งที่วัดได้

**ราคาที่ตั๋วยอมรับไว้แคบกว่าที่วัดได้** (#153) ตั๋วเขียนว่าสิ่งที่เหลือคือ node ที่มองไม่เห็น
ค้างในแท็บที่ไม่มีใครมอง ที่วัดได้คือ **มันไม่ได้จางเลย** — tween ไม่ได้เริ่มเพราะไม่มีเฟรม:

- ยังอยู่ในเอกสารที่ 0.5, 1 และ 3 วินาที ที่ `opacity: 1`, `pointer-events: auto`,
  `checkVisibility()` เป็นจริง ไม่อยู่ใต้ `aria-hidden` หรือ `inert`
- โฟกัสลงได้ทุกตัว — กล่องรูป **2** ตัว กล่องรหัสผ่าน **8** ตัว รวมช่องรหัสผ่านสามช่อง
- อยู่ในต้นไม้ accessibility ทั้งก้อน — **23** node กับ **35** node โดยหัวเรื่อง ช่องกรอก
  และปุ่มยังมีชื่อและไม่ถูก ignored
- **ตอนคนกลับมา มันถูกวาดใหม่เต็มความทึบแล้วค่อยจางให้ดู** เฟรมสุดท้ายที่ยังวาดอยู่ที่
  194–196 มิลลิวินาที
- เลขของกล่องเปลี่ยนรหัสผ่าน (การวัดที่ #169 ขอ และไม่เคยมีใครทำ) ตรงกับกล่องรูปทุกตัว

**ทางเข้าไม่ใช่การแข่งกับมือของคนเอง** (#179) ทั้งสองกล่องปิดตัวเอง *หลัง* `await` ของคำขอ —
กล่องรูปผ่าน `onSaved` กล่องรหัสผ่านผ่าน `closeChangePassword` — กดบันทึกแล้วสลับแท็บขณะคำขอ
ยังไม่กลับ จึงเป็นการปิดในแท็บที่ไม่มีเฟรมอยู่แล้ว วัดแล้ว เลขเดียวกันทุกตัว

**ทางเลือกที่สี่ที่ตั๋วเขียนว่าไม่มี** (#128, #204) ทางเข้าทั้งสามของข้อ (ข) ขยับสิ่งที่คนเห็น
และทางที่สี่ — ถอด node ตามจังหวะของเบราว์เซอร์แทนจังหวะของ framer-motion — ตายในชั่วโมงเดียวกับ
ที่คิดออก เพราะ `transitionend` กับ `animationend` ไม่ยิงเลยในแท็บที่ไม่มีเฟรม สิ่งที่ยังทำงานคือ
`setTimeout` (ถูกรัดเหลือราว 1Hz: 200 มาถึงที่ 1000 มิลลิวินาที) กับ scheduler ของ React เอง
ซึ่งเป็นเหตุที่การปิด *commit* ได้ในแท็บที่ไม่มีเฟรม — และนั่นคือช่อง: **ถอดลูกทิ้งในคอมมิตนั้น
โดยไม่มี `AnimatePresence` ถือไว้** ไม่มีอะไรเปลี่ยนสำหรับคนที่กำลังมองหน้าจอ

**วัดทั้งสองฝั่ง** (#203) ก่อนแก้: ค้างที่ 0.5, 1 และ 3 วินาที ทั้งสามทางเข้า · หลังแก้:
หายก่อน 0.5 วินาทีทั้งสามทาง และตัวสุ่มต่อเฟรมไม่เห็นมันเลย**สักเฟรม**หลังกลับมา · กรณีแท็บ
อยู่หน้า วัดที่ `HEAD` (ด้วย `git stash`) และบนตัวแก้: **12 เฟรม**ที่ยังวาดกล่องเท่ากันทั้งคู่
เฟรมสุดท้ายที่ **186** กับ **192** มิลลิวินาที ความทึบลดลงทั้งคู่ node หายทั้งคู่

**และตัวแก้รุ่นแรกตกการวัดข้อที่ทำให้ทางเลือกนี้ทำได้** ตัวฟัง `visibilitychange` รุ่นแรกไม่มี
dependency จึงทำงานอยู่หลังกล่องที่ **เปิด** อยู่ด้วย: สลับแท็บออกไปตอนกล่องเปิด ธงขึ้น ไม่มีอะไร
ลดมันลง แล้วการปิดในอีกหลายนาทีถัดมา ตอนแท็บอยู่หน้า ถอด node ทิ้งโดย **ไม่จางเลย** · การวัดสามอย่าง
แรกผ่านหมด เพราะทั้งสามปิดกล่องในแท็บที่ไม่มีเฟรม หรือไม่เคยออกจากแท็บเลย · ลำดับที่จับมันได้คือ
**ออกไปแล้วกลับมาขณะกล่องยังเปิด** ซึ่งเป็นโหมดที่สี่ของเครื่องมือ (`visible-after-hidden`)
รันทั้งสองฝั่ง: รุ่นแรก **0 เฟรม** · รุ่นที่แก้แล้ว **13 เฟรม** จบที่ ~195 มิลลิวินาที

**และเครื่องมือถูกอ่านตอนที่อินพุตของมันสกปรกที่สุด** (#186 อีกเครื่องมือหนึ่ง) การรันโหมดที่สี่
ครั้งแรกหลังเขียนไฟล์กลับ รายงาน **1 เฟรม** ซึ่งอ่านเหมือนตัวบกพร่องที่มันถูกเขียนมาจับเลย ·
โค้ดไม่ได้ผิด: dev server กำลังคอมไพล์ไฟล์ที่เพิ่งถูกเขียน และหน้าที่กำลังวัดอยู่ reload กลางการรัน ·
รันใหม่ตอนไม่มีอะไรคอมไพล์ได้ 12 เฟรม — **ปล่อยให้คอมไพล์จบก่อนเริ่มวัด**
