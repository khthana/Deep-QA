## 3. สามสิ่งที่รอบนี้สอน และทั้งสามเป็นเรื่องของการพิสูจน์ ไม่ใช่เรื่องของโค้ด

**ก. การเก็บกวาดที่เดินผ่านโค้ดที่มัตแตนต์ทำพัง เป็นหลักฐานเรื่องโค้ดนั้นไม่ได้**
`afterEach` ฉบับแรกของ `25a` ส่ง `DELETE` ไปที่ endpoint เดียวกับที่แถว 5 กำลังทดสอบ
มัตแตนต์ `silentremove` จึงทำให้การเก็บกวาดเสียไปด้วย แถวถัดจากนั้นตายที่ 409 ทั้งหมด
อ่านออกมาเหมือนมัตแตนต์ตัวนี้พังเก้าแถว ทั้งที่สิ่งที่มันพังคือการเก็บกวาด
ย้ายการเก็บกวาดไปเขียนลง schema ตรง ๆ ผ่าน `db/pool.js` แล้วมันฆ่าแถว 5 แถวเดียว

**เกณฑ์ตัดสินมัตแตนต์จึงมีสามข้อนับจากนี้** — (ก) แถวเป้าหมายต้องอยู่ในรายการที่ตาย
(ข) log ต้องไม่มี `error:` จากเซิร์ฟเวอร์เลย (ค) **การเก็บกวาดต้องไม่เดินผ่านโค้ดที่มัตแตนต์ทำพัง**

**ข. `waitForResponse` คืนค่าตอน header มาถึง ไม่ใช่ตอน body มาถึง** Chromium เก็บ body ไว้
แค่จนกว่าหน้าจะเปลี่ยน helper ที่เปิดหน้าแล้วอ่าน JSON ของหน้านั้นจึงแข่งกับสิ่งที่หน้าจะทำต่อ
`mySectionIds` ล้มสามครั้งในห้ารอบ แก้ด้วยการถามผ่าน `page.request` ซึ่ง response ไม่ผูกกับ
navigation **`e2e/support/clos-screen.js` กับ `e2e/tests/24a-...spec.js` ยังอ่าน body แบบเก่าอยู่**
ยังไม่เคยล้ม แต่มันคือความเสี่ยงเดียวกัน — เจ้าของงานตัดสินว่าจะเปิดตั๋วหรือไม่

**ค. หน้าที่คนกำลังดูอยู่ ไม่ใช่หน้าที่ข้อมูลใหม่จะไปลง** หน้าจอนี้เรียงตามรหัส

`Students.js` ตอบคำถามนี้ไว้ก่อนแล้ว (กลับหน้าแรก) และ **ทุกหน้าจอที่มีทั้งการแบ่งหน้าและการเพิ่ม
ต้องตอบคำถามนี้** แถวที่พิสูจน์ต้องเพิ่มจากหน้า 2 ไม่ใช่หน้า 1 มิฉะนั้นมันผ่านด้วยโชคของ seed

## 4. งานต่อไป

**ก. เดินใบตรวจของ #25 ด้วยมือ — 14 ข้อ (12 ☐ + 2 ◐)** เกือบทั้งหมดเป็นเรื่องถ้อยคำกับสี
ก่อนส่งใบเดินต้อง (ก) เช็คว่า seed รองรับทุกข้อ (ข) แยกข้อที่มีสองส่วนเป็นคนละข้อ
(ค) นับจำนวนแถวก่อนและหลังข้อที่มีการนำออก (ง) **รีสตาร์ต backend ของฝั่งเดินตรวจก่อน** —
`node server.js` ไม่มี reload route ที่แก้แล้วจะยังเสิร์ฟของเก่าจนกว่าจะ bounce

**ข. ข้อที่ code review บอกแล้วยังไม่ได้ทำ** — ตัดสินไว้ว่าเกินขอบตั๋ว ไม่ใช่ลืม:

- `sectionOf` / `offeringOf` เขียน join ของการตรวจสิทธิ์ซ้ำกันใน `enrolment.js` กับ `clos.js`
  — **ควรเปิดตั๋ว** เพราะมันคือ join ที่ ADR-0002 อาศัยอยู่ หน้าจอต่อไปที่ผูกกับตอนเรียนจะเป็นสำเนาที่สาม
- `CODE = /^\d{8}$/` ซ้ำกัน — แค่บันทึกไว้
- `SubjectStudents.js` แสดง `program_id` ดิบใต้หัว *หลักสูตร* ขณะที่ `Students.js` แปลเป็นชื่อ
  — แค่บันทึกไว้ จนกว่าเจ้าของงานจะเห็นตอนเดินและตัดสิน

**ค. สี่แถวที่ตกระหว่างการรันชุดเต็ม แต่ผ่านเมื่อรันแยก** — `16a` แถว 89, `18a` แถว 10,
`27a` แถว 4, `57a` ข้อมูลภาควิชาแถว 3 รันสี่ไฟล์นั้นแยกได้ **37/37** แล้วรันชุดเต็มซ้ำ
โดยไม่แก้โค้ดเลยก็ได้ **181/181** สองในสี่ตกที่การรอแบนเนอร์ครบ 10 วินาที **อ่านว่าเครื่องช้า
ไม่ใช่ลำดับหรือข้อมูลค้าง** ถ้าเห็นอีก การขยาย timeout ของแถวนำเข้าน่าจะเป็นคำตอบมากกว่าไล่ลำดับ
