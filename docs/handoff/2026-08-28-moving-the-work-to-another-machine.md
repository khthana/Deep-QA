# Handoff — 28 ส.ค. 2569 — ย้ายงานไปทำต่อที่เครื่องอื่น

แทน `2026-08-25-c-the-teardown-that-broke-with-the-thing-it-was-testing.md` ในเรื่องสถานะ
หัวข้อ *กับดัก* กับ *ข้อตกลงยืนพื้น* ของฉบับก่อน ๆ ยังใช้ได้ทั้งหมด

## 1. เอกสารนี้คืออะไร

**ไม่ใช่ handoff ของงาน rebuild** ไม่มีโค้ดหรือเทสต์เปลี่ยนในเซสชันนี้ เอกสารนี้มีไว้เพื่อการย้ายเครื่องอย่างเดียว
สถานะของงานยังเป็นไปตามฉบับ `2026-08-25-c-...` ทุกประการ ให้อ่านฉบับนั้นเรื่องว่างานอยู่ตรงไหนและทำอะไรต่อ

ยืนยันจาก git เมื่อ 28 ส.ค. 2569:

- commit ล่าสุด `de38ce3` — *The teardown that broke with the thing it was testing*
- working tree สะอาด · ไม่มี commit ที่ยังไม่ push · ไม่มี stash · มี branch เดียวคือ `main`

**ทุกอย่างที่อยู่ใน git อยู่บน `origin/main` แล้ว** การย้ายเครื่องจึงไม่มีความเสี่ยงว่างานที่ commit ไว้จะหาย
ของที่เสี่ยงคือของที่ **ไม่ได้** อยู่ใน git ซึ่งเป็นเนื้อหาทั้งหมดของเอกสารฉบับนี้

## 2. อะไรที่ `git clone` ไม่ให้

`README.md` หัวข้อ *Setting up on a new machine* อธิบายไว้แล้วว่าการคัดลอกโฟลเดอร์กับการ clone
ต่างกันตรงไหน ตารางนี้คือรายการที่ตรวจจาก `git status --ignored` จริงในวันที่ย้าย

| ของ | ขนาด | สร้างใหม่ได้ไหม |
|---|---|---|
| `.env` (ราก) | เล็ก | ได้ จาก `.env.example` แต่ `SECRET_KEY` ต้อง generate ใหม่ |
| `frontend/.env` | เล็ก | ได้ จาก `.env.example` หัวข้อ Frontend |
| `DEEP-QA-BACKEND/.env` · `DEEP-QA-FRONTEND/.env` | เล็ก | **ไม่ได้** — แต่**ไม่จำเป็นต่อการทำงาน** สองต้นนี้เป็น read-only reference ที่ไม่มีฐานข้อมูล ขนไปเพราะสร้างใหม่ไม่ได้เท่านั้น |
| `DEEP-QA-BACKEND/uploads/` | 3.6 MB | **ไม่ได้** — ไฟล์หลักฐานการประเมินของจริงราวสองร้อยไฟล์ เป็นข้อมูลส่วนบุคคล ไม่จำเป็นต่อ rebuild |
| `_local/` | 5.0 MB (รวม `machine-move/` ที่เพิ่งเพิ่ม 3.6 MB) | ดูหัวข้อ 3 |
| `mutation/.backup/` | 784 KB | **ได้** — สำเนาไฟล์ต้นฉบับของ harness สร้างใหม่เมื่อรันมัตแตนต์ |
| `node_modules/` ทุกตัว | ~4.6 GB | ได้ ด้วย `npm install` |
| `frontend/build/` | 17 MB | ได้ ด้วย `npm run build` |
| `e2e/test-results/` | 1 KB | ได้ |

**ฐานข้อมูลไม่ต้องขน** มันเป็น container พร้อม migration ที่มีลำดับ และ seed ที่ deterministic
`npm run db:up && npm run migrate && npm run seed` บนเครื่องใหม่ให้ข้อมูลชุดเดียวกันเป๊ะ — ไม่ต้อง dump

## 3. ของที่อยู่นอกโฟลเดอร์ และถูกย้ายเข้ามาแล้ว

คัดลอกมาไว้ที่ `_local/machine-move/` ทั้งหมด อ่าน `_local/machine-move/README.md` — มันเป็นรายการฉบับเต็ม
ต้นฉบับยังอยู่ที่เดิมบนเครื่องนี้ ไม่มีอะไรถูกย้ายหรือลบ

| | |
|---|---|
| `claude/memory/` | หน่วยความจำของ Claude Code ของโครงการนี้ 12 ไฟล์ **สร้างใหม่ไม่ได้ และเป็นของที่มีค่าที่สุดในกอง** |
| `claude/settings.json` | settings ระดับผู้ใช้ |
| `claude/scratchpad/` | scratchpad ของสองเซสชันที่ไม่ว่าง 512 ไฟล์ เกือบทั้งหมดเป็นของใช้แล้วทิ้ง เก็บไว้เผื่ออ้างอิง |
| `env/` | `.env` ทั้งสี่ไฟล์ รวบไว้ที่เดียว |

**`_local/` gitignored** มันจึงติดไปกับการคัดลอกโฟลเดอร์ และ **ไม่ติดไปกับ clone**
ถ้าย้ายด้วย clone ต้องพา `_local/machine-move/` ข้ามไปด้วยมือ ผ่าน USB หรือ password manager — ไม่ใช่อีเมลหรือแชท
เพราะ `env/` มีคริเดนเชียลจริงและ repository นี้เป็น public

### เอาหน่วยความจำกลับเข้าที่บนเครื่องใหม่

ชื่อโฟลเดอร์ใต้ `~/.claude/projects/` มาจาก path ของโครงการ **ถ้า path เปลี่ยน ชื่อโฟลเดอร์ก็เปลี่ยน**
อย่าเดาชื่อ ให้ทำตามนี้แทน:

1. วางโครงการไว้ที่ที่มันจะอยู่จริงบนเครื่องใหม่
2. เปิด Claude Code ในโฟลเดอร์นั้นหนึ่งครั้งแล้วปิด
3. ดูว่ามีโฟลเดอร์ใหม่ชื่ออะไรโผล่ใน `~/.claude/projects/`
4. คัดลอก `_local/machine-move/claude/memory/` ทั้งกองลงใน `<โฟลเดอร์นั้น>/memory/`

`MEMORY.md` เป็นดัชนีที่โหลดเข้า context ทุกเซสชัน มันต้องอยู่ในกองเดียวกันนั้นด้วย

## 4. ลำดับการติดตั้งบนเครื่องใหม่

ต้องมี Docker, Node 20 ขึ้นไป และ `gh` CLI ที่ล็อกอินแล้ว รายละเอียดทุกข้ออยู่ใน `README.md` แล้ว
ลำดับย่อ:

```bash
npm install --prefix db
npm install --prefix backend
npm install --prefix frontend
npm install --prefix e2e
npx playwright install --with-deps chromium   # ใน e2e/

cp .env.example .env        # แล้วเติมค่าจาก _local/machine-move/env/root.env
                            # ถ้าไม่มีของเก่า: SECRET_KEY ต้อง openssl rand -base64 32

cd db && npm run db:up && npm run migrate && npm run seed
```

พอร์ตที่ต้องว่าง — backend **3000** · frontend **5000** · PostgreSQL **5433** (ไม่ใช่ 5432 โดยตั้งใจ)
และฝั่ง Playwright ใช้ **3100 / 5100** กับ schema `deep_core_e2e` ของมันเอง ซึ่ง seed ใหม่ทุกครั้งที่รัน

`gh auth login` ให้ทำก่อนหยิบงาน — ตั๋วอยู่บน GitHub Issues ทั้งหมด และ `scripts/github` พึ่ง `gh`

ตรวจว่าย้ายสำเร็จด้วยสองชุดนี้ ตัวเลขที่ควรได้คือ backend **411/411** · browser **181/181**

backend **411/411 รันจริงบนเครื่องนี้ในวันที่ย้าย** (71 วินาที) จึงเป็นตัวเลขที่เชื่อถือได้
ส่วน browser **181/181** ยกมาจากฉบับ `2026-08-25-c-...` ไม่ได้รันซ้ำรอบนี้ — มันใช้เวลาราว 16 นาที

## 5. กับดัก

**clone อื่นที่ยังชี้ `master`** สาขาหลักของ `khthana/Deep-QA` ถูกเปลี่ยนชื่อ `master` → `main`
เมื่อ 17 ส.ค. 2569 ผ่าน GitHub API `origin/master` ไม่มีอยู่แล้ว **การเปลี่ยนชื่อเกิดฝั่ง server เท่านั้น**
clone เก่าบนเครื่องอื่นยังมี `master` ที่ track branch ที่ตายไปแล้ว ซ่อมด้วยมือ:

```bash
git branch -m master main && git fetch origin --prune && git branch -u origin/main main
```

ถ้า clone ใหม่บนเครื่องใหม่ ปัญหานี้ไม่เกิด — ข้อนี้มีไว้สำหรับ clone ที่มีอยู่ก่อนแล้วเท่านั้น
เก็บข้อนี้ไว้ในทุก handoff จนกว่าจะยืนยันว่าทุก clone ถูกซ่อมหมดแล้ว

**อย่า `git add` อะไรใน `DEEP-QA-BACKEND/` หรือ `_local/`** — `.env` มีคริเดนเชียลจริง
`uploads/` เป็นงานของนักศึกษาจริง และ repository นี้เป็น public

**อย่าพิมพ์ภาษาไทยผ่าน Bash** (cp874 `UnicodeEncodeError`) — เขียนผ่านสคริปต์ Python
ที่เปิดไฟล์ด้วย `io.open(..., encoding='utf-8', newline='\n')` และอย่าใส่ backtick ใน string
ที่อยู่ในเครื่องหมายคำพูดของ Bash เอกสารฉบับนี้เองก็เขียนด้วยวิธีนั้น

**รีสตาร์ต backend ก่อนเดินใบตรวจด้วยมือ** — `node server.js` ไม่มี reload
route ที่แก้แล้วจะยังเสิร์ฟของเก่าจนกว่าจะ bounce

**การคัดลอกโฟลเดอร์ต้องกัน `node_modules` ออก** ทั้งกองราว 4.7 GB โดย 4.6 GB เป็นของ frontend
ตัดออกแล้วเหลือราว 110 MB `README.md` มีคำสั่ง `robocopy` พร้อม `/XD node_modules build` ไว้แล้ว

**`claude/settings.json` ที่ขนไป ถือ trusted repo เป็น repository คนละตัวกับโครงการนี้**
บล็อก `autoMode.environment` ในนั้นระบุว่า trusted repo คือ `khthana/SAT-Project`
ซึ่งไม่ใช่ `khthana/Deep-QA` — มันเป็นของค้างจากโครงการอื่น
บนเครื่องใหม่ให้ลบบล็อกนั้นทิ้งหรือให้สร้างใหม่จากโฟลเดอร์ของโครงการนี้ อย่าปล่อยค้างไว้

**เมื่อเครื่องใหม่ใช้ได้แล้ว ให้ลบ `_local/machine-move/` ทิ้ง** มันเป็นของชั่วคราวสำหรับการย้ายรอบนี้เท่านั้น
เหตุผลไม่ใช่ความเป็นระเบียบ — `env/` คือ**สำเนาที่สองของคริเดนเชียลจริง ที่นั่งอยู่ในโฟลเดอร์ที่ OneDrive sync ขึ้น cloud**
