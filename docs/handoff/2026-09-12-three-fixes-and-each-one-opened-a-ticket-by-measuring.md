### #68 (ปิด) — คำตอบของคำขอที่ถูกแทนที่แล้ว ยังถูกวาด

แผงที่ paging ฝั่งเซิร์ฟเวอร์ยิงคำขอใหม่ทุกครั้งที่เปลี่ยนหน้าหรือเปลี่ยนคำค้น แล้ว `setState` กับคำตอบ
ที่**มาถึง**ทีหลัง ไม่ใช่คำตอบที่**ขอ**ทีหลัง คำตอบเก่าที่ช้ากว่าจึงทับของใหม่ ปิดสถานะกำลังโหลด และ
ขึ้นแบนเนอร์ของคำขอที่ไม่มีใครรอแล้ว แก้ด้วยธง `cancelled` ใน effect ตามรูปที่ `CohortPickers.js`
กับ `Plos.js` มีอยู่แล้ว

- **รายการเจ็ดไฟล์ในตั๋วเป็น grep ที่คนอื่นรันไว้** ตามหาเองแล้วเจอห้าไฟล์ที่ grep นั้นหาไม่เจอ
  และอีกสามไฟล์จากความเห็นในตั๋วเอง รวมสิบห้าไฟล์ — และการจับคู่ครบทุกไฟล์ในรายการ ตอบ
  *confirm before you change* ได้แค่ครึ่งเดียว
- **ตั๋วเสนอให้ทำ hook เดียวให้สิบห้าจอใช้ร่วมกัน คำตอบคือราคาที่การรวมต้องจ่ายด้วยการพิสูจน์**
  hook เดียวหลังสิบห้าจอ เปลี่ยนสิบห้าข้ออ้างให้เหลือข้อเดียวที่ไม่มีมัตแตนต์ตัวไหนแยกมันออกจากกันได้
- **และรอบนี้คือรอบที่สำมะโนเป็นคนเลือกจอที่จะพิสูจน์** ข้ออ้างนี้เป็นของสิบห้าจอเท่า ๆ กัน สิ่งที่ตัดสิน
  ว่าจะเขียนแถวกับมัตแตนต์ลงจอไหน คือจอไหนกวาดได้โดยไม่ชนใบอื่น — `Students.js` เป็นไฟล์เดียว
  ในสิบห้าที่ยังไม่มีใบไหนถือ
- อีกสิบหกจุดที่เหลือเป็น [#133](https://github.com/khthana/Deep-QA/issues/133) (`5f87468`)

### #132 (ปิด) — สเปกเอาสิ่งที่ตัวเองใส่ออก และสิ่งที่ไม่มีใครเอาออกถูกวัด

`17b` กับ `17c` เพิ่มนักศึกษาลงทะเบียนกลางแล้วไม่เอาออก สเปกที่รันทีหลังจึงเจอทะเบียนที่กว้างกว่า
ที่ตัวเองสร้าง (ซึ่งคือกลไกที่ #129 วัดไว้) แก้ด้วย `holdRegister()` ที่ถ่ายภาพทะเบียนใน `beforeAll`
แล้ว `release()` ลบส่วนเกินใน `afterAll`

- **ตัวช่วยถามแคตตาล็อกว่าใครอ้างถึง `student` บ้าง ไม่ได้ถือรายการตารางไว้เอง** (`pg_constraint`)
  ร่างแรกเขียนคอมเมนต์ว่าคีย์นอกเป็น RESTRICT ซึ่งผิด พิสูจน์สองทางด้วยสคริปต์ชั่วคราวแล้วแก้
- **ของจริงที่ตั๋วนี้ทิ้งไว้คือเครื่องมือ ไม่ใช่การเก็บกวาด** `e2e/support/leftovers.js` ถ่ายภาพทุกตาราง
  ในสคีมาก่อนและหลังการรัน แล้วพิมพ์รายงานท้ายทุกรอบ — **มันรายงาน ไม่ทำให้รอบล้ม** และมันเขียน
  ไว้เองว่าอะไรที่มันวัดไม่ได้ (ตารางที่อ่านไม่ได้ถูกนับแยก ไม่ถูกนับรวมเป็น *ขยับ*)
- เครื่องมือมีชุดทดสอบของตัวเอง 12 แถว (`cd e2e && npm run test:support`) ยิงกับ DB ปลอม
- **การนับที่ตั๋วขอคือการนับ*ไฟล์* ไม่ใช่การนับตาราง** และสองอย่างนี้ต่างกันจริง ๆ `subjects` ถูกขยับ
  โดยเจ็ดสเปก `program_subjects` โดยห้า และสี่ไฟล์ขยับแถว**ลง**ในห้าตาราง (`19a` `21a` `25a` `32a`)
- ส่วนที่เหลือ (16 สเปก · 17 ตาราง) เป็น [#134](https://github.com/khthana/Deep-QA/issues/134)

**และรอบสะอาดของ #132 ทำให้เจอข้อบกพร่องที่สอง** — `openRegister` กับ `openProgramSubjects`
รอ response แล้วอ่านตัวนับต่อทันที ซึ่งบางรอบอ่านได้ศูนย์เพราะ React ยังไม่วาด **ตัวช่วยที่รอคำตอบ
ยังไม่ได้รอการวาด และการ retry ไม่ช่วยอะไรเลยเมื่อค่าที่คาดไว้ผิด** แก้ด้วยการรอให้ตัวเลขที่คำตอบ
ถือมาปรากฏบนจอ พิสูจน์สดด้วยการทำให้มันรอ `carried + 1` แล้วแถวล้มจริง อีก 9 จอเป็น
[#135](https://github.com/khthana/Deep-QA/issues/135)

### #131 (ปิด) — คอมเมนต์บอกไว้แล้วว่าอันไหนทำเสมอ แต่โค้ดทำอีกอันก่อน

`POST /api/auth/logout` เขียนบันทึก `LOGOUT` ก่อนลบคุกกี้ บัญชีที่ถูกลบไปแล้วจึงชนคีย์นอกของ
`user_log` (ประวัติถูก CASCADE ไปพร้อมบัญชี) ตอบ 500 และ**การลบคุกกี้ไม่เคยได้ทำงาน** บน route
เดียวที่มีหน้าที่ลบมัน

- **คำตอบอยู่ในคอมเมนต์ของ route เองมาตั้งแต่ #92** — *"clearing is unconditional and idempotent …
  recording needs a name"* — แต่ลำดับในโค้ดพูดตรงข้าม **คอมเมนต์ที่ประกาศกฎ คือข้ออ้างเกี่ยวกับ
  โค้ดข้าง ๆ มัน และเป็นข้ออ้างที่ตรวจถูกที่สุด** (#83 อ่านกลับด้าน)
- ลงทั้งตัวเลือกที่ 1 และ 2 ของตั๋ว: ลบคุกกี้ก่อน แล้วถาม `accountStillExists` ก่อนเขียน
- **ครึ่งที่พิสูจน์ได้กับครึ่งที่พิสูจน์ไม่ได้ถูกเขียนแยกไว้** คำถามก่อนเขียนพิสูจน์แล้ว
  (`131:logstoanybody` ฆ่าแถวใหม่แถวเดียวจาก 739) ส่วน**ลำดับ**พิสูจน์ที่ seam นี้ไม่ได้ เพราะเมื่อ
  คำถามยังอยู่ ไม่มีอะไรโยน exception — สิ่งที่ลำดับกันไว้คือช่วงแคบระหว่างสองบรรทัด ซึ่งเป็นการ
  แข่งกันที่การทดสอบไม่มีที่จับ (รูปเดียวกับ #51) ไฟล์มัตแตนต์เขียนว่า *ยังไม่ได้ทดสอบ* ตามกฎของ #107
- **ข้อบกพร่องที่ไปไม่ถึงคือข้อบกพร่องที่มีวันหมดอายุ** วันนี้ยังไม่มี route ลบบัญชี แต่ #52 ทำให้
  เบราว์เซอร์ยิง logout เองเมื่อได้ธง `accessEnded` ซึ่งเหตุผลหนึ่งของมันคือสถานะนี้ตรง ๆ
- `13:N7` เล็งใหม่เป็นครั้งที่สอง (บรรทัดเดิมได้ guard และเยื้องเพิ่มหนึ่งชั้น) และกวาดยืนยันว่ายังฆ่า
  สามแถวเดิม — **การตรวจจุดยึดกับการกวาด ตอบคนละคำถาม**
- `mutation/README.md` บันทึกสำมะโนรอบที่สิบสี่: `backend/routes/auth.js` เป็น **กลุ่มเจ็ดกลุ่มแรก
  ของคลัง** (`10 · 13 · 50 · 52 · 97 · 119 · 131`) ยอด path ที่ชนกันยังเป็น 34

**หนึ่งเรื่องที่ยังไม่ได้ถาม** ตั๋วพาดหัวตัวเลือกไว้ว่า *ยังไม่ได้เลือก* และเลือก 1+2 ตามประโยคในตั๋วเอง
ที่ว่าทำคู่กันได้ — ยังไม่มีคอมเมนต์บนตั๋วที่บันทึกว่าเป็นการตัดสินของเจ้าของงาน

## Gotchas ที่ยังต้องพก

ยกมาทั้งชุดจากใบก่อนหน้า ยังใช้ได้ทุกข้อ และเพิ่มจากรอบนี้

- `git clone` ที่ทำไว้ก่อนเปลี่ยนชื่อ branch ยังชี้ `master` ที่ตายแล้ว แก้ด้วย
  `git remote set-head origin -a && git branch -m master main && git branch -u origin/main`
- **`python mutation/<ใบ>.py save` ก่อนทุกมัตแตนต์ และอ่าน `git status` หลัง `apply` ไม่ใช่แค่หลัง
  `restore`**
- **รายการ *ห้ามกวาดคู่กับ* ต้องสร้างจาก `FILES` ด้วยสคริปต์สำมะโนใน `mutation/README.md`
