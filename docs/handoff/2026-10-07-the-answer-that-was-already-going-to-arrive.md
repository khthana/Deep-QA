## งานที่ลงไป

### [#77](https://github.com/khthana/Deep-QA/issues/77) — ทางที่ 3 · **ตั๋วยังเปิด รอคำของเจ้าของสเปก**

ตั๋วนี้เป็นตั๋ว *วัดแล้วถาม* ใบก่อนวัดทางเลือกสามทางแล้วถาม เจ้าของสเปกเลือก **ทางที่ 3**
จึงกลายเป็นตั๋วลงมือสองวันถัดมา สิ่งที่ลงไป:

- **`backend/auth/authorise.js`** `attachRoles` อ่านบทบาทใหม่ทุก request อยู่แล้ว ที่มันไม่ทำคือ
  *บอกเบราว์เซอร์* ตอนนี้ส่ง `X-Deep-Grants` (base64 ของ JSON) ทันทีหลังสร้าง `req.auth`
  และก่อนเข้า route ใด ๆ ส่วนหัวจึงเป็นสิ่งที่ด่านกำลังจะตัดสินด้วย ไม่ใช่การอ่านรอบที่สองของมันเอง
- **`backend/app.js`** `cors` ได้ `exposedHeaders` เพราะส่วนหัวที่ไม่อยู่ในหกตัวที่ปลอดภัยโดยปริยาย
  อ่านข้ามต้นทางไม่ได้
- **`frontend/src/api/client.js`** listener ตัวที่สาม ข้าง `onSessionExpired` กับ `onAccessEnded`
  มีเลขลำดับกันคำตอบที่ออกไปก่อนแซงคำตอบที่ใหม่กว่า และอ่านส่วนหัว **เหนือ** กิ่ง `!response.ok`
  ของตัวเอง เพราะคำตอบ 403 จาก route ที่บทบาทนี้เข้าไม่ถึง ก็ตอบ *ใต้* ด่าน จึงพาส่วนหัวมาด้วย
  และเป็นคำตอบประเภทที่บอกว่า grants ขยับ
- **`frontend/src/context/AuthContext.js`** เปลี่ยน **รายการบทบาท** จากส่วนหัว ส่วน `acting`
  รับมาเฉพาะเมื่อบทบาทที่สวมอยู่ไม่อยู่ในรายการนั้นแล้ว — ส่วนหัวสร้างจากคุกกี้ *ตอนที่ request
  ออกไป* คำตอบของการสลับบทบาทจึงบรรยายบทบาทที่กำลัง *ถอย* ออกมา ถ้ารับทุกครั้งจะเดินคนถอย
  หนึ่งก้าวทุกครั้งที่เปลี่ยนหมวก

### ความแคบนั้นเป็นข้ออ้างที่สอง และมองไม่เห็นจนแถว 8 ได้ assert ของมัน

row 8 ให้บทบาทกรรมการกับคนที่สวมบทบาทอาจารย์อยู่ แล้วอ่านตัวเลือกใหม่ใน picker ส่วนหัวใบนั้น
บอก `acting` ว่า *กรรมการ* (บทบาทสูงสุดที่ถืออยู่ และ session ยังไม่เคยเลือกเอง) ดังนั้น
*รับ acting จากส่วนหัว* กับ *เก็บหมวกที่สวมไว้ตราบที่ยังถืออยู่* **วาดจอต่างกันตรงจุดนั้นพอดี**
ซึ่งเป็นที่ที่ฟิกซ์เจอร์ควรอยู่ (#117) ถ้าไม่มี assert นี้ กฎสองข้อคือแถวเดียว และไม่มีมัตแตนต์ใด
แยกมันได้ มีแล้ว `M12` ฆ่าแถว 8 และปล่อยแถว 9 ยืน

### สองแถว และลำดับสองแบบที่สร้างมันไม่ได้

สองแถวเพราะตั๋วรายงานสองทิศ (#66) ส่วน `grantee.reload()` ของ rows 2–3 **อยู่ที่เดิมโดยเจตนา**
การไปถึงครึ่งแรกของเกณฑ์ข้อ 2 ด้วยเส้นทางที่เก่าที่สุดที่มี ทำให้มันยืนอยู่ได้ไม่ว่าครึ่งที่สอง
จะเป็นอย่างไร — การถดถอยของส่วนหัวจึงเป็นสีแดงของแถว 8–9 ไม่ใช่ของทั้งไฟล์ คำบรรยายเหนือแถวนั้น
ที่เขียนว่า picker ตามทันเฉพาะเมื่อโหลดหน้าใหม่ ถูกเขียนใหม่แล้ว — ข้ออ้างในคำบรรยายหมดอายุ
เหมือนตัวเลข (#130)

แถว 9 ตายสองครั้งก่อนผ่าน ทั้งสองครั้งที่การจัดฉากของมันเอง ไม่ใช่ที่ข้ออ้าง:

- ให้บทบาทกรรมการ **ก่อน** ผู้รับเข้าระบบ `actingFrom` ให้บทบาทสูงสุดที่ถืออยู่ คนนั้นจึงมาถึง
  พร้อมหมวกนั้น และแดชบอร์ดอาจารย์ที่ `chooseSection` ต้องใช้ ไม่ใช่เปลือกที่เขาอยู่ แถวตายใน
  `chooseSection` ที่ timeout — **stack บอกว่ารอที่ไหน snapshot ที่บันทึกไว้บอกว่าจอตัดสินอะไร**
  และปุ่มบทบาทอ่านว่า *กรรมการหลักสูตร 0501* ก่อนมีการกดอะไรเลย (#160)
- สลับลำดับแล้ว มันค้างใน `switchTo` รอ `PUT /api/me/acting-role` ที่ไม่เคยเกิด — เพราะ
  **การสลับที่มันกำลังจัดฉากเกิดขึ้นแล้ว** ไม่มีคุกกี้ acting จนกว่าจะมีคนเลือกเอง การ reload
  ที่พาบทบาทใหม่เข้า picker จึงพาคนเข้าบทบาทนั้นไปด้วย สิ่งที่เขียนเป็นการจัดฉากคือข้อยืนยัน
  และตอนนี้ยืนยันตรงที่มันถูกใช้ (#51)

### รอบรีวิว — เจ็ดข้อ สองข้อผิด และหนึ่งข้อที่แรงกว่าที่รีวิวบอก

**ข้อที่สำคัญที่สุด คีย์ลำดับเป็นลำดับของอย่างอื่น** ฝั่ง client ประกาศเฉพาะรายการที่ใหม่ที่สุด
โดยคิดจาก `seq` ซึ่งเป็นลำดับที่ request **ออกเดิน** ส่วนคำบรรยายเหนือมันให้เหตุผลจากลำดับที่
request **ถูกตอบ** รีวิวจับได้ แต่ **ผลที่ตามมารีวิวบอกผิด** — มันเขียนว่า "หายเองและปลอดภัยกว่า
ทางกลับกันอย่างชัดเจน" ซึ่งตรงข้าม: ถ้าเซิร์ฟเวอร์อ่าน request ที่ออกไปทีหลังก่อน คำตอบที่มาถึง
เป็นใบที่สองจะมี **เลขตั๋วสูงกว่าแต่ snapshot เก่ากว่า** แล้วถูกนำมาใช้ เอาบทบาทที่ถูกถอนแล้ว
กลับขึ้น picker ซึ่งเป็นความผิดที่แถว 9 มีไว้พิสูจน์ว่าแก้แล้วพอดี **ข้อค้นพบจริงได้ แต่รัศมี
ความเสียหายของมันยังผิดไปทางที่ปลอดภัยได้** และทางนั้นคือทางที่ต้องคิดใหม่เอง

คีย์ที่ถูกคือ *เวลาที่อ่าน* ซึ่งมีแต่เซิร์ฟเวอร์รู้ จึงให้เซิร์ฟเวอร์บอก — `read_at` อยู่ข้าง `roles`
ในส่วนหัว ส่วน `seq` `ticket` และการรีเซ็ตตอน remount ถอดออกทั้งชุด เพราะตราเวลาไม่ต้องมีวงจรชีวิต
ซึ่งตอบข้อ *ชื่อที่อ่านไม่ออก* เรื่อง `announced` ที่อ่านเหมือนบูลีนไปด้วย **ส่วนที่คีย์นี้แยกไม่ได้
เขียนไว้บนโค้ด ไม่ใช่เถียงให้หาย** — การอ่านสองครั้งในมิลลิวินาทีเดียวกันเสมอกัน ใบที่มาถึงทีหลังชนะ
และสองใบนั้นบรรยายสถานะต่างกันได้เฉพาะถ้ามีการเขียนบทบาทคั่นกลาง

ตั๋วนั้น** และเปิดอยู่ · รีวิวแกนมาตรฐานเสนอให้รวม `held` ของ `AuthContext` กับ `isActing` ของ

**หนึ่งข้อที่ถูกแล้วกลายเป็นหมายเหตุ ไม่ใช่การแก้** ขั้นตอนของเกณฑ์ข้อ 2 เขียนว่ากดเมนู **ใด ๆ**
และ ⚙ ที่ได้จากการกดสองที่ ไม่ใช่การพิสูจน์คำว่าทุกที่ สิ่งที่สองการกดพิสูจน์คือ *กลไก* ซึ่งอยู่ที่
ไซต์เดียวในท่อของ client และยิงกับคำตอบทุกใบ ส่วนที่คำว่า *ใด ๆ* เพิ่มคือข้ออ้างเรื่องประชากรของจอ
ซึ่งตอบด้วยสำมะโน ไม่ใช่ด้วยแถว (#174) แถวนั้นจึงถือตัวเลข วัน และข้อยกเว้นหนึ่งจอของสำมะโนไว้
และบอกตรง ๆ ว่า **สำมะโนนี้เป็นการวัดที่ลงวันไว้ ไม่ใช่เครื่องมือ** — ไม่อยู่ใน `npm run census`
จึงไม่มีอะไรจับได้ถ้าจอใหม่ไม่ถามเซิร์ฟเวอร์ การยกมันขึ้นเป็นเครื่องมือเป็นตั๋ว ไม่ใช่บรรทัดในใบเกณฑ์

ข้ออ้างเรื่องลำดับเองก็ได้การปฏิบัติแบบเดียวกัน ในรูปสามทาง: `read_at` ตัดสินว่าการอ่านใบไหนชนะ
และไม่มีแถวไหนสร้างการอ่านสองใบที่สลับลำดับ นั่นคือ **ยังไม่ทดสอบ** ไม่ใช่เอื้อมไม่ถึงเชิงโครงสร้าง
เพราะ `route.fulfill` สร้างได้ และใบเกณฑ์บอกว่าเป็นอันไหน พร้อมวัน (#102)

## เรื่องที่จะกินเวลาถ้าไม่รู้ (gotchas)

- **clone อื่นยังมี `master` ที่ตายแล้ว** ปลายทางเปลี่ยนเป็น `main` แล้ว clone เก่าต้องแก้มือ:
  `git branch -m master main && git fetch origin && git branch -u origin/main main && git remote set-head origin -a`
- **พอร์ต 3100/5100 ของ `e2e/` ถูก Windows จองไว้** 3100 อยู่ในช่วง 3007–3106 อาการคือ
  "already running" หรือ webServer "exited early" อ่าน
  `netsh interface ipv4 show excludedportrange protocol=tcp` **ทุกครั้ง** แล้วเลือกจากนอกช่วง
  อย่ายกพอร์ตจากใบนี้ไปใช้ รอบนี้ใช้ `E2E_BACKEND_PORT=3400 E2E_FRONTEND_PORT=5310`
- **อย่ารัน `npm run format` หรือ `npx prettier --write`** prettier ที่ติดตั้งใหม่กว่าสไตล์ที่คอมมิตไว้
  `client.js` จึงมีข้อร้องเรียนค้างอยู่หนึ่งข้อ (`export const del`) ที่ **ไม่ใช่ของงานนี้** —
  ตรวจด้วย `npx prettier <file> | diff - <file>` ถ้าจะยืนยัน
- **คอนโซลเป็น cp874** อย่าพิมพ์ไทยหรือ ☑⚙◐☐ ผ่าน Bash ใช้ Read/Grep หรือ redirect ลงไฟล์แล้ว Read
  หรือ `PYTHONIOENCODING=utf-8` ส่งไทยขึ้น GitHub ด้วย `--body-file` กับพาธแบบ Windows
  และ `MSYS_NO_PATHCONV=1`
- **ห้ามแก้ไฟล์ใน `frontend/`, `e2e/` หรือ `mutation/` ขณะชุดทดสอบหรือฮาร์เนสรัน** การแก้แม้แต่
  คำบรรยายทำให้ CRA hot-reload กลางรอบ
