## สิ่งที่วัดได้

**ประชากรเป็นสามจุด ไม่ใช่จุดเดียว** ตั๋วเขียนเมื่อ 17 ต.ค. 2569 ตอนที่ช่องเลือกเป็นจุดเดียว
และ #215 ลงเมื่อ 23 ต.ค. ทำให้อีกสองจุดอ่านถ้อยคำเดียวกัน · บนจอจริงวันที่ตอบ ช่องเลือกกับ
ตารางบทบาทที่ถืออยู่อ่าน `ทั้งมหาวิทยาลัย (FULL_ADMIN)` ส่วนคอลัมน์บทบาทของรายการบัญชีอ่าน
`ผู้ดูแลระบบกลาง (ทั้งมหาวิทยาลัย (FULL_ADMIN))` คือ **วงเล็บซ้อนวงเล็บ** ซึ่งไม่มีแถวไหนเคยอ่าน

**และผู้อ่านมีคนเดียว** บัญชีที่ถือสิทธิ์ขอบเขตนี้ถูกกรองออกจากรายการของผู้ดูแลที่อาวุโสน้อยกว่า
**สองชั้น** คือ `COALESCE(SENIORITY, 99) >= $2` กับ `OWN_SCOPE = ANY($1)` ทั้งคู่อยู่ใน `where`
ของ `backend/routes/users.js` และใช้นิพจน์ที่ `backend/auth/administration.js` นิยามไว้
(ที่นั่นเองเป็น `>= $3` เพราะเป็นการอ่านบัญชีใบเดียว) · ชั้นอาวุโสคือชั้นที่กันผู้ถือสิทธิ์นี้
**ทุกคน** ส่วนบัญชีที่วัดจริงคือ `admin01` ซึ่งไม่มีทั้งภาควิชาและหลักสูตร ชั้นขอบเขตจึงกันมัน
อยู่แล้วด้วย — ผู้ดูแลคณะและผู้ดูแลภาควิชา `05` ค้นหาบัญชีนั้นเห็น **0 แถว** ฉะนั้นทางถอยของ
`scopeNamed` ที่อ่านรหัสเปล่า (§#215 แถว 3 กับ 4) ไปไม่ถึงขอบเขตนี้เลย

**และราคาที่ตั๋วเขียนไว้ไม่ตรง** ([#77](https://github.com/khthana/Deep-QA/issues/77)) ตั๋วเขียนว่า
แถว 4 ของ `90a` ต้องเปลี่ยน — แต่ข้ออ้างสองข้อของแถวนั้น (มีรายการเดียว และไม่มีคำนำหน้า)
**จริงทั้งคู่ทั้งก่อนและหลัง** ฉะนั้นสิ่งที่ค้างอยู่คือ **ข้ออ้างใหม่** หนึ่งข้อ มัตแตนต์ใหม่

## สิ่งที่ยังค้าง

- **ไม่มีอะไรของ #216 ค้าง** คำถามถูกตอบ โค้ดลงตามคำตอบ ทั้งสามจุดมีแถว และทางเลือกที่ไม่ได้เลือก
  ถูกเขียนให้รันได้เป็นมัตแตนต์
- **ไม่มีสำมะโนตัวไหนถามว่าจอไหนวาดค่าที่ schema เลือกให้คนอ่าน** นี่คือสปีชีส์ของใบนี้ และ
  ประชากรของมันคือค่าแบบ sentinel ทุกตัว ไม่ใช่ `FULL_ADMIN` ตัวเดียว — ยังไม่มีเครื่องมือและ
  ยังไม่มีตั๋ว ถ้าจะเปิด ให้นับด้วยกลไก ไม่ใช่ด้วยชื่อ
  ([#174](https://github.com/khthana/Deep-QA/issues/174))
- **ใบ `12` ถือแถวเกณฑ์ของ #216 ไว้หนึ่งแถว และตัวเลขของการกวาดอยู่บนใบ `11`** ซึ่งเป็นใบที่ตั๋ว
  เขียนไว้ ([#123](https://github.com/khthana/Deep-QA/issues/123)) — ใครแก้ตัวเลขต้องแก้ที่ใบ `11`
