## หกข้อที่ #119 ทิ้งไว้

### 1. ประโยคที่จริง ถูกอ่านเป็นคำตอบของคำถามอีกข้อ

หัวไฟล์ `backend/test/auth.test.js` เขียนว่าเส้นทาง Google ตรวจผ่าน `resolveGoogleAccount` เพราะ
หน้ายินยอมของ Google ขับด้วยชุดทดสอบไม่ได้ ทั้งสองครึ่งถูก และทั้งสองครึ่งพูดถึง**ครึ่งของ Google**
ในการเดินทางไป-กลับ มันถูกอ่านเป็นคำกล่าวถึงทั้งเส้นทาง บรรทัดที่ตัดสินว่าคนที่ Google ตอบให้แล้ว
ไปจบที่ไหนจึงไม่มี seam ไหนรันเลย

> **เหตุผลที่อธิบายว่าทำไมครึ่งหนึ่งของอะไรสักอย่างทดสอบไม่ได้ ไม่ใช่คำกล่าวถึงอีกครึ่งหนึ่ง**

มันอ่านเหมือนเป็นคำตอบนานพอที่ #66 จะเขียนปลายทางบนบรรทัดนั้นใหม่ โดยไม่มีเทสต์ตัวไหนดูอยู่

### 2. ความครอบคลุมที่เกือบใช่ คือสิ่งที่ทำให้มันรอด

`50a` ไล่ `GOOGLE_REFUSAL_REASONS` ทีละเหตุผล แล้วยืนยันว่าหน้าจอแสดงประโยคถูกตัว — ด้วยการ
**พิมพ์เหตุผลลงแถบที่อยู่เอง** (`openSignIn(page, 'login?error=' + reason)`) นั่นพิสูจน์ว่าหน้าจอ
อ่านเหตุผลจาก query string ได้ ไม่ใช่ว่า route เคยใส่เหตุผลลงไป

> **เมื่อมีเทสต์นั่งอยู่สองข้างของบรรทัดหนึ่ง ให้ตรวจว่ามีอะไรรันบรรทัดนั้นจริงไหม**

### 3. เส้น stub อยู่ที่ขอบของเครื่อง ไม่ใช่ขอบของฟีเจอร์

การแลก token กับการอ่าน profile คือสองคำขอเดียวที่ออกจากเครื่องนี้ stub เฉพาะสองตัวนั้น
แล้ว strategy จริง `resolveGoogleAccount` จริง ฐานข้อมูล seed จริง และ cookie จริง รันหมด
§Testing Decisions ห้าม stub ฐานข้อมูลและการลงชื่อเข้าใช้ ไม่มีอันไหนถูก stub

**วิธีทำ** ตั้ง env สองตัว → `createApp({ pool: api.pool })` ใหม่ (strategy ลงทะเบียนเฉพาะตอนมี
credentials) → `passport._strategy('google')` แล้วทับ `_oauth2.getOAuthAccessToken` กับ
`userProfile` → ยิง `GET /api/auth/google/callback?code=...` → `passport.unuse('google')` และคืน env

> **ถามว่าอะไรเข้าไม่ถึงจริง ๆ ไม่ใช่ว่าฟีเจอร์นี้ชื่อว่าอะไร**

### 4. เครื่องหมายไม่ใช่มัตแตนต์

มัตแตนต์สามตัวใน `mutation/119-google-landing.py` ฆ่าด้วย `cd backend && node --test
test/auth.test.js` **แถวที่มันค้ำจึงเป็น ☑ ไม่ใช่ ⚙** เครื่องหมายบอกว่า *seam ไหน* พิสูจน์แถว
ส่วนการกวาดบอกว่า *พิสูจน์จริงหรือเปล่า* — สองคำถามนี้แยกกัน ใบตรวจรับมีหัวข้อของตัวเองสำหรับ
สองแถวนี้ เพราะตารางมัตแตนต์ที่มีอยู่เป็นตารางของ ⚙

### 5. มัตแตนต์สองตัวฆ่าแถวเดียว คือปัญหาของแถว

`googlelandsonthechooser` กับ `googlelandswithoutasession` รอบแรกฆ่าแถวเดียวกัน เพราะปลายทางกับ
cookie ถูกเขียนเป็นข้ออ้างเดียว — รูปเดียวกับที่ #85 เจอกับ `role="alert"` แต่คนละสาเหตุ
ไม่ใช่ premise ที่ locator ยืนอยู่ เป็นแค่สองข้ออ้างที่นั่งอยู่ในแถวเดียว จึงแยกแถว
**redirect ไป `/main` โดยไม่มี session คือ redirect ไป `/login` ในอีกอึดใจ**

### 6. สาขาที่ถูกคลุมข้าง ๆ ทำให้สาขาที่ไม่ถูกคลุมดูเหมือนถูกคลุม

ตั๋วกำหนดขอบเขตไว้ที่บรรทัด `/main` และเขียนราวกับคำปฏิเสธมี route คลุมแล้ว สิ่งที่รันอยู่จริงคือ
`refuseToBrowser` บนสาขา `!googleConfigured()` ซึ่งตอบก่อนเข้า passport ด้วยซ้ำ ส่วนสาขาคำปฏิเสธ
ระดับ**บัญชี** ไม่มีอะไรรัน

ทำในตั๋วนี้แทนที่จะเลื่อน เพราะ stub ที่สาขาสำเร็จต้องใช้อยู่แล้วคือต้นทุนทั้งหมดของการไปถึงมัน
และไม่มีโค้ดที่ส่งมอบเปลี่ยนสักบรรทัด — **เลื่อนงานข้างเคียงได้ แต่อย่าเลื่อนครึ่งหลังของประโยค
ที่กำลังปิด** แถวในใบตรวจรับเขียนกำกับไว้เองว่าไม่ได้อยู่ในตั๋วเดิม

## สี่ข้อจาก /code-review ของ #119 เอง

- **การคืนค่า env ที่ไม่สมมาตร** `if (id !== undefined)` *คืน*ค่าได้แต่*ลบ*ไม่ได้ บล็อกที่ **ตั้ง**

  เพราะไปดู `backend/.env` แทน `.env` ที่ราก ซึ่งเป็นตัวที่ `db/pool.js` โหลด** วัดก่อนเชื่อผลรีวิว
  เหมือนที่วัดก่อนเชื่อตั๋ว แก้อยู่ดี: ทั้งสองบล็อกใช้ `withOAuthCredentials` ตัวเดียวกัน ซึ่งคืนค่า
  ด้วยการ**ลบ**สิ่งที่เดิมไม่ได้ตั้งไว้
- **คำกล่าวที่กว้างเกินไป สามที่** เขียนว่า *ไม่มี seam ไหนรันบรรทัดพวกนั้นเลย* จบประโยค — แก้เป็น

- **หัวข้อการชนของ `mutation/README.md` ค้างทันทีที่ตั๋วนี้ลง** `auth.js` ขึ้นจากสี่ใบเป็นห้า

- **บรรทัดนับของ `10-application-shell.md` ค้างแบบเดียวกันและหนักกว่า** อ่านว่า *14 ⚙ · 3 ☑ · 2 ☐*

## Gotchas ที่ยังต้องพก

ยกมาทั้งชุดจากใบก่อนหน้า ยังใช้ได้ทุกข้อ

- `git clone` ที่ทำไว้ก่อนเปลี่ยนชื่อ branch ยังชี้ `master` ที่ตายแล้ว แก้ด้วย
  `git remote set-head origin -a && git branch -m master main && git branch -u origin/main`
- e2e ใช้พอร์ต 5100 ซึ่ง Windows จองไว้เป็นช่วง ๆ ถ้าเจอ *already running* ทั้งที่ไม่มีอะไรฟัง
  ให้รันด้วย `E2E_FRONTEND_PORT=5300` ชุดเต็มใช้เวลาราว **18 นาที**
- `node server.js` ไม่มี reload — บันซ์ backend ก่อนเดินทุกครั้ง
- TaskStop ปิด shell แต่ไม่ปิดลูกของมัน เซิร์ฟเวอร์ที่ค้างจะทำให้การกวาดรอบถัดไปรายงานว่า
  *ไม่มีอะไรล้ม* ซึ่งหน้าตาเหมือนชุดมัตแตนต์ที่ฆ่าอะไรไม่ได้เลย
- **อย่ากวาดมัตแตนต์ระหว่างที่ชุด e2e กำลังรัน** การกวาดเขียนโค้ดที่พังลงดิสก์จริง — รอบนี้เลื่อน
  การกวาดรอบสุดท้ายไปจนชุดเบราว์เซอร์จบ ด้วยเหตุผลนี้
- **เดินด้วยมือก่อนกวาดมัตแตนต์และก่อนรันชุดเต็ม** ด้วยเหตุผลเดียวกัน
