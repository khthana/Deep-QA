## การกวาดที่ไม่ได้ใส่มัตแตนต์ สองครั้งในวันเดียว สองสาเหตุ

เช้า: การกวาดซ้ำยี่สิบตัวจบใน **31 วินาที** ทุกช่องผลว่าง เพราะ `& npx playwright test` ตายใน
PowerShell ที่ call operator · บ่าย: การกวาดสิบสองตัวจบใน **15 นาที** ได้ `10 ผ่าน` กับ
`22 ผ่าน` ทุกตัว เพราะ harness **ไม่มีคำสั่ง `apply`** — CLI ของมันคือ
`save | restore | list | <mutant>` จึงพิมพ์ usage แล้วจบด้วย**รหัสออก 0**

อาการเดียวกันทั้งสองครั้ง และอ่านไม่ต่างจากมัตแตนต์ที่ฆ่าอะไรไม่ได้ สิ่งที่อันตรายคือ
**ความน่าเชื่อ**: รอบบ่าย การกวาด B ให้ `10 ผ่าน` ซึ่งอ่านว่า *การย้ายทำให้สิบแถวของ #266
พิสูจน์อะไรไม่ได้อีก* ซึ่งเป็นสิ่งที่รีวิวเพิ่งเตือน และการกวาด C ให้ `22 ผ่าน` ซึ่ง**ตรงกับ
คำทำนาย** พอดี สิ่งที่บอกว่าผิดคือช่อง `dirty:` ในบันทึก ที่ถาม
`git status --porcelain -- frontend/src` หลัง apply — ว่างทั้งสิบสองรอบ สคริปต์รอบที่สาม
ทำให้ช่องนั้นเป็น**ประตู** ไม่ใช่ช่องให้อ่านทีหลัง
