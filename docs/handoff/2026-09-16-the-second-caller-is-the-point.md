## #133 (ปิด) — ยี่สิบสองจอวาดคำตอบของคำขอที่ตัวเองยังอยู่กับมัน

- **เลขของตั๋วเป็นข้ออ้างของวันที่เขียน** *สิบหกจุด* คือสิ่งที่ grep ของตั๋วจับได้ อีกหกจุดตั้งชื่อให้คำตอบ
  ก่อนวาด (`Plos` `GradingWeights` `ContinuousImprovement` `TeacherSection` `GrantsPanel` และรายการกิจกรรม
  ที่ `ActivityScores` อ่านข้างตาราง) จึงไม่มีทางถูกจับด้วยรูป `set…(await …)` — และ `TeacherDashboard`
  อยู่ในรายการที่ไล่มาแต่ **ไม่นับ** เพราะถามโดยไม่มีพารามิเตอร์ จึงไม่มีคำขอที่สองให้คำขอแรกแพ้
- **ยี่สิบสองจุดเป็นสองตระกูล และเส้นแบ่งคือ *อะไรแทนคำขอได้*** หกจุดมีตัวควบคุมอยู่บนจอตัวเอง จึงได้แถวของ
  ตัวเองใน `e2e/tests/133a-superseded-answer-on-one-screen.spec.js` (ถือคำตอบแรกด้วย `page.route`
  อ่านจอครั้งเดียวหลังคำตอบที่สองถูกวาด) สิบหกจุดที่เหลือแทนได้ด้วยการเดินทางเท่านั้น และทุกลิงก์บนจอนั้นเดิน
  *ขึ้น*ไปหารายการที่ถอดจอทิ้ง จึงได้ *ยังไม่ได้ทดสอบ* พร้อมเหตุผลและวันหมดอายุ — **ไม่ใช่ *ไม่ต้องมี***
- **`ActivityScores` ถูกตั๋วจัดผิดกลุ่ม** ตั๋วใส่ไว้ใต้ *`useParams`* แต่มีแต่ `sectionId` ที่มาจากเส้นทาง
  (ADR-0004) ส่วน `activityId` เป็น state ที่ `<select>` บนจอตั้ง และจุดที่สองของไฟล์คือ **คำตอบของการบันทึก**
  ซึ่งเป็นการอ่านเหมือนกันทุกประการ
- **ธงของ handler ไม่ใช่ธงของ effect** สำมะโนรูปของธง (24 ฟังก์ชันใน 20 ไฟล์) ตอบว่า *ลายเซ็นถูกไหม*
  ส่วนคอมเมนต์ที่สำมะโนนั้นทำให้เกิด — *สำหรับ handler คำตอบที่ซื่อสัตย์คือใช่* — ตอบ *ธงถูกไหม* และผิดบนสองจอ
  ไม่มีอะไรถอด handler ทิ้ง สิ่งที่มันถามได้จึงเป็น *ตัวควบคุมยังอยู่ที่เดิมไหม* ซึ่งเป็น `useRef`
  (`onScreen`) ไม่ใช่ธงของ effect
- **ราคาที่ต่างกันสองจอ** `Plos` ได้แถวที่เจ็ดของ `133a` เพราะ `save` ล้าง `editing` **ก่อน** สั่งโหลดใหม่
  ตัวกรองจึงกลับมาอยู่ใต้มือผู้ใช้ทั้งที่คำขอยังไม่กลับ ส่วน `ActivityScores.onImported` ได้ธงเดียวกันแต่ได้
  *ยังไม่ได้ทดสอบ* บนใบ `34` เพราะสร้างสถานการณ์ต้องอัปโหลดไฟล์ที่เขียนคะแนนทั้งห้อง
- **มัตแตนต์สองตัวไม่ใช่ข้ออ้างเดียวกัน และตัวเลขเป็นคนบอก** `ploshandlerstalewins` ถอดเฉพาะสิ่งที่ handler
  ส่งเข้าไป — **1 ล้ม 389 ผ่าน** แถวที่เจ็ดตัวเดียว ส่วน `plosstalewins` ถอดการตรวจออกจาก `load` ซึ่งเป็น
  บรรทัดเดียวที่ผู้เรียกทั้งสองวิ่งผ่าน — วัดใหม่ได้ **2 ล้ม 388 ผ่าน** เลขเดิม (1/388) เป็นเลขของชุดที่ยังไม่มี
  แถวที่เจ็ด *รายงานเลขที่วัดได้ ไม่ใช่เลขของตั๋ว* กินความถึงเลขของตัวเองเมื่อชั่วโมงก่อนด้วย
- **เก้าจุดยึดของใบอื่นหลุดเพราะการเยื้องโค้ดสองช่อง** (`28` `29` `30` `31` `32` `39` `40` `42` `45`)
  ทุกตัวเป็น `swallowrefusal` / `refusalkeepsloading` / `drilldownwontclose` ที่ยึดกับ `catch` หรือ `finally`
  ที่ตั๋วนี้ย้ายเข้าไปอยู่ใต้ `if (isCurrent())` — เล็งใหม่แล้ว**กวาดซ้ำทีละใบ** เพราะ *จุดยึดบอกว่ามัตแตนต์ยัง
  ใช้ได้ ไม่ได้บอกว่ามันยังพิสูจน์อะไรอยู่* ทั้งเก้ายังฆ่าแถวที่ใบของมันอ้าง
- **สองจุดเขียนไว้แทนการใส่ธง** `Plos.openEditor` เข้าถึงอันตรายเดียวกันได้ทางที่สอง แต่เป็นหนึ่งใน
  ตระกูลแปดจุดที่กลายเป็น #139 ส่วน `PloMapping.choose` **โครงสร้างเข้าไม่ถึง** — เซลล์ที่ค้างพก `outcome_id`
  ของหลักสูตรที่จากมา PLO เป็นของหลักสูตรเดียว และทุกช่องวาดจาก `grid.outcomes` ของหลักสูตรที่อยู่บนจอ
  จึงไม่มีช่องไหนเปิดหามันเจอ เขียนพร้อมวันที่ (#131) ตามแบบที่ `TeacherDashboard` วางไว้
- **`133a` เขียนลงฐานข้อมูลหนึ่งแถว** (แถวที่เจ็ดบันทึก PLO โดยไม่แก้ค่า แต่ `updated_at` ขยับ) จึงใช้
  `hold()` ของ #137 — *การเทียบด้วยคีย์มองไม่เห็นการเขียนทับ*

## Gotchas ที่ยังต้องพก

ยกมาทั้งชุดจากใบก่อนหน้า ยังใช้ได้ทุกข้อ และเพิ่มจากรอบนี้

- `git clone` ที่ทำไว้ก่อนเปลี่ยนชื่อ branch ยังชี้ `master` ที่ตายแล้ว แก้ด้วย
  `git remote set-head origin -a && git branch -m master main && git branch -u origin/main`
- **ตั๋วบน tracker อ้าง `ไฟล์:บรรทัด` — การเติมบรรทัดในคอมเมนต์ของไฟล์เดียวกันทำให้ตั๋วผิดทันที**
  รอบนี้การเติมเลขตั๋วในคอมเมนต์ของ `Students.js` ดันทุกอย่างข้างล่างลงหนึ่งบรรทัด แก้ด้วยการ**จัดบรรทัดใหม่
  ให้จำนวนบรรทัดเท่าเดิม** ไม่ใช่ไปตามแก้ตั๋ว และตรวจด้วย `sed -n '<n>p'` หลังแก้ทุกครั้ง
- **`prettier` ไม่ใช่ dependency ของ repo** — `npx prettier --check` จะติดตั้งให้เองแล้วบ่นเรื่องสไตล์
  ที่ repo ไม่ได้ใช้ อย่าถือผลของมันเป็นมาตรฐาน ให้ดูไฟล์ข้าง ๆ แทน
- **`gh issue list` คืน 30 รายการถ้าไม่ใส่ `--limit`**
- **สเปกที่เขียนหรือลบแถว ใช้ `hold()` จาก `support/hold.js` และประกาศ `beforeAll` ของมันก่อน `beforeAll` อื่นที่เขียน**
  แล้วรันไฟล์นั้นเดี่ยว ๆ อ่านรายงาน leftovers ว่าเหลือแค่ `user_log`
- **Python ที่รันเบื้องหลังโดย redirect stdout จะบัฟเฟอร์ไฟล์ progress ไว้ว่างจนจบ**
- **`python mutation/<ใบ>.py save` ก่อนทุกมัตแตนต์ และอ่าน `git status` หลัง `apply` ไม่ใช่แค่หลัง `restore`**
  — และเมื่อทั้งชุดถูกแก้ค้างไว้ทั้งตั๋ว `git status` บอกอะไรไม่ได้ ให้เทียบ **sha1** ก่อน `save` และหลัง `restore`
- **รายการ *ห้ามกวาดคู่กับ* ต้องสร้างจาก `FILES` ด้วยสคริปต์สำมะโนใน `mutation/README.md`**
- **สคริปต์นับเครื่องหมายต้องอ่านช่องสุดท้ายของแถว *และ* ช่องนั้นต้องขึ้นต้นด้วยเครื่องหมาย** —
  ตรวจด้วยการนับที่ commit ของใบส่งมอบก่อนหน้า
- **อย่าพิมพ์ภาษาไทยหรือ ☑ ⚙ ◐ ☐ ผ่าน Bash ด้วย Python** console เป็น cp874 — เขียนไฟล์ด้วย
  `io.open(..., encoding='utf-8')` แล้วอ่านด้วยเครื่องมืออ่านไฟล์
- **เขียนสคริปต์แก้ไฟล์ลงไฟล์ก่อนแล้วค่อยรัน** heredoc กิน backslash และสำลักภาษาไทยยาว ๆ
- **`.gitattributes` เป็น `* text=auto eol=lf`** — `io.open(...)` ต้องส่ง `newline=''` ตอนเขียน และการตัด
  ย่อหน้าใหม่ด้วย `split('\n\n')` กินบรรทัดว่างท้ายไฟล์ ให้เติมกลับ
- e2e ใช้พอร์ต 5100 ซึ่ง Windows จองไว้ ให้รันด้วย `E2E_FRONTEND_PORT=5300` ชุดเต็ม **390 แถวใช้ 19.2–20.7 นาที**
  เมื่อ 16 ก.ย. **หัวข้อ *Two test seams* ใน `CLAUDE.md` ยังเขียนว่า 3100/5100**
- **ท้ายทุกรอบ e2e มีรายงาน leftovers ของ #132** มันรายงาน ไม่ทำให้รอบล้ม และ `user_log` หลายร้อยแถวเป็นเรื่องปกติ
- **การรันสเปกไฟล์เดียวจะรายงานของที่ไฟล์นั้นทิ้งไว้เอง** เพราะ `globalSetup` drop/migrate/seed ใหม่ทุกครั้ง
- **อย่าแก้ไฟล์ spec `e2e/support` หรือ `frontend/src` ระหว่างที่ชุดกำลังรัน** (frontend ของ e2e คือ CRA dev
  server ที่ hot-reload)
- `node server.js` ไม่มี reload — บันซ์ backend ก่อนเดินทุกครั้ง
- TaskStop ปิด shell แต่ไม่ปิดลูกของมัน — ฆ่าเฉพาะ PID บน 3100/5300 และ **งานเบื้องหลังที่คิดว่าตายแล้ว
  อาจยังค้างมัตแตนต์ไว้ในต้นไม้** รอบนี้เจอมาแล้ว
- **อย่ากวาดมัตแตนต์ระหว่างที่ชุด e2e กำลังรัน** และ **เดินด้วยมือก่อนกวาดและก่อนรันชุดเต็ม**
- **docstring ในไฟล์มัตแตนต์ที่อ้าง regexp ต้องเป็น raw string** (`r"""`)
- **spec ที่รันแบบ `serial` รายงาน kill ต่ำกว่าจริง** — วัดทีละแถว
- **`node --test` นับ suite แม่ใน `# fail` และเทสต์ระดับบนสุดของไฟล์มี `not ok` ที่ไม่เยื้อง** — อ่านชื่อ
- **การรอที่เขียนเพื่อจังหวะเวลา ต้องมี timeout ที่ยอมให้หมดได้** และ `networkidle` ไม่มีความหมายหลังการนำทางภายใน SPA
- **ค้นบน tracker ก่อนเปิดตั๋ว** (`gh issue list --state all --search "<ชื่อ spec หรือไฟล์>"`)
- **`npx eslint` ใน `backend/` และ `e2e/` ออก exit 2 เพราะไม่มี config** ใช้ `node --check` ที่นั่น
