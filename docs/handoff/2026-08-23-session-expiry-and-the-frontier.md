## 2. #94 ทำอะไร และมันแก้ประโยคหนึ่งใน handoff ฉบับก่อน

ฉบับก่อนเขียนไว้ที่หัวข้อ 3 ว่า **"ห้ามแก้ด้วยการให้ `requireSession` ล้าง cookie"** ตอนนั้นถูก
เพราะประโยคนั้นพูดถึง #92 ซึ่งแก้ที่ *ปุ่ม* ตอนนี้มันไม่ใช่คำสั่งที่ควรอ่านตรงตัวอีกแล้ว

#94 คือเส้นทางของคนที่กด F5 แทนที่จะกดปุ่ม cookie อายุยาวกว่า token หนึ่งช่วงอายุเต็ม (#69 และยังถูก)
และในครึ่งชั่วโมงนั้น `GET /api/me` ตอบ `expired` ซ้ำไปเรื่อย ๆ กล่อง `fixed inset-0 z-[9999]` จึงถูก
วาดทับหน้าลงชื่อเข้าใช้ที่มันบอกให้ไปใช้ ทางแก้ที่ลงไปคือ **ล้าง cookie เฉพาะตอนที่ token ที่หมดอายุ
ถูกตอบให้คำถามตั้งต้นของ shell (`GET /api/me`) เท่านั้น** ผ่าน predicate ชื่อ `isBootstrapRead`
เส้นทางอื่นทั้งหมดยังไม่ล้างเหมือนเดิม และเหตุผลในคอมเมนต์เดิมยังปกครองอยู่ครบ —
`clearanywhere` คือ mutant ที่คอยกันไม่ให้ข้อยกเว้นนี้กว้างขึ้น

อ่านเหตุผลเต็มที่ `backend/auth/session.js` บรรทัด 143–164 และ 192–211 — ประโยคที่ห้ามคือ
"ล้างทุกครั้งที่ verify ไม่ผ่าน" ไม่ใช่ "ล้างเมื่อรู้แน่ว่าข่าวถูกส่งถึงแล้ว"
