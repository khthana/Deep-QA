## สิ่งที่ยังค้าง

- **ค้างอยู่อย่างเดียวคือรอบสะอาดของชุดเบราว์เซอร์** ดูแถวของมันในตารางข้างบน — ไม่ใช่สีแดง
  เป็นเรื่องหน่วยความจำของเครื่อง ใครรับงานต่อให้คืน commit ก่อนแล้วรันหนึ่งรอบ แล้วเติมตัวเลขลง
  แถวนั้น · ของที่ขยับในใบนี้คือ `118a` แฟ้มเดียว และมันผ่านห้าแถวใน 26.2 วินาทีตอนกวาด
  (ซึ่งเป็นรอบสะอาดของแฟ้มนั้น ไม่ใช่ของชุด)
- **ส่วนที่เหลือของ #219 ไม่ค้าง** สามคำถามถูกตอบพร้อมวันที่ การสำรวจทำด้วยเครื่องมือ เงื่อนไขกลับมา
  คิดใหม่เขียนครบทั้งสามรูป และสิ่งที่ไม่เอาเข้ามาถูกยื่นเป็นตั๋ว (#235, #236)
- **ล็อกของการกดไม่ได้ commit** มันเป็นการวัดที่มีวันกำกับ ไม่ใช่เครื่องมือ — รันเครื่องมือใหม่
  เมื่อสงสัย วิธีรันอยู่ใน docblock ของมันเอง และล็อกเก่าจะอ่าน `?` ที่จุดที่บรรทัดขยับไปแล้ว
  ([#173](https://github.com/khthana/Deep-QA/issues/173))
- **ยังไม่มีสำมะโนที่ถามว่าจุดกด *ยกเลิก* ใหม่ผูกขอบเขตหรือไม่** เครื่องมือที่มีตอบคำถาม
  *วันนี้เป็นอย่างไร* ไม่ใช่ *แฟ้มใหม่ทำถูกไหม* ถ้าจะเปิดเป็นด่าน ต้องนับด้วยกลไก ไม่ใช่ด้วยชื่อ
  ([#174](https://github.com/khthana/Deep-QA/issues/174))

## สิ่งที่จะกินเวลา

- **การวัดด้วย probe กินเวลารอบละ ~46 นาที** และต้องเป็นรอบที่ไม่มีสีแดง ไม่งั้นตัวเลขไม่ใช่การวัด

- **การกวาดสามตัวของ `118a` กินเวลา ~5 นาที** รวมรอบสะอาด
- **ห้ามแก้ไฟล์ใน `frontend/` `e2e/` หรือ `mutation/` ขณะชุดทดสอบหรือ harness กำลังรัน** —
  CRA hot-reload กลางรอบทำให้รอบนั้นใช้ไม่ได้ และ `restore` จะปฏิเสธ
- **พอร์ตของ `e2e` คือ 3400 กับ 5310 ที่เครื่องนี้** — 5100 กับ 3100 อยู่ในช่วงที่ Windows จอง
  (`netsh int ipv4 show excludedportrange protocol=tcp`) อย่ายกพอร์ตจากใบเก่ามาใช้
- **การโคลนใหม่ต้องแก้ปลายทางของ `master` ที่ตายแล้ว** —
  `git remote set-head origin -a && git branch -u origin/main main`
