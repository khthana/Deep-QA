[#182](https://github.com/khthana/Deep-QA/issues/182) เป็น**คำถามของเจ้าของที่เก็บ** ตาม
`docs/06` §Out of Scope #179 ให้ `ImportPanel` รับ prop ชื่อ `target` ซึ่งบอกว่ารายงานในแผง
เป็นเรื่องของอะไร โดยตั้งใจไม่ให้มีค่าตั้งต้น แต่ **prop ไม่ใช่อาร์กิวเมนต์** `isCurrent` ถูกส่งใน
การเรียก การลืมส่งมันจึง throw ส่วน `target=` ที่หายไปจาก JSX คือ `undefined` และจอยังวาด
ผู้เรียกรายที่สิบเอ็ดที่ลืมจึงได้พฤติกรรมเก่าก่อน #179 แบบเงียบ ๆ และ**ไม่มีเครื่องมือไหนในที่เก็บนี้
บอกได้** — `frontend/` ไม่มีฮาร์เนสทดสอบคอมโพเนนต์ ไม่มี `prop-types` และสำมะโนห้าตัวที่มีอยู่
อ่าน `await` ป้าย และ ref ของจอ ไม่เคยอ่าน prop ที่ JSX ส่งให้คอมโพเนนต์

คำตอบของเจ้าของงานเมื่อ 22 ต.ค. 2569: **กฎในสำมะโน** ซึ่งเป็นทางที่สามของสี่ทางในตั๋ว

**ถ้าจะอ่านประโยคเดียวจากใบนี้ — *เครื่องมือแดงถูกที่ ยังบอกวิธีแก้ผิดได้*** การทำลายจอจริงก่อน
จะเชื่อเครื่องมือ (#141) จับข้อบกพร่องสองข้อของสำมะโนรุ่นแรก ซึ่งฟิกซ์เจอร์ยี่สิบเอ็ดแถวของตัวมันเอง
เงียบทั้งคู่: `{...rest}` ถูกรายงานว่า *ไม่ได้ส่ง `target`* ซึ่งเป็นประโยคที่มันรู้ไม่ได้ และการประกาศ
ที่พิมพ์ชื่อผิดถูกรายงานหนึ่งที่ แล้วรายงานผู้เรียกอีกสิบที่ โดยสิบรายงานนั้นบอกวิธีแก้ผิด — ทั้งสองข้อ
**แดงถูกที่** exit code เป็น 1 ทั้งสองทาง แฟ้มและบรรทัดถูกทั้งสองทาง สิ่งที่ผิดคือ*ประโยค*กับ
*รัศมี* ซึ่งเป็นส่วนที่จำนวนนับไม่เคยบอก และฟิกซ์เจอร์ที่เขียนจากกฎไปไม่ถึง

**และการตรวจโค้ดจับพันธุ์เดียวกันอีกสองข้อ ในโค้ดของเครื่องมือเอง** บรรทัดสรุปพิมพ์ `problems 0`
**ก่อน** ขั้นที่เปลี่ยนแฟ้มโค้ดที่อ่านไม่ได้ให้เป็นปัญหา วันที่มีแฟ้ม `.jsx` เข้ามา สำมะโนจะพิมพ์
`problems 0` แล้วรายงานปัญหาหนึ่งข้อ แล้วคืนค่า 1 (`label-codes.js` ดันเข้าก่อนแล้วพิมพ์ทีหลัง) ·
และตัวกรองชื่อที่คอมโพเนนต์ไม่ได้แยกออกมา ซึ่งเป็นการแก้ข้อบกพร่องข้อที่สองข้างบน เขียนอยู่ใน
`main()` ที่ไม่มีฟิกซ์เจอร์ไหนถามได้ ตอนนี้อยู่ใน `declaration()` ซึ่งตอบ `sound` กับ `unsound`
และมีสามแถวถามมันตรง ๆ — อีกสามข้อเป็นกฎของ #123: `catch` เปล่าที่กลืนคำปฏิเสธการพาร์สในรอบ
ที่สอง · จำนวน `not code` ที่พี่น้องสามตัวใหม่พิมพ์ · และรายการจุดบอดที่ยังไม่ได้พูดถึง
`export { REQUIRED_PROPS }` การส่งออกต่อ และการประกาศสองครั้งในแฟ้มเดียวที่ครั้งหลังชนะเงียบ ๆ
และ**แปดการอ่านถูกรันซ้ำกับสำมะโนที่แก้แล้ว** ได้ประโยคเดิมทั้งแปด และตัวควบคุมเขียว (`_local/break182.py` ไม่คอมมิต)

## สิ่งที่วัดได้

**ข้อที่ตั๋วเขียนไว้และยังจริง** วัดซ้ำที่ `cdfa15e`: `<ImportPanel` มีสิบจุด และ**ทั้งสิบส่ง
`target`** — อ่านทุกจุด ไม่ใช่เกรป `target=` ซึ่งเป็นหลักฐานของรูปแบบที่พิมพ์ ไม่ใช่ของข้อที่อยาก
ได้ (#111) · ไม่มีแฟ้ม `*.test.js` ใต้ `frontend/src` · `prop-types` ไม่เป็น dependency ·
ไม่มีสำมะโนตัวไหนอ่าน `JSXAttribute` หรือ `JSXOpeningElement` เลย

**ข้อที่การวัดหักล้าง — ช่อง *พิสูจน์ได้ไหม* ของทางเลือกที่หนึ่ง** ตั๋วเขียนว่า **ไม่** เพราะ
*ไม่มีแถวไหนอ่าน console ของ dev server และคำเตือนไม่ทำให้อะไรแดง* ครึ่งแรกเป็นข้อเท็จจริงเรื่อง
ชุดทดสอบวันนี้ ครึ่งหลังเป็นคำกล่าวอ้างเรื่องสิ่งที่แถวหนึ่งทำได้ ซึ่งเป็นของต่างชนิดกัน (#141)
โพรบวัดแล้ว และถูกลบหลังจากนั้น (#207): `e2e` รัน **dev server ของ CRA** ไม่ใช่ build ฉะนั้น
`console.error` ที่ออกจากการ render **ถึง** `page.on('console')` จริง — แปดครั้งในการเปิดจอเดียว
ผ่าน double render ของ React · สิ่งที่ทำไม่ได้คือเน็ต**ทั้งคอนโซล** เพราะ 2 ใน 12 ข้อความของการ
เปิดจอหนึ่งครั้งเป็น `Failed to load resource: 401` จากการเข้าระบบ · เน็ตที่กรองด้วยข้อความทำได้

**และการวัดนั้นให้ทางเลือกที่ตั๋วไม่ได้เขียน** (#128 #204) ถ้าคอนโซลอ่านได้ แผงพูดประโยคนั้น
เองได้ด้วย JavaScript สามบรรทัด ไม่มี dependency ซึ่งซื้อของอย่างเดียวกับ `prop-types` ในราคา
ที่ถูกกว่า และมัตแตนต์ของมัน**แคบ**: ถอด `target=` ออกจากจอจริงหนึ่งจอทำให้คำเตือนปรากฏ และฆ่า
เฉพาะแถวที่อ่านมัน จอยังวาดอยู่ — ซึ่งเป็นความไม่สมมาตรที่ทางที่สองไม่มี `throw` ในแผงพิสูจน์ได้
ด้วยมัตแตนต์ที่ล้มทั้งจอเท่านั้น ซึ่งไม่ใช่รูปที่มัตแตนต์ต้องมี (#97) **ทางที่หนึ่งของตั๋วจึงถูกครอบ
โดยทางที่ไม่มีใครเขียน** และนั่นถูกเขียนลงไปในคำถามที่ถามเจ้าของงาน

## สิ่งที่ยังค้าง

- **ไม่มีมัตแตนต์ และนั่นถูก** สำมะโนเป็นเครื่องมือ ไม่ใช่คำกล่าวอ้างของแถวไหน (#171) สิ่งที่ค้ำมัน
  คือฟิกซ์เจอร์ของตัวเองกับการทำลายจอจริง ไม่ใช่การกวาด
- **ทางเลือกที่ไม่ได้เลือกสามทางยังเป็นทางเลือกที่ไม่ได้เลือก** และตั๋วเขียนไว้แล้วว่าแต่ละทางมีราคา
  เท่าไร ถ้าวันหนึ่งที่เก็บนี้ตัดสินใจเรื่องฮาร์เนสทดสอบคอมโพเนนต์ (ทางที่สี่) สำมะโนตัวนี้ไม่ขัดกับมัน
  — มันจับที่เวลา commit ส่วนฮาร์เนสจับที่เวลารัน
- **จุดบอดของสำมะโนเป็นของจริง** `{...props}` ไม่มีในต้นไม้วันนี้เลย ซึ่งเป็นเหตุผลที่การตัดสินใจ
  ว่าจะรายงานมันเป็น *อ่านไม่ได้* มีราคาเป็นศูนย์วันนี้ และคุ้มที่จะตัดสินใจตอนนี้แทนที่จะตอนนั้น
