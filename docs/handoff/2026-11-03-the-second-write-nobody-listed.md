สองแฟ้ม `frontend/src/components/RoleDropdown.js` ได้ `max-[916px]:min-w-0` ที่กล่องนอก
`max-[916px]:max-w-full` ที่ตัวกระตุ้น และป้ายได้กล่องของตัวเองเป็น `<span>` ที่
`max-[916px]:min-w-0 max-[916px]:truncate` ส่วน `frontend/src/components/Navbar.js` ได้
`max-[916px]:min-w-0` ที่คอลัมน์กลาง — **ขาดบรรทัดนั้นแล้วไม่มีอะไรถูกตัดเลย** ซึ่งเป็นเหตุที่
#264 ลงที่สองแฟ้ม

**หน่วยของ 916** 916 มาจาก probe ในฐานะความกว้างของ viewport แต่ `max-[916px]:` เป็น
media query ซึ่งอ่าน layout viewport วัดก่อนเขียนแถวใด ๆ: จอนี้ไม่มี scrollbar แนวตั้งที่ความสูง
720 `matchMedia('(max-width: 916px)')` จริงที่ 916 เท็จที่ 917 และชื่อตกบรรทัดที่ 916 ไม่ตกที่ 917
ทั้งสองจึงตรงกันพอดี บนจอที่มี scrollbar การตัดเริ่มเร็วกว่าในหน่วยพิกเซลของหน้าต่างราว 15px
เท่ากับที่การตกบรรทัดเลื่อนมา — เขียนเป็นขีดจำกัดไว้ใน docblock ของแถว

**`<button>` เป็น form control** `width: auto` ของมันคือ fit-content จึงไม่หดตามกล่องแม่
หลังแก้รอบแรกสองแถวยังแดงที่ `picker 498 · cut false` ทั้งที่สองข้างครบแล้ว สิ่งที่ปิดช่องคือ
`max-w-full` ซึ่งเป็น**การเขียนที่สองที่ไม่มีใครในรายการตัวเลือกพูดถึง** และการอ่านเดียวกันนั้น
หักล้างตัววัดที่ตั้งราคาตัวเลือกไว้ (ข้อถัดไป)

## ข้อที่ถูกหักล้าง และมันอยู่ที่ไหนบ้าง

ประโยค **ค กับการย้อน #261 เป็นกลไกเดียวกัน** ซึ่งอยู่ในความเห็นบน #264 ในใบก่อน และใน
`docs/lessons.md` §#264 อ่านมาจากราคาที่เท่ากันทุกความกว้าง และราคาที่เท่ากันนั้นเป็นของที่แขน ค
ของตัววัดสร้างขึ้นเอง: มันเขียน `textOverflow` กับ `overflow` ลงบนป้ายแล้วอ่านทั้งสองค่ากลับ
จากกล่องเดียวกันนั้น **โดยไม่เคยเขียน `max-width`** ป้ายจึงไม่ถูกย่อเลย และไม่มีแขนไหนอ่าน
**ผล**ของการย่อ คำตอบของเจ้าของงานไม่ได้พึ่งข้อนั้น ฉะนั้นคำตอบยืน แต่การวัดกลับไปที่เจ้าของงาน
ไม่ลงไปในข้อความคอมมิต (#257) ที่แก้แล้วคือ ความเห็นใหม่บน #264 · ย่อหน้าลงวันที่ในใบก่อน ·
§#264 ของ `docs/lessons.md` · docblock ของตัววัด · และคอมเมนต์ใน `RoleDropdown.js` เอง
ซึ่งเคยยกประโยคนั้นมาเป็นเหตุผลของการแก้

ตัววัดถูกซ่อม (เติม `max-width` และเติมการอ่าน `labelCut` ซึ่งถามทุกกล่องในปุ่มว่า
`scrollWidth > clientWidth` คือถามผล ไม่ใช่ถามคุณสมบัติ) แล้วแขน ค ก็ถูก**เอาออก** เพราะ
ข้อเสนอของมันกลายเป็นโค้ดไปแล้ว **จำนวนตัววัดใน `e2e/probes/` ยังเป็นเก้า** ไม่มีตัวใหม่

- **`truncate` ของ Tailwind เป็นสามคุณสมบัติ ไม่ใช่สองอย่างที่ชื่อบอก** อันที่สามคือ
  `white-space: nowrap` ซึ่งหมายความว่าใต้ประตู ป้ายถือการป้องกันของ #261 ไว้เองแล้ว

  `truncate` ออกจาก `span` โดยยังเหลือกล่องไว้
- **`<button>` ไม่หดตามกล่องแม่** `width: auto` ของ form control คือ fit-content ลูกโซ่
  `min-w-0` ซื้อแค่ *สองข้างคงกล่องไว้* การตัดต้องมี `max-w-full` ที่ปุ่มด้วย และอาการของการ
  ขาดบรรทัดนั้นคือ `picker 498 · cut false` เหนือกล่องกลางที่แคบแล้ว
- **จำนวนตัววัดใน `e2e/probes/` ถูกนับไว้สองที่** คือตารางแผนที่เอกสารของ `CLAUDE.md` และ

- **ความเห็นไทยที่โพสต์ขึ้น GitHub พิสูจน์ได้ด้วยการอ่านกลับ** `gh issue comment N --body-file`
