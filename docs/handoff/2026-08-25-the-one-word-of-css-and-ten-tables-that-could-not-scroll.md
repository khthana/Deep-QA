## 2. #98 — บั๊กที่กระทบสิบหน้า และแก้ด้วย CSS คำเดียว

หน้าที่มี `overflow-x-auto` ที่กรอบตารางมีสิบหน้า — Departments · Offerings · Plos ·
ProgramSubjects · Programs · RubricCriteria · Rubrics · Students · Subjects · Users —
และ **ทั้งสิบหน้าไม่เคยเลื่อนได้เลย** ตั้งแต่วันแรก

ต้นเหตุอยู่ที่ `frontend/src/pages/Mainpage.js` ไม่ใช่ที่หน้าไหนเลย `<main>` เป็น flex item
ที่ไม่มี `min-w-0` ซึ่ง flex item มี `min-width: auto` เป็นค่าเริ่มต้น เท่ากับความกว้างขั้นต่ำ
ของเนื้อหา `<main>` จึงย่อลงต่ำกว่าตารางที่กว้างที่สุดในมันไม่ได้ และถูกดันเลยขอบขวาของ
หน้าต่างแคบ แล้ว `overflow-x-hidden` ของกรอบเนื้อหาตัดส่วนที่ล้นทิ้ง ส่วน `overflow-x-auto`
ที่กรอบตารางไม่เคยได้ทำงาน **เพราะกรอบเองกว้างเท่าเนื้อหาไปแล้ว ไม่มีอะไรล้นออกจากมัน**

วัดที่ 900px บนหน้าเกณฑ์ **ก่อน** แก้โค้ด — `<main>` 1,094 · กรอบตาราง 1,060/1,060 ·
`document.scrollWidth` 900 หลังแก้ — 900 · 866/1,060 · 900

**การวัดก่อนแก้คือสิ่งที่ทำให้แก้ถูกที่** รายงานจากการเดินบอกว่า *ตารางหด* ตามหน้าต่าง
ซึ่งเป็นอาการของสาเหตุคนละตัว — ตารางที่ถูกบีบ ซึ่งจะต้องแก้ที่ตาราง ไม่ใช่ที่เปลือก
ตัวเลขสี่ตัวเป็นตัวตัดสินว่าเรื่องไหนจริง

## 3. spec ที่พิสูจน์ได้จริง กับสองแบบที่พิสูจน์ไม่ได้

`e2e/tests/98a-narrow-window.spec.js` สามข้อ เป็นไฟล์เดียวในชุดที่ตั้งความกว้างหน้าต่างเอง

- **ปุ่มที่ถูกตัดยังกดได้ผ่าน `locator.click()`** เพราะ Playwright จะเลื่อน ancestor ที่เลื่อนได้
  ทุกตัวให้ รวมถึงกล่อง `overflow-x-hidden` ที่คนไม่มีแถบเลื่อนให้เลื่อน `toBeVisible()`
  ก็เป็นจริงกับปุ่มที่ถูกตัด **การกดที่ซื่อสัตย์ตัวเดียวคือ `page.mouse.click(x, y)`**
  ที่พิกัดที่ปุ่มถูกวาด — มันโดนสิ่งที่วาดอยู่ตรงนั้น และไม่โดนอะไรเลยถ้าปุ่มอยู่นอกขอบ
- **หน้าจอไม่ได้พังที่ความกว้างเดียวกันทุกหน้า** วัดใต้มัตแตนต์แล้ว: ที่ 900px มีแต่หน้าเกณฑ์
  ที่บวม (`main` = 1,100) อีกแปดหน้ารายการเท่ากับ 900 พอดี ต้องแคบถึง 500px
  หน้าข้อมูลผู้ใช้งานถึงบวมเป็น 852 spec จึงมีสอง describe คนละความกว้าง
- **แถวที่สามฉบับแรกผ่านทั้งที่ใส่มัตแตนต์แล้ว** เขียนไว้กับหน้า Program Subjects ที่ 900px
  คือแถวที่พังไม่เป็น ถูกเขียนใหม่เป็นหน้าข้อมูลผู้ใช้งานที่ 500px
- **`serial` ปิดบังหลักฐานของมัตแตนต์** ฉบับแรกใช้ `test.describe.configure({ mode: 'serial' })`
  ใต้มัตแตนต์มันรายงานแค่หนึ่งข้อตกแล้วข้ามที่เหลือ แก้ด้วยการให้แต่ละแถวสร้าง state ของตัวเอง
  (`openMine` สร้างเมื่อยังไม่มี) และย้ายการลบไป `afterAll`

`mutation/98-narrow-window.py` สองตัว — `nominwidth` (บั๊กตัวเดิม) ฆ่าทั้งสามแถวคนละบรรทัด
`pagescrolls` (เอา `overflow-x-auto` ออกจากกรอบตาราง) ฆ่าแถวเดียวที่
`expect(reached).toBeGreaterThan(0)` ซึ่งเป็นบรรทัดที่แถวตรวจรับพูดถึงพอดี

## 5. กับดักที่เพิ่มจากฉบับก่อน

- **flex item ไม่มี `min-w-0` คือ `min-width: auto`** ทุกที่ที่วาง `flex-1` ทับเนื้อหาที่กว้างได้
  ต้องถามว่าเนื้อหาที่กว้างที่สุดในนั้นกว้างเท่าไร `overflow-x-auto` ที่อยู่ข้างในไม่ช่วยอะไร
  ถ้ากรอบที่ครอบมันโตตามเนื้อหาไปแล้ว
- **`locator.click()` และ `toBeVisible()` ไม่พิสูจน์ว่าคนกดถึง** แถวที่พูดถึงสิ่งที่มือคนทำได้
  ต้องกดที่พิกัด และต้องตรวจว่ากล่องของปุ่มอยู่ในหน้าต่างจริง
- **spec ที่ตั้ง viewport เองต้องตั้งในไฟล์ ไม่ใช่ในโปรเจกต์** เปลี่ยนค่าเริ่มต้นของโปรเจกต์
  จะทำให้ spec อื่นทั้งชุดรันที่ความกว้างที่มันไม่ได้ถูกเขียนมาเพื่อสิ่งนั้น
- **`serial` ทำให้มัตแตนต์รายงานไม่ครบ** แถวที่ตกจะข้ามแถวใต้มัน หลักฐานที่ได้จึงน้อยกว่าจริง
  ถ้าแถวใช้ state ร่วมกัน ให้แต่ละแถวสร้างเองเมื่อยังไม่มี แล้วเก็บกวาดใน `afterAll`
- **เครื่องหมายในตารางคือสิ่งที่คนอ่านนับ ย่อหน้าใต้ตารางคือสิ่งที่คนอ่านข้าม** commit แรก
  ของ #98 ติ๊กแถวเป็น ⚙ แล้วเขียนกำกับไว้สี่สิบบรรทัดถัดไปว่ายังไม่มีใครเดิน ผลคือตาราง
  อ่านว่า 0 ☐ ซึ่งแปลว่า #22 ปิดได้ ทั้งที่ยังไม่ได้ **แถวที่เครื่องพิสูจน์ได้ครึ่งหนึ่งและคน
  ต้องพิสูจน์อีกครึ่ง ให้แยกเป็นสองแถว** อย่าติ๊กรวดเดียวแล้วอธิบายทีหลัง
- **ตัวเลขในคำบรรยายของ checklist ให้นับด้วย regex เสมอ** สูตร
  `\|\s*(☑|⚙|◐|☐)\s*\|?\s*$` รันทับ `docs/acceptance/*.md`
- **A fresh clone lands on a dead `master`.** Run, verbatim:
  `git branch -m master main && git fetch origin --prune && git branch -u origin/main main`
