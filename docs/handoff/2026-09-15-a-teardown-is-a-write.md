  ตัวช่วย: ทำให้มันรอค่าเกินหนึ่ง แล้วรันสเปกหนึ่งไฟล์ต่อหนึ่งตัวช่วย ทุกความล้มเหลวอยู่ที่ `untilDrawn`

## Gotchas ที่ยังต้องพก

ยกมาทั้งชุดจากใบก่อนหน้า ยังใช้ได้ทุกข้อ และเพิ่มจากรอบนี้

- `git clone` ที่ทำไว้ก่อนเปลี่ยนชื่อ branch ยังชี้ `master` ที่ตายแล้ว แก้ด้วย
  `git remote set-head origin -a && git branch -m master main && git branch -u origin/main`
- **`gh issue list` คืน 30 รายการถ้าไม่ใส่ `--limit`** — ใบก่อนหน้านับใบที่เปิดผิดเพราะเรื่องนี้
- **สเปกที่เขียนหรือลบแถว ใช้ `hold()` จาก `support/hold.js` และประกาศ `beforeAll` ของมันก่อน `beforeAll` อื่นที่เขียน**
  Playwright รัน hook ตามลำดับที่ประกาศ แล้วรันไฟล์นั้นเดี่ยว ๆ อ่านรายงาน leftovers ว่าเหลือแค่ `user_log`
- **Python ที่รันเบื้องหลังโดย redirect stdout จะบัฟเฟอร์ไฟล์ progress ไว้ว่างจนจบ** — ให้สคริปต์เขียนผล
  ลงไฟล์ของมันเองแล้ว `flush` หรืออ่านไฟล์ผลแทน
- **`python mutation/<ใบ>.py save` ก่อนทุกมัตแตนต์ และอ่าน `git status` หลัง `apply` ไม่ใช่แค่หลัง `restore`**
- **รายการ *ห้ามกวาดคู่กับ* ต้องสร้างจาก `FILES` ด้วยสคริปต์สำมะโนใน `mutation/README.md`**
- **สคริปต์นับเครื่องหมายต้องอ่านช่องสุดท้ายของแถว *และ* ช่องนั้นต้องขึ้นต้นด้วยเครื่องหมาย** —
  ตรวจด้วยการนับที่ commit ของใบส่งมอบก่อนหน้า
- **อย่าพิมพ์ภาษาไทยหรือ ☑ ⚙ ◐ ☐ ผ่าน Bash ด้วย Python** console เป็น cp874 — เขียนไฟล์ด้วย
  `io.open(..., encoding='utf-8')` แล้วอ่านด้วยเครื่องมืออ่านไฟล์ และ `subprocess.run(..., text=True)` บนผลของ
  Playwright ต้องใส่ `encoding='utf-8', errors='replace'` ไม่งั้นโยนก่อนถึงบรรทัด restore
- **เขียนสคริปต์แก้ไฟล์ลงไฟล์ก่อนแล้วค่อยรัน** และตอนตัดบล็อกโค้ดด้วย `s.index("});\n")` ระวังมันจับ
  `createPool({ ... });` ที่อยู่ก่อน — ตรวจด้วย `npx playwright test --list` หลังแก้สเปกทุกครั้ง
- **`.gitattributes` เป็น `* text=auto eol=lf`** — `io.open(...)` ต้องส่ง `newline='\n'` หรือ `newline=''` ตอนเขียน
- e2e ใช้พอร์ต 5100 ซึ่ง Windows จองไว้ ให้รันด้วย `E2E_FRONTEND_PORT=5300` ชุดเต็ม **383 แถวใช้ 18.4–18.9 นาที**
  เมื่อ 15 ก.ย. **หัวข้อ *Two test seams* ใน `CLAUDE.md` ยังเขียนว่า 3100/5100**
- **ท้ายทุกรอบ e2e มีรายงาน leftovers ของ #132** มันรายงาน ไม่ทำให้รอบล้ม และ `user_log` หลายร้อยแถวเป็นเรื่องปกติ
- **การรันสเปกไฟล์เดียวจะรายงานของที่ไฟล์นั้นทิ้งไว้เอง** เพราะ `globalSetup` drop/migrate/seed ใหม่ทุกครั้ง

- **อย่ากวาดมัตแตนต์ระหว่างที่ชุด e2e กำลังรัน** และ **เดินด้วยมือก่อนกวาดและก่อนรันชุดเต็ม**
- **frontend ของ e2e คือ CRA dev server ที่ hot-reload** — อย่าแก้ `frontend/src` ระหว่างที่ชุด e2e รัน
- **docstring ในไฟล์มัตแตนต์ที่อ้าง regexp ต้องเป็น raw string** (`r"""`)
- **spec ที่รันแบบ `serial` รายงาน kill ต่ำกว่าจริง** — วัดทีละแถวด้วย `--grep` แต่ `--grep` ข้ามแถวที่แถวถัดไปพึ่งได้
- **`node --test` นับ suite แม่ใน `# fail` และเทสต์ระดับบนสุดของไฟล์มี `not ok` ที่ไม่เยื้อง** — อ่านชื่อ
- **ยอด kill ที่ดูเหมือนทั้งชุด ให้อ่านชื่อหา fixture ที่รั่วก่อน**
- **การรอที่เขียนเพื่อจังหวะเวลา ต้องมี timeout ที่ยอมให้หมดได้** และ `networkidle` ไม่มีความหมายหลังการนำทางภายใน SPA
- **ค้นบน tracker ก่อนเปิดตั๋ว** (`gh issue list --state all --search "<ชื่อ spec หรือไฟล์>"`)
- **`npx eslint` ใน `backend/` และ `e2e/` ออก exit 2 เพราะไม่มี config** ใช้ `node --check` ที่นั่น
