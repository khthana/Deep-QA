BR-20 พูดถึงคนหนึ่งกับข้อหนึ่ง ไม่มีข้อที่สาม ถ้าใครจะทำสัดส่วนรายนักศึกษา **ต้องตกลงกฎใหม่ก่อน**
ว่าผ่านกี่ข้อถึงเรียกว่าผ่าน แล้วกฎนั้นจะเป็นกฎของระบบ ไม่ใช่ของตั๋วนี้

เขียนว่า *57 คน* จะถูกอ่านว่าเป็นสัดส่วนของนักศึกษาไม่ว่าจะตั้งชื่อว่าอะไร** ตัวส่วนที่ไม่ใช่

ผู้ใช้อ่านถ้อยคำใหม่บนหน้าจอเองแล้วและตอบว่าอ่านรู้เรื่อง แถวจึงติ๊ก ☑ — **คนที่เขียนถ้อยคำ

### MISS ที่ apply ได้แต่ไม่ตัดสินอะไร

มัตแตนต์สองตัวของ #38 ต้องเขียนสองรอบ **ทั้งคู่ apply ผ่าน ข้อความที่ผูกไว้ยังอยู่ครบ
แต่สิ่งที่มันแก้ไม่เปลี่ยนพฤติกรรมเลย** — ตัวหนึ่งลบความกว้างขั้นต่ำของตารางที่กว้างเกินจออยู่แล้ว
อีกตัวแคบคอลัมน์บน seed ที่วัดครบทุกข้อ

**MISS แบบนี้อ่านไม่ออกจากผลของคำสั่ง apply อ่านออกจากการที่ไม่มีแถวไหนตายเท่านั้น**
ซึ่งเป็นเหตุผลที่ทุกตัวต้องถูกกวาดจริง ไม่ใช่แค่ตรวจว่า apply ผ่าน

การไล่หาสาเหตุตัวแรกยังเปิดว่าแถวนั้นยืนยันสิ่งที่เป็นจริงเสมอ — เปลือกของทุกหน้าจอมี
`overflow-x-hidden` อยู่แล้ว **หน้าจึงเลื่อนข้างไม่ได้ไม่ว่าจะเขียนโค้ดอย่างไร** ข้ออ้างที่เป็นจริง
เสมอคือข้ออ้างที่ไม่ได้พูดอะไร

### สิ่งที่เทสต์ทุกชุดผ่านแต่การเดินจับได้

กล่อง *ผลการเรียนรู้ที่ควรปรับปรุง* เขียนว่า *ทุกผลการเรียนรู้ผ่านเกณฑ์* บนหน้าที่คอลัมน์สุดท้าย
แสดงขีดตรงคำตัดสินนั้นพอดี — **รายการว่างถูกอ่านเป็นข่าวดี แทนที่จะเป็นคำถามที่ยังไม่ได้ถาม**

265 เทสต์กับรีวิวสองแกนมองไม่เห็น เพราะทุกแถวในเบราว์เซอร์ทำงานกับข้อที่มีคะแนนอยู่แล้ว
กรณีนี้เกิดต่อเมื่อมีข้อที่ยังไม่ถูกวัด และไม่เคยมีแถวไหนสร้างมันแล้วอ่านกล่องนั้น
`38:attentionclaimsallpassed` จึงเป็นมัตแตนต์ตัวเดียวใน 334 ตัวที่เขียนขึ้น **หลัง** คนมองหน้าจอ

### walk backend ต้องรีสตาร์ต *หลัง* แก้ route ครั้งสุดท้าย

รู้อยู่แล้วว่า `node server.js` ไม่ reload แต่รอบนี้ยังพลาด — รีสตาร์ตตอนต้นการเดิน แล้วแก้ route
ระหว่างเดิน หน้าจอขึ้น `undefined จาก undefined` **เทสต์ทุกชุดผ่านหมด เพราะแต่ละชุดปั่นเซิร์ฟเวอร์
ของตัวเองขึ้นใหม่ทุกครั้ง** มีแต่การเดินบนเซิร์ฟเวอร์ที่ค้างอยู่จริงเท่านั้นที่เห็น

### เซสชันรอดการรีสตาร์ต backend

`session` เก็บในฐานข้อมูล ไม่ใช่หน่วยความจำ **การรีสตาร์ต backend ไม่ทำให้หลุด** — รอบแรกที่หลุด
เป็นเพราะอายุเซสชันเอง ไม่ใช่เพราะรีสตาร์ต อย่ารบกวนผู้ใช้ให้ล็อกอินใหม่โดยไม่ตรวจก่อน

### พิกัดของเครื่องมือคลิกไม่ใช่ CSS pixel

`getBoundingClientRect()` ให้พิกัดใน viewport (1360 กว้าง) แต่เครื่องมือคลิกใช้พิกัดของภาพ
ที่ถ่ายมา (1509 กว้าง) คลิกจึงไปตกผิดที่โดยไม่มีข้อผิดพลาดใด ๆ **ถ่ายภาพแล้วอ่านพิกัดจากภาพ**
และถ้า `document.visibilityState` เป็น `hidden` คลิกจะไม่ถึงหน้าเลย ต้องให้ผู้ใช้สลับแท็บมาก่อน

## #109 ปิดแล้ว และตั๋วเองวินิจฉัยผิด

`24a` แถว 3 ตกประมาณ 1 ใน 3 ตั๋วเขียนไว้ว่า **กลุ่มเมนูของตอนเรียนปิดตัวเองและปิดค้าง**
ซึ่งจะเป็นบั๊กบนหน้าจอที่กระทบ ADR-0004 — **ผิด** เมนูเปิดอยู่ตลอด ข้อความจริงที่มันพิมพ์คือ
`strict mode violation` — locator ชี้สองที่ เพราะ breadcrumb ขึ้นชื่อเดียวกันเป็นลิงก์ด้วย
เมื่อเข้าไปอยู่ในหน้านั้น

**ตั๋วผิดเพราะคนเขียนตั๋ว (ผมเอง) อ่านแค่ว่าตกบรรทัดไหน ไม่ได้อ่านว่ามันพิมพ์อะไรออกมา**
ข้อความนั้นบอกสาเหตุไว้ครบตั้งแต่ครั้งแรกที่เห็น — และการวินิจฉัยผิดนั้นถูกส่งต่อไปอีกสองที่:
ทั้งตั๋วและ agent ที่ถูกส่งไปไล่โค้ดต่างพูดถึง state ค้างกับ `AnimatePresence` ซึ่งเป็นข้อสังเกต
ที่ดีเรื่องคุณภาพโค้ดแต่ไม่ใช่สาเหตุ **อ่าน log ก่อนตั้งทฤษฎี**

เบาะแสที่ยืนยันได้ตั้งแต่แรกถ้าดู: **รอบที่ตกคือรอบที่ช้าทุกครั้ง** (44 วิ กับ 72 วิ เทียบกับ 28 วิ)
เพราะยิ่งช้า breadcrumb ยิ่งทัน mount ก่อน assertion — เป็นรูปของ race ไม่ใช่ของ logic ที่ผิดเสมอ

### วิธีพิสูจน์ flake ว่าแก้ถูก

อย่าแก้แล้วรันผ่านหนึ่งครั้งแล้วเรียกว่าจบ ลำดับที่ใช้ได้คือ **บังคับให้มันตกทุกครั้งก่อน** —
รอ breadcrumb ขึ้นก่อนค่อย assert ทำให้ 2/6 กลายเป็น 3/3 — แล้วค่อยแก้ ได้ 3/3 แล้ว 6/6
การบังคับนั้นถูกเก็บไว้ในแถวถาวร แถวจึงรันในสภาพที่เคยตกเสมอ ไม่ใช่รอดเพราะบังเอิญเร็ว

### navigation สามอันและชื่อที่ซ้อนกัน

หน้าหนึ่งมี `<nav>` สามอัน — แถบบน เมนูข้าง breadcrumb เดิมมีแต่ breadcrumb ที่มีป้ายชื่อ
ตอนนี้ทั้งสามมีแล้ว (`แถบด้านบน` · `เมนูหลัก` · `Breadcrumb`) เพราะเมนูกับ breadcrumb ถือลิงก์
**ชื่อเดียวกัน** ทุกครั้งที่อยู่ในหน้าที่เมนูเข้าถึงได้ — 24 ชื่อที่อยู่ทั้งสองที่

`e2e/support/shell.js` มี `menuLink(page, name)` แล้ว **อย่าถามหน้าเพจหาลิงก์ที่เมนูถืออยู่
ให้ถามเมนู** และมันใช้ `exact: true` เพราะ Playwright จับชื่อแบบ substring โดยปริยาย
ขณะที่ชื่อในเชลล์นี้ซ้อนกันจริง — `ข้อมูลผู้ใช้งาน` อยู่ใน `แก้ไขข้อมูลผู้ใช้งาน`
และ `ข้อมูลหลัก` อยู่ใน `ข้อมูลหลักสูตร`

มีอีกหกจุดที่กำกวมแบบเดียวกันรออยู่ใน `10a` `30a` `31a` `32a` ยังไม่ตกเพราะบังเอิญทำงานตอนที่
ยังอยู่หน้าก่อนหน้า ชื่อจึงยังมีที่เดียว — แก้หมดแล้ว **การเพิ่ม landmark ให้เมนูยังทำให้
`page.locator('nav')` ใน `avatarButton` กำกวมขึ้นมาทันที** ซึ่งเป็นหนี้ที่การแก้นี้ก่อเอง
และปิดในคอมมิตเดียวกัน — เพิ่ม `<nav>` ที่ไหนต้องไล่ดู locator ที่พูดว่า `nav` ลอย ๆ เสมอ
