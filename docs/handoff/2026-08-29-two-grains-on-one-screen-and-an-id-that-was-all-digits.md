## 5. สิ่งที่คนต่อควรรู้จากสองตั๋วนี้

- **สอง grain บนจอเดียว (#32)** กิจกรรมเป็นของตอนเรียน (`activities.section_id`) หมวดคะแนน
  ที่ใช้จัดกลุ่มเป็นของการเปิดสอน (ADR-0003) — คำตอบจึงเป็น `{ section, categories, activities }`
  แยกกัน และ**กลุ่มมาจากสัดส่วน ไม่ใช่จากรายการ** หมวดว่างต้องถูกวาด
- **สัดส่วนถูกอ่านผ่านตอนเรียน** `course_sections → semester_courses → subject_score_ratio`
  จาก id ที่ `sectionOf` ตรวจสิทธิ์ไปแล้ว — ตั้งใจไม่ import `offeringOf` เพิ่ม เพื่อไม่ให้กลายเป็น
  ผู้ใช้รายที่สี่ที่ #104 ต้องตามยุบ
- **ด่านลบสองด่านในคำสั่งเดียว** `activity_scores` CASCADE (เงียบ) `activity_evidence` RESTRICT
  และ soft-delete (FK ไม่อ่าน `is_deleted` ด่านจึงต้องไม่อ่านด้วย) — `whyNot()` วินิจฉัยหลัง
  `rowCount === 0` และคืน `{status, message}` เพราะเคสสุดท้ายคือ 404 ไม่ใช่การปฏิเสธ
- **seed มีกิจกรรมที่ลบได้ตอนเรียนละหนึ่งแถว** `แบบฝึกหัดท้ายบท (ตอนเรียนที่ N ปีการศึกษา Y)` —
  ไม่มีคะแนน ไม่มี CLO — เพราะก่อนหน้านี้ทั้งระบบไม่มีอะไรให้ลบเลย `db/test/seed.test.js`
  ยกเว้นมันจาก invariant สองข้อ**โดยระบุชื่อ** แล้วปักหมุดว่ามีแถวเดียวจริง
- **แถว 9 ของ `32a` ถูกประกาศไว้ก่อนแถว 5** เพราะแถว 5 ใช้กิจกรรมที่ลบได้หมดไป และ schema
  ถูก reseed ต่อรอบรัน ไม่ใช่ต่อแถว — เจอเพราะแถว 9 ตายกับมัตแตนต์ที่ไม่เกี่ยวกันเลยสามตัว
- **`integerId`** (`backend/lib/fields.js`) — `/^\d+$/` อย่างเดียวไม่พอ id ที่เป็นตัวเลขล้วนแต่
  ล้น `integer` เคยตอบ 500 เทสต์ของ #32 เจอเอง สาม route บนเส้นทางนี้ใช้แล้ว ที่เหลือคือ #107
- **เลขสัปดาห์เป็นของคนพิมพ์ (#31)** ซ้ำได้ ไม่เรียงก็ได้ ลบแล้วไม่ renumber — ต่างจากเลขลำดับ
  ของ #28/#29 โดยตั้งใจ และ ADR-0001 มีหัวข้อ *Amended by #31* อธิบายว่าทำไม

## 6. กับดัก

**อย่าฆ่า node ที่พอร์ต 3100/5100 โดยไม่ดูก่อนว่าอะไรรันอยู่** (ใหม่ในเซสชันนี้) — เห็น
"leftover" สองตัวแล้วสั่ง kill ทั้งที่มันคือ webServer ของชุด e2e เต็มที่กำลังรันอยู่ ผลคือรอบนั้น
จบแบบ *3 did not run* พร้อม exit 0 ซึ่งอ่านเผิน ๆ เหมือนผ่าน — ตรวจ `Get-Process` StartTime
เทียบกับงาน background ที่ยังค้างก่อนเสมอ

**clone อื่นที่ยังชี้ `master`** — สาขาหลักถูกเปลี่ยนชื่อ `master` → `main` ฝั่ง server เมื่อ
17 ส.ค. 2569 clone เก่าบนเครื่องอื่นซ่อมด้วย:

```bash
git branch -m master main && git fetch origin --prune && git branch -u origin/main main
```

เก็บข้อนี้ไว้ในทุก handoff จนกว่าจะยืนยันว่าทุก clone ถูกซ่อมหมดแล้ว

**อย่า `git add` อะไรใน `DEEP-QA-BACKEND/` หรือ `_local/`** — `.env` มีคริเดนเชียลจริง
`uploads/` เป็นงานของนักศึกษาจริง และ repository นี้เป็น public

**อย่าพิมพ์ภาษาไทยผ่าน Bash** (cp874 `UnicodeEncodeError`) — ใช้ Write tool หรือสคริปต์ Python
`io.open(..., encoding='utf-8', newline='\n')` · และ `python mutation/<file>.py list` พิมพ์ `\r`
ท้ายบรรทัดบน Windows ต้อง `| tr -d '\r'` ก่อน grep ไม่งั้นการ dry-apply จะรายงาน MISS ทั้งชุด

**รีสตาร์ต backend ก่อนเดินใบตรวจด้วยมือ** — `node server.js` ไม่มี reload

**สภาพเครื่อง ณ จบเซสชัน** — backend (3000) กับ frontend (5000) ถูกเปิดค้างไว้ตอนเดิน #31
ถ้าจะใช้ต้อง bounce ก่อน · `grader-app-1` ที่เคยนั่งทับพอร์ต 3000 ถูก stop ไว้ คืนได้ด้วย
`docker start grader-app-1`
