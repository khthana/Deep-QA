## เรื่องที่จะกินเวลาถ้าไม่รู้ (gotchas)

- **clone อื่นยังมี `master` ที่ตายแล้ว** ปลายทางเปลี่ยนเป็น `main` แล้ว clone เก่าต้องแก้มือ:
  `git branch -m master main && git fetch origin && git branch -u origin/main main && git remote set-head origin -a`
- **`git add -A` ถูกปฏิเสธโดยตัวจัดประเภทของโหมดอัตโนมัติ** เพราะรีโปมี `DEEP-QA-BACKEND/` กับ
  `_local/` อยู่ข้างใน **stage ด้วยพาธชัดเจนเสมอ** และห้าม `git add` อะไรใต้สองที่นั้น
- **การแทรกบรรทัดไทยเข้าไปใน *สคริปต์ที่เขียนไฟล์อื่น* ต้องเขียน `\n` ให้ตรงกับที่โค้ดรอบตัวใช้**
  รอบนี้บรรทัดคอมเมนต์ที่แทรกลงไปจบด้วย `\n` ที่เป็นตัวอักษรสองตัว ไม่ใช่บรรทัดใหม่ ผลคือสคริปต์
  รันผ่าน แต่แฟ้ม **ปลายทาง** ได้บรรทัดยาวหนึ่งบรรทัดที่มี `\n` อยู่ข้างใน — อาการที่เห็นคือ
  *บรรทัดหายไปจากไฟล์ปลายทาง* และ `anchors.py` ตายด้วย `SyntaxError` ที่วงเล็บ อ่านด้วย
  `repr()` ของบรรทัดนั้น ไม่ใช่ด้วยตา
- **การกวาดบอกไม่ได้ว่าการแก้ของคุณทำแถวไหนพัง** ชุดเต็มคือสิ่งที่บอก (#83)
- **กวาดมัตแตนต์ที่เล็งใหม่ด้วยชุดที่กว้างกว่าไฟล์ของมันเอง** รอบนี้ชุดเจ็ดไฟล์เจอการฆ่าตัวที่สาม
  ที่ไฟล์เดียวมองไม่เห็น (#202)
- **heredoc กินแบ็กสแลช** — เขียนสคริปต์แก้ไฟล์ด้วยเครื่องมือเขียนไฟล์ และ **ยึดสมอบน ASCII**
  ที่ไม่ซ้ำ
- **`prettier --check` ไม่ใช่ประตูที่ใช้ได้กับแฟ้มหน้าจอเหล่านี้** · **อย่ารัน `npm run format` หรือ
  `npx prettier --write`** (#189)
- **พอร์ต 3100/5100 ของ `e2e/` ถูก Windows จองไว้** อ่าน
  `netsh interface ipv4 show excludedportrange protocol=tcp` **ทุกครั้ง** แล้วเลือกจากนอกช่วง
  อย่ายกพอร์ตจากใบนี้ไปใช้ (รอบนี้ใช้ 3400/5310)
- **คอนเทนเนอร์ `deep-core-postgres` ต้องสตาร์ตหลังรีบูต** อาการคือ webServer timeout
- **คอนโซลเป็น cp874** อย่าพิมพ์ไทยหรือ ☑⚙◐☐ ผ่าน Bash · ส่งไทยขึ้น GitHub ด้วย `--body-file`
  กับพาธแบบ Windows และ `MSYS_NO_PATHCONV=1` · `gh issue close` **ไม่มี** `--comment-file` ·
  ข้อความคอมมิตภาษาไทยส่งด้วย `git commit -F <file>`
- **ห้ามแก้ไฟล์ใน `frontend/`, `e2e/` หรือ `mutation/` ขณะชุดทดสอบหรือฮาร์เนสรัน** และห้าม grep
  ต้นไม้ขณะกวาด · แก้เอกสารล้วนระหว่างชุดทดสอบรันได้
