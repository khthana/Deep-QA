## 6. กับดักที่เพิ่มจากฉบับก่อน

- **Chromium เก็บ response body ไว้แค่จนกว่าหน้าจะเปลี่ยน** ถ้าเขียน support ที่คืน
  `Response` ให้ผู้เรียกไปอ่าน `.json()` ทีหลัง มันจะแพ้การแข่งกับสิ่งที่หน้าจอทำต่อ
  และขึ้นว่า *Response body is not available for a response that was navigated away from*
  อ่าน `.body()` ทิ้งทันทีที่คำตอบมาถึง Playwright จะ cache ไว้ให้ `waitForSections`
  ใน `e2e/support/teaching-screen.js` ทำแบบนี้แล้ว ตัวอื่นยังไม่ได้ทำ
- **มัตแตนต์ที่เอา parameter ออกจาก SQL ทำให้ statement ผิดกฎ ไม่ใช่ทำให้พฤติกรรมเปลี่ยน**
  ใช้ `COALESCE(col, $n)` หรือ `CASE WHEN TRUE THEN col ELSE $n END` เพื่อคง parameter ไว้
  และ `AND FALSE` สำหรับ DELETE ที่ต้องการให้ถูกกฎหมายแต่ไม่ลบอะไร
- **ถ้ามัตแตนต์ฆ่าได้หลายแถว ให้สงสัยการปนเปื้อนก่อนดีใจ** ดูว่าแถวที่ตายเพิ่มนั้น
  ตายที่บรรทัดเรื่องของมันเองหรือตายเพราะแถวก่อนหน้าทิ้งข้อมูลไว้
- **sweep ของรอบก่อนอาจยังไม่ตาย** ถ้าผลออกมาเร็วผิดปกติหรือไม่มีจำนวนเทสต์เลย
  ให้เชื่อว่ามี process เก่าถือพอร์ต 3100/5100 อยู่และกำลังใส่/ถอนมัตแตนต์ทับกัน
  ฆ่าด้วย `taskkill /PID <pid> /T /F` แล้วตรวจว่าพอร์ตว่างสองครั้ง **ระวังอย่าฆ่า
  stack ที่ผู้ใช้เดินอยู่บนพอร์ต 3000/5000**
- **A fresh clone lands on a dead `master`.** Run, verbatim:
  `git branch -m master main && git fetch origin --prune && git branch -u origin/main main`
