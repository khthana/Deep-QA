## สิ่งที่วัดได้ และสี่อย่างที่ตั๋วไม่ได้เขียน

**ทุกข้ออ้างของตั๋วเป็นจริง** `backend/routes/users.js` มีเจ็ดเส้นทาง — รายการ · แม่แบบนำเข้า ·
รายตัวตาม id · สร้าง · แก้ · เปลี่ยนสถานะ · นำเข้า — **ไม่มีเส้นไหนลบ** ·
`backend/lib/userPhoto.removePhoto` มีอยู่จริง ถูกเรียกโดยทางเปลี่ยนรูป
และหัวไฟล์ของมันเขียนไว้เองว่า route ลบบัญชีต้องเรียกมัน

1. **คำตอบอยู่ในสเปกอยู่แล้ว** `docs/06` user story 19 คือ *create, edit and deactivate user
   accounts* และ user story 29 กับ 40 เขียนหลักเดียวกันไว้ให้ Program กับ Program Subject คือ
   *deactivated rather than deleted* — การไม่มี route ลบจึงเป็นการตัดสินใจที่ลงลายลักษณ์อักษรแล้ว
2. **แต่ของที่ส่งมอบมา*มี*ปุ่มลบ** `UserTable.js` วาดปุ่มถังขยะต่อแถวหลังกล่องยืนยัน ยิงไปที่
   `DELETE /api/user/delete/:user_id` และ `userModel.deleteUser` ลบแถว `users` จริงหลังด่านธุรกิจ
   สองด่าน โดยกวาด `course_sections_teacher` ด้วยมือ ไม่แตะ `user_image` และไม่ลบไฟล์ —
   การไม่มี route ของการสร้างใหม่จึงเป็น**การเบนที่เลือกเอง** ไม่ใช่ของตกหล่น ทั้งสองครึ่งนี้
   ต้องอยู่ในคำถามของเจ้าของ เพราะมันชี้คนละทางบนความว่างเดียวกัน (#86 จากอีกด้าน)
3. **ที่อยู่ของข้อกำหนดคือไมเกรชัน ไม่ใช่ตั๋ว** `0004` เลือก `ON DELETE CASCADE` สวนหลัก `RESTRICT`
   ของ `0001` โดย**อ้าง `deleteUser` ของของเดิมเป็นเหตุ** จึงเป็นไฟล์ที่คนเขียนทางลบต้องอ่านอยู่ดี
   และ CASCADE ทำให้ข้อกำหนดเป็นจริงกับ**ทุกทางที่ลบแถว `users`** — route ในอนาคต สคริปต์ดูแลระบบ
   หรือมือคนที่เปิด `psql` — ไม่ใช่แค่ route เดียวที่ตั๋วจะผูกได้
4. **ราคาเล็กกว่าที่ไมเกรชันเขียนไว้** ประโยค *still served* ของ `0004` เป็นเรื่องของระบบที่ส่งมอบ
   ซึ่งเสิร์ฟรูปผ่าน `express.static` ที่ไม่มีด่าน · ตั้งแต่ #47 การสร้างใหม่**ไม่มี static mount
   เลย** และ `GET /me/photo` อ่าน `user_image` ของ `req.auth.userId` เท่านั้น ไฟล์กำพร้าจึงไปไม่ถึง
   ใครผ่าน route ใด — ราคาคือพื้นที่ดิสก์กับการเก็บรูปของคนที่บัญชีหายไปแล้ว **ไม่ใช่การรั่ว**
   ประโยคนั้นถูกต้องวันที่เขียน และหมดอายุด้วยการแก้ของตั๋วอื่น จึงถูกลงวันที่ ไม่ได้ถูกลบ (#130)

**และข้อกำหนดนี้มีขอบ ซึ่งเป็นเหตุให้คอมเมนต์ที่เดียวพอ** `activity_evidence.uploaded_by` เป็น
`ON DELETE SET NULL` ลบบัญชีไม่ลบแถวหลักฐานและไฟล์ของมัน · `user_image` เป็นตารางเดียวที่ทั้ง
cascade จาก `users` และถือ path ของไฟล์ · `course_sections_teacher.user_id` ที่นี่เป็น
`ON DELETE RESTRICT` ฉะนั้น route ลบบัญชีในอนาคตจะถูก**ปฏิเสธ**ถ้าอาจารย์คนนั้นมีภาระงานสอน
ต่างจากของเดิมที่กวาดแถวนั้นทิ้งเองก่อน
