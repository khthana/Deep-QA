### [#118](https://github.com/khthana/Deep-QA/issues/118) — กล่องยืนยันตัดคำไทยกลางคำ (`9d8737a`)

งานหลักของรอบนี้ อ่านเรื่องเต็มที่ `docs/lessons.md` §#118 สรุปสิ่งที่คนถัดไปต้องรู้:

**สาเหตุไม่ใช่ CSS เลยสักตัว** ตั๋วสงสัย `break-words` กับ `max-w-sm` วัดแล้วไม่ใช่ทั้งคู่ และวัดเพิ่ม
`lang="th"` กับ `word-break: keep-all` ก็ไม่ใช่ ย่อหน้า**ไม่เคยล้นกรอบ** (`scrollWidth` เท่ากับ
`clientWidth` เสมอ) `overflow-wrap` จึงไม่เคยทำงาน — **คลาสที่มีอยู่ ไม่ใช่คลาสที่ทำงาน** ตัวจริงคือ
Chromium ถาม ICU ว่าคำไทยจบตรงไหน แล้ว `Intl.Segmenter('th')` ตอบ `ใน|ปี|การ|ศึกษา` การตัดหลัง
`การ` จึงเป็นขอบที่เบราว์เซอร์**เลือกเอง** ไม่ใช่การฝ่าฝืนกฎ

**วิธีแก้อยู่ที่ตัวข้อความ ไม่ใช่ที่ CSS** U+2060 WORD JOINER ระหว่างตัวอักษรไทยทุกคู่ที่ติดกัน เหลือไว้
เฉพาะช่องว่างที่คนเขียนใส่ `break-words` **คงไว้** และมีอะไรค้ำเป็นครั้งแรก เพราะ `overflow-wrap`
ตัดทับ joiner ได้เมื่อจำเป็น ซึ่งคือเหตุผลที่ไม่เลือก `white-space: nowrap`

**ราคาที่ต้องรู้** ประโยคใน DOM ไม่ใช่ประโยคในซอร์สอีกต่อไป locator ที่สร้างจากชิ้นส่วนของซอร์สจึงพัง —
มีที่เดียวคือ `18a` แถว 6 ซ่อมด้วย `e2e/support/confirm-dialog.js` ที่ถอด joiner ออกแล้วอ่าน
**แถวที่ถามว่า *กล่องพูดว่าอะไร* ไปที่ไฟล์นั้น แถวที่ถามว่า *บรรทัดตกตรงไหน* ไปที่ `line-breaks.js`
และห้ามถอดอะไร**

**วิธีหาว่าอะไรพังอีกบ้าง** `grep "exact: false"` เป็นคำถามที่ผิด `getByText` จับ substring อยู่แล้ว
ไม่ว่าจะเขียนออปชันหรือไม่ ต้องสำรวจ**ตามค่า** — ทุกสตริงที่ไปถึง `message=` ปะทะทุก matcher ในชุด —
ได้ 19 ตัวที่*อาจ*เห็น เพราะการสำรวจบอกได้แค่ว่าชิ้นส่วนนี้อยู่ในประโยคของกล่องไหนสักใบ ไม่ได้บอกว่า
กล่องนั้นเปิดอยู่ตอนนั้นไหม **ชุดเต็มคือเครื่องมือที่ตอบอีก 18 ตัว**

**สิ่งที่วัดแล้วตัดสินใจไม่ทำ** หัวเรื่องไม่ถูกกาว — วัดครบ 19 หัวเรื่อง ยาวสุด 32 ตัวอักษร ไม่มีอันไหน
ตกบรรทัดในกล่อง 336px จึงตัดกลางคำไม่ได้ และถ้ากาวจะพัง `getByRole('heading', { name })`
ทั้งชุด **การวัดมีวันที่กำกับ** เพราะหัวเรื่องที่ยาวกว่านี้จะเปลี่ยนคำตอบ

## เรื่องที่ต้องรู้ก่อนเริ่ม (gotchas)

- **clone บนเครื่องอื่นยังมี `master` ที่ตาย** การเปลี่ยนชื่อ default branch เป็น `main` เมื่อ 17 ส.ค. 2569
