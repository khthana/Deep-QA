`notice` ถูกเขียนทับด้วยข้อความถัดไปเท่านั้น ไม่เคยถูกล้าง และเป็นแบบเดียวกันทั้งหกหน้าจอ
(`Departments`, `Users`, `Programs`, `ProgramSubjects`, `Subjects`, `Students`) ที่เดียวที่ล้างจริงคือ
`components/users/GrantsPanel.js` บรรทัด 65, 83 ซึ่งเป็นรูปแบบที่ควรยกไปใช้
**ห้ามแก้ด้วย timeout** — #85 คือตั๋วที่บอกว่าแถบหายเร็วเกินกว่าจะอ่านทัน สิ่งที่ต้องผูกคือการกระทำถัดไป
ของผู้ใช้ ไม่ใช่นาฬิกา

**[#92](https://github.com/khthana/Deep-QA/issues/92) กล่อง *Session หมดอายุ* ออกไม่ได้** — อันนี้เป็น
ทางตัน ไม่ใช่ความรำคาญ และ**ควรแก้ก่อนเริ่ม #64** เพราะมันดักคนเดิน checklist ทุกครั้งที่ลุกจากจอ
เกินครึ่งชั่วโมง สามอย่างประกอบกัน แต่ละอย่างสมเหตุสมผลของตัวเอง

1. cookie อายุยาวเป็นสองเท่าของ token (`COOKIE_LIFETIME_SECONDS = LIFETIME_SECONDS * 2`) พอ JWT ตาย
   cookie ยังอยู่และยังถูกส่งไปทุก request อีกหนึ่งช่วงอายุเต็ม
2. `requireSession` **จงใจ**ไม่ล้าง cookie ตอน verify ไม่ผ่าน มีคอมเมนต์อธิบายไว้ และเหตุผลยังถูก —
   middleware ตัวนี้ติดทุก route การล้างทุกครั้งที่พลาดจะทำให้ clock skew ครั้งเดียวเตะคนออกจากระบบ
3. `/auth/logout` อยู่หลัง `requireSession` คอมเมนต์เขียนว่า *"nothing to log and nothing to clear"*
   ซึ่งครึ่งหลังไม่จริง — ทางเดียวที่จะล้าง cookie ได้ต้องการ session ที่ยังมีชีวิต ซึ่งคนที่ติดอยู่ไม่มี

ทุกครั้งที่โหลดหน้าใหม่ `AuthContext` ยิง `/api/me` ได้ 401 `reason: 'expired'` → กล่องขึ้นอีก และปุ่ม
ในกล่องคือ `window.location.reload()` เปล่า ๆ กล่องเป็น `fixed inset-0 z-[9999]` คลุมทั้งจอ หน้าลงชื่อ
เข้าใช้ข้างใต้จึงกดไม่ได้ **ทางออกเฉพาะหน้า** DevTools → Application → Cookies →
`http://localhost:3000` → ลบ `token` (Console ทำไม่ได้ cookie เป็น `httpOnly`)
**ทางแก้ที่เสนอไว้ในตั๋ว** ถอด `requireSession` ออกจาก `POST /api/auth/logout` แล้วล้าง cookie เสมอ
แบบ idempotent ส่วน `recordActivity(..., 'LOGOUT')` ทำเฉพาะเมื่ออ่าน token ได้ แล้วให้ปุ่มในกล่อง
เรียก logout ก่อนไปหน้าลงชื่อเข้าใช้ **ห้ามแก้ด้วยการให้ `requireSession` ล้าง cookie** — นั่นทำลาย
เหตุผลที่คอมเมนต์นั้นปกป้องอยู่ ยังไม่ได้ลงมือ รอคำสั่ง

## 6. กับดักที่จะกัด

- **กองที่เดิน checklist คือ 3000/5000 schema `deep_core`** ไม่ใช่ 3100/5100 ของ Playwright
  และสองกองนี้ขึ้นพร้อมกันไม่ได้
- **ล้างฐานข้อมูลก่อนเริ่มเดินและหลังเดินจบเสมอ** — `cd db && npm run reset && npm run migrate &&
  npm run seed` เพราะ `npm run seed` เฉย ๆ เป็น upsert ที่ทิ้งของเก่าไว้ แถวที่เดินบนทะเบียนสกปรก
  คือแถวที่ต้องเดินใหม่ (ตอนจบ session นี้ล้างแล้ว `07`, `Z1`, `66010001` หายหมด)
- **backend/frontend ถูกยกขึ้นค้างไว้ตอนจบ session** ถ้าจะรัน e2e ต้องปิดก่อน และการหยุด background
  task ไม่พอบน Windows — `netstat -ano | grep -E ":(3000|5000)\s.*LISTENING"` แล้ว
  `taskkill //PID n //T //F`
- **A fresh clone lands on a dead `master`.** Run, verbatim:
  `git branch -m master main && git fetch origin --prune && git branch -u origin/main main`
- **Thai through a Bash heredoc is unreliable** (cp874) — เขียนด้วย Write tool แล้วแปะด้วย Python
  `io.open(..., encoding='utf-8', newline='\n')` ผูก anchor กับ ASCII หรือเลขบรรทัด
  และระวัง: การแก้สคริปต์ patch ผ่าน heredoc ทำให้ `\\n` ในสตริงกลายเป็นบรรทัดใหม่จริง (เจอมาแล้ว)
- ที่เหลือของ `2026-08-21-users-walked.md` หัวข้อ 7 ยังใช้ได้ทั้งหมด
