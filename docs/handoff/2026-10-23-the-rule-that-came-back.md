## คำตอบของเจ้าของงาน (23 ต.ค. 2569)

## สิ่งที่วัดได้

**ตัวเลขของใบผิดสองที่ และประชากรไม่ใช่หก** ใบเขียนว่าหน้าที่ลงทั้งหกหน้ามีฟอร์มเพิ่มของตัวเอง
จริงสี่หน้า — `/teacher/teacherDashboard` ไม่มีทั้งตัวกรองและฟอร์ม ซึ่ง docstring ของมันเขียนไว้เองโดยเจตนา
และ `/main/programLevelByIntake` ไม่มีฟอร์ม มีการเจาะลึกกับตัวเลือกสองตัวแทน · และรูปที่ใบทั้งใบต้องใช้
คือสองสิทธิ์ของรหัสบทบาทเดียวที่ขอบเขตต่างกัน เพราะ `landingPath` คีย์ด้วย `role_id` เดียว —
สร้างให้ `FULL_ADMIN` ไม่ได้เลย primary key ของ `user_roles` คือ `(user_id, role_id, scope_id)`
และขอบเขตของบทบาทนั้นเป็นสตริง `'FULL_ADMIN'` ตรง ๆ สิทธิ์ที่สองจึงเป็นแถวเดิม ·
`FACULTY_ADMIN` ต้องมีคณะที่สอง ซึ่ง seed ไม่มี **เอื้อมถึงจริงห้าหน้า และหนึ่งในห้าต้องใช้ SQL**

**UI ที่ส่งมอบตอบคำถาม Out of Scope ก่อนที่เจ้าของงานจะตอบ**
`DEEP-QA-FRONTEND/src/components/RoleDropdown.js` เรียก `window.location.reload()` ทุกครั้งที่สลับ
ของที่ส่งมอบจึงทิ้งหน้า ทิ้งตัวกรอง และทิ้งร่างที่พิมพ์ค้าง **ทุกครั้ง** ไม่ใช่เฉพาะครั้งที่อยู่กับที่
ข้อ 1 จึงแคบกว่าของที่ส่งมอบ ไม่ใช่เท่ากัน และทุกข้อในใบขยับตัวเลขที่ **การสร้างใหม่** เลือกไว้ใน #155
ไม่ใช่ตัวเลขที่โค้ดนักศึกษาเลือก — ไม่มีข้อไหนเป็นการเบี่ยง (#156) นั่นคือสิ่งที่ทำให้ทั้งสี่ข้อทำได้

**ข้อ 2 ตามที่ใบเขียนเป็นสีแดง และแถวเดียวบอกใน 40 วินาที** เอาสิทธิ์ที่สวมอยู่ใส่เป็น dependency
ของ `load` ใน `ProgramSubjects` แล้ว `155a` แถว 2 ตก — จอที่การสลับแบบย้ายกำลังเดินออกจากมัน

กล่องไม่ได้ผิด มันไม่อยู่ · โพรบทั้งสองถูกลบเมื่อตอบแล้ว (#207)

**ที่ลงไปเป็นสามจุด ไม่ใช่สองจุด** `RoleDropdown` บอกว่าการสลับอยู่กับที่ · เชลล์ส่งเลขลงไปผ่าน

ส่วนปีรับเข้าไม่อ่าน เพราะมันเป็นของหลักสูตร ไม่ใช่ของสิทธิ์

**แถวหนึ่งถูกจอที่มันยืนอยู่ห้ามไม่ให้อ่านข้ออ้างที่สองของตัวเอง** ร่างแรกของ `198a` แถว 1 อ้างว่า
ร่างรอด **และ** ตารางกลายเป็นแถวของสิทธิ์ใหม่ ตารางไม่อยู่ในเอกสารขณะที่ฟอร์มเพิ่มเปิดอยู่ —
กล่องแทนรายการ ไม่ได้ซ้อนทับมัน — การ poll จึงอ่านได้ `[]` สิบห้าวินาทีบนจอที่ทำงานถูก
**ข้ออ้างสองข้อที่สังเกตพร้อมกันในสถานะเดียวไม่ได้ เป็นสองแถว** การวาดยังเป็นข้ออ้างของ `155a`
แถว 1 และแถวนี้จับคู่ร่างกับ **request** ซึ่งสังเกตได้ขณะฟอร์มเปิด

**และเมื่อกลไกย้าย การฆ่าของมัตแตนต์ก็ย้ายตาม** `nokey` ยก `<Outlet key={screenEpoch} />`
ซึ่งไม่มีอยู่แล้ว ถูกเล็งใหม่ไปที่ dependency ที่มันกลายเป็น — ข้ออ้างเดิม ไม่ใช่ความผิดคนละอย่าง
(#203) — และเปลี่ยนชื่อเป็น `noscreendep` · `alwaysreread` เป็นกรณีที่คมกว่า มันยังทำซ้ำข้อที่ถูกปฏิเสธ
อย่างซื่อตรง แต่ `155a` แถว 2 เดินออกจาก `/main/course-in-program` ซึ่งไม่ใช่หน้าที่ลงของใคร
และตอนนี้ไม่อ่านรุ่นเลย แถวนั้นจึงไม่ตายใต้มันอีก การฆ่าย้ายไป `198a` แถว 2 ซึ่งเดินออกจาก
หน้าที่ลงของกรรมการหลักสูตรเอง และข้ออ้างของ `155a` แถว 2 **สำหรับจอที่ไม่ใช่หน้าที่ลง**
กลายเป็นสิ่งที่เอื้อมไม่ถึงโดยโครงสร้าง ไม่ใช่สิ่งที่ไม่มีใครพิสูจน์ (#179) — ไม่มีมัตแตนต์ไหน
ทำให้จอหนึ่งอ่านรุ่นที่มันไม่อ่านซ้ำได้ สถานการณ์ของทั้งสองแถวยังถูกค้ำด้วย `81:staysput`
ซึ่งกวาดซ้ำวันเดียวกันและฆ่าทั้งคู่

**การรีวิวเจอครึ่งที่การ mount ใหม่เคยทำให้จริงโดยโครงสร้าง และนั่นเป็นจุดที่สี่**
การ mount ใหม่อ่านใหม่ทุกอย่างที่จอขอตอน mount ส่วน dependency อ่านใหม่รายการเดียว ·

สิทธิ์ใบใหม่หมายถึงการ mount ใหม่ · หลังการแก้มันไม่จริงอีกแล้ว ตัวเลือกหลักสูตรในฟอร์มเพิ่ม
ค้างเป็นของหมวกใบเก่าจนกว่าจะ reload ซึ่งเป็นข้อบกพร่องที่ #155 เปิดไว้**อ่านกลับทาง** ·

dependency เดียวกันชั่วโมงเดียวกัน แต่จอที่ *พิสูจน์* กฎที่หลายจอถือเป็นคำตอบของสำมะโน

## สิ่งที่ยังค้าง

- **ไม่มีอะไรของ #198 ค้าง** คำตอบของเจ้าของงานถูกลงมือทั้งสามจุด บวกจุดที่สี่ที่การรีวิวเจอ
  คือการอ่านที่สองของ `Rubrics` กับ `Programs` และวัดด้วยมัตแตนต์หกตัว
- **[#230](https://github.com/khthana/Deep-QA/issues/230) คือราคาของคำตอบ** ไม่มีใครถามว่าหน้าที่ลง
  หน้าถัดไปใส่รุ่นใน dependency แล้วหรือยัง — สำมะโนตัวที่เจ็ดของ `frontend/scripts/`
  (ถ้าคำตอบคือสำมะโน) ประชากรที่ถูกคือ *ไฟล์ที่ `landingPath` ชี้ไป* ไม่ใช่ชื่อคอมโพเนนต์ (#182)
  · **ใบนี้มีสองคำถามแล้ว** หน้าที่ลงหน้าใหม่อ่านรุ่นหรือไม่ **และ**การอ่านที่สองของหน้าที่ลง
  หน้าหนึ่งอ่านมันหรือไม่ — เขียนลงใบเมื่อ 23 ต.ค. 2569 หลังการรีวิว
- **หนึ่งในห้าหน้าที่ลงต้องใช้ SQL ถึงจะสร้างสถานการณ์ได้** `FACULTY_ADMIN` ต้องมีคณะที่สอง
  ซึ่ง seed ไม่มี การขยาย seed เป็นคำตอบของเจ้าของงาน ไม่ใช่ของตั๋ว

## สิ่งที่จะกินเวลา

- **ชุดเบราว์เซอร์กินเวลา ~46 นาที** และใบที่แตะ `frontend/` ต้องรัน
- **การกวาดห้าตัวกินเวลา** แต่ละตัวต้อง `save` `apply` ชุดย่อย แล้ว `restore` — และต้องอ่าน
  `git status` ทั้งหลัง `apply` และหลัง `restore` (#124 · #126)
- **สองสิทธิ์ของรหัสเดียวต้องเตรียมเองใน `beforeAll`** `198a` ให้ `PROG_MANAGER/0503` แก่ `multi01`
  ผ่าน HTTP ในฐานะ `admin@` และถอนคืนใน `afterAll` ลง `cleanupFailure`

## สิ่งที่ต้องไม่ลืม

- **โคลนอื่นยังมี `master` ที่ตายแล้ว** — `git branch -m master main && git fetch origin &&
  git branch -u origin/main main && git remote set-head origin -a`
- `git add -A` ถูกปฏิเสธที่เครื่องนี้ — **stage ทีละพาธ** และไม่มีอะไรใต้ `DEEP-QA-BACKEND/`
  หรือ `_local/` เข้าไป
- **อย่ารัน `npm run format`** (#189) · prettier ที่ติดตั้งใหม่กว่าสไตล์ที่คอมมิตไว้
- **ห้ามแก้ `frontend/` `e2e/` หรือ `mutation/` ระหว่างชุดเบราว์เซอร์รัน** (#146) — การแก้แค่คอมเมนต์
  ก็ทำให้ hot reload ปนรอบนั้น
- **Playwright ถูกปฏิเสธผ่าน Bash ที่เครื่องนี้** ใช้เครื่องมือ PowerShell
- **อาร์กิวเมนต์ชื่อแฟ้มทดสอบจับเป็น substring** — `98a` จับ `198a` ด้วย · `python mutation/anchors.py`
  เป็นตัวที่นับคำสั่งเหล่านั้นให้ (#154 · #158)
- **นับเซลล์ ไม่ใช่นับแค่เครื่องหมาย** หลังแก้แถวตาราง (#79 · #175) — ตารางเกณฑ์ของใบ 10
  นับได้ 5 เซลล์ทุกแถวเท่าหัวตาราง
