## แปดข้อที่ #85 ทิ้งไว้ และสี่ข้อมาจาก /code-review ของมันเอง

### 1. attribute ที่ locator ยืนอยู่บนมัน พิสูจน์ด้วยการกลายพันธุ์ไม่ได้

#85 ขอ `role="alert"` บนแถบคำปฏิเสธ เพื่อให้มันถูก*ประกาศ* ไม่ใช่แค่ถูกวาด พอได้ role มาแล้ว
`refusalBanner` ใน `e2e/support/sign-in-screen.js` ก็เลิกหาแถบด้วย class ของ Tailwind
แล้วใช้ `getByRole('alert')` แทน ซึ่งเป็นที่ที่ locator ควรอยู่ **ผลข้างเคียงคือ role
กลายเป็น *สิ่งที่แถบเป็น* ในสายตาของทั้งไฟล์** เขียนมัตแตนต์ถอด attribute นั้นออกสองตัว
(ตัวหนึ่งถอดที่แถบ อีกตัวให้ `ContentMotionDIV` กินมันทิ้ง) ทั้งคู่ฆ่า **เก้าจากสิบสามแถว
และเป็นเก้าแถวเดียวกัน** spec แยกสองตัวนี้ออกจากกันไม่ได้เลย

เหตุผลไม่ใช่ว่าเทสต์อ่อน แต่เป็นว่า **สิ่งนั้นกลายเป็น*ข้อตั้ง*ของแถวเหล่านั้น ไม่ใช่ข้ออ้าง
ของแถวไหน** ถ้า role หายไป ชุดเทสต์จะไม่เขียวตั้งแต่แรก มัตแตนต์ที่บอกเรื่องนี้จึงพิสูจน์แค่ว่า
เทสต์รันได้ ลบทิ้งทั้งสองตัว แล้วครึ่ง *ถูกประกาศ* เป็น ◐ ที่บอกตรง ๆ ว่าครึ่งไหนพิสูจน์แล้ว
(attribute ไปถึง DOM จริง) และครึ่งไหนยังไม่ได้เดิน (หูของคนจริง กับคำถามว่า *assertive*
เหมาะไหม ซึ่งเป็นของ [#111](https://github.com/khthana/Deep-QA/issues/111))

**เกณฑ์ที่ใช้ได้: ถ้าจะย้าย locator ไปยืนบน attribute ไหน ให้รู้ตัวว่ากำลังแลก** — locator
ที่ถูกที่ขึ้น กับความสามารถในการพิสูจน์ attribute นั้นด้วยการกลายพันธุ์ การแลกนี้คุ้ม
แต่ต้องเขียนไว้ ไม่ใช่ปล่อยให้คนรอบหน้าเจอไฟล์แดงทั้งไฟล์แล้วเดาเอง

### 2. แต่ attribute ฝาแฝดของมันพิสูจน์ได้ และนั่นคือสิ่งที่ทำให้ข้อ 1 เป็นเส้น ไม่ใช่อารมณ์

/code-review ของตั๋วนี้อ่านสเปกแล้วพบว่า **ทำไปครึ่งเดียว** ตั๋วเขียนว่า *ควรผูกกับฟอร์มด้วย
`role="alert"`* ส่วนที่ทำคือ *ประกาศ* — ประโยคถูกอ่านตอนมันโผล่แล้วก็จบ ไม่มีอะไรผูกมันกับ
ช่องกรอกสองช่องที่มันพูดถึง คนที่กด Tab กลับเข้าไปในช่องรหัสผ่านสิบวินาทีต่อมาได้ยินชื่อช่อง
แล้วเงียบ ซึ่งเป็นสถานการณ์เดียวกับที่ตั๋วบรรยายไว้เองในหัวข้อ *ทำไมมันเจ็บ*

เติม `aria-describedby` แล้วเขียนมัตแตนต์ให้มัน — `refusaldescribesnothing` **ฆ่าแถวเดียว**
หน้าจอเดียวกัน ตั๋วเดียวกัน attribute ประเภทเดียวกันกับ `role="alert"` ผลตรงข้ามกันสนิท
เพราะไม่มี locator ไหนหาอะไรด้วย `aria-describedby`

**สิ่งที่ตัดสินว่า attribute หนึ่งพิสูจน์ได้ด้วยการกลายพันธุ์หรือไม่ ไม่ใช่ว่ามันสำคัญแค่ไหน
แต่คือชุดทดสอบหาของ*ด้วย*มันหรือเปล่า** attribute ที่เทสต์ใช้หาของคือ*ข้อตั้ง* ส่วน attribute
ที่เทสต์อ่านจากของที่หาเจอแล้วคือ*ข้ออ้าง* อย่างแรกพิสูจน์ไม่ได้ อย่างหลังพิสูจน์ได้ตามปกติ

### 3. `...rest` ไม่ใช่การกระทำที่เป็นกลางใน component ที่มี 63 จุดเรียก

ร่างแรกให้ `ContentMotionDIV` รับ `...rest` เพื่อให้ `role` ผ่านไปถึง `motion.div` ได้
/code-review จับได้ว่านั่นเปลี่ยนหน้าจออื่นไปด้วยเงียบ ๆ — **มีสี่จุดเรียกที่ส่ง prop
ที่ component นี้ทิ้งมาตลอด** (`Navbar.js` ส่ง `initial`/`animate`/`exit` กับ `style`
ให้กล่องเปลี่ยนรหัสผ่าน `PageNotFound.js` ส่งของตัวเองสองที่) การ spread ทำให้ทั้งสี่จุด
*มีผลขึ้นมาพร้อมกัน* คือหน้าจอสี่หน้าเปลี่ยนวิธีปรากฏ ภายในตั๋วที่ว่าด้วยอายุของประโยคบนหน้าที่ห้า

เปลี่ยนเป็นรับ `role` กับ `id` เป็น prop ที่มีชื่อ ผลข้างเคียงเป็นศูนย์
**prop ที่ตายอยู่สี่จุดนั้นควรเก็บกวาด แต่ไม่ใช่ด้วยการเปลี่ยนหน้าตาหน้าจอสี่หน้า
เป็นผลพลอยได้ของการแก้ ARIA** ใครจะทำ ให้เปิดเป็นตั๋วของตัวเอง

### 4. ปุ่มปิดที่ *ไม่ได้* ทำ และเหตุผลที่ไม่ได้ทำ

ตั๋วขอให้คำปฏิเสธอยู่ *จนกว่าผู้ใช้จะลงมือทำอะไร (แก้ช่องกรอก **หรือกดปิด**)* ครึ่งแรกทำแล้ว
ปุ่มปิดไม่ได้ทำ และเป็น**การตัดสินใจ ไม่ใช่การหลงลืม** — `docs/06` §Out of Scope เขียนว่า
*"The UI is reproduced as-is. Any proposal to change it is raised as a question, not implemented"*
ปุ่มปิดคือ control ที่ไม่มีอยู่บนหน้าจอที่ส่งมอบ การเพิ่มมันคือข้อเสนอที่กฎข้อนั้นให้ส่งกลับ
เป็นคำถาม ส่วนคำว่า *หรือ* ในตั๋วทำให้ทางใดทางหนึ่งพอสำหรับข้อกำหนดที่ตั๋วอ้างจริง ๆ คือ
WCAG 2.2 §2.2.1 ซึ่งว่าด้วยเวลาที่ผู้ใช้ไม่ได้ตั้งและขยายไม่ได้ — พอนาฬิกาหายไป ก็ไม่เหลือ
เวลาให้ขยาย **เขียนไว้เพราะการไม่ทำที่ไม่ได้บันทึก อ่านไม่ต่างจากการลืม**

### 5. สองแถวที่เป็นคู่ และแถวที่ผ่านมาตั้งแต่ก่อนแก้

`50a` ได้สองแถวจากตั๋วนี้ — *คำปฏิเสธยังอยู่หลังผ่านไปห้าวินาที* กับ *พิมพ์แล้วมันหายไป*
แถวหลัง **ผ่านมาตั้งแต่ก่อนแก้** เพราะ `setTimeout` สามวินาทีเก็บประโยคไปก่อนที่แถวจะไปดู
มันจึงแยก *การกระทำ* ออกจาก *นาฬิกา* ไม่ได้ด้วยตัวเอง สิ่งที่ตัดนาฬิกาออกจากคำอธิบายคือแถวแรก
**แถวที่ผ่านทั้งก่อนและหลังการแก้ ไม่ใช่แถวที่ไร้ค่า แต่เป็นแถวที่ยังไม่ครบ** — หาแถวคู่ของมัน
ให้เจอ แล้วเขียนไว้ในใบว่าอ่านแยกกันไม่ได้ มัตแตนต์สองตัวของตั๋วนี้เป็นคนพิสูจน์ว่ามันเป็นคู่จริง:
`refusaltimesout` ฆ่าแถวแรกอย่างเดียว `typingleavesitup` ฆ่าแถวหลังอย่างเดียว

## สามข้อที่ #50 ทิ้งไว้

### 1. การเดินไม่ใช่ตาข่ายเดียว และ #50 คือใบที่แสดงว่าทำไม

#50 เดินสามแถวและ **ติ๊กครบทั้งสาม ไม่เจออะไรเลย** — เป็นใบที่สองในคลังต่อจาก #36
แต่สิ่งที่ทำให้ใบนี้ต่างจาก #36 คือมันไม่ได้ *ไม่มีของ* ตั๋วนี้เจอข้อบกพร่องสี่อย่าง
และทั้งสี่อย่างถูกจับด้วยการ **อ่านโค้ดเทียบกับข้อกำหนด** ไม่ใช่ด้วยตา

เหตุผลตรงไปตรงมา: ทั้งสี่อย่างมองไม่เห็นบนหน้าจอที่ทำงานถูกต้องอยู่แล้วในสภาพปกติ

- กุญแจ `outsideValidity` ที่หายไปจากตารางคำ — เห็นได้ก็ต่อเมื่อมีผู้ประเมินภายนอกที่รอบปิดไปแล้ว
  มาลงชื่อเข้าใช้ด้วย Google ซึ่งเป็นสภาพที่ seed ไม่มีและการเดินสร้างไม่ได้
- คำปฏิเสธที่เป็นหน้า JSON — เห็นได้ก็ต่อเมื่อกดปุ่ม Google บนเครื่องที่ไม่ได้ตั้งค่า OAuth
  ซึ่งเป็นเครื่องของทุกคน แต่ไม่มีใครกดเพราะไม่มีใครใช้เส้นทางนั้นตอนพัฒนา
- ป้ายกำกับที่ชี้ไปที่ id ที่ไม่มีอยู่ — หน้าตาเหมือนกันทุกพิกเซล เห็นได้ด้วยการ *คลิกที่ตัวหนังสือ*
  ซึ่งไม่มีใครทำ หรือด้วยโปรแกรมอ่านหน้าจอ
- หน้าที่ไม่มีใครพาไปถึง — ตามนิยามแล้วไม่มีใครไปถึง

**การเดินตอบคำถามว่า *สิ่งที่วาดออกมาอ่านรู้เรื่องไหม* การอ่านโค้ดตอบคำถามว่า *สิ่งที่ควรมี
มีครบไหม*** สองคำถามนี้ไม่ทับกัน และตั๋วที่เจอของด้วยวิธีหนึ่งไม่ได้แปลว่าอีกวิธีเสียเปล่า

### 2. คำที่เดินทางในที่อยู่ ต้องมีปลายทางทั้งสองข้างที่ตรวจกันได้

`GOOGLE_REFUSALS` ในหน้าจอกับ `refuse()` ใน `admit` เป็น contract ข้ามแพ็กเกจที่ไม่มีตัวแปลไหน
บังคับให้ตรงกัน redirect ไม่มี body มีแต่ `?error=<key>` ฝั่งหนึ่งจึงตามหลังอีกฝั่งได้เงียบ ๆ
และตามหลังไปหกเดือน

ทางที่เลือกคือ **สองด้าน จับคนละครึ่ง**:

- `backend/auth/accounts.js` ประกาศ `GOOGLE_REFUSAL_REASONS` และเทสต์ฝั่ง backend
  **อ่าน `refuse()` ออกมาจากซอร์สของ `admit` เอง** มาเทียบกับรายการ — รายการจึงตามหลังกฎไม่ได้
- `e2e/tests/50a-sign-in.spec.js` วนรายการนั้น เปิด `/login?error=<key>` ทีละตัว
  แล้ว assert ว่าหน้าจอแสดง `REFUSALS[key]` — หน้าจอจึงตามหลังรายการไม่ได้

**ไม่มี seam ไหนย้ายไปครอบอีกครึ่งได้** การลบกุญแจออกจากรายการไม่ฆ่าแถวฝั่ง browser
เพราะลูปก็สั้นลงตาม เขียนไว้ตรง ๆ ใน `mutation/50-sign-in-screens.py` แล้ว
เพราะเป็นสิ่งที่คนอ่านชุดมัตแตนต์แล้วจะเข้าใจผิดได้ว่าครอบคลุมครบ

### 3. รหัสสถานะที่ไม่มีใครอ่าน คือคำตอบที่ไม่ได้ตอบ

`/api/auth/google-login` ตอบ `503` พร้อม JSON ซึ่งถูกต้องตามหลัก HTTP ทุกประการ
และผิดทั้งหมดในทางปฏิบัติ เพราะผู้เรียกคือเบราว์เซอร์ที่ทำ top-level navigation
สิ่งที่คนได้จริงคือหน้า `{"message":"..."}` บน origin ของ API อยู่นอกแอปพลิเคชัน
ไม่มีทางกลับนอกจากปุ่ม back

**ถามว่าใครเป็นคนอ่านคำตอบ ก่อนจะเลือกรูปแบบของคำตอบ** ถ้าเป็นโค้ด รหัสสถานะคือคำตอบ
ถ้าเป็นเบราว์เซอร์ที่กำลังนำทาง คำตอบคือหน้าจอที่มีคำอธิบาย — ซึ่ง callback ของเส้นทาง
เดียวกันทำถูกอยู่ก่อนแล้ว และเหตุผลก็เขียนอยู่ในนั้น ทั้งสองทางใช้ `refuseToBrowser` ตัวเดียวกันแล้ว

## เรื่องเดินสะดุด

**ส่วนขยาย Chrome ที่ต่ออยู่ไม่ได้อยู่บนเครื่องนี้** `localhost:5000` ที่นั่นตอบ
`ERR_CONNECTION_REFUSED` ทั้งที่ curl จากเครื่องนี้ได้ 200 — การเดินรอบนี้ผู้ใช้จึงขับเอง
โหลดหน้าแล้วดูก่อนโทษ stack เสมอ

## Gotchas ที่ยังต้องพก

- `git clone` ที่ทำไว้ก่อนเปลี่ยนชื่อ branch ยังชี้ `master` ที่ตายแล้ว แก้ด้วย
  `git remote set-head origin -a && git branch -m master main && git branch -u origin/main`
- e2e ใช้พอร์ต 5100 ซึ่ง Windows จองไว้เป็นช่วง ๆ ถ้าเจอ *already running* ทั้งที่ไม่มีอะไรฟัง
  ให้รันด้วย `E2E_FRONTEND_PORT=5300`
- `node server.js` ไม่มี reload — บันซ์ backend ก่อนเดินทุกครั้ง
- TaskStop ปิด shell แต่ไม่ปิดลูกของมัน เซิร์ฟเวอร์ที่ค้างจะทำให้การกวาดรอบถัดไปรายงานว่า
  *ไม่มีอะไรล้ม* ซึ่งหน้าตาเหมือนชุดมัตแตนต์ที่ฆ่าอะไรไม่ได้เลย
- **เดินด้วยมือก่อนกวาดมัตแตนต์และก่อนรันชุดเต็ม** การกวาดเขียนโค้ดที่พังลงดิสก์จริง
  หน้าจอที่เดินอยู่จะเสิร์ฟของที่พังโดยตั้งใจ
