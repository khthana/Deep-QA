### #122 — อาการเดียวบนสองจอ แต่เป็นสองข้อบกพร่อง

ตั๋วบอกว่าทั้งสองจอเปลี่ยนเป็นสีแดง *เมื่อ `total > 100`* จริงอยู่ข้างเดียว: เงื่อนไขของ
สัดส่วนคะแนน คือ `total === 100 ? green : red` ดังนั้นสีที่นั่น **ไม่เคยแปลว่า *เกิน* เลย มันแปลว่า
*ไม่เท่ากับร้อยพอดี* และ 80 แดงเท่ากับ 120** กฎของสองจอต่างกัน (`= 100` กับ `<= 100` เพราะการ
ระบุน้ำหนักที่ยังไม่ครบเป็นเรื่องถูกต้อง แต่เกณฑ์การให้คะแนนที่ยังไม่ครบไม่ใช่) ประโยคเดียวที่เขียน
ตามคำบรรยายของตั๋วจะทำให้คนที่ค้างอยู่ที่ 90 ไม่ได้ยินอะไรเลย **ตั๋วที่พูดรวมข้ามจอ มักพูดรวมที่
*อาการ* — ตรวจก่อนว่ากฎมันรวมกันได้จริงหรือไม่ ก่อนที่การแก้จะรวม**

และตำแหน่งของคำเป็นส่วนหนึ่งของการแก้ ไม่ใช่การจัดหน้า: ตัวเลขอยู่ **นอก** live region ส่วนคำ
ตัดสินอยู่ข้างใน เพราะ region ที่ถือ `รวม {total} / 100` จะประกาศยอดวิ่งใหม่ทุกการกดแป้น และใช้
`aria-live="polite"` ไม่ใช่ `role="status"` เพราะ role ที่แอปนี้ประกาศด้วยเป็นของ `Notice` และ
spec ทั่วคลังกรอง `getByRole('status')` ด้วยข้อความที่คาดไว้

### #96 — ตั๋วที่ติดอยู่กับคำถามที่ไม่มีใครถาม

`CloForm.js` และใบตรวจรับเขียนเหตุผลเดียวกันไว้ว่าแก้ไม่ได้จนกว่าจะมีคนตัดสินว่า `CLO-3ก`
เรียงตรงไหน ตั๋วจึงเปิดค้าง **สิบห้าวัน** เจ้าของตอบในประโยคเดียวว่า **รหัสไม่มีตัวอักษร มีแต่ตัวเลข**
และข้ออ้างของการติดนั้นก็ไม่จริงตั้งแต่ต้น **การเจอคำถามคือครึ่งเดียวของงาน อีกครึ่งคือถามมัน**
คำถามที่ถูกจดไว้สองที่ในสองไฟล์ ไม่ได้ใกล้คำตอบขึ้นเพราะการจดนั้น

การกวาดคือสิ่งที่จับคำกล่าวอ้างเกินจริงได้ และเป็นวิธีอ่านการกวาดแบบที่สี่ — **ตัวรอดบนแถวที่
ไม่มีใครสงสัย** มัตแตนต์ทั้งสองทิ้ง `27a` ไว้เขียวหมด เพราะแถวนั้นยืนยันว่า *จอรักษาลำดับที่ route
ส่งมา* ไม่ใช่ยืนยันว่าลำดับนั้นคืออะไร บนเก้าตัวที่ seed มี ลำดับตัวอักษรกับลำดับตัวเลขตรงกันพอดี
**ตรงไหนที่ใบตรวจรับเขียนว่า *เรียงตาม X* ให้ดูว่า assertion อ่าน X จริง หรือแค่ส่งมันผ่าน**

/code-review ของตั๋วนี้เองยังเจอสาขาที่มัตแตนต์ทั้งสองตัวมองไม่เห็น เพราะทั้งคู่แปรค่า
*คุณสมบัติเดียวกัน* คือลำดับ ลบ `NULLIF` ออกแล้วไม่มีอะไรสลับที่ แต่ `''::numeric` เป็น cast ที่
Postgres ปฏิเสธ และรหัสที่ไม่มีตัวเลขสักตัวหนึ่งรหัสทำให้ **ทุกจอที่ลิสต์ผลลัพธ์ตอบ 500**
**มัตแตนต์สองตัวที่แปรคุณสมบัติเดียวกัน มองไม่เห็นคุณสมบัติที่สาม** และคำถามที่หาช่องเจอไม่ใช่
*บรรทัดนี้ถูกคลุมหรือยัง* แต่เป็น *มัตแตนต์ต้องเปลี่ยนอะไร จึงจะพังในแบบที่สองตัวเดิมทำไม่ได้*

### #107 — ยามที่ grep เหมือนกัน แต่ไม่ใช่ยามตัวเดียวกัน

สิบสามจุดในเก้าไฟล์ route เขียน `/^\d+$/` ด้วยมือแล้วส่งสตริงต่อให้ PostgreSQL นั่นคือยามครึ่งเดียว:
`2147483648` เป็นตัวเลขล้วน ผ่านมันไปได้ และล้นคอลัมน์ `integer` เป็น 22003 — ซึ่ง error handler
รายงานเป็น เกิดข้อผิดพลาดในระบบ ให้กับที่อยู่ที่คนพิมพ์เข้ามาเอง ทั้งสิบสามใช้ `integerId` จาก
`lib/fields` แล้ว และแต่ละจุดตอบ ไม่พบ ของตัวเอง

จุดที่สิบสี่คือ `weights.js` และมัน **ตั้งใจไม่แก้** มันอ่าน `score_ratio_id` จาก *body* ซึ่ง `null`
ที่นั่นไม่ได้แปลว่า *ปฏิเสธ* แต่แปลว่า *หมวดที่เกณฑ์ชุดนี้ยังไม่มี* แล้วแถวจะถูก insert รหัสที่เกณฑ์
ชุดนั้นไม่มีถูกปฏิเสธ **ด้วยชื่อ** สี่สิบบรรทัดถัดลงไป ก่อนจะกลายเป็นพารามิเตอร์ของ query จึงไม่มี
22003 ให้กัน และ `integerId` ที่นั่นจะเปลี่ยนการปฏิเสธให้กลายเป็นการ insert เงียบ ๆ เจอเพราะ
เขียนแถวทดสอบก่อน แล้วเห็นมันตอบ **404 ไม่ใช่ 500 อย่างที่อีกสิบสามจุดตอบ** แถวที่ตรึงเรื่องนี้อยู่ใน
`weights.test.js` การ "ทำ #107 ให้ครบ" ในอนาคตจึงจะล้มเทสต์ แทนที่จะปล่อยของถอยหลังออกไป

**รหัสที่ตั๋วเสนอมาเอง มองไม่เห็นครึ่งหนึ่งของยาม และการถามก่อนกวาดคือสิ่งที่จับได้**
`Number('99999999999999999999')` คือ 1e20 ซึ่งตกที่ `Number.isSafeInteger` **ก่อนที่ `id <=
INT4_MAX` จะถูกพิจารณา** ทุกแถวที่เขียนด้วยรหัสของตั๋วจะทิ้งเงื่อนไขเพดาน — เงื่อนไขที่ว่าด้วย
คอลัมน์ `integer` จริง ๆ — ไว้โดยไม่มีอะไรพิสูจน์ และ `nobound` จะรอดการกวาดที่เขียวสนิท
`2147483648` เป็นรหัสเดียวที่มีแต่เพดานเท่านั้นที่ปฏิเสธได้ **เมื่อยามเป็นโซ่ของเงื่อนไข ค่าที่ประดิษฐ์
หนึ่งค่าพิสูจน์ได้หนึ่งข้อ** — นับข้อ แล้วประดิษฐ์ค่าให้ครบข้อละหนึ่ง และทำก่อนกวาด ไม่ใช่หลัง

สิ่งที่ดีที่สุดที่การกวาดเจอ อยู่ในไฟล์ของตั๋วอื่น `mutation/anchors.py` รายงาน MISS สองตัวใน
`24-teacher-dashboard.py` ทันทีที่ `teaching.js` ถูกเขียนใหม่ — รูปแบบของ #123 จับได้ด้วยเครื่องมือ
ที่สร้างมาเพื่อมันโดยตรง แต่การเล็งใหม่ไปที่ `if` ตัวใหม่ **ฆ่าอะไรไม่ได้เลย** เพราะการแก้เอง: route
เดิมตรวจค่าหนึ่งแล้ว bind อีกค่าหนึ่ง ตอนนี้มัน bind ค่าที่ตรวจแล้ว การลบการปฏิเสธออกจึง bind
`null` `WHERE section_id = NULL` ไม่ตรงแถวไหน และคนเรียกได้ 404 เท่าเดิมโดยบังเอิญ
**ยามที่คืนค่าที่มันตรวจแล้ว พังด้วยการลบการปฏิเสธออกอย่างเดียวไม่ได้** — **การตรวจสมอบอกได้ว่า
มัตแตนต์ไม่ตรงกับอะไรแล้ว มีแต่การกวาดที่บอกได้ว่ามันไม่ได้พิสูจน์อะไรแล้ว**

## /code-review ของ #107 เอง เจอหกข้อ และสามข้อเป็นเลขในไฟล์เดียวกับที่ตั๋วเพิ่งแก้

ที่เพิ่งถูกยกเป็นสิบ **การแก้เลขในที่ที่จำได้ว่าเคยเขียน ไม่ใช่การแก้เลข** — grep หาค่าเดิมหลังแก้เสร็จ
ทุกครั้ง เพราะเลขผิดตัวเดียวกันถูกพิมพ์ซ้ำลงในร้อยแก้วที่เขียนพร้อมกับโค้ด

## Gotchas ที่ยังต้องพก

ยกมาทั้งชุดจากใบก่อนหน้า ยังใช้ได้ทุกข้อ และเพิ่มสองข้อจากรอบนี้

- `git clone` ที่ทำไว้ก่อนเปลี่ยนชื่อ branch ยังชี้ `master` ที่ตายแล้ว แก้ด้วย
  `git remote set-head origin -a && git branch -m master main && git branch -u origin/main`
- e2e ใช้พอร์ต 5100 ซึ่ง Windows จองไว้เป็นช่วง ๆ ถ้าเจอ *already running* ทั้งที่ไม่มีอะไรฟัง
  ให้รันด้วย `E2E_FRONTEND_PORT=5300` ชุดเต็มใช้เวลาราว **18 นาที** (รอบนี้ 17.8 นาที 361 แถว)
- `node server.js` ไม่มี reload — บันซ์ backend ก่อนเดินทุกครั้ง
- TaskStop ปิด shell แต่ไม่ปิดลูกของมัน เซิร์ฟเวอร์ที่ค้างจะทำให้การกวาดรอบถัดไปรายงานว่า
  *ไม่มีอะไรล้ม* ซึ่งหน้าตาเหมือนชุดมัตแตนต์ที่ฆ่าอะไรไม่ได้เลย
- **อย่ากวาดมัตแตนต์ระหว่างที่ชุด e2e กำลังรัน** การกวาดเขียนโค้ดที่พังลงดิสก์จริง
- **เดินด้วยมือก่อนกวาดมัตแตนต์และก่อนรันชุดเต็ม** ด้วยเหตุผลเดียวกัน
- **การแก้ไฟล์ใน `frontend/src` ระหว่างที่ชุด e2e กำลังรัน จะทำให้ CRA คอมไพล์ใหม่กลางคัน และการ
  รันรอบนั้นใช้ไม่ได้** เอกสารกับ `backend/` แก้ได้ปลอดภัย — รอบนี้แก้ทั้งหกข้อจาก /code-review
  ระหว่างชุดเบราว์เซอร์กำลังรัน โดยไม่มีข้อไหนแตะ `frontend/src` ผลการรันจึงยังใช้ได้
- **docstring ในไฟล์มัตแตนต์ที่อ้าง regexp ต้องเป็น raw string** (`r"""`) ไม่อย่างนั้น
  `mutation/anchors.py` จะพ่น `SyntaxWarning: invalid escape sequence` ทับ output ของตัวเอง
  ซึ่งเป็นเสียงรบกวนชนิดที่ทำให้คนอ่านทีหลังเลิกอ่านตัวเลขของมัน
