- **กติกาที่นับแล้วค่อยเขียนต้องตอบเรื่องคำขอที่มาพร้อมกัน** ทุก route ที่เขียนจับ row lock สองตัว
  ตามลำดับคงที่ — แถว `student_course` ของนักศึกษา (ด่าน BR-07 เพราะเป็นแถวเดียวที่แทน
  *คนนี้อยู่ตรงไหนในห้องนี้* ได้ และสถานะที่ต้องกันคือ *ไม่มีแถวสมาชิก* ซึ่งล็อกแถวที่ไม่มีไม่ได้)
  แล้วจึงแถว `student_group` ของกลุ่มปลายทาง (ด่าน BR-06) การลบกลุ่มใช้แค่ตัวหลัง ไม่มีวง deadlock
- **เพิ่มไม่ใช่ย้าย** `POST` ปฏิเสธคนที่อยู่กลุ่มอื่นพร้อมชื่อกลุ่มนั้น `PUT` เป็นการย้ายและเขียน
  `MOVE_STUDENT` บรรทัดเดียว หน้าจอไม่ถอยจากอันหนึ่งไปอีกอันเลย เพราะเกณฑ์ข้อ 5 ขอว่า
  *ย้ายต้องถูกบันทึกเป็นการย้าย ไม่ใช่ลบแล้วเพิ่ม*
- **เปลี่ยนชื่อกลุ่มไม่มีบรรทัดในประวัติ** `action_type` มี CHECK ห้าค่าและไม่มีการเปลี่ยนชื่อ —
  ทุกบรรทัดคัดลอกชื่อ ณ เวลานั้นไว้แล้ว สิ่งที่การเปลี่ยนชื่อจะบันทึกจึงถูกบันทึกไปแล้วบรรทัดละครั้ง
- **migration 0007** partial unique index บน `(section_id, group_name) WHERE group_name <> ''`
  0003 ไม่ใส่เพราะ default เป็นสตริงว่าง — index แบบมีเงื่อนไขพูดทั้งสองเรื่องพร้อมกัน และทำให้
  ชื่อซ้ำเป็น 23505 แทนที่จะเป็น SELECT ที่แข่งกันเอง
- **ลบกลุ่มพากันออกจากกลุ่ม ไม่ปฏิเสธ** CASCADE ลบแถวสมาชิกอยู่แล้ว สิ่งที่มันทำไม่ได้คือบอกว่ามันลบ
  route จึงเขียน `REMOVE_STUDENT` ให้ทุกคนก่อน แล้ว `DELETE_GROUP` แล้วจึงลบ — ทรานแซกชันเดียว
- **`importRows` รับ `{ message }` ได้แล้ว** นอกจาก `reason` ที่เป็นคีย์ของ REFUSALS เพราะประโยค
  ที่ต้องเอ่ยชื่อกลุ่มเป็นประโยคที่มีรู ไม่ใช่ค่าคงที่ — เหตุผลเดียวกับที่ `whole` ของ #30 คืนประโยค
- **seed ทิ้ง 11 คนท้ายของแต่ละตอนเรียนปีนี้ไว้ไม่มีกลุ่ม** (`UNGROUPED_TAIL = MAX_GROUP_SIZE + 1`)
  ห้องที่ทุกคนมีกลุ่มแล้วคือ fixture ที่หน้าจอนี้ทำอะไรไม่ได้เลย และเพดานพิสูจน์ได้ทางเดียวคือ
  ตั้งกลุ่มให้ครบสิบแล้วโดนปฏิเสธคนที่สิบเอ็ด

## 4. สิ่งที่ชุดทดสอบจับได้ (และเป็นเหตุผลที่ทั้งสาม seam มีอยู่)

**backend suite จับ route ที่ตอบก่อน COMMIT** — `DELETE` ตอบ 204 แล้วการอ่านครั้งถัดไปยังเห็นกลุ่มอยู่
เพราะ handler เรียก `res.send()` ข้างในทรานแซกชัน แล้วค่อย COMMIT — supertest resolve ทันทีที่
response มาถึง ซึ่งเร็วกว่า COMMIT แก้เป็น `work()` คืน `{ status, body }` และ `inSection` เป็นคน
ตอบหลัง COMMIT ความล้มเหลวนอกห้องทดสอบแย่กว่า: COMMIT ที่ล้มหลัง 204 ทิ้งคนไว้หน้าจอที่บอกว่าลบแล้ว

**db suite จับ seed test สองแถว** — `every enrolled student of the current year has a group` เป็นเท็จ
โดยตั้งใจแล้ว เขียนใหม่เป็น *แต่ละตอนเรียนเหลือ `UNGROUPED_TAIL` พอดี* (นับรายตอนเรียน ไม่ใช่ผลรวม
เพราะผลรวมถูกได้ทั้งที่ตอนเรียนหนึ่งจัดครบและอีกตอนไม่จัดเลย) และ `reset and migrate` ต้องรู้จัก 0007
**db/test เป็น seam ที่สาม อย่าลืมรันเมื่อแตะ `db/`**

**การกวาดเองจับอะไรไม่ได้** — มัตแตนต์ทุกตัวตายที่แถวที่มันค้ำ ตารางเต็มอยู่ในใบตรวจรับ

**code-review จับสี่อย่าง และสองอย่างเป็นของจริง**

- **ล็อกสองชั้นใช้กับ import ไม่ได้** ส่วนหัวของไฟล์เขียนว่า *ทุก route ที่เขียนจับ row lock สองตัว*
  ซึ่งไม่จริงสำหรับการนำเข้า — `verify` ของ `importRows` รันก่อน BEGIN และ `insert` ไม่ได้ล็อกอะไรเลย
  ที่แย่กว่านั้นคือ **แผนสองล็อกเองก็ผิดสำหรับการนำเข้า**: ทรานแซกชันเดียวถือกลุ่มของบรรทัดแรกไว้
  แล้วเอื้อมไปหานักศึกษาของบรรทัดที่สอง ส่วน typed add ถือนักศึกษาคนนั้นแล้วเอื้อมไปหากลุ่มนั้น — ครบวง
  แก้เป็น **ล็อกเดียว** คือแถว `course_sections` `FOR UPDATE` เป็นคำสั่งแรกหลัง BEGIN ของทุกเส้นทาง
  ที่เขียน ล็อกเดียวไม่มีวงให้ deadlock และการนำเข้าถามกติกาทั้งสองข้อซ้ำใต้ล็อกนั้น
- **ใบตรวจรับเคลมเกินจริงหนึ่งแถว** เกณฑ์ข้อ 6 ติด ⚙ ทั้งที่ไม่มีแถวเบราว์เซอร์ไหน assert ว่า
  *ลบกลุ่ม* กับ *นำออก* ขึ้นในประวัติ (เป็นความผิดพลาดแบบเดียวกับที่ #33 เคยโดน) แก้ด้วยการเพิ่ม
  assertion เข้าแถว 8 และเพิ่มมัตแตนต์ `deletewritesnoexits` ตัวที่สิบสี่ แล้วจึงติด ⚙ ได้จริง
- อีกสองอย่างเป็นเรื่องรูปแบบ: `notThisSection` กำลังจะกลายเป็นสำเนาที่สี่ (ยกขึ้น module level ของ
  `enrolment.js` แล้ว export คู่กับ `sectionOf` — อีกสองสำเนาใน `teachingPlan.js`/`activities.js`
  เป็นงานของ #104 ไม่แตะเพราะอยู่ในชุดมัตแตนต์ของตั๋วอื่น) และ `refuse` ชนกับ
  `auth/accounts.js` ที่ใช้ชื่อเดียวกันแต่สัญญาตรงข้าม (เปลี่ยนเป็น `refusedWith`)

## 7. กับดัก

**`before` ระดับบนสุดสองอันของ `node --test` ไม่ได้รันเรียงกัน** (ใหม่) — อันที่สองเริ่มโดยไม่รอ
อันแรก ไฟล์ทดสอบของ #26 จึงอ่าน `api` ได้เป็น `undefined` ทั้งไฟล์ในรอบแรก **ใช้ hook เดียว**

**route ที่ตอบข้างในทรานแซกชันคือ route ที่โกหก** (ใหม่) — `res.send()` ก่อน `COMMIT` ทำให้ผู้เรียก
รู้ผลก่อนที่ผลจะจริง เขียน handler ให้คืนคำตอบแล้วให้ตัวห่อเป็นคนส่งหลัง COMMIT

**ล็อกละเอียดหลายตัวในทรานแซกชันที่แตะหลายแถวคือ deadlock ที่รอเวลา** (ใหม่) — กฎ *ล็อกตามลำดับ
คงที่* กันวงได้เฉพาะกับเส้นทางที่ถือทีละคู่ การนำเข้าถือของบรรทัดก่อนไว้ตอนเอื้อมหาของบรรทัดถัดไป
ถ้ามีเส้นทางที่เขียนเป็นชุด ให้ใช้ **ล็อกเดียวที่หยาบพอ** ครอบทุกเส้นทางแทน

**ตารางคิวเดินมือถูกก๊อปส่งต่อมาโดยไม่มีใครตรวจ** — นับจากใบตรวจรับเสมอ (คำสั่งอยู่หัวข้อ 5)

**`restore` ของ harness เขียนทับทุกไฟล์ใน `FILES`** — อย่าแก้ไฟล์ในชุดระหว่างที่กวาดค้างอยู่ และ
**`save` เป็นคำสั่งแรกของสคริปต์กวาดเสมอ**

**อย่าให้ assertion ของ e2e เทียบกับคำตอบของ API ที่เติม control นั้นเอง** — `26a` แถว 1 นับกับ
`UNGROUPED_TAIL` ของ seed ด้วยเหตุผลนี้
