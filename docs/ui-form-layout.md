# การจัดวางช่องในฟอร์ม

กฎห้าข้อนี้เป็นคำตอบของเจ้าของงานเมื่อ 19 พ.ย. 2569 (การซักของ #290) ต่อข้อสังเกตว่า ในฟอร์มแก้ไขของ *ข้อมูลภาควิชา*
และ *ข้อมูลหลักสูตร* ช่อง *สถานะ* ยาวเกินไป ช่องรหัสกว้างเกินไป และชื่อไทยกับชื่ออังกฤษอยู่บรรทัดเดียวกันจนชื่อยาวไม่มีที่
ระบบนี้ใช้งานจริง (ไม่ใช่การจำลองวิทยานิพนธ์) การเปลี่ยนการจัดวางจึงเป็นคำถามของเจ้าของงาน และนี่คือคำตอบ

## กฎ

1. **ชื่อไทยและชื่ออังกฤษอยู่คนละบรรทัด เต็มความกว้างของฟอร์ม** — ชื่อหลักสูตรจริงยาวเกินครึ่งฟอร์ม
2. **ช่องสั้นกว้างตามค่าที่คนพิมพ์** — ตั้งแต่ `md` ขึ้นไป รหัส ปี หน่วยกิต และลำดับ กว้าง `md:w-32` (128px) ·
   ใต้ `md` ทุกช่องยังเต็มจอ · ช่องสั้นที่ระบุตัวตนของระเบียน (รหัสกับปี หรือรหัสกับหน่วยกิต) อยู่แถวบนสุดด้วยกัน
3. **ช่องสถานะแคบ (`md:w-40`, 160px) และอยู่แถวสุดท้าย** — คำอธิบายใต้ช่องยังอยู่ใน `<label>` และกว้างเต็มฟอร์ม
   เพราะ label ที่ห่อช่องคือสิ่งที่ให้ชื่อที่เข้าถึงได้ (`getByRole('combobox', { name: 'สถานะ' })`, #180, #228)
   จึงหดเฉพาะตัวควบคุม ไม่หดทั้ง label
4. **dropdown ที่แสดงชื่อ เต็มความกว้าง; dropdown ที่ตัวเลือกเป็นชุดตายตัว แคบ** — *หลักสูตร* *รายวิชา* *อยู่ใต้ข้อ*
   แสดงชื่อที่ยาวได้ถึงขีดของคอลัมน์ จึงเต็มความกว้าง · *ประเภท* และ *ประเภทรายวิชา* กว้าง `md:w-40` และอยู่แถวเดียวกับ
   ช่องสั้นอื่นได้ (เช่น *ประเภท* กับ *ลำดับการแสดงผล* ของ PLO)
5. **ความกว้างตามค่าที่พิมพ์จริง ไม่ใช่ตามขีดของฐานข้อมูล** — รหัสใช้ขนาดเดียว `md:w-32` เว้นแต่ placeholder ถูกตัด
   ซึ่งใช้ `md:w-48` (192px) — ที่เดียวตอนนี้คือ *รหัสผลการเรียนรู้* ของ PLO ที่ placeholder คือ *เช่น PLO-1 หรือ PLO-1-2*

## กลไก

แต่ละฟอร์มมี `Field` ของตัวเองที่รับ `width` ซึ่งห่อเฉพาะตัวควบคุมไว้ใน `<span className="block md:w-…">` และค่าคงที่
`SHORT` `CHOICE` `CODE` ในไฟล์ของตัวเอง — คัดลอก ไม่แชร์ เพราะการเปลี่ยนการจัดวางครั้งเดียวไม่ใช่การรวมคอมโพเนนต์ด้วย (#68)
แถวที่มีช่องสั้นสองช่องใช้ `flex flex-col gap-4 md:flex-row` ชื่อและช่องกว้างใช้ `space-y-4`

## ขอบเขต

#290 ใช้กฎนี้กับห้าฟอร์มที่มีช่องสถานะ: ภาควิชา หลักสูตร รายวิชา รายวิชาในหลักสูตร และผลการเรียนรู้ของหลักสูตร (PLO)
ฟอร์มที่เหลือเป็นงานของ [#291](https://github.com/khthana/Deep-QA/issues/291) ซึ่งเดินด้วยมือก่อนแล้วจึงแก้

## การพิสูจน์

การจัดวางเป็นเรื่องรูปลักษณ์ จึงเป็นแถวเดินมือ (☑/◐/☐) ในใบตรวจรับของแต่ละจอ ที่ 375, 768 และ 1280px ด้วยชื่อยาว
ไม่มีแถว ⚙ ใหม่ — spec ของห้าจอต้องผ่านทั้งหมด ซึ่งเป็นการพิสูจน์ว่าการจัดวางไม่ได้พังพฤติกรรม ไม่ใช่ว่าการจัดวางถูก
