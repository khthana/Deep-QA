# ใบตรวจรับ #36 — ผลลัพธ์การเรียนรู้รายวิชา

[#36](https://github.com/khthana/Deep-QA/issues/36) · หน้าจอ `/teacher/teacherDashboard/:sectionId/courseResults`

## สิ่งที่ต้องเข้าใจก่อนเดิน

**เลขคณิตของตั๋วนี้ไม่ใช่ของใหม่** มาตราส่วนเต็ม 5 (BR-18) เกณฑ์ร้อยละ 60 (BR-17) ช่วงคะแนนห้าช่วง
(BR-20) และกฎที่ว่า *ช่องว่างไม่ใช่ศูนย์* ทั้งหมดอยู่ใน `backend/lib/attainment.js` ตั้งแต่ #38 แล้ว
ใบนี้จึงไม่พิสูจน์มันซ้ำ — `learning-details.test.js` เป็นเจ้าของ และสำเนาที่สองจะเป็นสำเนาที่เก่าก่อน

**สิ่งที่ใหม่คือการเปรียบเทียบข้ามปี** และมันตั้งอยู่บนสองการตัดสินใจที่ไม่มีกฎข้อไหนใน `docs/01`–`05`
ตัดสินให้ ทั้งสองข้อผู้ใช้เป็นคนเลือกเมื่อ 3 กันยายน 2569 ก่อนเขียนโค้ดบรรทัดแรก

**ข้อแรก — ปีก่อนหน้าคือทุกตอนเรียนของวิชานั้น รวบเป็นตัวเลขเดียว** ไม่ใช่เฉพาะตอนเรียนที่ผู้สอนคนนี้เคยสอน
R079 ถามว่า*รายวิชา*ดีขึ้นไหม และรายวิชาที่มีคนสอนสามคนในปี 2568 มีคำตอบเดียวไม่ใช่สามคำตอบ —
อีกทั้งการเทียบกับเฉพาะห้องของตัวเองจะหายไปทันทีที่มีคนใหม่มารับวิชาต่อ ซึ่งเป็นตอนที่คำถามนี้มีค่าที่สุดพอดี

นี่กว้างกว่าด่านของตอนเรียนฐาน จึง**บันทึกไว้ใน ADR-0002** และถูกจำกัดด้วย*รูปร่างของคำตอบ*
ไม่ใช่ด้วยการตรวจที่ลืมได้: คำตอบไม่มี `section_id` ไม่มีเลขตอนเรียน ไม่มีชื่อผู้สอน ไม่มีนักศึกษา
และไม่มีพารามิเตอร์ไหนที่เอ่ยถึงตอนเรียนของปีก่อนได้เลย

**ข้อสอง — เสนอเฉพาะปีที่ชุดเลข CLO ตรงกันเป๊ะ** เรดาร์ซ้อนสองปีบนแกนชุดเดียว และแกนคือ CLO —
แต่ CLO เป็นของ (หลักสูตร รายวิชา ปีการศึกษา) ตาม ADR-0003 ดังนั้น CLO-3 ของปี 2568 กับของปี 2569
เป็นคนละแถวและไม่จำเป็นต้องพูดเรื่องเดียวกัน การจับคู่ด้วยเลขเป็นทางเดียวที่มี และซื่อสัตย์ก็ต่อเมื่อ
สองปีเห็นตรงกันว่าเลขพวกนั้นคืออะไร

ระบบที่ส่งมอบมาเอื้อมไปหาความคิดเดียวกันจากอีกด้าน — มันเทียบชุด PLO ที่ CLO ผูกไว้และบังคับให้ตรงกัน
100% ซึ่งเป็นสัญชาตญาณเดียวกันบน schema ที่ CLO ห้อยอยู่กับตอนเรียน ข้อจำกัดนี้จึงไม่ใช่สิ่งที่รีบิลด์คิดขึ้นเอง

**ปีที่ยังไม่มีคะแนนก็ไม่ถูกเสนอ** มันจะวาดรูปหลายเหลี่ยมที่ว่างเปล่า และตัวควบคุมที่ให้ผลว่างเปล่า
แย่กว่าการไม่มีตัวควบคุม — ข้อสังเกตเดียวกับที่การเดิน #42 ทิ้งไว้เรื่อง `CohortPickers`

**ไม่มีเพดานว่าย้อนได้กี่ปี** โค้ดที่ส่งมอบมาหยุดที่สองปี ซึ่งไม่มีเอกสารไหนขอไว้ และแนวโน้มห้าปีของรายวิชา
คือคำถามที่ TABEE ถามจริง ๆ ทุกปีที่วาดได้จะถูกเสนอ ส่วนจะวาดกี่ปีพร้อมกันเป็นเรื่องของหน้าจอ

**กราฟเขียนเป็น SVG ด้วยมือ ไม่ได้ใช้ไลบรารี** เหตุผลที่สามเป็นตัวตัดสิน: ไลบรารีกราฟจะเป็น dependency
ที่ใหญ่ที่สุดของแอปนี้เพื่อหน้าจอเดียว · ป้ายภาษาไทยบนแกนเป็นปัญหาของมันไม่ใช่ของเรา · และ**กราฟบน
canvas คือรูปภาพ** ซึ่งทั้ง screen reader และ browser seam อ่านไม่ได้ทั้งคู่ ซึ่งเป็นผู้อ่านสองรายที่
repo นี้มีจริง ทุกจุดบนกราฟนี้เป็น element ที่มี `<title>` และตารางข้างล่างมีตัวเลขทุกตัวที่กราฟวาด

### สิ่งที่การเดินเจอก่อนจะได้เห็นอะไรสักแถว

ก้าวแรกไปเปิดหน้าจอของตอนเรียน 3 (ปี 2568 ปีเก่าสุดของวิชา จึงไม่มีปีเทียบ) แล้ว **เบราว์เซอร์หยุดตอบ**
ทั้ง JS ทั้งภาพถ่ายหน้าจอ time out หมด

สิ่งที่ทำคือ**ไม่เดา** `available_years` ที่ว่างเปล่าเป็นสาขาที่แถวทดสอบทั้งสาม seam ไม่เคยเข้าเลย
เพราะทุกแถวเปิดปีล่าสุด จึงเขียนแถวใหม่ใน `36a` ให้เข้าสาขานั้นโดยเฉพาะ — หน้าจอวาดกราฟครบ
ไม่มีช่องติ๊ก ไม่มี *กำลังโหลดข้อมูล…* ค้าง และผ่าน **หน้าจอไม่ได้พัง** แถวนั้นอยู่ในตารางข้างบนแล้ว
เป็นแถว ⚙ ที่เกิดจากการเดินโดยที่การเดินยังไม่ทันเห็นอะไรด้วยตาเลยสักแถว

**ผมวินิจฉัยผิดสองรอบก่อนจะเจอของจริง** รอบแรกสงสัยโค้ดหน้าจอตัวเอง รอบสองโทษส่วนขยาย Chrome
ผู้ใช้เป็นคนทักว่า *"ผมว่า server น่าจะตาย"* ซึ่งถูก — CRA dev server ที่พอร์ต 5000 ค้างตายไปแล้ว
**แต่ยัง listening อยู่** `curl` จึงค้างแทนที่จะได้ connection refused และไม่มีสัญญาณอะไรบอกว่าตาย
`navigate` ตอบว่าสำเร็จเพราะสั่งไปได้ แต่หน้าไม่เคยโหลด จึงไม่มีเอกสารให้อ่านหรือถ่าย

บทเรียน: **พอร์ตที่ listening ไม่ได้แปลว่าเซิร์ฟเวอร์ยังตอบ** ก่อนโทษเบราว์เซอร์ ให้ `curl --max-time`
ที่ frontend ก่อน

อีกข้อที่กินเวลา: ผมกรอกอีเมลให้ผู้ใช้เป็น `teacher.one@deep.local` ซึ่ง **ไม่มีในฐานข้อมูล**
(ของจริงคือ `@kmitl.ac.th`) ผู้ใช้กรอกรหัสผ่านสองรอบโดยไม่มีทางเข้าได้ และหน้าจอก็ไม่ได้บอกสาเหตุ
ที่แท้จริง ซึ่งตรงกับ [#97](https://github.com/khthana/Deep-QA/issues/97) พอดี

## สิ่งที่รีวิวสองแกนเจอ และแก้ไปแล้ว

ทุกข้อข้างล่างนี้เขียวก่อนรีวิว — ชุดทดสอบผ่านหมดทั้งสอง seam

**คะแนนของคนที่ออกจากตอนเรียนไปแล้วยังถูกนับ** #38 เดินจากทะเบียนเข้าหาคะแนน คนที่ถอนออกไปจึงไม่เป็น
แถวที่นั่นตั้งแต่ต้น ส่วน route นี้พับจากคะแนนออกไป — ไม่มี join กลับไปที่ `student_course` คะแนนที่คนถอน
ทิ้งไว้จึงยังดันค่าเฉลี่ยขึ้นที่นี่แต่ไม่ดันที่นั่น **ตอนเรียนเดียวกันจะมีคะแนนเฉลี่ยสองค่าบนสองหน้าจอ**
ซึ่งเป็นการเลื่อนแบบที่หัวไฟล์ `lib/attainment.js` เตือนไว้เอง · มีชุดทดสอบแล้ว และมันล้มถ้าเอา join ออก

**ยิง query หนึ่งครั้งต่อหนึ่งปีที่เทียบได้ ทุกครั้งที่โหลด** แม้ยังไม่มีใครติ๊กอะไร และตั๋วนี้จงใจไม่ใส่เพดาน
ว่าย้อนได้กี่ปี — วิชาที่มีสิบปีเทียบได้จะยิงสิบครั้งเพื่อวาดแค่ช่องติ๊ก รวมเป็น query เดียวด้วย
`GROUP BY academic_year` แล้ว

**นับนักศึกษาซ้ำเมื่อคนหนึ่งลงสองตอนเรียนในปีเดียว** เดิมบวกจำนวนคนของแต่ละตอนเรียน ขณะที่ `foldBy`
รวบเขาเป็นคนเดียว — ตัวส่วนบนจอจึงไม่ใช่ตัวส่วนที่ค่าเฉลี่ยข้าง ๆ ถูกคำนวณด้วย เปลี่ยนเป็น
`count(DISTINCT student_id)` ทั้งปี

**เส้นที่ห้าถูกวาดเหมือนเส้นแรกเป๊ะ** จานสีมีสี่ชุดและ `seriesStyle` วนกลับ ปีเปรียบเทียบที่สี่จึงได้
สีเดียวกันและลายเส้นเดียวกันกับปีนี้ คำอธิบายสัญลักษณ์จะมีสองบรรทัดที่แยกไม่ออก ตอนนี้หน้าจอ
**ไม่เสนอปีที่มันวาดไม่ได้** — ช่องที่ยังไม่ติ๊กจะถูกปิดเมื่อครบ พร้อมประโยคบอกเหตุผล

**คำปฏิเสธพาหน้าจอหายไปทั้งหน้า** เดิม `catch` เคลียร์ `data` ทิ้ง ปีที่ถูกปฏิเสธจึงค้างอยู่ใน state
โดยไม่มีตัวควบคุมเหลือให้เอาออก มีแต่รีโหลดถึงจะกลับมา ตอนนี้แยกสองกรณี: การอ่านฐานล้มแปลว่าดูตอนเรียนนี้
ไม่ได้เลย หน้าจอจึงว่างใต้คำปฏิเสธ ส่วนปีที่ล้มแปลว่าล้มเฉพาะปีนั้น กราฟอยู่ต่อและช่องติ๊กถูกดีดกลับ
ไปตรงกับสิ่งที่วาดอยู่

**ไม่มีด่านกันคำตอบเก่ามาทับ** ติ๊กเร็ว ๆ สองครั้งคือสองคำขอที่ค้างอยู่พร้อมกัน ตัวที่ช้ากว่าชนะ —
ข้อบกพร่องเดียวกับที่ [#68](https://github.com/khthana/Deep-QA/issues/68) ตั้งชื่อไว้บนอีกหน้าจอ
ใส่ ticket กันไว้แล้ว ไม่เพิ่มตัวอย่างที่สองให้ปัญหาที่มีตั๋วอยู่แล้ว

รูปหลายเหลี่ยมได้ ตอนนี้เขียนบอกว่าทำไมไม่มีกราฟ และตารางข้างล่างยังมีตัวเลขครบ
