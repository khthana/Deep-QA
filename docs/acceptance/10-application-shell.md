## ตั้งต้น

```
docker start deep-core-postgres
cd db      && npm run seed
cd backend && npm start          # http://localhost:3000
cd frontend && npm start         # http://localhost:5000
```

ทุกบัญชีใน seed ใช้รหัสผ่านเดียวกัน คือค่า `PASSWORD` ใน `db/seed.js`

## รายการที่ต้องเดิน

ช่องสุดท้ายมีสี่ค่า

- **☑** เดินจบแล้ว
- **◐** ครึ่งของ server เดินแล้วและผ่าน ส่วนที่เหลือคือสิ่งที่หน้าจอวาด (แถบสี ตาราง dropdown) ยังต้องมีคนดู

- **⚙** ครอบคลุมด้วย browser seam แล้ว (#65) ไม่ต้องเดินด้วยมือซ้ำ แถวบอกไฟล์ที่ครอบคลุมไว้ ถ้าแถวนั้นพูดถึงสิ่งที่วาดด้วย (เมนู ถ้อยคำ สี) ครึ่งนั้นยังเป็นงานของคนเดิน และแถวจะเขียนกำกับไว้

| 6 | Session ที่หมดอายุจริง ตอนโหลดหน้าใหม่ | เข้าระบบ → ทิ้งแท็บไว้เกิน 30 นาที → กด F5 | กล่อง *Session หมดอายุ* ขึ้น **ไม่ใช่** การถูกพากลับหน้า login เงียบ ๆ — ครอบคลุมโดย `e2e/tests/10a-shell.spec.js` (row 6) **ด้วยสองครึ่งที่ประกอบกัน** เพราะไม่มีชุดทดสอบใดนั่งรอครึ่งชั่วโมงได้: ครึ่งแรกอ่าน cookie จริงที่ server ตั้งให้ แล้ว assert ว่ามันอยู่ต่อหลัง `exp` ของ token เกินห้านาที — นั่นคือช่วงเวลาที่แท็บแบบนั้นตกอยู่ และเป็นสิ่งเดียวที่ #69 แก้ ครึ่งที่สองวาง token ที่ตายแล้วลงในช่วงนั้น แล้วโหลดหน้าใหม่ แล้ว assert ทั้งกล่องและปุ่ม *เข้าสู่ระบบใหม่* สองครึ่งรวมกันคือแท็บที่เปิดค้าง ครึ่งใดครึ่งหนึ่งไม่ใช่ — สิ่งที่ยังไม่ได้พิสูจน์คือแท็บอายุ 31 นาทีจริง ๆ | ⚙ |
| 6 | กดปุ่มในกล่องแล้วกลับเข้าใช้งานได้ | เข้าระบบ → ทิ้งจน session หมดอายุ → กด *เข้าสู่ระบบใหม่* | กล่องหายไป และหน้าที่อยู่ข้างหลังเป็นหน้าที่**ลงชื่อเข้าใช้ได้จริง** — [#92](https://github.com/khthana/Deep-QA/issues/92) คือตอนที่ปุ่มนี้เป็น `window.location.reload()` เปล่า ๆ ซึ่งกลับมาที่เดิม เพราะ cookie อายุยาวกว่า token ข้างใน — ครอบคลุมโดย `e2e/tests/10a-shell.spec.js` (row 6) ที่ assert สามชั้น: กล่องมีจำนวนเป็นศูนย์, cookie หายไปจริง และการลงชื่อเข้าใช้ครั้งใหม่สำเร็จ — สองข้อแรกผ่านได้ด้วยหน้าตาย | ⚙ |
| 6 | 401 กับ 403 ไม่ใช่เรื่องเดียวกัน | เข้าด้วย `teacher.one@` แล้วเปิด `http://localhost:3000/api/users` | ได้ 403 พร้อมข้อความ *ไม่มีสิทธิ์* — ไม่ใช่กล่อง session หมดอายุ — ครอบคลุมโดย `e2e/tests/10a-shell.spec.js` (row 6) ซึ่ง assert **ทั้งสองครึ่ง**: ข้อความ *ไม่มีสิทธิ์* ขึ้น *และ* กล่อง *Session หมดอายุ* มีจำนวนเป็นศูนย์ ครึ่งหลังคือครึ่งที่ `utils/session.js` ที่สืบทอดมาทำผิด | ⚙ |
| 7 | เปลี่ยนรหัสผ่านตัวเองได้ และใช้ได้ครั้งถัดไป | เข้าด้วย `teacher.two@` → เมนูผู้ใช้ → เปลี่ยนรหัสผ่าน → ออกจากระบบ → เข้าด้วยรหัสใหม่ | เข้าได้ด้วยรหัสใหม่, รหัสเดิมถูกปฏิเสธ (**อย่าลืม `npm run seed` ใหม่หลังทดสอบข้อนี้**) — ครอบคลุมโดย `e2e/tests/10a-shell.spec.js` (row 7) ซึ่งเปลี่ยนรหัสผ่านผ่านกล่องจริง ออกจากระบบผ่านปุ่มจริง แล้วลองรหัสเดิมได้ 401 *อีเมลหรือรหัสผ่านไม่ถูกต้อง* และยังอยู่ที่หน้า `/` จากนั้นเข้าด้วยรหัสใหม่ได้ แล้ว **เปลี่ยนกลับ** ก่อนจบเทสต์ เพราะทุก spec ในชุดนี้ใช้ schema ที่ seed ร่วมกัน | ⚙ |
| 7 | รหัสเดิมผิด | ในกล่องเดียวกัน ใส่รหัสเดิมผิด | ขึ้น *รหัสผ่านเดิมไม่ถูกต้อง* ในกล่อง ไม่ใช่การเด้งออก — ครอบคลุมโดย `e2e/tests/10a-shell.spec.js` (row 7) ซึ่ง assert ว่า server ตอบ 403 (ไม่ใช่ 401), ข้อความขึ้นในกล่อง, หัวข้อ *เปลี่ยนรหัสผ่าน* ยังอยู่ และไม่มีกล่อง session หมดอายุ | ⚙ |
| 8 | ซ่อนเมนูไม่ใช่สิ่งเดียวที่กันไว้ | ครึ่ง server อยู่ที่ `shell.test.js` แล้ว ครึ่งนี้: เข้าด้วย `teacher.one@` แล้วพิมพ์ `http://localhost:5000/main/users` ตรง ๆ | เข้าถึงข้อมูลผู้ใช้ไม่ได้ แม้จะข้ามเมนูไปแล้ว — ครอบคลุมโดย `e2e/tests/11a-users-refusals.spec.js` (row 8) ซึ่งเป็นแถวเดียวกันคำต่อคำ: `teacher.one@` พิมพ์ `/main/users` แล้ว assert ว่า server ตอบ 403 ข้อความ *ไม่มีสิทธิ์* ขึ้น และไม่มีแถวผู้ใช้ใดถูกวาด ไม่ทำซ้ำที่นี่ | ⚙ |

## สิ่งที่ยังไม่ปิดใน #10

1. **เมนูของ EXT_ASSESSOR ยังไม่มีข้อกำหนดรองรับ** — `docs/01` ROLE-6 และ R005 พูดถึงเฉพาะว่า
   บัญชีนี้มีอายุจำกัด ไม่มีเอกสารฉบับใดระบุว่าผู้ประเมินภายนอกเห็นหน้าจอใด
   `frontend/src/components/SidebarItem/ExtAssessor.js` จึงใส่ไว้หนึ่งรายการเป็นที่วางชั่วคราว
   **เกณฑ์ข้อ 2 จึงผ่านเพียงบางส่วน** ชุดเมนูจริงเป็นการตัดสินใจของเจ้าของข้อกำหนด — ตั๋ว #49
2. ~~**`/main/users` กับสิทธิ์ที่ไม่ตรงกัน**~~ — **ปิดแล้วที่ #11** `backend/routes/users.js` รับทั้ง
   FULL_ADMIN, FACULTY_ADMIN และ DEPT_ADMIN ตาม `docs/05` A11 แล้วกรองรายชื่อด้วยขอบเขตของ
   ผู้เรียกแทน ดู `docs/acceptance/11-user-accounts.md` เกณฑ์ข้อ 8
3. **การต่ออายุ token ทับการสลับบทบาท** — ถ้า request ที่ค้างอยู่จบหลังการสลับ และตอนนั้นเหลือ
   อายุน้อยกว่า 10 นาที cookie ที่ต่ออายุจะพา `acting` ตัวเก่ากลับมา เป็น race ที่แคบ
   แต่แก้ไม่ได้ด้วยเทสต์ที่ seam เดียว — ตั๋ว #51
4. **หน้าจอเข้าสู่ระบบของ #8 ถูกสร้างขึ้นใน #10** — `Login.js`, `LoginForm.js`, `LoginGoogle.js`,
   `UserNotFound.js` และ `SelectApp.js` เป็นครึ่ง UI ของ #8 แต่เกิดในตั๋วนี้ #8 ปิดไปแล้ว
   เกณฑ์ฝั่งหน้าจอของมันจึงไม่มีตั๋วใดถือไว้ — ตั๋ว #50
5. **ไม่มีการปรับ acting ให้ตรงกันข้ามแท็บ** — สลับบทบาทในแท็บหนึ่ง แท็บที่เปิดค้างอีกแท็บยังวาด
   sidebar เดิมจนกว่าจะโหลดใหม่ server ไม่ได้ผิด (มันบังคับตาม cookie ล่าสุดเสมอ) แต่คนที่หน้าจอ
   เห็นเมนูที่ไม่ตรงกับสิ่งที่กดได้
6. **URL ของระบบ portfolio ฝังไว้ในโค้ด** — `https://portfolio.deep-core.net/teacher` อยู่ใน
   `Navbar.js:146` และ `SelectApp.js:411` ควรมาจาก environment เหมือน `REACT_APP_API_URL` (ฝากไว้ที่ #50)
7. **เส้นทางต่ออายุ token ยังไม่มีเทสต์** — `RENEW_BELOW_SECONDS` ไม่มีเทสต์ใดเดินผ่าน และเกณฑ์ข้อ 4
   ส่วนใหญ่พิสูจน์กับ `guardedApp` ที่เป็น route จำลอง มากกว่ากับ `/api/users` ที่ส่งมอบจริง
8. **โค้ดที่ไปไม่ถึง** — `Mainpage.js:321` มีสาขา `alert.messages` ที่ไม่มีใครตั้งค่าให้
   และ `/user-not-found` อ่าน `?reason` ได้แต่ไม่มีที่ใดพาไปที่นั่น (ข้อหลังฝากไว้ที่ #50)
9. ~~**เกณฑ์ข้อ 6 ครึ่งที่ว่าด้วยการหมดอายุจริง ยังไปไม่ถึงจาก browser**~~ — ปิดแล้วด้วย #69
   `cookieOptions()` เคยตั้ง `maxAge` เท่ากับอายุของ token พอดี browser จึงทิ้ง cookie ในวินาทีเดียวกับที่
   token ตาย และ `reason: 'expired'` ไปไม่ถึงจาก browser เลย ทางที่เลือกคือให้ cookie อยู่นานกว่า token
   (`COOKIE_LIFETIME_SECONDS = LIFETIME_SECONDS * 2`) — ไม่ได้เพิ่มสิทธิ์ใด ๆ เพราะสิ่งที่ถูกตรวจคือ token
   ซึ่งตายแล้ว สิ่งที่ได้มาคือช่วงเวลาที่คนซึ่งลุกจากจอไปแล้วกลับมายังได้รับ *คำอธิบาย* แทนที่จะถูกนับเป็น
   คนแปลกหน้าที่ไม่เคยเข้าระบบ อีกสองทางที่ตั๋วเสนอ (cookie แยกที่บอกว่า "เคยเข้าระบบ" ซึ่งเป็นร่องรอย
   ฝั่ง client ที่โกหกได้ และการพาไปหน้า login พร้อม `?error=` ซึ่งแยก "ไม่เคยเข้า" ออกจาก "หมดอายุ" ไม่ได้
   ด้วยตัวเอง) ไม่ได้ถูกเลือก แถวที่สองของข้อ 6 ถูกเขียนใหม่ตามทางที่เลือก: ของเดิมเขียนว่า "ลบ cookie แล้ว F5"
   ซึ่งไม่มีทางไหนทำได้ตามตัวอักษร — ลบ cookie ทิ้งคือไม่เหลืออะไรให้ server อ่าน ได้ `anonymous` เสมอ
