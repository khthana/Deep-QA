## สิ่งที่ต้องเข้าใจก่อนเดิน

**สี่ id ในคำขอเดียว และเป็นของสอง grain** กิจกรรมกับสัปดาห์เป็นของ **ตอนเรียน** (#31, #32)
ส่วนหมวดคะแนนกับ CLO เป็นของ **รายวิชาที่เปิดสอน** (ADR-0003 — #30 และ #27) ทุกตัวถูกตรวจกับ
**รายการชุดเดียวกับที่ picker ใช้** ไม่ใช่กับ foreign key เพราะสามในสี่ FK ยอมรับ id ของ grain อื่น
(`activities.score_ratio_id` ไม่มี composite key ให้ผูกเลย migration 0003 เขียนไว้ตรง ๆ)
การตรวจกับรายการเดียวกับที่เสนอ ทำให้ picker กับตัวตรวจไม่มีทางเห็นไม่ตรงกัน

**การบันทึกแทนที่แถว CLO ทั้งชุด** `activity_clo_mapping` ไม่มี unique key บน (activity_id, clo_id)
— key ของมันคือลำดับ — ดังนั้น *CLO ซ้ำ* เป็นเรื่องของ service layer และไม่มีอะไรนอกตารางอ้างถึง
id ของแถว mapping การลบทิ้งแล้วเขียนใหม่ในทรานแซกชันเดียวจึงทั้งถูกและเป็นรูปที่ทำให้
**บันทึกครั้งที่สองเป็นการแก้ ไม่ใช่การสร้างซ้ำ**

**ถอด CLO ที่มีคะแนนแล้วไม่ได้ และ schema ไม่ได้ห้ามไว้** `activity_scores` ถือ
(student_id, activity_id, clo_id) โดยชี้ไปที่ `subject_clo` ไม่ใช่ที่แถว mapping การถอดแถวที่
นักศึกษาถูกให้คะแนนไปแล้วจึงทิ้งคะแนนไว้กับผลการเรียนรู้ที่กิจกรรมไม่ได้วัดอีกต่อไป — เงียบ ๆ
แบบเดียวกับ CASCADE ของ #32 route จึงต้องห้ามเอง

**สิ่งที่จงใจไม่บังคับคือผลรวม 100** BR-11 อ่านได้สองแบบในเอกสารต้นทาง (docs/01 ว่า *หนึ่ง CLO
ต่อหนึ่งแถว* · docs/02 ว่าเป็นผลรวม) และเกณฑ์ของ #33 ไม่ได้ขอทั้งสองอย่าง กติกาที่เก็บไว้จึงเป็น
ข้อที่เถียงไม่ได้: **สัดส่วนของคะแนนเต็มรวมกันเกิน 100 ไม่ได้** ส่วนน้อยกว่า 100 คือการเชื่อมโยง
ที่ยังทำไม่เสร็จ ซึ่งคนทำงานมีสิทธิ์บันทึกแล้วกลับมาทำต่อ หน้าจอจึง**แสดงผลรวมให้เห็น** แทนการห้าม

**ด่านนี้กันการ*ถอด* CLO ไม่ได้กันการ*ย้ายฐาน*** เมื่อคะแนนถูกบันทึกแล้ว การแก้คะแนนเต็มของ
กิจกรรม (20 → 5) หรือแก้น้ำหนักของแถว (60 → 10) ยังทำได้ ทั้งที่มันย้ายฐานที่คะแนนเดิมถูกให้ไว้
เงียบ ๆ แบบเดียวกัน — #33 ไม่ได้ขอด่านนี้ และการล็อกคะแนนเต็มของกิจกรรมที่มีคะแนนแล้วเป็นเรื่องของ
หน้าจอที่กรอกคะแนน (#34) จึงเปิดเป็น
[#108](https://github.com/khthana/Deep-QA/issues/108) ไว้แทนที่จะตัดสินใจแทนใน ticket นี้

**กิจกรรมที่ไม่ผูก CLO เลยเป็นสถานะที่ถูกต้อง** และเป็นสถานะที่ต้องมองเห็นจากหน้ารายการ เพราะมัน
คือกิจกรรมที่จะไม่ถูกนับในผลลัพธ์การเรียนรู้ข้อใดเลย การ์ดจึงเขียนว่า *ยังไม่ได้เชื่อมโยง*

## ตั้งต้น

```
docker start deep-core-postgres
cd db      && npm run reset && npm run migrate && npm run seed
cd backend && npm start          # http://localhost:3000
cd frontend && npm start         # http://localhost:5000
```

**ต้อง reset + seed ใหม่ก่อนเดินใบนี้ และต้อง kill แล้ว start backend ใหม่** — `node server.js`
ไม่มี reload ทุกบัญชีใน seed ใช้รหัสผ่าน `deep-core-local`

ทางเข้า: เลือกตอนเรียนจากหน้า *รายวิชา* → เมนู **กิจกรรมการเรียนรู้ในรายวิชา** → ปุ่ม **เพิ่มกิจกรรม**
(หรือปุ่มดินสอบนการ์ด) ที่อยู่คือ `/teacher/teacherDashboard/<section_id>/learningActivities`

seed ให้ตอนเรียนละหกกิจกรรม สามหมวดคะแนน CLO เก้าข้อ (CLO-1..CLO-9) และแผนการสอนสามสัปดาห์

| `section_id` | ปีการศึกษา | ผู้สอน | ใช้เดินอะไร |
|---|---|---|---|
| `1` | 2569 (ปัจจุบัน) | `teacher.one@` | เกือบทุกข้อ |
| `3` | **2568 (ปีก่อน)** | `teacher.one@` | ชุด CLO และหมวดคะแนนของปีก่อน |
