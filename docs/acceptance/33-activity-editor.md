## สิ่งที่ต้องเข้าใจก่อนเดิน

**สี่ id ในคำขอเดียว และเป็นของสอง grain** กิจกรรมกับสัปดาห์เป็นของ **ตอนเรียน** (#31, #32)
ส่วนหมวดคะแนนกับ CLO เป็นของ **รายวิชาที่เปิดสอน** (ADR-0003 — #30 และ #27) ทุกตัวถูกตรวจกับ
**รายการชุดเดียวกับที่ picker ใช้** ไม่ใช่กับ foreign key เพราะสามในสี่ FK ยอมรับ id ของ grain อื่น
(`activities.score_ratio_id` ไม่มี composite key ให้ผูกเลย migration 0003 เขียนไว้ตรง ๆ)
การตรวจกับรายการเดียวกับที่เสนอ ทำให้ picker กับตัวตรวจไม่มีทางเห็นไม่ตรงกัน

**การบันทึกแทนที่แถว CLO ทั้งชุด** `activity_clo_mapping` ไม่มี unique key บน (activity_id, clo_id)
— key ของมันคือลำดับ — ดังนั้น *CLO ซ้ำ* เป็นเรื่องของ service layer และไม่มีอะไรนอกตารางอ้างถึง
id ของแถว mapping การลบทิ้งแล้วเขียนใหม่ในทรานแซกชันเดียวจึงทั้งถูกและเป็นรูปที่ทำให้
**บันทึกครั้งที่สองเป็นการแก้ ไม่ใช่การสร้างซ้ำ**

**ถอด CLO ที่มีคะแนนแล้วไม่ได้ และ schema ไม่ได้ห้ามไว้** `activity_scores` ถือ
(student_id, activity_id, clo_id) โดยชี้ไปที่ `subject_clo` ไม่ใช่ที่แถว mapping การถอดแถวที่
นักศึกษาถูกให้คะแนนไปแล้วจึงทิ้งคะแนนไว้กับผลการเรียนรู้ที่กิจกรรมไม่ได้วัดอีกต่อไป — เงียบ ๆ
แบบเดียวกับ CASCADE ของ #32 route จึงต้องห้ามเอง

**สิ่งที่จงใจไม่บังคับคือผลรวม 100** BR-11 อ่านได้สองแบบในเอกสารต้นทาง (docs/01 ว่า *หนึ่ง CLO
ต่อหนึ่งแถว* · docs/02 ว่าเป็นผลรวม) และเกณฑ์ของ #33 ไม่ได้ขอทั้งสองอย่าง กติกาที่เก็บไว้จึงเป็น
ข้อที่เถียงไม่ได้: **สัดส่วนของคะแนนเต็มรวมกันเกิน 100 ไม่ได้** ส่วนน้อยกว่า 100 คือการเชื่อมโยง
ที่ยังทำไม่เสร็จ ซึ่งคนทำงานมีสิทธิ์บันทึกแล้วกลับมาทำต่อ หน้าจอจึง**แสดงผลรวมให้เห็น** แทนการห้าม

**ด่านนี้กันการ*ถอด* CLO ไม่ได้กันการ*ย้ายฐาน*** เมื่อคะแนนถูกบันทึกแล้ว การแก้คะแนนเต็มของ
กิจกรรม (20 → 5) หรือแก้น้ำหนักของแถว (60 → 10) ยังทำได้ ทั้งที่มันย้ายฐานที่คะแนนเดิมถูกให้ไว้
เงียบ ๆ แบบเดียวกัน — #33 ไม่ได้ขอด่านนี้ และการล็อกคะแนนเต็มของกิจกรรมที่มีคะแนนแล้วเป็นเรื่องของ
หน้าจอที่กรอกคะแนน (#34) จึงเปิดเป็น
[#108](https://github.com/khthana/Deep-QA/issues/108) ไว้แทนที่จะตัดสินใจแทนใน ticket นี้

**กิจกรรมที่ไม่ผูก CLO เลยเป็นสถานะที่ถูกต้อง** และเป็นสถานะที่ต้องมองเห็นจากหน้ารายการ เพราะมัน
คือกิจกรรมที่จะไม่ถูกนับในผลลัพธ์การเรียนรู้ข้อใดเลย การ์ดจึงเขียนว่า *ยังไม่ได้เชื่อมโยง*

## ตั้งต้น

```
docker start deep-core-postgres
cd db      && npm run reset && npm run migrate && npm run seed
cd backend && npm start          # http://localhost:3000
cd frontend && npm start         # http://localhost:5000
```

**ต้อง reset + seed ใหม่ก่อนเดินใบนี้ และต้อง kill แล้ว start backend ใหม่** — `node server.js`
ไม่มี reload ทุกบัญชีใน seed ใช้รหัสผ่าน `deep-core-local`

ทางเข้า: เลือกตอนเรียนจากหน้า *รายวิชา* → เมนู **กิจกรรมการเรียนรู้ในรายวิชา** → ปุ่ม **เพิ่มกิจกรรม**
(หรือปุ่มดินสอบนการ์ด) ที่อยู่คือ `/teacher/teacherDashboard/<section_id>/learningActivities`

seed ให้ตอนเรียนละหกกิจกรรม สามหมวดคะแนน CLO เก้าข้อ (CLO-1..CLO-9) และแผนการสอนสามสัปดาห์

| `section_id` | ปีการศึกษา | ผู้สอน | ใช้เดินอะไร |
|---|---|---|---|
| `1` | 2569 (ปัจจุบัน) | `teacher.one@` | เกือบทุกข้อ |
| `3` | **2568 (ปีก่อน)** | `teacher.one@` | ชุด CLO และหมวดคะแนนของปีก่อน |

## วัดแล้วว่าประโยคที่เติมเข้ามาไม่ได้เบียดบรรทัดเดิม — #122 (7 ก.ย. 2569)

ตั๋วนี้เติม `div` ครอบใหม่รอบผลรวมกับประโยค เพื่อให้สองสิ่งนี้เดินด้วยกัน
กฎของ #111 (การแก้ accessibility ไม่เปลี่ยนการจัดวางระหว่างทาง) จึงต้อง**วัด** บนสถานะ 110 / 100:

|---|---|---|---|---|

| 500px | 65–232 (y=40) | 65–191 | 203–**346** | หัวข้อขึ้นบรรทัดของมันเอง |

**ที่ 500px หัวข้อแยกไปอยู่บรรทัดบน แต่ผลรวมกับประโยคยังอยู่ด้วยกัน —

ทั้งสามชิ้นจะเป็น flex item อิสระของ `justify-between` และประโยคอาจหลุดจากเลขที่มันอธิบาย

**สิ่งที่เจอระหว่างวัด และไม่ใช่เรื่องของ #122** — ที่ 900px และ 500px
การขับหน้าจอนี้ตั้งแต่ต้นไม่ได้ เพราะปุ่ม *เพิ่มกิจกรรม* ไม่เคยหยุดนิ่ง

### มัตแตนต์

`mutation/127-activity-dates.py` เก้าตัว ถือ `activities.js` ไฟล์เดียว ส่วนมัตแตนต์ของช่วงปีกับการเลือกประโยค
อยู่ใน `125-validity-era.py` ซึ่งตั้งแต่ #127 ถือ `lib/year.js` ด้วย กวาดเมื่อ 19 ก.ย. 2569 ด้วยชุด backend
ทั้งชุด — baseline **748 ผ่านทั้ง 748** และทุกตัวฆ่าแถวของ #127

- `activityeraisaccepted` · `misdatedislost` · `onlyannouncement` — ฆ่า **4** (พ.ศ. · 1500 · ตอนแก้ · 29 ก.พ. ของ พ.ศ.)
- `createsentenceisakey` — ฆ่า **3** (แถวที่อ่านประโยคจาก route สร้าง) · `editsentenceisakey` — ฆ่า **1** (แถวตอนแก้)
- `yearaftercalendar` — ฆ่า **1** (29 ก.พ. ของ พ.ศ.) · `anytail` — ฆ่า **1** (`2026-09-30 junk`)
- `rollsintonextmonth` — ฆ่า **1** (แถวปฏิทิน)
- `dayistext` — ฆ่า **3** (แถวปฏิทินที่ส่ง timestamp · แถวที่รับ timestamp · แถวที่ส่งเวลาคั่นด้วยช่องว่าง) — อ่านปฏิทินจากสตริงทั้งเส้นแทนที่จะอ่านจากวัน ซึ่ง**ไม่ใช่การปฏิเสธ**: `new Date` ของ timestamp ที่ต่อ `T00:00:00Z` ท้ายเป็นวันที่ใช้ไม่ได้ `toISOString` โยน error และ route ตอบ 500 — มันพิสูจน์ว่าการตัดเอาแค่วันจำเป็น ไม่ได้แสดงว่าการปฏิเสธ timestamp หน้าตาเป็นอย่างไร

รอบของ `dayistext` มีแถวของ `weights.test.js` ล้มห้าแถวด้วย ตัวแรกตายที่ `connect EADDRINUSE` บนพอร์ตชั่วคราวของ
supertest เอง ที่เหลือล้มเพราะสิ่งที่ตัวแรกทิ้งไว้ รันมัตแตนต์เดียวกันกับไฟล์นั้นไฟล์เดียวผ่าน 25 จาก 25

การบันทึกที่ถูก *ยกเลิก* แซงโดยไม่มีฟอร์มที่สองมาแทน จึงเงียบทั้งประโยคสำเร็จและคำปฏิเสธ —
คนที่กด *บันทึก* ไม่ได้ยินอะไรเลยเกี่ยวกับการเขียนที่ตัวเองสั่ง ตั๋วฝากเรื่องนี้ไว้เองว่าเป็น

`showing` จึงไม่ได้แปลว่า *ฟอร์มไหนเปิดอยู่* อีกต่อไป แต่แปลว่า **สิ่งล่าสุดที่เปิดขึ้นบนจอนี้**

— `{data && (` แทน `{!loading && data && (` และบรรทัด *กำลังโหลดข้อมูล…* ขึ้นเฉพาะตอนที่ยังไม่มีอะไร

การแก้นั้นเปิดประตูที่ #146 นับไว้ว่าปิด: ระหว่างการโหลดมีดินสอให้กดแล้ว และทั้ง `save` กับ `remove`

แทนที่จะถือคำตอบเก่าไว้ใน `mine` และ `remove` จับ `sent` ไว้ตอนถูกกด แล้วถามคำถามเดียวกันก่อน

- **`removalsentatthelanding` คือการถอดเงื่อนไขทิ้งในผล** `sent` ที่จับข้างการเปรียบเทียบเท่ากับ ref ตัวเอง ใบมัตแตนต์เคยเขียนว่าไม่ใช่ แก้คำบรรยายแล้ว การฆ่ายังเป็นการฆ่า
- **คำตอบนี้แยกประโยคของการบันทึกออกจาก `mine`** ก่อนหน้านั้น `146:activitiesclosewins` ฆ่าทั้งการปิดและประโยคด้วยตัวเดียว ตอนนี้มันเห็นแค่การปิด ครึ่ง *ไม่มีประโยคสำเร็จ* ของแถว [#146](https://github.com/khthana/Deep-QA/issues/146) จึงได้ `activitiessavebannerunguarded` (`true ||` หน้าเงื่อนไข) — การกวาดซ้ำของ `146` เป็นที่ที่เห็นมัน *สมอที่ยังอยู่ไม่ได้แปลว่ายังพิสูจน์อะไรได้* (#107)

กวาดทีละตัว — baseline ของ `149a` **29 ผ่านทั้ง 29** (1.6 นาที) และของ `146a` **49 ผ่านทั้ง 49** (2.5–2.6 นาที) ทุกรันเวลาเท่า baseline ล้ม + ผ่าน = จำนวนแถวพอดี อ่านจากชื่อ describe *กิจกรรมการเรียนรู้ (LearningActivities.js)*:

- `149:activitiesremovalbannerunsaid` กับ `149a` **ล้ม 1 ผ่าน 28** ที่ *the banner of the removal* ของแถวใหม่ แถวเดียว
- `149:activitiessavebannerunguarded` กับ `149a` **ล้ม 1 ผ่าน 28** ที่ *the banner of the save before* และกับ `146a` **ล้ม 1 ผ่าน 48** ที่ *the first save's banner* ของแถวที่ `closewins` ฆ่าที่ฟอร์ม
- `146:activitiesclosewins` **ล้ม 1 ผ่าน 48** ที่ assertion ของฟอร์ม
- `146:activitiescancelclears` **ล้ม 1 ผ่าน 48** — เหมือน 20 ก.ย.

หกตัวของจอนี้ใน `149` ตอนนี้ และ baseline ของ `149a` คือ 29 ไม่ใช่ 22 ที่ตัวเลขข้างบนอ่าน

## การโหลดใหม่ที่ล้มเหลวเก็บสิ่งที่วาดไว้ — #151 (22 ก.ย. 2569)

ตั้งแต่ #149 จอเก็บรายการและฟอร์มไว้ระหว่างการโหลดใหม่ แต่การโหลดที่**ล้มเหลว**ยังล้างทั้งคู่: `catch` ของ `load` ตั้ง `data` เป็น `null` ฟอร์มจึงถูกถอดพร้อมสิ่งที่พิมพ์ไว้ คำตอบ (22 ก.ย. 2569) คือคำตอบของ #149 ต่อไปอีกขั้น — **การโหลดที่ล้มเหลวเก็บสิ่งที่จอวาดไว้ล่าสุด** และคำปฏิเสธขึ้นเหนือมัน การโหลดครั้งแรกที่ล้มไม่มีอะไรให้เก็บ `loading && !data` วาดเหมือนเดิม ซึ่งตั๋วนี้ไม่เปลี่ยน

ทุกแถว **เดินด้วยมือไม่ได้** การเขียนถูกตอบด้วย 200 ที่แต่งขึ้น และการโหลดที่ตามมาด้วย 409 ที่แต่งขึ้น (`e2e/support/gate.js`) จึงไม่มีแถวไหนเขียนฐานข้อมูลผ่านการบันทึก เข้าด้วย `teacher.one@kmitl.ac.th` ครอบคลุมโดย describe *กิจกรรมการเรียนรู้ (LearningActivities.js)* ใน `151a-failed-reload-keeps-the-list.spec.js` จุดอ่านคือหลังคำปฏิเสธถึงหน้า แล้ว 250 ms อ่านครั้งเดียว (#52) สิ่งที่ค้ำมันคือการกวาดข้างล่าง

### มัตแตนต์

`151:activitiesblanks` ใส่ `setData(null)` กลับเข้า `catch` ของจอนี้ — โค้ดก่อน #151 — และ `151:activitiesblinks` ล้าง `data` แล้วคืนมันในจังหวะถัดไป ฟอร์มจึงถูกถอดแล้ววาดใหม่ เปิดอยู่แต่สิ่งที่พิมพ์หายไป `blinks` เพิ่มหลังการตรวจ: `blanks` ฆ่าแถวฟอร์มที่ *the second card's form* ซึ่งอ่านก่อน *what was typed* ครึ่งหลังนั้นจึงไม่มีมัตแตนต์ไปถึง กวาดทั้งสิบสี่ตัวของใบ `151` เมื่อ 22 ก.ย. 2569 ด้วย `151a` ทั้งไฟล์บนข้อความสุดท้ายของมัน — baseline **14 ผ่านทั้ง 14** (0.8 นาที) `activitiesblanks` **ล้ม 2 ผ่าน 12** (0.9 นาที) ที่ *the second card's form* และที่ *the cards drawn before the reload* `activitiesblinks` **ล้ม 1 ผ่าน 13** (0.9 นาที) ที่ *what was typed* แถวเดียว ไม่ใช่ที่ timeout และไม่มีแถวของจออื่นตาย อ่านจากชื่อ describe ไม่ใช่จากจำนวน

### สิ่งที่วัดได้แต่ไม่ใช่ของตั๋วนี้

ตั๋วเขียนว่า *แบนเนอร์คำปฏิเสธบอกว่าการโหลดล้มเหลว* วัดแล้วจริงแค่เมื่อมีฟอร์มอื่นเปิดทีหลัง: ถ้าไม่มีอะไรเปิด `save` ตั้งประโยคสำเร็จ*หลัง*การโหลด ประโยคนั้นจึงทับคำปฏิเสธ (วัดด้วย probe ที่ลบทิ้งแล้ว: บนจอ ผลการเรียนรู้รายวิชา คำปฏิเสธ 0 ประโยคสำเร็จ 1 และบนแถวรายการของ `151a` ทั้งเจ็ดจอ คำปฏิเสธ 0 ทุกจอ) — ตอนนี้คือ *บันทึก…แล้ว* เหนือรายการ ที่ยังไม่มีสิ่งที่บันทึก ซึ่งเป็นคำถามของเจ้าของ ไม่ได้แก้ในตั๋วนี้
