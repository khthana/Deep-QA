## สิ่งที่ต้องเข้าใจก่อนเดิน

**ตั๋วนี้ไม่มี route เป็นของตัวเอง และนั่นคือสาระของมัน** เกณฑ์ข้อ 5 ขอให้คะแนนใช้มาตราส่วนห้าคะแนน
ชุดเดียวกับผลลัพธ์รายวิชา วิธีที่ถูกที่สุดคือเขียนเทสต์มายืนยัน วิธีที่ซื่อสัตย์คือทำให้มันผิดไม่ได้ —
และการอ่าน `GET /teaching/sections/:id/learning-details` ของ #38 คือวิธีหลัง

grain ที่ #37 ต้องการ — นักศึกษาทุกคนของตอนเรียนนี้ ต่อผลการเรียนรู้ทุกข้อของมัน บวกค่าเฉลี่ยของ
ตอนเรียนรายข้อ — คือสิ่งที่ heatmap ของ #38 คำนวณอยู่แล้ว หลังด่านเดียวกันเป๊ะ และ
`backend/lib/attainment.js` เขียนกฎไว้ตรง ๆ ว่า *query อยู่ใน route เพราะสิ่งที่ต่างกันระหว่างหน้าจอ
คือคะแนนชุดไหนที่นับ* — ตรงนี้มันไม่ต่างกันเลยแม้แต่นิดเดียว route ของตัวเองจึงจะเป็นสำเนาที่สองของ
query ที่มีอนาคตเดียวคือขัดแย้งกับสำเนาแรก **ผู้ใช้เป็นคนเลือกข้อนี้เมื่อ 3 กันยายน 2569 ก่อนเขียนโค้ด**

ราคาที่จ่ายคือการผูกกัน และควรพูดออกมาให้ชัด: ถ้ารูปคำตอบของ #38 ขยับ หน้าจอนี้ขยับตาม
นั่นคือราคาปกติของการมีคำตอบเดียวแทนที่จะมีสอง และแถวใน `37a` จะพังเสียงดังถ้าวันหนึ่งจ่ายมันแบบไม่ระวัง

**ผลพลอยได้ที่ไม่ใช่ของแถม: ทะเบียนมาพร้อมกราฟ** endpoint รายชื่อชั้นเรียนแบ่งหน้าละสิบ ตอนเรียนห้าสิบเจ็ดคน
หลังตัวเลือกที่แบ่งหน้าคือคนกด *ถัดไป* ห้าครั้งเพื่อหานักศึกษาหนึ่งคน การอ่านคำตอบของ heatmap แทน
แปลว่าทะเบียนทั้งห้องอยู่บนหน้าจอแล้ว ช่องค้นหาจึงกรองสิ่งที่อยู่ในหน่วยความจำ การติ๊กชื่อไม่ยิง request เลย
และกราฟวาดใหม่ในเฟรมเดียวกับที่ติ๊ก

**สี่คนบนกราฟเดียว และค่าเฉลี่ยไม่กินสีของใคร** จานสีของ `RadarChart` มีสี่ชุดที่แยกออกจากกันได้
(สี + ลายเส้น) ถ้าค่าเฉลี่ยกินไปหนึ่งชุด การ *ดูการกระจาย* จะจบที่สามคน ค่าเฉลี่ยจึงได้เส้นของตัวเอง —
เทา ประถี่ มีพื้นอ่อน อยู่นอกจานสี — เพราะมันเป็นพื้นหลังที่คนอื่นถูกอ่านเทียบกับมัน ไม่ใช่คู่แข่งของใคร
**ผู้ใช้เป็นคนเลือกข้อนี้เมื่อ 3 กันยายน 2569 ก่อนเขียนโค้ดเช่นกัน** และเส้นของนักศึกษาถูกถอดพื้นออก
เพราะรูปหลายเหลี่ยมสี่รูปที่ถมทับกันคือโคลน — ค่าเฉลี่ยเป็นเส้นเดียวบนกราฟนี้ที่มีพื้น

**เพดานสิบแกนเป็นของกราฟ ไม่ใช่ของข้อมูล** ป้ายแกนวางบนวงรัศมี 154 แล้วยื่นออกนอก พอเกินสิบข้อ
ป้ายจะเริ่มชนกันที่หัวและท้ายวง ซึ่งเป็นที่ที่มุมระหว่างสองแกนแคบที่สุด ผลการเรียนรู้ทุกข้อยังมีแถวของมัน
ในตารางข้างล่างครบถ้วน เพราะตารางคือที่ที่ตัวเลขถูกอ่านจริงมาตั้งแต่ต้น

## บันทึกการเดินด้วยมือ

**เดินจบเมื่อ 4 กันยายน 2569** ผู้ใช้เป็นคนเข้าระบบเอง ผมขับเบราว์เซอร์ผ่านส่วนขยาย Chrome
เซิร์ฟเวอร์เดินที่ 3000/5000 schema `deep_core` — **การเดินนี้อ่านอย่างเดียว ไม่ได้เขียนอะไรลงฐานข้อมูล**
จึงไม่ต้องนับแถวก่อนหลัง สิ่งที่เปลี่ยนคือโค้ด ไม่ใช่ข้อมูล

### การเดินเปลี่ยนหน้าจอไปสองอย่าง

ทั้งสองอย่างเป็นเรื่องถ้อยคำและรูปลักษณ์ ซึ่งเป็นสิ่งที่ไม่มี seam ไหนพิสูจน์แทนได้ และเป็นเหตุผลที่
สี่แถวนี้ถูกเขียนเป็นแถวที่ต้องใช้ตาตั้งแต่แรกแทนที่จะปล่อยให้ชุดทดสอบตัดสิน

**ประโยคตอนยังไม่ได้เลือกใคร ถูกเขียนใหม่ทั้งประโยค** ของเดิม *ยังไม่ได้เลือกนักศึกษา —
กราฟกำลังแสดงเฉพาะค่าเฉลี่ยของทั้งตอนเรียน* รายงานความบกพร่องมากกว่าจะชี้ขั้นต่อไป และซ้ำกับ
ประโยคเหนือกราฟที่บอกวิธีทำอยู่แล้ว ผู้ใช้สั่งให้เป็นคำชวนที่บอกว่าเลือกจากไหนและเลือกได้กี่คน

**และคำว่า *ทางซ้าย* ถูกตัดออกในนาทีสุดท้าย** ผู้ใช้เลือกถ้อยคำที่มีคำนั้นอยู่ แต่แถวจอแคบเพิ่งเดิน
ไปก่อนหน้าและวัดไว้เองว่า ต่ำกว่า `lg` ผังยุบเหลือคอลัมน์เดียวและตัวเลือกเลื่อนไปอยู่**เหนือ**กราฟ
คำว่าซ้ายจะชี้ไปที่ที่ไม่มีอะไรอยู่ประมาณครึ่งหนึ่งของเวลา — บอกผู้ใช้แล้วผู้ใช้สั่งให้ตัด
**นี่คือลำดับการเดินที่ทำให้จับได้** ถ้าเดินแถวถ้อยคำก่อนแถวจอแคบ ประโยคนั้นคงผ่านไปแล้ว

### สองอย่างที่การเดินเจอแล้วไม่ได้แก้ในตั๋วนี้

**[#113](https://github.com/khthana/Deep-QA/issues/113) — ห้าช่วงคะแนนอ่อนเกินไปทุกช่วง**
ผู้ใช้ทักว่า *สีมันออกไปทางอ่อนไปหน่อย* ตอนตอบแถวสีในตาราง วัดจากหน้าจอจริงได้ว่าพื้นของทุกช่วง
ต่างจากสีขาวแค่ 1.03–1.22 เท่า ขณะที่ตัวอักษรบนพื้นมี contrast 6.6–8.6 คือเหลือที่ให้เข้มขึ้นอีกมาก
ไม่แก้ที่นี่เพราะพาเลตอยู่ใน `lib/bands.js` ใช้ร่วมสี่หน้าจอ และ `38a` กับใบตรวจรับของ #38 และ #42
เขียน token ไว้เป็นหลักฐานของแถวที่เดินไปแล้ว การเปลี่ยนสีจึงบังคับให้ต้อง**เดินซ้ำ** ไม่ใช่แก้แต่ตัวหนังสือ

**[#114](https://github.com/khthana/Deep-QA/issues/114) — คำอธิบายสัญลักษณ์ตัดเป็นสามบรรทัด**
ที่จอกว้างพร้อมเมนูซ้ายเปิด ซึ่งเป็นสถานะตั้งต้น คำอธิบายเหลือที่ราว 200px ทั้งชื่อและคำกำกับลายเส้น
จึงถูกหั่นเป็นสามบรรทัด ห้าบรรทัดกลายเป็นสิบห้า พอยุบเมนูซ้ายกลับเป็นบรรทัดเดียวทันที
อ่านออก ไม่ล้น หน้าไม่เลื่อน — เป็นความรุงรังล้วน ๆ ผู้ใช้ตัดสินว่าเปิดตั๋วไว้ก่อน
**ปิดแล้ว 17 ต.ค. 2569 — ดู §#114 ข้างล่าง** และสิ่งที่การวัดเจอไม่ใช่สิ่งที่ตั๋วเขียนไว้

### สิ่งที่ seed แถมมาให้เอง

นักศึกษาสองคนที่เลือกมาเทียบกันชื่อ **กมลชนก** เหมือนกันทั้งคู่ — 66010031 ทองคำ กับ
66010067 สุวรรณชาติ ซึ่งเป็นเหตุผลที่ป้ายทุกที่บนหน้าจอนี้ขึ้นรหัสก่อนชื่อ ถ้าขึ้นชื่ออย่างเดียว
คำอธิบายสัญลักษณ์จะมีสองบรรทัดที่อ่านเหมือนกันโดยไม่มีอะไรบอกว่าเป็นคนละคน

และคะแนนของ seed เกาะกลุ่มกันมาก — ค่าเฉลี่ยรายคนอยู่ระหว่าง 3.54 ถึง 4.29 เท่านั้น
เส้นทั้งสี่จึงทับกันเกือบตลอดวง โดยเฉพาะช่วง CLO-2 ถึง CLO-3 **ซึ่งเป็นสถานการณ์ที่ทำให้ลายเส้น
มีความหมายจริง ๆ ไม่ใช่ของประดับ** เป็นเหตุผลเดียวกับที่ #36 เจอตอนเดิน คือ 2568 กับ 2569
คะแนนใกล้กันจนถ้ามีแต่สีจะอ่านเป็นเส้นเดียว

### กับดักที่เจอซ้ำระหว่างเดิน

**เซิร์ฟเวอร์เดินจอตายไปทั้งคู่ก่อนเริ่ม** `curl --max-time` เป็นสิ่งแรกที่ทำ และทั้ง 3000 และ 5000
ไม่ตอบ ไม่มีอะไร listen อยู่เลย สตาร์ทใหม่ทั้งคู่แล้วรอจนตอบ 200 จริงจึงเริ่ม — ถ้าไม่ curl ก่อน
รอบนี้จะเสียเวลาไปกับการโทษส่วนขยายเหมือนรอบ #36

**`document.hidden` เป็น true ทุกครั้งที่ผู้ใช้หันมาพิมพ์ตอบ** ซึ่งทำให้ถ่ายภาพไม่ได้เลย —
`Page.captureScreenshot` timeout เพราะ renderer ถูก throttle ส่วน `javascript_tool` ยังทำงานปกติ
**การวัดจึงทำผ่าน JS ได้ทั้งหมด แต่การให้ผู้ใช้ *ดู* ต้องให้เขาหันไปดูหน้าจอเอง** ซึ่งเร็วกว่าถ่ายภาพส่งด้วย

## #114 — คำอธิบายสัญลักษณ์ของกราฟเรดาร์อยู่ใต้กราฟ (17 ตุลาคม 2569)

ตั๋วถูกเปิดไว้ระหว่างการเดินด้วยมือของใบนี้เมื่อ 4 ก.ย. 2569 และรออยู่หกสัปดาห์ ข้ออาการยัง

### หนึ่ง — ทางที่สามของตั๋วเป็น no-op ที่ความกว้างของเกณฑ์เอง

ตั๋วเสนอสามทางและเขียนกำกับทางที่สาม (`xl` แทน `lg`) ว่า *เปลี่ยนผังที่คนเห็นบ่อยที่สุด
จึงเป็นทางที่ควรดูด้วยตาก่อน* — CSS ที่เสิร์ฟจริงมี `xl` = 1280px และเกณฑ์ข้อแรกอยู่ที่
`innerWidth` 1396 ซึ่งเกินไปแล้ว ทางนั้นจึงไม่เปลี่ยนอะไรเลยที่ความกว้างที่ตั๋วเองใช้ตัดสิน
**ทางที่ตั๋วบอกว่าควรดูก่อน เป็นทางที่แก้ไม่ได้** นี่คือ *as today* ของ #152 อีกชั้นหนึ่ง —
ไม่ใช่ข้ออ้างเรื่องวันนี้ แต่เป็นข้ออ้างเรื่องทางเลือกที่เสนอ และวัดด้วยเกณฑ์ของตั๋วเอง

### สอง — สาเหตุที่ตั๋วเขียนไว้ไม่ใช่สาเหตุ

ตั๋วว่า *กราฟจองไปก่อน 448px คำอธิบายได้เศษที่เหลือ* วัดเมื่อ 17 ต.ค. 2569 แล้วกราฟ
**ไม่เคยได้ 448 เลยตอนเมนูซ้ายเปิด** เพราะการ์ดของกราฟเป็นครึ่งที่แคบของกริด
`lg:grid-cols-[20rem_minmax(0,1fr)]` ซึ่งมีคอลัมน์รายชื่อ 320px กินไปอีกชั้นหนึ่ง กราฟกับ
คำอธิบายจึงแบ่งกันแค่ 578px และ `<ul>` ตกไปอยู่ที่ min-content **188px ตายตัว** —
ตายตัวจริง ๆ คือกว้างเท่ากันที่ 1024 และที่ 1396

### สาม — อาการที่หนักกว่าที่ตั๋วบรรยาย และตั๋วไม่ได้พูดถึง

เพราะกราฟเป็นฝั่งที่หดได้ (`w-full max-w-md`) ส่วนคำอธิบายหดต่อไม่ได้แล้ว สิ่งที่ถูกบีบจึงเป็น
