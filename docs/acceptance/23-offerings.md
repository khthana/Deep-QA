## หน้าจอนี้ต่างจากทุกหน้าก่อนหน้าอย่างไร

สามอย่าง และทั้งสามอย่างเปลี่ยนสิ่งที่ต้องเดิน

**บทบาทเดียว** `PROG_MANAGER` เท่านั้น ไม่มี `DEPT_ADMIN` และ **ไม่มี `FACULTY_ADMIN`** ซึ่งเป็นตัวที่
คนอ่านจะสงสัยมากที่สุด เพราะทุกหน้าตั้งแต่ #14 ถึง #17 ให้คณะเข้าได้ และ #18 หยุดที่ภาควิชา
หน้านี้หยุดต่ำลงไปอีกหนึ่งชั้น นี่คือเกณฑ์ข้อ 9 และเป็นข้อที่ควรเดินด้วยตาตัวเองอย่างน้อยหนึ่งบัญชี

**ไม่มีการปิดการใช้งาน** ตั้งแต่ #15 ถึง #18 การลบที่มีของอ้างอิงจะกลายเป็นการปิดใช้งาน ตอบ 200 พร้อม
`deactivated: true` ที่นี่ไม่มี — ทั้ง `semester_courses` และ `course_sections` ไม่มีคอลัมน์ `is_active`
เลย และตั้งใจให้เป็นแบบนั้น การเปิดสอนคือบันทึกของภาคการศึกษาที่เกิดขึ้นจริง ภาคที่มีนักศึกษาลงทะเบียน
แล้วจะทำให้ไม่เคยเกิดขึ้นไม่ได้ ดังนั้นเกณฑ์ข้อ 8 คือ **การปฏิเสธ** ตอบ 409 และแถวยังอยู่เหมือนเดิม
ทุกประการ ถ้าเดินแล้วเห็นข้อความว่า *ปิดการใช้งานแทนการลบ* แปลว่ามีอะไรผิด

**สองระดับในหน้าเดียว** หน้ารายการคือภาคการศึกษาที่กำลังวางแผน กด *ตอนเรียนและผู้สอน* แล้วจะเข้าไปที่
ตอนเรียนของการเปิดสอนนั้น ไม่มีการเปลี่ยน URL — เป็นหน้าเดียวสองมุมมอง ด้วยเหตุผลเดียวกับฟอร์มแก้ไข
ของ #18 คือมุมมองที่สองไปถึงได้จากแถวข้างบนมันเท่านั้น

## ตั้งต้น

```
docker start deep-core-postgres
cd db      && npm run reset && npm run migrate && npm run seed
cd backend && npm start          # http://localhost:3000
cd frontend && npm start         # http://localhost:5000
```

ทุกบัญชีใน seed ใช้รหัสผ่านเดียวกัน คือ `deep-core-local` — ค่าของตัวแปร `PASSWORD` ใน `db/seed.js` ไม่ใช่คำว่า `PASSWORD`
เมนูที่ใช้ตลอดเอกสารนี้คือ *หลักสูตร → การเปิดรายวิชาในภาคการศึกษา* (`/main/course-in-term`)

**ต้อง restart backend ก่อนเดิน** — process ที่ค้างจากตั๋วก่อนจะตอบ 404 ให้ทุก route ของ #23

seed มีการเปิดสอนอยู่แล้วสองรายการ ทั้งคู่เป็นวิชา `01076105` ของหลักสูตร `0501`

| ปีการศึกษา | ภาค | ตอนเรียน | ผู้สอน | นักศึกษา |
|---|---|---|---|---|
| 2568 | 2 | `1`, `2` | `teacher.one@`, `multi.role@` | 113 คน พร้อมคะแนน |
| 2567 | 2 | `1` | `teacher.one@` | 60 คน พร้อมคะแนน |

**ทั้งสองรายการมีของอ้างอิงอยู่แล้ว** จึงเป็นแถวที่ใช้เดินเกณฑ์ข้อ 8 ครึ่งที่ *ถูกป้องกัน*
ส่วนครึ่งที่ *ลบได้จริง* ต้องเปิดรายวิชาใหม่เองในข้อ 1 ก่อน — อย่าพยายามลบของ seed แล้วคาดว่าจะสำเร็จ

**หลักสูตร `0501` มีรายวิชาเดียวใน seed** ถ้าอยากเดินข้อ 7 (คัดลอก) ให้เห็นผลมากกว่าหนึ่งวิชา
ให้ไปเพิ่มรายวิชาเข้าหลักสูตรที่หน้า *รายวิชาในหลักสูตร* ก่อนด้วยบัญชี `prog.manager@` เอง

หลายข้อข้างล่างเขียนข้อมูลจริงลงฐานข้อมูล — **`npm run reset && npm run migrate && npm run seed`
ใหม่หลังเดินจบ** ก่อนเริ่มตั๋วถัดไป (`npm run seed` เฉย ๆ เป็น upsert จึงไม่ลบสิ่งที่เดินไว้ออก)

## รายการที่ต้องเดิน

ช่องสุดท้ายมีสี่ค่า

- **☑** เดินจบแล้ว
- **◐** ครึ่งของ server เดินแล้วและผ่าน ส่วนที่เหลือคือสิ่งที่หน้าจอวาด (แถบสี ตาราง dropdown) ยังต้องมีคนดู
- **☐** ยังไม่ได้เดิน
- **⚙** ครอบคลุมด้วย browser seam แล้ว (#65) ไม่ต้องเดินด้วยมือซ้ำ แถวบอกไฟล์ที่ครอบคลุมไว้ ถ้าแถวนั้นพูดถึงสิ่งที่วาดด้วย (เมนู ถ้อยคำ สี) ครึ่งนั้นยังเป็นงานของคนเดิน และแถวจะเขียนกำกับไว้

## มัตแตนต์ที่พิสูจน์แถว ⚙

`mutation/23-offerings.py` สิบเจ็ดตัว อ่านวิธีใช้ที่ `mutation/README.md` ก่อน

ทุกแถวที่ติด ⚙ มีมัตแตนต์ของตัวเอง และมัตแตนต์นั้นต้องตายที่ assertion ของแถวนั้นจริง ๆ ไม่ใช่แค่ที่ spec ไฟล์เดียวกันตาย — รอบแรกของตั๋วนี้มีแถว ⚙ สิบเอ็ดแถว ในนั้นมีมัตแตนต์ของตัวเองอยู่สองแถว — แถวเกณฑ์ข้อสี่ครึ่งหลัง (`additive`) และแถวเกณฑ์ข้อเก้าที่ปฏิเสธทุกบทบาท ซึ่ง `wideopen` ครอบไว้เพียงสองบัญชีจากสี่บัญชีที่แถวนั้นระบุชื่อ — อีกเก้าแถวไม่มีเลย ซึ่งเท่ากับการติด ⚙ จากการที่เทสต์ผ่าน ไม่ใช่จากการที่เทสต์แยกแยะอะไรได้ เก้าตัวที่เพิ่มมาทีหลังจึงเกิดขึ้นจากการรีวิวรอบนั้น และ `wideopen` ถูกขยายให้ครอบทั้งสี่บัญชีที่แถวนั้นระบุชื่อไว้ รวมเป็นสิบเจ็ดตัว

เดินจริงเมื่อ 22 สิงหาคม 2569 บน `backend/test/offerings.test.js` (21 subtests) และบน
`npx playwright test 23` (12 tests) ตัวเลขข้างล่างนี้คือสิ่งที่มัตแตนต์ฆ่าได้จริง ไม่ใช่สิ่งที่
ควรจะฆ่าได้

### `sectionglobal` — เลขตอนเรียนที่ไม่ซ้ำกันทั้งระบบ

ตายทั้งหมด 12 จาก 21 subtests ตัวที่แถวที่ 3 อ้างถึง คือ *a section number repeats
across subjects and is refused within one Offering* ตายด้วย `409 !== 201` — คือการ
เพิ่มตอนเรียน `1` ให้รายวิชาที่สองถูกปฏิเสธ ซึ่งเป็นเหตุผลที่ถูกต้อง ตรงกับครึ่งที่มัตแตนต์นี้เล็งไว้

ต้องพูดตรง ๆ ว่านี่เป็นมัตแตนต์ที่ทื่อกว่าที่ตั้งใจ อีกสิบเอ็ดตัวที่ตายไปด้วยตายเพราะ `freshOffering`
สร้างตอนเรียน `1` เหมือนกัน และกฎเดิมชนกับตอนเรียนที่ seed มีอยู่แล้ว จึงพลอยล้มไปด้วย
สิ่งที่ทำให้มันยังเป็นหลักฐานที่ใช้ได้คือ **มันไม่ใช่การพังทั้งไฟล์** — 9 subtests ยังผ่าน seed ยัง
โหลดขึ้น และทุกตัวที่ตายตายที่ assertion ไม่ใช่ตายใน `before()` ถ้าเป็นอย่างหลัง มันจะไม่ได้
บอกอะไรเลยว่า assertion ไหนเป็นตัวแยกแยะ

และนั่นคือเหตุผลที่มัตแตนต์ตัวนี้ **ไม่ได้กลายพันธุ์ที่ migration** ทั้งที่เกณฑ์ข้อสามเป็นข้อเท็จจริง
เรื่อง constraint การไปแคบ `UNIQUE (semester_course_id, section_number)` ให้เหลือ
`(section_number)` เป็นสิ่งที่นึกออกก่อน แต่ seed เองเปิดตอนเรียน `1` ไว้ทั้งใต้ปี 2568 และ
2567 ข้อจำกัดแบบนั้นจึงล้มตั้งแต่ตอน seed และทุก subtest ในไฟล์จะ error พร้อมกันใน
`before()` มัตแตนต์ตัวนี้จึงจำลองกฎเดิมที่ route แทน — pre-check เลขตอนเรียนทั้งระบบก่อน
`INSERT`

### `wideopen` — รับบทบาทอื่นทั้งสี่เข้ามาด้วย

ฝั่ง backend ตาย 2 subtests: *every other role is refused at the server, Faculty Admin
included* ตายด้วย `200 !== 403` และ *a copy is refused when either end is not a term,
or both are the same* ตายด้วย `200 !== 403` เช่นกัน (แถวหลังตรวจบทบาทซ้ำอีกชั้นที่เส้นทาง
คัดลอก)

ฝั่งเบราว์เซอร์ตายทั้งสี่แถวของ `23b` — `ผู้ดูแลระบบ`, `ผู้ดูแลระดับคณะ`,
`ผู้ดูแลระดับภาควิชา` และ `อาจารย์ผู้สอน` ทุกบัญชีเข้าหน้าได้ และทุกบัญชีตายด้วย
`Expected: 403 / Received: 200` ที่ตัว response ตรง ๆ

ตอนแรกมัตแตนต์นี้เติมเข้ามาแค่สองบทบาท และจึงพิสูจน์ได้แค่สองแถวจากสี่ ส่วนอีกสองแถวยัง
เขียวอยู่ ที่เขียวโดยไม่มีอะไรมาท้าทายไม่ใช่หลักฐาน เพราะการที่มัตแตนต์เลือกไม่แตะสองบทบาทนั้น
เป็นการเลือกของคนเขียนมัตแตนต์ ไม่ใช่คำตอบของระบบ ตอนนี้จึงเติม `FULL_ADMIN` กับ `TEACHER`
เข้าไปด้วย เพื่อให้มันพูดแทนแถวทั้งแถวที่บอกว่า *ทุกบทบาทอื่นถูกปฏิเสธ* ความคมที่อยากได้
จากมัตแตนต์เดิม — ที่ว่าแถวที่เขียนอย่างหลวม ๆ ว่า "บทบาทอื่นเข้าไม่ได้" จะรอด — ยังเป็นจริงที่
`23b` เดินทั้งสี่บัญชีแยกแถวกัน จึงรู้ว่าทั้งสี่ตายจริง ไม่ใช่สองตายหนึ่งรอด

### `nocheckteacher` — `teacherRefusal` ตอบ `null` ทุกกรณี

ตาย 1 subtest คือ *a teacher who is not a registered user cannot be assigned* ซึ่งเป็น
ตัวที่ตั๋วระบุชื่อไว้ว่าต้องมีเทสต์ subtest เดียวนี้ถือ assertion ทั้งสองครึ่ง: รหัสที่ไม่มีอยู่จริง ซึ่งภายใต้
มัตแตนต์จะทะลุไปตายที่ foreign key แล้วกลับมาเป็น error ที่ไม่ได้ตั้งใจแทนที่จะเป็นประโยคของ
เกณฑ์ข้อห้า และบัญชีที่มีจริงแต่ถูกระงับ ซึ่งภายใต้มัตแตนต์จะถูก **รับเข้าเงียบ ๆ** — ครึ่งหลังนี่
เงียบกว่ามาก เพราะไม่มีอะไรพัง มีแต่ผู้สอนที่ระบบระงับไปแล้วโผล่มาอยู่หน้าตอนเรียน

### `nocheckplacement` — ไม่ถามว่ารายวิชาอยู่ในหลักสูตรหรือยัง

ตาย 2 subtests คือ *a subject that is not in the programme cannot be opened* ซึ่งคือ
เกณฑ์ข้อหกทั้งข้อ และ *a subject closed in the catalogue cannot be opened, however the

ตัวเดียวกัน มัตแตนต์ที่ตัดคำถามแรกออกจึงพาคำตอบที่สองไปด้วย

### `nosyllabus` — เอาการตรวจแผนการสอนรายสัปดาห์ออก

ตาย 1 subtest คือ *a weekly plan protects the section it belongs to, and the Offering

รายละเอียดอยู่ในหัวข้อ *แผนการสอนรายสัปดาห์กับ CASCADE ตัวเดียวในหกตัว* ข้างล่าง

### `nocatalogue` — เอาชั้นคลังรายวิชาออกจาก `placementRefusal`

### `additive` — การกำหนดผู้สอนกลายเป็นการเพิ่ม ไม่ใช่การแทนที่

ฝั่ง backend ตาย 1 subtest คือ *teachers are assigned to a section and reassigned

ข้อควรรู้ตอนอ่านผล: `23a` เป็น `mode: 'serial'` แถวที่เหลือหลังแถวที่ตายจึงขึ้นว่า *did not run*
ไม่ใช่ว่าผ่าน การนับ "ตายกี่แถว" ที่ seam เบราว์เซอร์จึงต้องอ่านคู่กับจำนวนที่ไม่ได้รัน

### มัตแตนต์อีกเก้าตัวที่เป็นของแถวเบราว์เซอร์ล้วน ๆ

เก้าตัวนี้เกิดขึ้นเพราะการตรวจซ้ำหลัง `/code-review` พบว่าแถว ⚙ สิบเอ็ดแถวมีมัตแตนต์ของตัวเอง
อยู่เพียงสองแถว ที่เหลืออาศัยว่า spec ไฟล์นั้นมีมัตแตนต์ตัวหนึ่งตายอยู่แล้ว ซึ่งไม่ใช่หลักฐานของแถว
นั้น ทุกตัวเดินด้วย `npx playwright test 23a` หรือ `23b` ตัวเดียว เมื่อ 22 สิงหาคม 2569

`nolanding` — หน้าไม่พาไปที่ตอนเรียนหลังเปิดรายวิชา ค้างอยู่ที่หน้ารายการ ตายที่ `23a`
แถว 1 ที่ `waitForDetail` ใน `openSubject` — `Test timeout of 60000ms exceeded` ที่
`support/offerings-screen.js:40` เพราะการอ่าน `GET /api/offerings/:id` ที่การพาไปนั้น
ทำให้เกิด ไม่เคยเกิด นี่คือ assertion ของแถวนี้เอง ไม่ใช่ของแถวก่อนหน้า: ครึ่งแรกของเกณฑ์ข้อ
หนึ่งคือ *หน้าจอพาไปที่หน้าตอนเรียนทันที* และการรออ่านรายละเอียดคือที่ที่แถวนี้สังเกตมัน
การเปิดสอนยังเกิดขึ้นจริงทุกอย่างและ backend ไม่รู้สึกอะไร สิ่งที่หายไปมีอยู่บนหน้าจอที่เดียว

`dupupsert` — การเพิ่มตอนเรียนกลายเป็น upsert เลขที่ซ้ำจึงตอบ 201 แทน 409 ตายที่ `23a`
แถว 2 ตรง assertion ข้อความปฏิเสธ — จำนวนการ์ดยังเท่าเดิม มัตแตนต์ตัวนี้จึงรอดจากเทสต์ที่
นับการ์ดอย่างเดียว

`noassign` — การกำหนดผู้สอนลบของเก่าออกแล้วไม่เขียนของใหม่ลง ตายที่ `23a` แถว 4 ครึ่งแรก
คู่กับ `additive` ที่ตายที่ครึ่งหลัง สองตัวรวมกันจึงครอบเกณฑ์ข้อสี่ทั้งข้อ: กำหนดได้ และกำหนดใหม่
แล้วแทนที่ของเดิม

`noconfirm` — ปุ่มลบตอนเรียนลบทันทีโดยไม่ถาม ตายที่ `23a` แถว 8 ตัวแรก ที่ assertion ว่า
กล่องยืนยันต้องปรากฏ — นี่คือมัตแตนต์ของครึ่ง *ถามก่อน* ซึ่งเทสต์ที่ดูแค่ว่าสุดท้ายแล้วตอนเรียน

`norestrictcatch` — เอาการดัก 23503 ออกจากการลบการเปิดสอน ตายที่ `23a` แถว 8 ตัวที่สอง

ใหม่ 1 รายวิชาเหมือนเดิม เทอมที่ได้มาจึงเป็นเทอมที่ไม่มีใครลงทะเบียนได้

`nocopyreport` — รายงานไม่เอ่ยถึงรายวิชาที่ข้ามเพราะเปิดสอนอยู่แล้ว ตายที่ `23a` แถว 7 ตรง
การกดคัดลอกครั้งที่สอง — สองมัตแตนต์นี้คู่กันแยกเกณฑ์ข้อเจ็ดออกเป็นสองครึ่ง: *คัดลอกได้* กับ

## สิ่งที่ `/code-review` เจอ และแก้ไปแล้ว

### แผนการสอนรายสัปดาห์กับ CASCADE ตัวเดียวในหกตัว

ข้อนี้ร้ายแรงที่สุดที่รีวิวเจอ และเป็นข้อที่เขียนขึ้นมาผิดตั้งแต่ในความคิด ไม่ใช่ผิดตอนพิมพ์
เส้นทางลบเดิมเขียนไว้ว่า *"ทุกอย่างที่ชี้มาที่ตอนเรียนเป็นบันทึกของคนอื่น ฐานข้อมูลปฏิเสธให้เองผ่าน
`ON DELETE RESTRICT` บนห้าตารางที่ถือมันไว้ ตารางที่หกที่เพิ่มมาทีหลังจึงถูกคุ้มตั้งแต่วันที่เพิ่ม"*
ตารางที่หกมีอยู่แล้ว และมันไม่ใช่ `RESTRICT` — `course_syllabus.section_id` เป็น
`ON DELETE CASCADE` (migration 0002 บรรทัด 141)

แปลว่า: กรรมการหลักสูตรลบการเปิดสอนที่ยังไม่มีนักศึกษาลงทะเบียน แต่ผู้สอนกรอก มคอ.3
ไว้แล้วทั้งเทอม ห้าตารางที่เป็น `RESTRICT` ไม่ร้องอะไร การลบผ่านฉลุย และแผนการสอนทุก
สัปดาห์หายไปกับมัน คืน `204` ไม่มีคำเตือน ไม่มีร่องรอย งานของอาจารย์ทั้งเทอมหายไปเงียบ ๆ
โดยที่คนกดไม่รู้ว่าตัวเองทำอะไรลงไป

`CASCADE` ตรงนั้นไม่ผิด แผนการสอนเขียนขึ้น *เกี่ยวกับ* ตอนเรียนหนึ่ง และไม่มีชีวิตอยู่ได้ถ้าไม่มี
ตอนเรียนนั้น สิ่งที่ผิดคือการคุ้มครองที่เขียนแบบ *whitelist by omission* — ปลอดภัยเพราะบังเอิญ
ว่าทุก FK เป็น `RESTRICT` ไม่ใช่เพราะมีใครตรวจ ตอนนี้จึงถามชื่อมันตรง ๆ ด้วย `hasSyllabus`
ก่อนลบทั้งสองชั้น และตารางถัดไปที่ผูกด้วย `CASCADE` ต้องมาเพิ่มตรงนี้ด้วย ถ้อยคำของ
`offeringInUse` กับ `sectionInUse` ก็เติมคำว่า *มีแผนการสอนรายสัปดาห์แล้ว* เข้าไป เพราะ
ตอนนี้มันปฏิเสธด้วยเหตุผลที่สามจริง ๆ

### รายวิชาที่ปิดในคลัง แต่ยังอยู่ในหลักสูตร

`routes/subjects.js` ปิดรายวิชาที่มีของอ้างอิงอยู่ด้วยการตั้ง `subjects.is_active = false` และ
ไม่แตะการจับคู่ใน `program_subjects` สถานะ *ปิดในคลัง แต่ยังใช้งานในหลักสูตร* จึงมีอยู่จริง
ตัวเลือกรายวิชาบนหน้าจอนี้กรองทั้งสองชั้นอยู่แล้ว แต่ `placementRefusal` ถามแค่ชั้นเดียว
แปลว่าคนที่พิมพ์ที่อยู่เอง หรือเส้นทางคัดลอก จะเปิดรายวิชาที่เลิกใช้แล้วได้ — และคัดลอกจะ
เปิดใหม่ให้ทุกเทอมด้วย ตอนนี้ถามทั้งสองชั้น และตอบด้วยประโยคคนละประโยค เพราะเป็นคนละ
ความผิดที่แก้คนละที่: ชั้นหนึ่งแก้ที่ ข้อมูลรายวิชา อีกชั้นแก้ที่ รายวิชาในหลักสูตร

### ถังที่สี่ในรายงานการคัดลอก

การเติมชั้นคลังรายวิชาเข้าไปใน `placementRefusal` ทำให้ฟังก์ชันเดียวกันตอบได้สองเหตุผล และ
เส้นทางคัดลอกที่เรียกมันอยู่ก่อนแล้วก็รับทั้งสองเหตุผลไปกองไว้ในถังเดียว ชื่อ `skipped_unplaced`
ซึ่งหน้าจอพิมพ์ออกมาว่า *ข้ามเพราะไม่อยู่ในหลักสูตรแล้ว* — ประโยคที่สำหรับรายวิชาที่ปิดในคลัง
แต่ยังอยู่ในหลักสูตรนั้นเป็นเท็จ และพาคนไปแก้ผิดหน้า ตอนนี้แยกเป็น `skipped_closed` อีกถังหนึ่ง
พร้อมบรรทัดของตัวเองบนหน้าจอ เพราะสองความผิดนี้แก้คนละที่ เทสต์ *a subject closed in the
catalogue is named under its own heading* คุมข้อนี้ไว้ และ `nocatalogue` ฆ่ามันได้

### เลขตอนเรียนที่ยาวเกินคอลัมน์

`section_number` เป็น `varchar(10)` ตัวอักษรที่สิบเอ็ดทำให้ Postgres ยก 22001 ซึ่งไม่ใช่ทั้ง
23505 ที่กรณีซ้ำดักไว้ และไม่ใช่ 23503 ที่การลบดักไว้ มันจึงหล่นไปถึง error handler กลาง
กลายเป็น 500 สำหรับการพิมพ์ผิดธรรมดา ฟอร์มจำกัดไว้ที่สิบตัวอยู่แล้ว แต่นั่นเป็นความเอื้อเฟื้อ
ต่อคนพิมพ์ ไม่ใช่กฎ — ตอนนี้กฎอยู่ที่ server

### กดคัดลอกสองครั้งพร้อมกัน

`skipped_existing` เป็นการอ่านแล้วค่อยเขียน คำขอสองอันจึงเห็นเทอมปลายทางว่างทั้งคู่ได้ และ
ตัวที่แพ้ไปชนดัชนี unique ตอนนี้ตอบ 409 ด้วยประโยคเดียวกับที่การเปิดรายวิชาทีละรายการตอบ
แทนที่จะเป็น 500 จากการกดปุ่มสองที **ข้อนี้ไม่มีเทสต์คุม** เพราะเป็นการแข่งกันของสองคำขอที่
ทำให้เกิดขึ้นอย่างแน่นอนในเทสต์ไม่ได้ — บันทึกไว้ตรงนี้ว่าเป็นการป้องกันที่ยังไม่ได้พิสูจน์

### สามข้อบนหน้าจอ

`defaultSemester` ไม่เคยมีผล เพราะ `useState` ตั้งต้นที่ `1` ซึ่งเป็นค่าจริง `current.semester ||
defaultSemester` จึงลัดวงจรตลอด — เปิดฟอร์มจากรายการที่กรองเป็นภาคปลาย แล้วฟอร์มขึ้น
ภาคต้น ตอนนี้ตั้งต้นด้วย `''` · การกำหนดผู้สอนที่ถูกปฏิเสธเคยปิดกล่องแล้วทิ้งรายชื่อที่ติ๊กไว้ทั้งหมด
ตอนนี้ `onSection` ตอบว่าสำเร็จหรือไม่ และกล่องปิดเฉพาะตอนสำเร็จ · ปุ่มคัดลอกกดได้ตั้งแต่
ก่อนรายชื่อหลักสูตรมาถึง ซึ่งจะส่ง `program_id` เป็น `undefined` ตอนนี้กันไว้และบอกให้ลองใหม่

## สิ่งที่ตัดสินใจไว้และควรรู้ก่อนแก้

### ทำไมผู้สอนถึงตรวจกับ `users` ไม่ใช่กับบทบาท `TEACHER`

ตั๋วเขียนว่า *"A Section may only be assigned to someone already registered as a user"* และ
`docs/06` บรรทัด 167 ก็เขียนแบบเดียวกัน จึงตีความตามตัวอักษร คือปฏิเสธเมื่อไม่มีใน `users`
ไม่ใช่เมื่อไม่มีบทบาท `TEACHER` — เพราะตอนเรียนบางตอนสอนโดยคนที่ถือบทบาทอื่น และการเพิ่มเงื่อนไข
บทบาทเข้าไปคือการเพิ่มกฎที่ข้อกำหนดไม่ได้ขอ ถ้าวันหนึ่งพบว่าต้องจำกัด นี่คือที่ที่ต้องแก้ คือ
`teacherRefusal` ใน `backend/routes/offerings.js` และ `/offerings/teachers` ที่วาด picker

### ทำไมการคัดลอกถึงพาผู้สอนไปด้วย

ตั๋วเขียนว่าคัดลอก *"the Offerings and Sections"* และผู้สอนเป็นของที่สาม แต่ประโยคเหนือขึ้นไป
เขียนว่า *"an entire semester's arrangement"* และการคัดลอกที่ทิ้งทุกตอนเรียนไว้โดยไม่มีผู้สอน
คือการประหยัดงานครึ่งที่เล็กกว่า จึงเลือกพาไปด้วย ผลที่ตามมาคือคนที่ลาออกไปแล้วต้องถูกจัดการ
ซึ่งเป็นที่มาของ `dropped_teachers` ในรายงาน

### ทำไม `offeringInUse` ไม่ได้เสนอให้ปิดการใช้งานแทน

ทุกประโยคทรงเดียวกันที่อยู่เหนือมัน — `departmentInUse` และเพื่อน ๆ — จบด้วย
*หากต้องการเลิกใช้งานให้ปิดการใช้งานแทน* ประโยคนี้ไม่จบแบบนั้นเพราะไม่มีปุ่มนั้นให้กด
ทั้งสองตารางไม่มีคอลัมน์ `is_active` และการเพิ่มเข้าไปทีหลังจะทำให้เกิดแถวที่คะแนนยังห้อยอยู่ใต้มัน
แต่หน้าจอไม่แสดงแล้ว ถ้ามีคนเสนอให้เพิ่ม ให้อ่านย่อหน้านี้ก่อน

### รายวิชา `01076105` ใช้เดินไม่ได้ในชุด e2e
