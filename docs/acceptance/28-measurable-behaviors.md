# ตรวจรับด้วยมือ — #28 Measurable Behaviors

`docs/06-implementation-plan.md` §Acceptance กำหนดว่า ticket หนึ่งจะเสร็จเมื่อ automated test ผ่าน
**และ** checklist ที่ทำด้วยมือถูกเดินจนครบ เอกสารนี้คือครึ่งหลังของ #28

ครึ่งแรกอยู่ที่ `backend/test/behaviors.test.js` (16 subtests) — ทุกเกณฑ์ที่พิสูจน์ได้ที่ seam ของ
HTTP surface ถูกพิสูจน์ที่นั่นแล้ว รวมทั้งสามข้อที่**ไม่มีหน้าจอไหนแสดงได้เลย** คือ ค่า enum
นอกรายการถูกปฏิเสธ (dropdown ส่งค่านอกไม่ได้) การจับคู่พฤติกรรมกับ CLO ใน address
(ทดสอบด้วย CLO สองตัวของบัญชีเดียวกัน — บทเรียนของ #22) และ `clo_id` ใน body ที่ถูกเมิน

seam ที่สองคือเบราว์เซอร์ — `e2e/tests/28a-measurable-behaviors.spec.js` (8 แถว) ดูหัวข้อ
*มัตแตนต์ที่พิสูจน์แถว ⚙* ท้ายเอกสาร ซึ่งเป็นเหตุผลว่าทำไมแถวเหล่านั้นถึงถือว่าครอบแล้วจริง

## สิ่งที่ต้องเข้าใจก่อนเดิน — พฤติกรรมบ่งชี้เป็นของ CLO และของอย่างอื่นไม่มีเลย

`subject_clo_measurable_behavior` มีแค่ `clo_id` — ไม่มีตอนเรียน ไม่มีปี ไม่มีหลักสูตร ไม่มีเจ้าของ
ทั้ง ADR-0003 จึงมาถึงหน้านี้โดยการสืบทอด: เข้าผ่านตอนเรียนไหนของการเปิดสอนก็เห็นชุดเดียวกัน
และ CLO รหัสเดียวกันของคนละปีถือคนละชุด `behaviors.js` ไม่ได้ถามคำถามสิทธิ์เอง —
มัน import `offeringOf` กับ `cloOf` จาก `clos.js` แบบเดียวกับที่ #22 import `reachableRubric`
(การที่ join ตัวนี้เคยถูกเขียนซ้ำสามที่คือ [#104](https://github.com/khthana/Deep-QA/issues/104)
— #28 ตั้งใจไม่เป็นสำเนาที่สี่)

**ทุกการอ่านแถวเป็น `WHERE id = $1 AND clo_id = $2` เสมอ** ไม่ใช่ `WHERE id = $1` เดี่ยว ๆ —
ขาดครึ่งหลังเมื่อไหร่ address ของ CLO-1 จะแก้พฤติกรรมของ CLO-2 ได้ทั้งที่ route ดูถูกต้องทุกบรรทัด

**เลขลำดับเป็นของเซิร์ฟเวอร์ ไม่ใช่ของฟอร์ม** เพิ่มแล้วได้เลขถัดไป ลบแล้วที่เหลือถูกจัดใหม่เป็น 1..N
ไม่มีช่องว่าง — พฤติกรรมที่สืบทอดจากโค้ดเดิม ซึ่ง migration 0002 ยึดตอนตั้ง `UNIQUE (clo_id,
behavior_no)` ไว้แล้ว เลขที่ส่งมาใน body ถูกเมินแบบเดียวกับปีที่ส่งมาหา #27

**ไม่มีใครถูกบันทึกว่าเป็นคนแก้** ตารางไม่มี `updated_by` (ADR-0001 ชั้น 2 — แบบเดียวกับ
`student_course` ของ #25) หน้าจอจึงไม่มีบรรทัด *แก้ไขล่าสุดโดย* และนั่นคือการตัดสินของ schema
ไม่ใช่ของหน้านี้

**การลบไม่มีด่านกั้น และนั่นคือคำตอบของ schema เช่นกัน** ไม่มีตารางไหนอ้างถึงพฤติกรรมบ่งชี้ —
มันเป็นคำอธิบาย ไม่ใช่สิ่งที่คะแนนไปเกาะ กล่องยืนยันของหน้าจอจึงเป็นด่านเดียวระหว่างมือลั่นกับของหาย
และประโยคในกล่องต้องบอกว่ากำลังจะลบข้อไหน

**สองรายการปิดถูกตรวจในโค้ดก่อนถึงฐานข้อมูล** enum จะปฏิเสธค่านอกรายการอยู่แล้ว แต่เป็น 22P02
ที่ไปถึง error handler แล้วกลายเป็น *เกิดข้อผิดพลาดในระบบ* — ประโยคผิดสำหรับค่าที่คนเลือกจากรายการ
route ตอบ `invalidBehavior` แทน ทั้ง POST และ PUT ค่าหกระดับคือ R064 และสี่ประเภทคือ R063
(Quiz เป็นคำของ §8 ที่ตั้งใจไม่อยู่ในรายการ — ดูโน้ตใน migration 0002)

## ตั้งต้น

```
docker start deep-core-postgres
cd db      && npm run reset && npm run migrate && npm run seed
cd backend && npm start          # http://localhost:3000
cd frontend && npm start         # http://localhost:5000
```

**ต้อง reset + seed ใหม่จริง ๆ ก่อนเดินใบนี้** — `db/term.js` ทำให้ seed เดินตามนาฬิกา

**ต้อง kill แล้ว start backend ใหม่ก่อนเดิน** — `node server.js` ไม่มี reload ตรวจด้วยการ login
แล้วยิง `GET /api/teaching/sections/1/clos/<clo_id>/behaviors` หนึ่งครั้ง ต้องได้ 200 พร้อมรายการ
(ยิงแบบไม่ login ตรวจอะไรไม่ได้ — ทุก path ใต้ `/api` ตอบ 401 เหมือนกันหมด)

ทุกบัญชีใน seed ใช้รหัสผ่านเดียวกัน คือ `deep-core-local`

ทางเข้า: เลือกตอนเรียนจากหน้า *รายวิชา* → เมนู **ผลการเรียนรู้รายวิชา** → กดลิงก์
**พฤติกรรมบ่งชี้** บนการ์ดของ CLO ที่ต้องการ ที่อยู่ที่ได้คือ
`/teacher/teacherDashboard/<section_id>/courseOutcomes/<clo_id>/behaviors`

seed ให้ **CLO ทุกตัวของทั้งสองปีมีพฤติกรรมบ่งชี้คนละ 2 ข้อ** (ข้อ 1 กับ ข้อ 2) ระดับกับประเภท
ไล่สลับกันตามสูตรใน `db/seed.js` — สองข้อของ CLO เดียวกันจึงถือค่าไม่ซ้ำกัน

| `section_id` (ที่อยู่) | ปีการศึกษา | ผู้สอน | ใช้เดินอะไร |
|---|---|---|---|
| `1` | 2569 (ปัจจุบัน) | `teacher.one@` | เกือบทุกข้อ |
| `2` | 2569 (ปัจจุบัน) | `multi.role@` (สลับเป็น *อาจารย์ผู้สอน* ก่อน) | ข้อชุดเดียวกันข้ามตอนเรียน |
| `3` | **2568 (ปีก่อน)** | `teacher.one@` | ข้อปีอื่นมีชุดของตัวเอง |

## คำตอบที่ถูกแทนที่ — #133 (16 ก.ย. 2569)

`load` ของหน้าจอนี้รับธง `isCurrent` แล้ว และวาดคำตอบก็ต่อเมื่อคำขอที่ทำให้มันเกิด ยังเป็นคำขอ
ที่หน้าจอต้องการอยู่ — กฎเดียวกับ #68 ตัวอักษรต่อตัวอักษร ซึ่งเขียนไว้บน `frontend/src/pages/Students.js`

**แต่ตรงนี้ยังไม่ได้ทดสอบ ไม่ใช่ไม่ต้องมี** พารามิเตอร์ทุกตัวของหน้านี้มาจาก `useParams`
สิ่งเดียวที่แทนคำขอได้คือการเดินจาก CLO หนึ่งไปอีกอันบนเส้นทางเดิม โดยคอมโพเนนต์ไม่ถูกถอด
ซึ่งทุกลิงก์บนจอนี้เดิน*ขึ้น*ไปหารายการที่ถอดหน้านี้ทิ้ง — วัดเมื่อ 16 ก.ย. 2569 และเป็นคำกล่าว
**ที่มีวันหมดอายุ** ตั๋วที่เพิ่มทางเดินระหว่างพี่น้องบนเส้นทางนี้ ทำให้มันเข้าถึงได้ทันที
และต้องมีแถวของตัวเองในวันนั้น รายการทั้งยี่สิบสองจุดพร้อมสถานะอยู่ที่
`docs/acceptance/57-pager.md` §ครึ่งหลังปิดแล้ว — #133
และตัวติดตามของสิบหกจุดที่ยังไม่มีแถวของตัวเองคือ #141

## รายการที่โหลดใหม่ถูกแทนที่ — #140 (17 ก.ย. 2569)

`frontend/src/pages/MeasurableBehaviors.js` โหลดใหม่หลังการบันทึกและการลบ ก่อนตั๋วนี้ทุกจุดเรียก `load()` เฉย ๆ แล้วรับค่าตั้งต้นที่ตอบว่า
*ยังเป็นคำขอปัจจุบัน* เสมอ ตอนนี้ทั้งสองจุดส่ง `() => onScreen.current === load` และค่าตั้งต้นถูกเอาออก
ทุกจอ — รูปเดียวกับอีกเก้าจอที่มีแถวของตัวเอง เหตุผลอยู่บน `frontend/src/pages/Students.js`

**แต่ตรงนี้ยังไม่ได้ทดสอบ ไม่ใช่ไม่ต้องมี** คำตอบที่ถูกแทนต้องมีอะไรสักอย่างเปลี่ยนสิ่งที่ `load` ขอ
ระหว่างที่การโหลดยังไม่กลับ และสิ่งที่ `load` ของจอนี้ขอมาจาก `useParams` ทั้งหมด
จึงไม่มีแถวและไม่มีมัตแตนต์ — วัดเมื่อ 17 ก.ย. 2569 ด้วยเหตุผลเดียวกับส่วน #133 ข้างบน และ**หมดอายุ
วันเดียวกัน**: ทางเดินระหว่างพี่น้องบนเส้นทางนี้ หรือตัวควบคุมบนจอที่ป้อนเข้า `load` ทำให้จุดเหล่านี้

รายการใต้ฟอร์มถูกวาดอยู่เสมอและไม่ปิดปุ่มไหนเลย ดินสอของการ์ดอื่นจึงมาแทนฟอร์ม ได้ทันทีโดยไม่ต้องมี
*ยกเลิก* ด้วยซ้ำ
ฟอร์มที่สองจึงถูกปิดไปพร้อมสิ่งที่พิมพ์ค้างไว้
และประโยคของการบันทึกครั้งก่อนมาขึ้นในที่ที่อ่านได้ว่า
เป็นเรื่องของรายการที่คนกำลังมองอยู่ ตอนนี้ `showing` จำ **สิ่งล่าสุดที่เปิดขึ้นบนจอนี้**
ทุกตัวควบคุมที่เปิดอะไรขึ้นมาเขียนมัน และคำตอบที่เจอการเปิดอื่นไม่ปิดอะไรและไม่พูดอะไร ทั้งประโยคสำเร็จ

`frontend/src/pages/Departments.js`

สิ่งที่ไม่ได้เปลี่ยนคือสิ่งที่หน้าจอปิดการใช้งาน ทั้งรายการและดินสอทุกตัวยังกดได้ระหว่างการบันทึก

**ฟอร์มอยู่ต่อ แต่สิ่งที่พิมพ์ในนั้นไม่อยู่**
([#149](https://github.com/khthana/Deep-QA/issues/149)) จอนี้วาดทั้งรายการและฟอร์มไว้ใน
`{!loading && data && (` อันเดียวกัน และการโหลดทุกครั้งขึ้นต้นด้วย `setLoading(true)`
การโหลดที่ตามหลังการบันทึกจึง **ถอดฟอร์มทิ้ง** ตลอดช่วงที่คำขอยังไม่กลับ แล้วสร้างใหม่โดยอ่านค่า
จากระเบียน #146 กันไม่ให้คำตอบที่มาช้า *ปิด* ฟอร์มที่คนย้ายไปแล้ว แต่ไม่ได้กันสิ่งที่พิมพ์ค้างไว้
ในฟอร์มนั้น แถวข้างล่างไม่ได้อ้างถึงเนื้อในฟอร์ม (มันอ่านว่าฟอร์มไหนเปิดอยู่ กับการมีหรือไม่มีประโยค)
จึงไม่มีการอ้างเกิน แต่ก็ยังไม่มีแถวไหนถือเรื่องนี้ไว้ หกจอที่เป็นรายการไม่มีรูปนี้ — `!loading`
ของมันครอบแค่แถวในตาราง ฟอร์มอยู่นอกนั้นและรอดการโหลด ซึ่งเป็นเหตุผลที่แถวของจอเหล่านั้น
อ่านค่าที่พิมพ์ไว้ในช่องได้หลังการโหลด (`inputValue()`) และแถวของจอนี้อ่านไม่ได้

**ย่อหน้านี้คือสภาพของวันที่ 20 ก.ย. 2569** — แก้แล้วเมื่อ 21 ก.ย. 2569 ตามคำตอบของเจ้าของ
จอนี้เก็บสิ่งที่วาดไว้ระหว่างการโหลด ฟอร์มจึงรอด และแถวของ `149a` อ่าน `inputValue()` ได้แล้ว
ดูหัวข้อ #149 ท้ายใบนี้

ทุกแถวข้างล่าง **เดินด้วยมือไม่ได้** มันต้องการคำขอที่ถูกกักไว้จนกว่าแถวจะปล่อย ซึ่ง
`e2e/support/gate.js` ทำให้

`teacher.one@kmitl.ac.th`

`146a-save-closes-a-later-form.spec.js` จุดรอของแถวที่การบันทึกสำเร็จคือการโหลดรายการ
ที่ตามมา — การปิดฟอร์มที่ข้อบกพร่องจะวาด commit ไปก่อนคำขอนั้นถูกส่ง — แล้วอ่านครั้งเดียวหลังจากนั้น
250 ms ส่วนแถวคำปฏิเสธไม่มีจุดแบบนั้น (คำปฏิเสธไม่โหลดอะไรใหม่
และประโยคที่ถูกต้องคือประโยคที่ไม่ถูกวาด)
จึงนับจากตอนที่คำตอบถึงหน้า ตัวเลขนั้นตัดสินผลได้ (#52) สิ่งที่ค้ำมันคือการกวาดข้างล่าง

**คำถามที่ตั๋วฝากไว้ ถูกตอบแล้ว (20 ก.ย. 2569)** ร่างแรกให้ *ยกเลิก* เขียน `null` ลง `showing`
การบันทึกที่ถูก *ยกเลิก* แซงโดยไม่มีฟอร์มที่สองมาแทน จึงเงียบทั้งประโยคสำเร็จและคำปฏิเสธ —
คนที่กด *บันทึก* ไม่ได้ยินอะไรเลยเกี่ยวกับการเขียนที่ตัวเองสั่ง ตั๋วฝากเรื่องนี้ไว้เองว่าเป็น
*คำถามเรื่องสิ่งที่คนเห็น แบบเดียวกับ #143* ซึ่ง `docs/06` §Out of Scope บอกว่าเป็นคำถาม
ไม่ใช่การแก้ คำตอบของอาจารย์คือ **ให้ขึ้นเหมือนเดิมเมื่อไม่มีใครมาแทน**

`showing` จึงไม่ได้แปลว่า *ฟอร์มไหนเปิดอยู่* อีกต่อไป แต่แปลว่า **สิ่งล่าสุดที่เปิดขึ้นบนจอนี้**
— *ยกเลิก* ไม่เขียนมัน และการบันทึกที่ปิดฟอร์มของตัวเองก็ไม่เขียน `null` จึงเหลือความหมายเดียว
คือ *ยังไม่มีอะไรเปิดขึ้นเลย* บรรทัดที่เทียบ (`showing.current === sent`) ไม่ถูกแตะเลย

## การโหลดใหม่ไม่ถอดฟอร์มที่คนกำลังพิมพ์ — #149 และ #148 (21 ก.ย. 2569)

— `{data && (` แทน `{!loading && data && (` และบรรทัด *กำลังโหลดข้อมูล…* ขึ้นเฉพาะตอนที่ยังไม่มีอะไร
ให้วาด (`{loading && !data && …}`) ฟอร์มจึงรอดการโหลด และสิ่งที่พิมพ์ค้างไว้อยู่ต่อ

การแก้นั้นเปิดประตูที่ #146 นับไว้ว่าปิด: ระหว่างการโหลดมีดินสอให้กดแล้ว และทั้ง `save` กับ `remove`
ตั้งประโยคของตัวเอง*หลัง*การโหลด ประโยคของการบันทึกจึงถาม `showing.current === sent` ตอนที่มันตัดสิน
แทนที่จะถือคำตอบเก่าไว้ใน `mine` และ `remove` จับ `sent` ไว้ตอนถูกกด แล้วถามคำถามเดียวกันก่อน
ประโยค *ลบพฤติกรรมบ่งชี้แล้ว*

ทุกแถวข้างล่าง **เดินด้วยมือไม่ได้** มันต้องการคำขอที่ถูกกักไว้ที่ route จนกว่าแถวจะปล่อย
(`e2e/support/gate.js`) การเขียนที่ถูกกักถูกตอบด้วย 200 ที่แต่งขึ้น จึงไม่มีแถวไหนเขียนฐานข้อมูล
เข้าด้วย `teacher.one@kmitl.ac.th` ครอบคลุมโดย describe *พฤติกรรมบ่งชี้ (MeasurableBehaviors.js)* ใน
`149a-reload-keeps-the-open-form.spec.js` จุดอ่านคือหลังคำตอบที่ถูกกักถึงหน้า แล้ว 250 ms อ่านครั้งเดียว

### สิ่งที่การตรวจเจอ และการกวาดที่มันขอ (21 ก.ย. 2569)

การตรวจโค้ดอ่านสามข้อที่การกวาดครั้งแรกไม่เห็น

- **ไม่มีแถวไหนถามว่าประโยคของการลบยังขึ้น** ทุกแถวถามแค่ให้มันเงียบ ตัวที่ทำให้มันไม่พูดอีกเลยจะรอด ทุกไฟล์ แถว *a removal nothing took the place of says what it did* กับ `behaviorsremovalbannerunsaid` (`false &&` หน้าเงื่อนไข) เพิ่มเข้ามา — *สองตัวที่แปรคุณสมบัติเดียวกันไม่เห็นอันที่สาม* (#96)
- **`removalsentatthelanding` คือการถอดเงื่อนไขทิ้งในผล** `sent` ที่จับข้างการเปรียบเทียบเท่ากับ ref ตัวเอง ใบมัตแตนต์เคยเขียนว่าไม่ใช่ แก้คำบรรยายแล้ว การฆ่ายังเป็นการฆ่า
- **คำตอบนี้แยกประโยคของการบันทึกออกจาก `mine`** ก่อนหน้านั้น `146:behaviorsclosewins` ฆ่าทั้งการปิดและประโยคด้วยตัวเดียว ตอนนี้มันเห็นแค่การปิด ครึ่ง *ไม่มีประโยคสำเร็จ* ของแถว [#146](https://github.com/khthana/Deep-QA/issues/146) จึงได้ `behaviorssavebannerunguarded` (`true ||` หน้าเงื่อนไข) — การกวาดซ้ำของ `146` เป็นที่ที่เห็นมัน *สมอที่ยังอยู่ไม่ได้แปลว่ายังพิสูจน์อะไรได้* (#107)

กวาดทีละตัว — baseline ของ `149a` **29 ผ่านทั้ง 29** (1.6 นาที) และของ `146a` **49 ผ่านทั้ง 49** (2.5–2.6 นาที) ทุกรันเวลาเท่า baseline ล้ม + ผ่าน = จำนวนแถวพอดี อ่านจากชื่อ describe *พฤติกรรมบ่งชี้ (MeasurableBehaviors.js)*:

## การโหลดใหม่ที่ล้มเหลวเก็บสิ่งที่วาดไว้ — #151 (22 ก.ย. 2569)

ตั้งแต่ #149 จอเก็บรายการและฟอร์มไว้ระหว่างการโหลดใหม่ แต่การโหลดที่**ล้มเหลว**ยังล้างทั้งคู่: `catch` ของ `load` ตั้ง `data` เป็น `null` ฟอร์มจึงถูกถอดพร้อมสิ่งที่พิมพ์ไว้ คำตอบ (22 ก.ย. 2569) คือคำตอบของ #149 ต่อไปอีกขั้น — **การโหลดที่ล้มเหลวเก็บสิ่งที่จอวาดไว้ล่าสุด** และคำปฏิเสธขึ้นเหนือมัน การโหลดครั้งแรกที่ล้มไม่มีอะไรให้เก็บ `loading && !data` วาดเหมือนเดิม ซึ่งตั๋วนี้ไม่เปลี่ยน

ทุกแถว **เดินด้วยมือไม่ได้** การเขียนถูกตอบด้วย 200 ที่แต่งขึ้น และการโหลดที่ตามมาด้วย 409 ที่แต่งขึ้น (`e2e/support/gate.js`) จึงไม่มีแถวไหนเขียนฐานข้อมูลผ่านการบันทึก เข้าด้วย `teacher.one@kmitl.ac.th` ครอบคลุมโดย describe *พฤติกรรมบ่งชี้ (MeasurableBehaviors.js)* ใน `151a-failed-reload-keeps-the-list.spec.js` จุดอ่านคือหลังคำปฏิเสธถึงหน้า แล้ว 250 ms อ่านครั้งเดียว (#52) สิ่งที่ค้ำมันคือการกวาดข้างล่าง

`151:behaviorsblanks` ใส่ `setData(null)` กลับเข้า `catch` ของจอนี้ — โค้ดก่อน #151 — และ `151:behaviorsblinks` ล้าง `data` แล้วคืนมันในจังหวะถัดไป ฟอร์มจึงถูกถอดแล้ววาดใหม่ เปิดอยู่แต่สิ่งที่พิมพ์หายไป `blinks` เพิ่มหลังการตรวจ: `blanks` ฆ่าแถวฟอร์มที่ *the second card's form* ซึ่งอ่านก่อน *what was typed* ครึ่งหลังนั้นจึงไม่มีมัตแตนต์ไปถึง กวาดทั้งสิบสี่ตัวของใบ `151` เมื่อ 22 ก.ย. 2569 ด้วย `151a` ทั้งไฟล์บนข้อความสุดท้ายของมัน — baseline **14 ผ่านทั้ง 14** (0.8 นาที) `behaviorsblanks` **ล้ม 2 ผ่าน 12** (0.9 นาที) ที่ *the second card's form* และที่ *the cards drawn before the reload* `behaviorsblinks` **ล้ม 1 ผ่าน 13** (0.9 นาที) ที่ *what was typed* แถวเดียว ไม่ใช่ที่ timeout และไม่มีแถวของจออื่นตาย อ่านจากชื่อ describe ไม่ใช่จากจำนวน

### สิ่งที่วัดได้แต่ไม่ใช่ของตั๋วนี้

ตั๋วเขียนว่า *แบนเนอร์คำปฏิเสธบอกว่าการโหลดล้มเหลว* วัดแล้วจริงแค่เมื่อมีฟอร์มอื่นเปิดทีหลัง: ถ้าไม่มีอะไรเปิด `save` ตั้งประโยคสำเร็จ*หลัง*การโหลด ประโยคนั้นจึงทับคำปฏิเสธ (วัดด้วย probe ที่ลบทิ้งแล้ว: บนจอ ผลการเรียนรู้รายวิชา คำปฏิเสธ 0 ประโยคสำเร็จ 1 และบนแถวรายการของ `151a` ทั้งเจ็ดจอ คำปฏิเสธ 0 ทุกจอ) — ตอนนี้คือ *บันทึก…แล้ว* เหนือรายการ ที่ยังไม่มีสิ่งที่บันทึก ซึ่งเป็นคำถามของเจ้าของ ไม่ได้แก้ในตั๋วนี้ — เปิดเป็น [#152](https://github.com/khthana/Deep-QA/issues/152)
