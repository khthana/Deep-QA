## สิ่งที่ต้องเข้าใจก่อนเดิน — เกณฑ์ไม่มีหลักสูตรเป็นของตัวเอง

`rubric_details` **ไม่มีคอลัมน์ `program_id`** สิ่งเดียวที่บอกว่าใครเขียนเกณฑ์ได้คือ Rubric ที่อยู่เหนือมัน
ซึ่ง address เป็นคนระบุ ทุก verb ของหน้านี้จึงตรวจ Rubric ก่อนเสมอ และตรวจ **สองครึ่งที่แยกกัน**

1. Rubric นั้นอยู่ในความรับผิดชอบของบัญชีนี้หรือไม่ — ใช้ `reachableRubric` ตัวเดียวกับ #21
   ไม่ได้ถามฐานข้อมูลเองซ้ำ เพราะสองคำตอบต่อคำถามเดียวจะเพี้ยนออกจากกันสักวัน
2. **เกณฑ์นั้นอยู่ใต้ Rubric ตัวที่ address ระบุหรือไม่** — ทุกคำสั่งเป็น `WHERE id = $1 AND rubric_id = $2`
   ไม่ใช่ `WHERE id = $1` เดี่ยว ๆ ถ้าขาดครึ่งหลัง บัญชีที่เข้าถึง Rubric A ได้จะแก้เกณฑ์ของ Rubric B
   ได้ด้วยการเรียก `/rubrics/A/criteria/<id ของ B>` การตรวจแม่ผ่าน แถวถูกหาเจอด้วย id ของตัวเอง
   และไม่มีอะไรบังคับให้สองอย่างตรงกันเลย นั่นคือเกณฑ์ข้อ 6 ของตั๋วที่พังทั้งที่ route ดูถูกต้อง

`rubric-criteria.test.js` จึงทดสอบครึ่งที่สองด้วย Rubric **สองตัวของบัญชีเดียวกัน** ที่ซึ่ง reach
ไม่ได้ทำงานอะไรเลย สิ่งที่ปฏิเสธคือการจับคู่

## route เข้มกว่า schema โดยตั้งใจ — คำอธิบายทั้งสี่ระดับ

`level_1_description` ถึง `level_4_description` เป็น `text` ที่ **ไม่มี `NOT NULL`** แต่เกณฑ์ข้อ 3
ของตั๋วบอกว่าเกณฑ์หนึ่งข้อต้องมีคำอธิบายครบทั้งสี่ระดับ route จึงเข้มกว่า schema ของตัวเอง
เหมือนที่ #21 เข้มกว่า `rubrics.program_id` ที่เป็น nullable

เหตุผลไม่ใช่ความเรียบร้อย — Rubric ที่เขียนคำอธิบายไว้ครึ่งเดียวแย่กว่าไม่มี Rubric เลย
มันดูเหมือนแนวทางแต่ไม่ได้ให้แนวทาง และผู้ตรวจที่อ่านจะเติมช่องว่างด้วยดุลพินิจของตัวเอง
ซึ่งคือสิ่งเดียวที่ Rubric มีไว้เพื่อกำจัด

เทสต์จึงลองไม่ส่ง **ทีละระดับครบทั้งสี่** ไม่ใช่ระดับเดียว — validator ที่ตรวจแค่ `level_4_description`
จะผ่านชุดทดสอบที่ลองไม่ส่งแค่ระดับนั้น

## น้ำหนักเป็นตัวเลข ไม่ใช่สตริง

`weight` เป็น `numeric(5,2)` และ **node-postgres อ่านคอลัมน์ `numeric` กลับมาเป็นสตริง** —
`'1.00'` ไม่ใช่ `1` เพราะชนิดนี้กว้างกว่า double ของ JavaScript และ driver ไม่ยอมย่อให้เงียบ ๆ
ที่นี่มันล้น double ไม่ได้ (ห้าหลัก ทศนิยมสองตำแหน่ง แทนได้ตรง ๆ ในฐานสอง) route จึง cast เป็น
`float8` ขาออก JSON จึงพา *ตัวเลข* ถ้าปล่อยเป็นสตริง หน้าจอจะเขียน `12.50` ตรงที่คนพิมพ์ `12.5`
และอะไรก็ตามที่บวกน้ำหนักสองค่าจะได้การต่อสตริง

**ทศนิยมเกินสองตำแหน่งถูกปฏิเสธ** เพราะ PostgreSQL ไม่ได้ปฏิเสธ — มันปัดให้เงียบ ๆ
แถวที่กลับมาจึงไม่ใช่แถวที่ส่งไป และไม่มีใครบอกคนกรอกเลย การตรวจเขียนด้วยค่าความคลาดเคลื่อน
ไม่ใช่ `Math.round(w * 100) !== w * 100` ซึ่งเป็นรูปที่เขียนไว้ตอนแรกและ **ปฏิเสธ 1.1, 8.2 และ 0.07**
เพราะหนึ่งในสิบไม่ลงตัวในฐานสอง เทสต์มีแถวที่ยิงค่าเหล่านั้นเข้าไปโดยเฉพาะ

**น้ำหนัก 0 ถูกปฏิเสธเป็นการตัดสินใจ ไม่ใช่เลขคณิต** เกณฑ์ที่มีน้ำหนักศูนย์ถูกตรวจ ถูกแสดง
และไม่มีผลอะไรเลย ซึ่งเป็นความผิดพลาดที่หน้าตาเหมือนการตั้งค่า วิธีเอาเกณฑ์ออกคือลบมัน

## สิ่งที่ตั๋วเขียนไว้แล้วโค้ดไม่ทำตาม และทำไม

**`FACULTY_ADMIN` เข้าหน้านี้ไม่ได้** ตั๋วไม่ได้พูดถึงคณะโดยตรง แต่ `MAINTAINERS` ของหน้านี้
คือตัวเดียวกับของ #21 ซึ่ง [#79](https://github.com/khthana/Deep-QA/issues/79) ระบุ **A04** ไว้ตรง ๆ
และเหตุผลของ #79 ใช้กับหน้านี้ยิ่งกว่าหน้าแม่ของมัน — คณะถือ *รายชื่อ* ภาควิชาและหลักสูตร
ส่วนสิ่งที่อยู่ *ข้างใน* หลักสูตร ซึ่งเกณฑ์การให้คะแนนของ Rubric อยู่ลึกที่สุดในนั้น เป็นของภาควิชากับกรรมการหลักสูตร

**หน้านี้ไม่แบ่งหน้า** ต่างจากทุกหน้าข้อมูลหลักในระบบ Rubric คือหน้ากระดาษที่ผู้ตรวจอ่านระหว่างตรวจงาน
แนวทางที่ถูกตัดครึ่งไปอยู่คนละหน้าแย่กว่าแนวทางที่ยาว หน้าจอบอกจำนวนแทน

**หน้านี้ไม่มีตัวเลือกหลักสูตรและไม่มีตัวกรอง** ไม่มีอะไรให้เลือก — เกณฑ์อยู่ใต้ Rubric เดียว
และ Rubric อยู่ใต้หลักสูตรเดียว address คือคำตอบทั้งหมด (ADR-0004 รูปเดิม ต่ำลงมาหนึ่งชั้น)

## ข้อจำกัดที่รู้อยู่ ไม่ใช่บั๊กของตั๋วนี้

**คำอธิบายสี่ระดับที่ยาวมากทำให้ตารางกว้างเกินจอ** ย่อหน้านี้เคยเขียนว่าตารางเลื่อนแนวนอนได้
เพราะกรอบตารางมี `overflow-x-auto` เหมือนทุกตารางกว้างในระบบนี้ **ซึ่งไม่จริง** และการเดินด้วยมือ
เป็นสิ่งที่จับได้ — `overflow-x-auto` ที่กรอบไม่เคยได้ทำงาน เพราะกรอบเองกว้างตามเนื้อหาไปแล้ว
เรื่องนี้กลายเป็น [#98](https://github.com/khthana/Deep-QA/issues/98) และแก้แล้วที่ `Mainpage.js`
ไม่ใช่ที่หน้านี้ รายละเอียดอยู่ในบันทึกการเดินด้านล่าง

## ตั้งต้น

```
docker start deep-core-postgres
cd db      && npm run reset && npm run migrate && npm run seed
cd backend && npm start          # http://localhost:3000
cd frontend && npm start         # http://localhost:5000
```

ทุกบัญชีใน seed ใช้รหัสผ่านเดียวกัน คือค่า `PASSWORD` ใน `db/seed.js:58`
อีเมลต้องพิมพ์เต็มรวมโดเมน `@kmitl.ac.th` — อีเมลหรือรหัสผ่านที่ผิดทำให้หน้าจอขึ้นกล่อง
*Session หมดอายุ* ทับประโยคจริงไว้ หลงทางง่ายมาก ([#97](https://github.com/khthana/Deep-QA/issues/97) ยังไม่แก้)

**ต้อง restart backend ก่อนเดิน** — process ที่ค้างจากตั๋วก่อนจะตอบ *ไม่พบเส้นทางที่เรียกบนเซิร์ฟเวอร์นี้*
ให้ทุก route ของ #22 และ **`Server running` ใน log ไม่ใช่หลักฐานว่า route ใหม่อยู่ในนั้น**

**seed ไม่ได้เปลี่ยนในตั๋วนี้** ถ้าเพิ่งเดิน #21 จบ ให้ `npm run seed` ใหม่ก่อน เพราะแถวของ #21
ลบ `RUB-01` ทิ้งไปหนึ่งแถว ข้อมูลที่แถวข้างล่างอ้างถึงคือ

- **`RUB-01` มีเกณฑ์ย่อย 3 ข้อ และ `RUB-02` มี 2 ข้อ** ที่เหลือของ `0501` ยังว่าง
- เกณฑ์ที่ seed สร้างมีคำอธิบายครบทั้งสี่ระดับทุกข้อ ชื่อไทยอ่านว่า *`<ชื่อ Rubric>` — เกณฑ์ที่ `<n>`*
  และ **น้ำหนักเป็น 1 ทุกข้อ** แถวที่ต้องเห็นน้ำหนักต่างกันจึงต้องพิมพ์เอง
- **ลำดับของเกณฑ์ที่ seed สร้างคือ 1, 2, 3 เรียงตรงกับเลขในชื่อ** แถวที่พิสูจน์เรื่องการเรียง
  จึงต้องสร้างเกณฑ์เองอย่างน้อยสองข้อที่ลำดับสวนทางกับชื่อ ([#96](https://github.com/khthana/Deep-QA/issues/96))
- `0503` มี `RUB-51` กับ `RUB-52` ซึ่ง **ไม่มีเกณฑ์ย่อยเลย** ใช้สำหรับแถวที่ต้องเห็น Rubric ว่าง

หลายข้อข้างล่างเขียนข้อมูลจริงลงฐานข้อมูล — **`npm run seed` ใหม่หลังเดินจบ** ก่อนเริ่มตั๋วถัดไป

## บันทึกการเดินด้วยมือ

**เดินครบทั้งแปดแถวแล้ว 2026-08-24 ถึง 2026-08-25** โดยเจ้าของงาน ผ่านเจ็ดแถว
**ตกหนึ่งแถว** คือตารางเลื่อนแนวนอน ซึ่งเป็นที่มาของ #98 แก้แล้วในวันเดียวกัน
แถวที่ตกถูก**แยกเป็นสองแถว** — ครึ่งที่เบราว์เซอร์พิสูจน์ได้เป็น ⚙ ส่วนครึ่งที่ต้องมีคนลากขอบ
หน้าต่างเอง **เดินซ้ำแล้ว 2026-08-25 หลังแก้ #98 และผ่าน** รายละเอียดอยู่สองย่อหน้าถัดไป

**การเดินซ้ำ 2026-08-25** ที่หน้าต่างราวครึ่งจอบนหน้าเกณฑ์ของ `RUB-01` ซึ่งมีเกณฑ์
`การตอบคำถามจากผู้ฟัง` ที่คำอธิบายระดับ 4 ยาว 156 ตัวอักษรอยู่ — **มีแถบเลื่อนใต้ตาราง**
ซึ่งเป็นสิ่งที่ก่อนแก้ไม่มี ลากแถบนั้นไปขวาสุดด้วยเมาส์แล้ว **ปุ่มในคอลัมน์ จัดการ โผล่มาครบทั้งปุ่ม**
**หัวเรื่องกับแถบเมนูซ้ายอยู่นิ่ง** และ **ขอบล่างของหน้าเว็บไม่มีแถบเลื่อนของทั้งหน้า** คือมีแถบเดียว
เป็นของตาราง ปิดท้ายด้วยการกด *ลบ* ที่แถวนั้นจริง ๆ เพราะแถวเขียนว่า *กดถึง* ไม่ใช่ *เห็น* —
กล่อง *ยืนยันการลบเกณฑ์การให้คะแนน* เด้งขึ้นมา แล้วกด *ยกเลิก* เกณฑ์จึงยังอยู่

**แถวที่ตก — ตารางเลื่อนแนวนอนไม่ได้ และคอลัมน์ จัดการ กดไม่ถึงบนจอแคบ** ย่อหน้าต่างลงมา
ราวครึ่งจอแล้วคอลัมน์ขวาสุดหายไปโดยไม่มีแถบเลื่อนให้ตามไปหา ต้นเหตุไม่ได้อยู่ที่หน้านี้ —
`frontend/src/pages/Mainpage.js:63` วาง `<main>` เป็น `flex-1` **โดยไม่มี `min-w-0`**
flex item จึงย่อลงต่ำกว่าความกว้างขั้นต่ำของเนื้อหาไม่ได้ ตารางที่ต้องการราว 1,100px
(สี่คอลัมน์คำอธิบายที่ `min-w-48` เท่ากับ 192px ต่อคอลัมน์ บวกคอลัมน์ที่เหลือ) จึงดัน `<main>`
ให้กว้างเกินจอ แล้ว `Mainpage.js:92` ที่เป็น `overflow-x-hidden` ตัดส่วนที่ล้นทิ้ง
`overflow-x-auto` ที่กรอบตารางไม่เคยได้ทำงาน เพราะกรอบเองก็กว้างตามเนื้อหาไปแล้ว
เรื่องนี้กระทบทุกหน้าที่มีตารางกว้าง ไม่ใช่ของตั๋วนี้ตั๋วเดียว แต่หน้านี้เจอหนักที่สุด
เพราะคอลัมน์ที่หายไปคือคอลัมน์ที่มีปุ่ม ลบ

**แก้แล้ว 2026-08-25 ใน #98** สิ่งที่วัดได้ก่อนแก้ ที่หน้าต่างกว้าง 900px
บนหน้านี้ — `<main>` กว้าง 1,094px · กรอบตาราง `clientWidth` กับ `scrollWidth` เท่ากันที่ 1,060
· `document.scrollWidth` เท่ากับ 900 นั่นคือทั้งบั๊กในสี่ตัวเลข กรอบไม่มีอะไรให้เลื่อนเพราะกว้าง
เท่าเนื้อหาไปแล้ว ส่วนที่ล้นคือ `<main>` ซึ่งเปลือกตัดทิ้ง หลังเติม `min-w-0` ที่ `<main>`
ตัวเลขชุดเดียวกันอ่านว่า 900 · 866 กับ 1,060 · 900 — คือกรอบเลื่อนได้และหน้าไม่เลื่อน
**การวัดนี้ทำก่อนแก้โค้ด** เพราะรายงานจากการเดินบอกว่า *ตารางหด* ตามหน้าต่าง ซึ่งเป็นอาการของ
สาเหตุคนละตัวกับที่เขียนไว้ข้างบน และสองสาเหตุนั้นต้องแก้คนละที่กัน ตัวเลขเป็นตัวตัดสิน

**เกณฑ์ข้อสี่ของ #98 ขอให้คนเดินแถวนี้ซ้ำจนผ่าน และเดินแล้ว** ⚙ ของแถวบนมาจาก browser seam
กับมัตแตนต์ ไม่ใช่จากการเดิน จึงไม่ได้แทนที่การเดินที่ตั๋วนั้นขอ และนั่นคือเหตุผลที่แถวถูกแยกเป็นสอง

## บันทึกที่กดซ้ำได้ระหว่างที่การเขียนยังไม่กลับ — #142 (19 ก.ย. 2569)

`frontend/src/pages/RubricCriteria.js` เคยมีธง `busy` ตัวเดียว ทั้งการอ่านแถวของ *แก้ไข* และการเขียน (บันทึก ลบ)
ถือมันไว้ และ `finally` ของการอ่านปลดมันเสมอ ไม่ว่าหลังจากนั้นจะมีการเขียนหยิบธงไปแล้วหรือไม่ การอ่านที่
มาถึงช้าจึงคืนปุ่ม *บันทึก* ให้ระหว่างที่การเขียนยังไม่กลับ ตอนนี้การเขียนถือ `writing` การอ่านถือ `reading`
และปุ่มกับกล่องยืนยันปิดด้วย `writing || reading` การอ่านยังปลดธงของตัวเองเสมอเหมือนที่เคยปลด
ธงตัวเดียว สิ่งเดียวที่เปลี่ยนคือมันไม่ได้ปลด `writing` — JSX ไม่ได้เปลี่ยน เหตุผลอยู่บน
`frontend/src/pages/Departments.js`

วัดก่อนแก้บนข้อมูลภาควิชาที่ `8bb9a92` ลำดับของตั๋ว (อ่าน อ่านอีกแถว บันทึก) แดงตามที่ตั๋วบอก
ส่วน *อ่านแล้วลบ* กับ *บันทึกแล้วลบ* ไม่ใช่ทางเข้า กล่องยืนยันเปิดมาแบบถูกปิดทั้งสองกรณี สิ่งเดียวที่ปลดธง
ของงานอื่นก่อนเวลาได้จึงเป็นการอ่าน เพราะเป็นสิ่งเดียวที่ตารางยอมให้เริ่มระหว่างที่ธงยกอยู่ และมันทำได้
สองลำดับ — การอ่านที่ถูกแทนแล้ว (ลำดับของตั๋ว) กับการอ่านที่ยังเป็นคำขอปัจจุบัน ซึ่งเริ่มจากตารางหลัง
สิ่งที่ส่งการเขียนถูกปิดด้วย *ยกเลิก* ลำดับหลังมี *ยกเลิก* สองตัวให้กด — ของกล่องยืนยันซึ่งไม่เคยถูกปิด
และของฟอร์มซึ่งกดได้ระหว่างบันทึกแค่บนข้อมูลภาควิชา หลักสูตร และรายวิชา อีกสี่ฟอร์มปิดมันด้วยธง
*แถวที่เรียกสองทางเข้าคือสองแถว* (#66) จอนี้ปิด *ยกเลิก* ของฟอร์มระหว่างบันทึก — วัดจากแถวที่หมดเวลาที่การกดนั้นเมื่อรันกับโค้ดเก่า — ทางของกล่องยืนยันจึงเป็นทางเดียวบนจอนี้

ตั๋วเสนอให้นับงานที่ค้าง แต่ตัวนับจะปิดฟอร์มของแถวที่สองไว้จนกว่าคำตอบของแถวแรกซึ่งถูกทิ้งไปแล้วจะมาถึง
ซึ่งเป็นการเปลี่ยน UI (`docs/06` §Out of Scope) รุ่นแรกของการแก้ให้การอ่านปลดเฉพาะเมื่อยังเป็นการกด

### มัตแตนต์

ก่อนแก้ (19 ก.ย. 2569 ที่ `8bb9a92`) แถวที่อ่าน *บันทึก* ทุกแถวล้มที่ assertion ของตัวเอง
