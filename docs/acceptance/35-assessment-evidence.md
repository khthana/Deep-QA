# ใบตรวจรับ #35 — หลักฐานการประเมิน

[#35](https://github.com/khthana/Deep-QA/issues/35) · หน้าจอ `/teacher/teacherDashboard/:sectionId/learningActivities/:activityId/evidence`

## สิ่งที่ต้องเข้าใจก่อนเดิน

**ตั๋วนี้มีอยู่เพราะข้อบกพร่องด้านความปลอดภัยสองข้อ พอ ๆ กับเพราะตัวฟีเจอร์** ทั้งสองข้ออยู่ในตัวตั๋วเอง
ไม่ใช่หมายเหตุที่ผัดไว้ทีหลัง และทั้งสองข้อคือเหตุผลที่โค้ดชุดนี้หน้าตาเป็นอย่างที่เป็น

**ข้อแรก — การตรวจชนิดไฟล์ไม่มีที่อยู่ จึงไม่ได้อยู่ที่ไหนเลย** `evidenceUpload.js` ที่ส่งมอบมามีหกบรรทัด
คือ memory storage กับ `limits.fileSize` และ **ไม่มี `fileFilter` เลย** BR-15 บอกว่ารองรับเฉพาะ PDF
และมันไม่ได้ถูกบังคับที่เบราว์เซอร์ ไม่ได้ถูกบังคับที่เซิร์ฟเวอร์ และไม่ได้ถูกบังคับที่ schema ด้วย —
migration 0003 เขียนไว้ตรง ๆ ว่าจงใจ เพราะคอลัมน์นั้นเก็บสตริงที่ผู้อัปโหลดเป็นคนเขียน

การตรวจจึงอยู่ที่ **ไบต์** `looksLikePdf` อ่านห้าไบต์แรก การทดสอบที่อัปโหลด `.png` แล้วดูมันถูกปฏิเสธ
พิสูจน์ได้แค่ว่ามีคนอ่านนามสกุล — แถวที่มีความหมายคืออัปโหลด**ไบต์ของ PNG ที่ชื่อ `brief.pdf`
และประกาศตัวว่าเป็น `application/pdf`** เพราะสองอย่างหลังผู้อัปโหลดเขียนเองได้ ส่วนลายเซ็นเขียนไม่ได้

**ข้อสอง — ไดเรกทอรีตอบทุกคน** `app.use('/static', express.static('/data/evidence'))` หนึ่งบรรทัด
ไม่มีด่าน ไฟล์หลักฐานทุกไฟล์ในระบบเปิดได้โดยใครก็ตามที่รู้หรือเดาที่อยู่ถูก รวมถึงผลงานของนักศึกษา
และที่อยู่นั้นสร้างจาก `Date.now()` กับชื่อไฟล์เดิม การเดาจึงไม่ใช่เรื่องไกลตัว

ที่นี่ **ไม่มี static mount** `GET /evidence/:id/file` อ่านแถว ตัดสินว่า *คนนี้* มีสิทธิ์เปิด *ไฟล์นี้* หรือไม่
แล้วจึงอ่านไบต์ — รูปเดียวกับทุกการอ่านในระบบนี้ (ADR-0002) และเป็นสิ่งเดียวที่ไดเรกทอรีสถิตทำไม่ได้เลย

**สองทางเข้า ไม่ใช่ทางเดียว** อาจารย์เข้าถึงหลักฐานของตอนเรียนที่ตัวเองสอน — `sectionOf` ตอบข้อนั้น
เหมือนทุก route ที่มี grain เป็นตอนเรียน ส่วนกรรมการหลักสูตรกับผู้ประเมินภายนอกเข้าถึงด้วย **คนละทาง**:
drill-down ของ #42 เอ่ยชื่อหลักฐานที่ตัวเลขตั้งอยู่บนอยู่แล้ว และเขียนบนจอว่าการเปิดไฟล์รอตั๋วนี้ สิทธิ์ของ
พวกเขาไม่ใช่ *คุณสอนตอนเรียนนี้* — พวกเขาไม่ได้สอนอะไรเลย — แต่คือ *ไฟล์นี้ห้อยอยู่กับกิจกรรมที่ผูกกับ
CLO ของหลักสูตรที่คุณอ่านได้* ซึ่งเป็นเส้นทางเดียวกับที่ drill-down เดินลงมา หลวมกว่านี้แปลว่ายื่นผลงาน
นักศึกษาของหลักสูตรหนึ่งให้คนอ่านของอีกหลักสูตรหนึ่ง

**ชื่อไฟล์ที่เก็บไม่เคยเป็นชื่อที่ส่งมา** service ที่ส่งมอบมาสร้าง path บนดิสก์จาก `Date.now()` บวกชื่อไฟล์
ของผู้ใช้ นั่นคือ path ที่ผู้อัปโหลดเป็นคนเขียน: `../` ในชื่อพาออกนอกโฟลเดอร์ และสองไฟล์ในมิลลิวินาที
เดียวกันชนกัน ที่นี่ชื่อบนดิสก์เป็นชื่อสุ่มที่โมดูลเลือกเอง ส่วนชื่อที่ส่งมาอยู่ใน `file_name` ซึ่งใช้แสดงผล
กับใส่ `Content-Disposition` เท่านั้น

**ลบแล้วยังอยู่ แต่เปิดไม่ได้** migration 0003 กำหนดให้ evidence เป็น soft delete และพ่อแม่เป็น RESTRICT
เพราะมันคือสิ่งที่การตรวจประกันคุณภาพจะถูกนำมาดู *เปิดไม่ได้แล้ว* จึงเป็นคุณสมบัติของ **แถว** ไม่ใช่ของดิสก์:
ทุกการอ่านที่นี่ ทั้งรายการและตัวไฟล์ เป็น `NOT is_deleted` และคนที่ถือ id เดิมได้ ไม่พบ

**ทำไมหน้านี้ใช้ multipart ทั้งที่การนำเข้าอื่นไม่ใช้** `client.js` อธิบายไว้ว่าไฟล์ CSV ส่งเป็น `text/csv`
เพราะ input อ่านไฟล์เป็นตัวอักษรได้ และไม่ต้องเขียนอะไรลงดิสก์ PDF ไม่ใช่ตัวอักษร และมันมาพร้อมสองฟิลด์ —
ประเภทหลักฐาน กับคำอธิบายที่ **อาจเอ่ยชื่อนักศึกษา** การใส่คำอธิบายลง query string คือการเขียนมันลง
access log ทุกตัวที่คำขอผ่าน อันนี้จึงเป็น multipart ซึ่งคือสิ่งที่ฟอร์มที่มีไฟล์กับสองฟิลด์เป็นอยู่แล้ว

## ข้อมูลที่ใช้เดิน

`activity_evidence` ใน seed **ว่างเปล่า** ทุกแถวที่เดินจึงต้องแนบไฟล์ของตัวเองก่อน แล้วเก็บกวาดเอง
ทั้งฝั่ง HTTP และฝั่งเบราว์เซอร์ทำแบบนั้น และ `EVIDENCE_DIR` ของทั้งสองชุดชี้ไปที่ไดเรกทอรีของตัวเอง
ใต้ temp ของระบบ — การรันชุดทดสอบจึงไม่แตะ `_local/evidence` และไม่ทิ้งอะไรไว้ในต้นไม้

ตอนเรียน **1** ของ `teacher.one@` มีกิจกรรม 6 รายการ กิจกรรมแรกผูกกับ CLO ที่ชี้ไป **PLO-2**
ซึ่งเป็นข้อที่ drill-down ของ #42 เปิดได้ กรรมการ `prog.manager@` (0501) จึงเปิดไฟล์ของมันได้
และ `prog.manager.0503@` เปิดไม่ได้

### สิ่งที่การกวาดจับได้ในชุดทดสอบเอง ไม่ใช่ในโค้ด

รอบแรก `openaskstheservernothing` ควรฆ่าแถว 1 ตัวเดียว แต่ฆ่าแถว 2 ไปด้วย สาเหตุไม่ได้อยู่ที่โค้ด:
แถว 1 เก็บกวาดไฟล์ของตัวเอง **ต่อเมื่อมันผ่าน** พอมัตแตนต์ทำให้มันล้ม ไฟล์จึงค้างบนชั้น แล้วแถว 2
ซึ่งยืนยันว่า *ชั้นว่าง* ก็ล้มตาม ข้ออ้าง "ชั้นว่าง" จึงเป็นจริงโดยบังเอิญมาตลอด

แก้สองที่: แถว 1 ย้ายการเก็บกวาดไปอยู่ใน `finally` และแถว 2 เปลี่ยนไปยืนยันว่า **ไฟล์นี้ไม่อยู่บนชั้น**
แทนที่จะยืนยันเรื่องทั้งชั้น กวาดซ้ำแล้วมัตแตนต์ตัวนั้นฆ่าแถว 1 ตัวเดียว

**กวาดซ้ำอีกรอบหลังการเดินด้วยมือ** เพราะการเดินแก้ `ActivityEvidence.js` กับ `ProgramLevelByIntake.js`
ซึ่งอยู่ในชุด `FILES` ของสคริปต์นี้ ผลออกมาตรงกับตารางข้างบนทุกช่อง — สี่ตัวฆ่าแถวของตัวเองตัวเดียว
และ `uploadsendsnofile` ฆ่าสามแถวด้วยเหตุผลเดิม ป้ายอ่านออกเสียงที่การเดินแก้ไม่ได้เพิ่มมัตแตนต์ตัวใหม่
เพราะถ้อยคำเป็นแถวที่ตาคนถือ ไม่ใช่แถว ⚙

## สิ่งที่รีวิวสองแกนเจอ และแก้ไปแล้ว

ทุกข้อข้างล่างนี้เขียวก่อนรีวิว — ชุดทดสอบผ่านหมด และไม่มีข้อไหนที่ชุดทดสอบเดิมจะเห็นได้

**คำขอที่ไม่มี body เลย ตอบ 500** `blankToNull(req.body.evidence_type)` — multer คืนค่าออกก่อน
ถ้าคำขอไม่ใช่ multipart และ body parser ปล่อย `req.body` เป็น `undefined` การอ่านฟิลด์จึง throw
แล้วถูกตอบว่า *เกิดข้อผิดพลาดในระบบ* ซึ่งเป็นความสับสนแบบเดียวกับที่ `acceptFile` ที่อยู่ห่างไปสองบรรทัด
มีไว้เพื่อกำจัด `enrolment.js` กันข้อนี้ไว้แล้วด้วย `req.body ?? {}` · มีชุดทดสอบแล้ว

**PUT ล้าง `description` เสมอ** `description = $3` ไม่ผ่าน COALESCE ต่างจาก `evidence_type`
กับ `file_name` การเปลี่ยนไฟล์อย่างเดียวผ่าน HTTP จึงล้างคำอธิบายเงียบ ๆ หน้าจอไม่เจอเพราะ `formOf`
ส่ง `description` มาทุกครั้ง — **แต่สัญญาคือ endpoint ไม่ใช่หน้าจอ** ตอนนี้ *ไม่ส่งมา* กับ *ส่งมาว่าง*
เป็นคนละคำสั่ง · มีชุดทดสอบทั้งสองทาง

**บัฟเฟอร์ 50 MB ก่อนถามว่าเป็นตอนเรียนของใคร** `acceptFile` อ่าน body ทั้งก้อนเข้าหน่วยความจำ
ก่อน `sectionOf` จะได้ทำงาน บัญชีที่ถือ TEACHER อยู่จึงทำให้เซิร์ฟเวอร์ถือ 50 MB ไว้เพื่อตอนเรียนที่
ตัวเองไม่เกี่ยวได้ ย้ายการตรวจขึ้นเป็น middleware `withSection` ที่วางไว้ **ก่อน** `acceptFile`

**multer error ตัวอื่นยังหลุด** แปลงเฉพาะ `LIMIT_FILE_SIZE` ตัวอื่น ๆ (ไฟล์ที่สอง ฟิลด์ผิด body ขาด)
ยังไปถึง handler เป็น *เกิดข้อผิดพลาดในระบบ* ตอนนี้ `MulterError` ทุกตัวเป็น 400 พร้อมประโยคของตัวเอง

**ไม่มี `X-Content-Type-Options: nosniff`** ไฟล์เสิร์ฟด้วย `Content-Disposition: inline` ห้าไบต์
ของ `%PDF-` ไม่ได้ทำให้ส่วนที่เหลือเป็น PDF — ไฟล์ที่เป็นทั้ง PDF และอย่างอื่นจะถูกเบราว์เซอร์เดา
ในบริบทของแอปนี้เอง หนึ่งบรรทัด และเป็นเศษสุดท้ายของข้อบกพร่องเรื่องการดาวน์โหลด

**หัวไฟล์ `app.js` ตกยุค** มันเขียนว่า *"ยังไม่มี static evidence directory ซึ่งเป็นของ #35"* —
#35 มาแล้วและ **จงใจไม่สร้างมันเลย** เขียนใหม่ให้บอกเหตุผล เพราะ #47 (รูปโปรไฟล์) จะเจอทางเลือกเดียวกัน

**ทางเข้าที่สองไม่ได้อยู่ในตั๋ว** ตั๋วเขียนว่า *"an authenticated caller entitled to that Section"*
ซึ่งอ่านตรงตัวคือทางของอาจารย์อย่างเดียว และจะทำให้ drill-down ของ #42 เอ่ยชื่อไฟล์ที่คนอ่านหน้านั้น
เปิดไม่ได้ ทางที่สองจึงจงใจ และ **บันทึกไว้ใน ADR-0002** แล้ว ไม่ใช่แค่ในหัวไฟล์ของ route

**ใบ #42 แถว 5 อ้างเกินจริง** ติ๊ก ⚙ ให้ทั้งแถว ทั้งที่ `readerlockedout` พิสูจน์แค่ว่ากรรมการได้ไบต์
ไม่มี spec ไหนยืนยันว่าประโยคเดิมหายไป แยกเป็นสองแถวแล้ว: ครึ่งเปิดไฟล์ ⚙ ครึ่งถ้อยคำ ☐

**ที่รีวิวเสนอแต่ไม่แก้** โค้ดเปิดไฟล์ซ้ำกันห้าบรรทัดระหว่าง `ActivityEvidence.js` กับ
`ProgramLevelByIntake.js` — `lib/fields.js` เขียนกฎของ repo ไว้เองว่า **แยกออกมาเมื่อมีผู้เรียกรายที่สาม**
และรีวิวก็บอกอย่างเดียวกัน จึงปล่อยไว้จนกว่าจะมีรายที่สาม
