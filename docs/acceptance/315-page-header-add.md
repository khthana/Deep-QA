# ตรวจรับ — #315 ปุ่มเพิ่มหลักของทุกหน้าวาดผ่าน PageHeader

[#315](https://github.com/khthana/Deep-QA/issues/315) — `docs/ui-consistency.md` ข้อ 6 (คำตอบของเจ้าของงาน 27 พ.ย. 2569)
ปุ่มเพิ่มหลักเป็นไอคอน `IoMdAdd` สี `bg-secondary` มุมขวาบนเหนือรายการ วาดโดย `frontend/src/components/PageHeader.js`
ที่เดียว แทนปุ่ม `bg-primary` ไม่มีไอคอนที่แต่ละหน้าเขียนเอง · คำบนปุ่มคงเดิม จึงเป็นชื่อของปุ่มเหมือนเดิม

## สิ่งที่ตั๋วไม่ได้เขียน และวัดได้ตอนลงมือ (27 พ.ย. 2569)

- **ประชากรเป็นสิบหน้า ไม่ใช่เก้า** — ตั๋วนับปุ่มที่ขึ้นต้นด้วย *เพิ่ม* และ grep ทุกปุ่ม `bg-primary` ใน `pages/` พบอีกสอง:
  *เปิดรายวิชา* ของ `Offerings.js` และ *แนบหลักฐาน* ของ `ActivityEvidence.js` · สิบหน้าคือ Plos · Rubrics · RubricCriteria ·
  Offerings · CourseOutcomes · MeasurableBehaviors · AchievementCriteria · LearningActivities · TeachingPlan · ActivityEvidence
- **นักศึกษาในรายวิชา (`SubjectStudents.js`) ไม่ได้เปลี่ยน** — *เพิ่มนักศึกษา* ของมันเป็นปุ่มส่งของฟอร์มช่องเดียวที่เปิดอยู่ตลอด
  ไม่ใช่ปุ่มที่เปิดฟอร์ม และ docblock ของ `PageHeader.js` บอกไว้แล้วว่าหน้านี้ไม่ส่ง `onAdd` ด้วยเหตุนั้น · ปุ่มเพิ่มบนหัวหน้า
  จะต้องซ่อนช่องนั้น (เปลี่ยนพฤติกรรม และทุก spec ที่กรอก `#student_id` ตรง) หรือเป็นปุ่มที่แค่ย้ายโฟกัส — เป็นรูปเดียวกับ
  ช่อง *สร้างกลุ่ม* และ *เพิ่มกลุ่มเรียน* ที่ [#335](https://github.com/khthana/Deep-QA/issues/335) ถามเจ้าของงาน จึงเป็นคำถาม ไม่ใช่งาน
- **ปุ่มที่ตั๋วบอกว่า *ปิดอยู่วันนี้*** คือ *เพิ่ม Rubric* (ระหว่างรายการที่วาดเป็นของหลักสูตรอื่น #276) และ *เปิดรายวิชา*
  (ก่อนรู้ภาค #279) — `PageHeader` รับ `addDisabled` · ปุ่มของ `SubjectStudents` ที่ตั๋วนับเป็นปุ่มส่ง ดูข้อบน
- **ระหว่างที่ฟอร์มเปิด ปุ่มซ่อนทุกหน้า** (เกณฑ์ข้อ 3) — เป็นสิ่งที่ทั้งสิบหน้าทำอยู่แล้ว: หน้าผู้ดูแลสามหน้าที่ฟอร์มแทนที่
  รายการ (Plos · RubricCriteria · Offerings) ซ่อนทั้งหัว และหกหน้าอาจารย์ที่ปุ่ม *กลายเป็น* ฟอร์ม ซ่อนปุ่ม · ถูกที่สุด เพราะ
  ไม่มีอะไรต้องเปลี่ยน และตั๋วหน้าต่างลอย #319–#334 จะถามใหม่ · หน้าอาจารย์ไม่วาด `PageHeader` เลยระหว่างนั้น เพราะแถบเปล่า
  จะเพิ่มช่องว่างเหนือฟอร์ม · Rubrics แก้ในแถว ปุ่มเพิ่มจึงอยู่ตลอดอย่างเดิม
- **มัตแตนต์ 23 ตัว re-aim** เพราะการย้ายเลื่อนการเยื้อง (21 ตัว ทั้งที่เดิม ในรูปเดิม) และ `disabled` กลายเป็น `addDisabled`
  (`21:addduringload` · `279:s279openbeforeterm` เอา prop ออก — ความผิดเดียวกัน) · ทุกตัวติดหนี้การกวาดใน #336
  เพราะการ re-aim ไม่ได้พิสูจน์อะไร (#107 #68)

## รายการที่ต้องเดิน

ช่องสุดท้ายมีสี่ค่า

- **☑** เดินด้วยมือจบแล้ว หรือพิสูจน์ที่ seam HTTP แล้ว — **สองอย่างนี้เป็น ☑ เท่ากัน** ⚙ สงวนไว้ให้ browser seam เท่านั้น และแถวบอกเองว่าอะไรพิสูจน์มัน (`CLAUDE.md` §Marks on the sheets · [#194](https://github.com/khthana/Deep-QA/issues/194))
- **◐** เดินไปได้ครึ่งเดียว อีกครึ่งยังไม่ได้เดิน — **แถวนั้นบอกไว้เองว่าครึ่งไหนยังขาด และครึ่งนั้นรออะไร** · ส่วนใหญ่ครึ่งที่เดินแล้วคือครึ่งของ server และครึ่งที่เหลือคือสิ่งที่หน้าจอวาด (แถบสี ตาราง dropdown) ซึ่งยังต้องมีคนดู — **แต่นั่นเป็นกรณีที่พบบ่อย ไม่ใช่นิยาม** ครึ่งที่เหลือรออยู่สามอย่าง คือ **คน** (เช่น attribute ที่ไปถึง DOM แล้ว แต่ยังไม่มีใครเปิดโปรแกรมอ่านหน้าจอฟัง) · **ตั๋ว** ซึ่งแถวจะอ้างเลขไว้ · หรือ **ไม่รออะไรเลย** เพราะไม่มีตัวควบคุมบนจอสร้างคำขอนั้นได้ ซึ่งเป็น ◐ ถาวรโดยโครงสร้าง — **สามอย่างนี้นับแยกกัน** (`CLAUDE.md` §Marks on the sheets · [#157](https://github.com/khthana/Deep-QA/issues/157))
- **☐** ยังไม่ได้เดิน
- **⚙** ครอบคลุมด้วย browser seam แล้ว (#65) ไม่ต้องเดินด้วยมือซ้ำ แถวบอกไฟล์ที่ครอบคลุมไว้ และมาร์กนี้ได้มาเมื่อมัตแตนต์ฆ่า assertion ของแถวนั้นเอง — **ถ้าแถวนั้นพูดถึงสิ่งที่วาดด้วย (เมนู ถ้อยคำ สี) ครึ่งนั้นยังเป็นงานของคนเดิน และแถวจะเขียนกำกับไว้** (`CLAUDE.md` §Two test seams · [#194](https://github.com/khthana/Deep-QA/issues/194))
