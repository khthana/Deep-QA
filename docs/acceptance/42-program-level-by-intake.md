# ใบตรวจรับ #42 — ผลการเรียนรู้ระดับหลักสูตรตามปีรับเข้า

[#42](https://github.com/khthana/Deep-QA/issues/42) · หน้าจอ `/main/programLevelByIntake`

## สิ่งที่ต้องเข้าใจก่อนเดิน

**หน้านี้ไม่เก็บอะไรเลย** ทุกตัวเลขบนจอเป็นความเห็นเกี่ยวกับคะแนนที่ #34 บันทึกไว้ เหมือน #38
ต่างกันที่ระดับ — #38 ถามว่า *ตอนเรียนหนึ่งทำได้แค่ไหนกับผลการเรียนรู้รายวิชาข้อหนึ่ง* ส่วนหน้านี้ถามว่า
*นักศึกษารุ่นหนึ่งทำได้แค่ไหนกับผลการเรียนรู้ระดับหลักสูตรข้อหนึ่ง จากทุกรายวิชาที่รุ่นนั้นเรียนมา*

**การรวบยอดมีสองขั้น และสองขั้นนี้สลับกันไม่ได้**

1. คะแนนของนักศึกษาหนึ่งคนต่อ CLO หนึ่งข้อ — กฎของ #38 ไม่เปลี่ยนเลย: ได้เท่าไรหารด้วยที่มีให้ทำ
   คูณห้า ช่องที่ยังไม่มีคะแนนถูกตัดออกจากทั้งเศษและส่วน
2. คะแนนของคนคนนั้นต่อ PLO หนึ่งข้อ — **ค่าเฉลี่ยของคะแนน CLO** ทุกข้อที่ชี้มาที่ PLO นั้น
   โดยแต่ละ CLO นับหนึ่งเสียงเท่ากัน

ขั้นที่สองเป็นการตัดสินใจ ไม่ใช่สิ่งที่กฎข้อไหนเขียนไว้ **ผู้ใช้เลือกไว้ก่อนสร้าง** และเป็นกฎเดียวกับ
ที่ระบบเดิมใช้ (`DEEP-QA-BACKEND/services/ploScoreService.js`) ทางเลือกอีกทางคือรวมคะแนนดิบทั้งกอง
ซึ่งเป็นกฎของ #38 ยกขึ้นมาอีกชั้น — แต่จะทำให้ CLO ที่บังเอิญมีงานวัดเยอะพูดแทน PLO ของมันดังกว่า
CLO ที่มีงานวัดน้อย โดยไม่มีอะไรในข้อกำหนดบอกว่าควรเป็นเช่นนั้น และกรรมการที่อ่านว่า
*PLO-2 คือค่าเฉลี่ยของ CLO สามข้อที่รับใช้มัน* ตรวจเลขตามได้ ส่วนน้ำหนักที่มองไม่เห็น ตรวจไม่ได้

**กฎทั้งหมดย้ายไปอยู่ที่ `backend/lib/attainment.js` แล้ว** ตอน #38 มันอยู่ในไฟล์ route ของ #38 เอง
ซึ่งเป็นเหตุผลทั้งหมดที่ไฟล์นั้นมีอยู่ พอ #42 ต้องใช้ทุกข้อเหมือนกันเป๊ะ สำเนาที่สองของการ normalise
คือหนี้ชนิดที่ไม่ส่งเสียงตอนมันเพี้ยน — สองหน้าจอจะยังวาดตัวเลขที่ดูสมเหตุสมผลต่อไป และมีแต่คนที่เอา
สองใบมาวางข้างกันเท่านั้นที่จะเห็นว่ามันไม่ตรงกัน

**เกณฑ์ข้อ 5 ทำได้ครึ่งเดียวโดยตั้งใจ** หน้าจอ *เอ่ยชื่อ* หลักฐานของกิจกรรมที่เป็นที่มาของตัวเลข แต่
*เปิดไม่ได้* — [#35](https://github.com/khthana/Deep-QA/issues/35) เป็นเจ้าของทั้งการอัปโหลดและการ
ดาวน์โหลดที่ตรวจสิทธิ์ก่อน และหนึ่งในสองข้อบกพร่องที่ตั๋วนั้นมีไว้แก้คือระบบเดิมเสิร์ฟโฟลเดอร์หลักฐาน
เป็นไฟล์สถิตโดยไม่ตรวจอะไรเลย ปุ่มดาวน์โหลดที่นี่จึงเท่ากับเขียนเกณฑ์ของ #35 ซ้ำอีกรอบโดยไม่มีด่าน
**ผู้ใช้ตัดสินใจข้อนี้เมื่อ 3 ก.ย. 2569**

**ผู้ประเมินภายนอกอ่านหน้านี้ได้** ไม่ใช่เพราะข้อกำหนดบอก แต่เพราะเปลือกหน้าจอส่งเขามาที่นี่อยู่แล้ว
และเขียนเหตุผลไว้ที่ `frontend/src/components/SidebarItem/ExtAssessor.js` — เมนูของบทบาทนี้มีรายการ
เดียวและชี้มาที่นี่ ถ้า route ปฏิเสธเขา เมนูนั้นจะพาไปสู่คำปฏิเสธ ชุดหน้าจอที่ถูกต้องของบทบาทนี้ยังเป็น
[#49](https://github.com/khthana/Deep-QA/issues/49) และรายชื่อ `READERS` คือที่ที่มันจะเปลี่ยน

## ข้อมูลที่ใช้เดิน

seed มีสองรุ่น — **2566** (113 คน สองตอนเรียนของการเปิดสอนปี 2569) และ **2565** (60 คน ตอนเรียนเดียว
ของปี 2568) ทั้งสองรุ่นเรียนรายวิชาเดียวกันคนละปี หลักสูตร 0501 มีผลการเรียนรู้ข้อหลักสิบสามข้อ และ
**เจ็ดข้อเท่านั้นที่มี CLO ชี้มา** — อีกหกข้อจึงเป็นแถวที่ไม่มีใครถูกวัด ซึ่งเป็นกรณีที่เกณฑ์ข้อ 1 พูดถึง

**รุ่น 2566 กินสองตอนเรียนที่สอนโดยคนละคน** จึงเป็นข้อมูลที่ทำให้เกณฑ์ข้อ 2 ตรวจได้จริง — การรวบยอด
ที่หยุดอยู่ที่ตอนเรียนเดียวจะรายงานครึ่งรุ่นโดยไม่บอกใคร

### สองตัวที่ต้องเขียนใหม่ก่อนจะเชื่อได้

กวาดรอบแรกไม่ผ่านสองตัว และทั้งสองสอนคนละเรื่อง

**`drilldownwontclose` ไม่ฆ่าใครเลย** แถว 3 ถามแค่ว่าหัวข้อของแผงหายไปหรือยัง และการกดซ้ำที่
*ดึงข้อมูลใหม่* แทนที่จะหุบ ก็ทำให้แผงว่างไปชั่วขณะระหว่างรอคำตอบ — คำยืนยันจึงผ่านบนช่องว่างไม่กี่
ร้อยมิลลิวินาที ระหว่างทางไปสู่แผงเดิมที่กลับมา แถวนี้ตอนนี้อ่าน **ปุ่ม** ซึ่งเขียนว่า *ซ่อนที่มา* ตลอดเวลา
ที่ข้อนั้นเปิดอยู่ และไม่ได้เป็นอย่างอื่นชั่วขณะ

**`intakefrozen` ฆ่าทั้งหกแถว** ตัวเดิมตัดปีออกจาก dependency array ของ effect ซึ่งทำให้รายงาน
*แรก* ไม่โหลดด้วย — หน้าจอหายไปทั้งหน้า ไม่ใช่แค่ตัวเลือกที่ขับอะไรไม่ได้ มัตแตนต์ที่เอาหน้าจอไปทั้งหน้า
ไม่ได้พิสูจน์อะไรเกี่ยวกับแถวที่มันถูกเขียนมาเพื่อ ตัวใหม่แก้ที่ตัวจัดการ `onChange` ให้เมินตัวเลือกที่ถูกเลือก
แล้วใส่ปีล่าสุดกลับไป — รายงานยังวาด ตัวเลขยังถูกต้องสำหรับรุ่นที่มันแสดง และสิ่งเดียวที่ผิดคือมันเป็น
รุ่นเดิมเสมอ
