# ตรวจรับด้วยมือ — #24 Teacher dashboard and Section context

`docs/06-implementation-plan.md` §Acceptance กำหนดว่า ticket หนึ่งจะเสร็จเมื่อ automated test ผ่าน
**และ** checklist ที่ทำด้วยมือถูกเดินจนครบ เอกสารนี้คือครึ่งหลังของ #24

ครึ่งแรกอยู่ที่ `backend/test/teaching.test.js` (10 subtests) — ทุกเกณฑ์ที่พิสูจน์ได้ที่ seam ของ
HTTP surface ถูกพิสูจน์ที่นั่นแล้ว รวมทั้งข้อ 8 ที่ตั๋วสั่งให้มีเทสต์ตรง ๆ คือการปฏิเสธข้ามตอนเรียน
โดยใช้ผู้สอนใน seed ที่ไม่ได้สอนอะไรเลย

seam ที่สองคือเบราว์เซอร์ — `e2e/tests/24a-teacher-dashboard.spec.js` (7 ข้อ) ดูหัวข้อ
*มัตแตนต์ที่พิสูจน์แถว ⚙* ท้ายเอกสาร ซึ่งเป็นเหตุผลว่าทำไมแถวเหล่านั้นถึงถือว่าครอบแล้วจริง

## หน้าจอนี้ต่างจากทุกหน้าก่อนหน้าอย่างไร

**บริบทอยู่ในที่อยู่ ไม่ได้อยู่ในความจำ** ทุกหน้าก่อนหน้านี้ทำงานกับสิ่งที่ผู้ใช้กรอกหรือกรองในหน้านั้นเอง
หน้านี้เป็นหน้าแรกที่ *เลือกอะไรบางอย่างไว้* แล้วหน้าถัดไปทั้งหมดทำงานกับสิ่งนั้น สิ่งที่ถือมันไว้คือ
`section_id` ใน URL และไม่มีอะไรอื่นเลย — ADR-0004 ระบบที่รับสืบมาเก็บไว้ใน `localStorage` ด้วยชื่อ
`{subject_name_en}-Section-{n}` ซึ่งชี้ไปที่ตอนเรียนสองตอนทันทีที่วิชาหนึ่งถูกสอนสองปี ซึ่งเป็นรูปร่าง
ปกติของ seed ไม่ใช่กรณีโชคร้าย

**สองด่าน และตอบคนละคำถาม** `requireRole('TEACHER')` ตัดสินว่า route เปิดให้หรือไม่ และอ่านจาก
บทบาทที่ *กำลังสวมอยู่* ส่วนทะเบียนผู้สอน (`course_sections_teacher`) ตัดสินว่าตอนเรียนไหนไปถึงได้
ด่านหนึ่งไม่ได้แทนอีกด่าน — เพื่อนร่วมภาควิชาผ่านด่านแรกทุกคน และตอนเรียนของเขาก็ยังไม่ใช่ของเรา

**เทอมมาจากปฏิทิน ไม่ได้มาจาก config** `db/term.js` แปลงวันที่เป็น (ปีการศึกษา, ภาค) ตามกฎของคณะ —
มิ.ย.–ต.ค. คือภาคต้น ที่เหลือคือภาคปลาย และปีการศึกษาเปลี่ยนที่เดือนมิถุนายนพร้อมกัน `db/seed.js`
อ่านฟังก์ชันเดียวกัน ซึ่งเป็นเหตุผลที่ฐานข้อมูลที่เพิ่ง seed จะมีของอยู่บนหน้านี้เสมอ

## ตั้งต้น

```
docker start deep-core-postgres
cd db      && npm run reset && npm run migrate && npm run seed
cd backend && npm start          # http://localhost:3000
cd frontend && npm start         # http://localhost:5000
```

**ต้อง reset + seed ใหม่จริง ๆ ก่อนเดินใบนี้** ไม่ใช่ `npm run seed` เฉย ๆ — seed เดิมที่ค้างจาก
ตั๋วก่อนหน้าใส่ปีการศึกษาไว้เป็นค่าคงที่ `2568` การเปิดสอนของมันจึงไม่ใช่เทอมปัจจุบันอีกแล้ว และหน้านี้
จะว่างเปล่าด้วยเหตุผลที่ไม่ใช่ข้อบกพร่อง

**ต้อง restart backend ก่อนเดิน** — process ที่ค้างจากตั๋วก่อนจะตอบ 404 ให้ทุก route ของ #24

ทุกบัญชีใน seed ใช้รหัสผ่านเดียวกัน คือ `deep-core-local` — ค่าของตัวแปร `PASSWORD` ใน `db/seed.js`
ไม่ใช่คำว่า `PASSWORD` เมนูที่ใช้ตลอดเอกสารนี้คือ *รายวิชา* (`/teacher/teacherDashboard`)

seed หลังเดินคำสั่งข้างบนจะมีการเปิดสอนสองรายการ ทั้งคู่เป็นวิชา `01076105` ของหลักสูตร `0501`
และ **ปีการศึกษากับภาคของรายการแรกคือเทอมที่ปฏิทินอยู่ตอนนี้** ไม่ใช่ `2568/2` อีกต่อไป

| ปีการศึกษา | ภาค | ตอนเรียน | ผู้สอน | นักศึกษา |
|---|---|---|---|---|
| เทอมปัจจุบัน | ตามปฏิทิน | `1` | `teacher.one@` | 57 คน |
| เทอมปัจจุบัน | ตามปฏิทิน | `2` | `multi.role@` | 56 คน |
| ปีก่อนหน้า | ภาคเดียวกัน | `1` | `teacher.one@` | 60 คน |

สามบัญชีที่ใบนี้ใช้ และเหตุผลที่ต้องเป็นสามบัญชี

- `teacher.one@` — สอนตอนเรียน `1` **ทั้งเทอมนี้และปีก่อน** จึงเป็นบัญชีเดียวที่แยกแยะได้ว่าหน้าจอกรอง
  ตามเทอมจริงหรือแค่แสดงทุกอย่างที่สอน ถ้าเห็นสองการ์ดคือผิด
- `teacher.two@` — **ไม่ได้สอนอะไรเลย** ใช้เดินสถานะว่าง และใช้เดินการปฏิเสธข้ามตอนเรียน
- `multi.role@` — ถือทั้ง `PROG_MANAGER` และ `TEACHER` และสวมตัวที่อาวุโสกว่าโดยปริยาย

## รายการที่ต้องเดิน

ช่องสุดท้ายมีสี่ค่า

- **☑** เดินจบแล้ว
- **◐** ครึ่งของ server เดินแล้วและผ่าน ส่วนที่เหลือคือสิ่งที่หน้าจอวาด (เมนู ถ้อยคำ) ยังต้องมีคนดู
- **☐** ยังไม่ได้เดิน
- **⚙** ครอบคลุมด้วย browser seam แล้ว (#65) ไม่ต้องเดินด้วยมือซ้ำ แถวบอกไฟล์ที่ครอบคลุมไว้ ถ้าแถวนั้นพูดถึงสิ่งที่วาดด้วย (เมนู ถ้อยคำ สี) ครึ่งนั้นยังเป็นงานของคนเดิน และแถวจะเขียนกำกับไว้

## บันทึกการเดินด้วยมือ

เดินเมื่อ **23 สิงหาคม 2569** โดยอาจารย์ที่ปรึกษา บน dev stack (postgres 5433 schema `deep_core`,
backend 3000, frontend 5000) ทุกแถวที่ไม่ใช่ ⚙ เดินจบและผ่านทั้งหมด รวมทั้งขากลับของแถว 7 ซึ่ง
ไม่มีเทสต์ใดครอบ สิ่งที่ควรรู้สำหรับคนที่จะเดินซ้ำ

**backend ที่ค้างอยู่จะตอบ 404 ที่อ่านเหมือนเน็ตมีปัญหา** การเดินรอบนี้เสียเวลาไปกับเรื่องนี้ก่อน
เป็นอันดับแรก เส้นทางของ #24 เพิ่งถูกเพิ่ม แต่ process ของ backend สตาร์ตค้างมาตั้งแต่ก่อนหน้านั้น
node ไม่โหลดโค้ดใหม่เอง `/api/teaching/sections` จึงตอบ 404 พร้อม body `{"error":"Not found"}`
ซึ่งไม่มีฟิลด์ `message` หน้าจอเลยตกไปใช้ข้อความสำรองว่า *เกิดข้อผิดพลาดในการเชื่อมต่อเซิร์ฟเวอร์*
ทั้งที่การเชื่อมต่อปกติดี — **ถ้าเพิ่งเพิ่ม route ใหม่ ต้องรีสตาร์ต backend ก่อนเดิน**

**การ reset ฐานข้อมูลไม่ได้ทำให้ใครหลุดจากระบบ** session เป็น JWT ที่ตรวจด้วยลายเซ็น ไม่ได้ตรวจกับ
ตารางใด และ seed ใส่แถวกลับด้วยลำดับเดิม `user_id` จึงเป็นเลขชุดเดิม คุกกี้เก่าเลยยังใช้ได้จริง
ปิดเบราว์เซอร์ก็ไม่หายเพราะคุกกี้มี `maxAge` ตามที่ #69 ตั้งใจ ล้างได้ด้วยปุ่มออกจากระบบเท่านั้น

**เลขที่ใช้เดินรอบนี้** ตอนเรียนของเทอมปัจจุบันคือ `section_id` 1 (57 คน) ของปีก่อนคือ 3 (2568)
และตอนเรียนของ `multi.role@` คือ 2 (ตอนเรียน 2 ปี 2569) เลขพวกนี้มาจาก seed ที่สร้างใหม่ทั้งชุด
ถ้า reset อีกครั้งลำดับเดิมก็ให้เลขเดิม แต่อย่าเชื่อโดยไม่ตรวจ

**หนี้ที่การเดินรอบนี้เปิดเจอ** 404 ของ `backend/app.js:101` ตอบด้วยฟิลด์ `error` ขณะที่ทุกการ
ปฏิเสธอื่นในระบบตอบด้วย `message` และ `frontend/src/api/client.js:83` อ่านเฉพาะ `message`
เส้นทางนี้จึงเป็นเส้นทางเดียวที่ทำให้หน้าจอบอกสาเหตุผิด

### ทำไม `notoken` ถึงเป็นตัวที่ควรอ่านก่อน

ADR-0004 แทนที่ `%SUBJECT%` ที่อ่านจาก `localStorage` ด้วย `section_id` ที่อ่านจากที่อยู่ และบรรทัด
เดียวที่ทำการแทนที่นั้น **ไม่มี assertion อยู่ที่ไหนเลยตอนที่ commit แรกของตั๋วนี้ผ่าน** โทเคนที่ไม่ถูก
แทนที่จะพาไปที่ path ที่ยังมีคำว่า `%SECTION%` อยู่ ซึ่ง router ส่งต่อไปที่ `NotBuiltYet` — บนหน้าจอ
แยกไม่ออกเลยจากหน้าที่ยังไม่ได้สร้างจริง ๆ ซึ่งตอนนี้มีสิบสามหน้า ทุกแถวที่เหลือในไฟล์ผ่านหมดโดยที่
บรรทัดนั้นพัง แถวที่เพิ่มเข้ามาทีหลังจึงเป็นแถวเดียวในไฟล์ที่กดรายการในเมนูจริง ๆ

### ทำไม `staydashboard` ถึงฆ่าสามแถวแล้วยังเก็บไว้

แถว 3 แถวเมนู และแถว 5 เป็นผลสามอย่างของข้ออ้างเดียวกัน คือ *ที่อยู่เป็นตัวถือบริบท* มัตแตนต์ที่เอา
id ออกจากที่อยู่จึงควรฆ่าทั้งสาม และตัวที่ฆ่าได้แค่หนึ่งจะแปลว่าอีกสองแถวผ่านด้วยเหตุผลอื่น สิ่งที่แยกแยะ
*ระหว่าง* สามแถวนั้นอยู่ที่อื่น — `notoken` สำหรับเมนู และ `rememberedsection` สำหรับการรีเฟรช

### บรรทัด 102 ของแถว 3 ไม่มีมิวแตนต์ของตัวเอง

แถว 3 ยืนอยู่บน assertion สองบรรทัด บรรทัด 102 ว่าสิ่งที่อยู่ในที่อยู่เป็นตัวเลข
(`toMatch(/^\d+$/)`) และบรรทัด 103 ว่าหน้าที่เปิดขึ้นคือตอนเรียนนั้น มิวแตนต์ในชุดนี้
ฆ่าบรรทัด 103 (`nosectionnumber`) และฆ่าการตอบ 200 ใน helper (`staydashboard`)
แต่ **ไม่มีตัวไหนฆ่าบรรทัด 102 โดยตรง** — ถ้า `sectionInUrl` คืนค่าคงที่เป็นตัวเลข
บรรทัดนั้นก็ยังผ่าน

ที่ไม่เขียนมิวแตนต์นั้นเพราะตัวที่เขียนได้จะพิสูจน์อะไรไม่ได้เลย มิวแตนต์ที่แก้ helper
เป็นมิวแตนต์ของเทสต์ไม่ใช่ของโปรแกรม ส่วนมิวแตนต์ที่ใส่เลขที่เป็นตัวเลขแต่ผิดตัว
(เช่น `section_number` แทน `section_id`) จะตายที่ helper อีกเหมือนกัน คือไม่ได้แยกอะไรใหม่
จึงบันทึกช่องว่างนี้ไว้ตรง ๆ แทนที่จะเติมมันด้วยมิวแตนต์ที่พิสูจน์น้อยกว่าที่มันดูเหมือนจะพิสูจน์

## สิ่งที่ตัดสินใจไว้และควรรู้ก่อนแก้

### ทำไมเทอมถึงเดินทางกลับมาพร้อมรายการ

`GET /api/teaching/sections` ตอบ `{ term, sections }` ไม่ใช่ `sections` เฉย ๆ เพราะเกณฑ์ข้อ 2 ขอ
สถานะว่างที่อธิบายตัวเอง และ *"ท่านไม่มีตอนเรียนในภาคต้น ปีการศึกษา 2569"* เป็นคนละประโยคกับ
*"ยังไม่มีอะไรที่นี่"* หน้าจอแต่งประโยคแรกเองไม่ได้ถ้าไม่มีใครบอกว่า server มองไปที่เทอมไหน และ
หน้าจอที่อ่านนาฬิกาของตัวเองจะไม่ตรงกับ server หนึ่งวันต่อปี — วันที่เทอมเปลี่ยนพอดี ซึ่งเป็นวันเดียว
ที่มีคนสังเกตเห็น

### ทำไมการอ่านทีละตอนถึงไม่จำกัดเทอม

หน้าหลักเสนอเฉพาะตอนเรียนของเทอมนี้ แต่ผู้สอนที่ตามลิงก์ไปหาตอนเรียนของปีที่แล้วกำลังขอตอนเรียนที่
เขาสอนจริง และทะเบียนผู้สอนก็ยืนยันแบบนั้น การปฏิเสธตรงนั้นคือการเอากฎของ *รายการ* ไปบังคับเป็น
กฎของ *สิทธิ์* ซึ่งเป็นความสับสนที่ ADR-0002 มีไว้กัน มัตแตนต์ `currenttermonly` คือรูปร่างของ
ข้อผิดพลาดนั้น

### ทำไมตอนเรียนที่ไม่ใช่ของตัวเองถึงเป็น 404 ไม่ใช่ 403

คำตอบประจำบ้านสำหรับ GET ทีละรายการ ย้อนไปได้ถึง `departmentNotFound` — ประโยคเดียวสำหรับ
แถวที่ไม่มีอยู่จริงและแถวที่ไม่ใช่ของคุณ เพราะสองประโยคทำให้ไล่เลข id หาได้ว่าตอนเรียนไหนมีจริง
ประโยคที่ใช้คือ `sectionNotFound` ซึ่ง #23 เขียนไว้แล้ว

### ทำไมปีที่นักศึกษาเข้าถึงไม่ได้เลื่อนตามนาฬิกา

`COHORTS` ใน `db/seed.js` มี `year` ที่เดินตามปฏิทินและ `admission` ที่เป็นค่าคงที่ ทั้งสองเคยห่างกัน
สองปีตอนที่เขียน และตอนนี้ห่างขึ้นเรื่อย ๆ ตั้งใจให้เป็นแบบนั้น — `backend/test/students.test.js`
อ่านรหัส `66010001` กับ `65010001` กลับมาด้วยชื่อ เพราะข้ออ้างว่า *"ปีที่เข้าศึกษาถูกถอดมาจากรหัส"*
ต้องมีรหัสที่เขียนไว้จริงถึงจะเป็นข้ออ้างได้ และไม่มีอะไรในระบบอ่านช่องว่างระหว่างสองปีนั้น

### รายวิชาเดียวทั้งระบบ ยังเป็นข้อจำกัดอยู่

`docs/acceptance/23-offerings.md` บันทึกไว้แล้วว่า seed มีรายวิชาเดียว หน้านี้จึงเดินได้แค่การ์ดเดียว
ต่อบัญชี แถวที่อยากเห็น *หลายการ์ดเรียงกัน* ต้องเปิดรายวิชาที่สองเองก่อนด้วย `prog.manager@` แล้ว
กำหนด `teacher.one@` เป็นผู้สอน — ไม่ใช่ข้อบกพร่องของ #24 แต่เป็นสิ่งที่คนเดินจะสะดุดถ้าไม่รู้
