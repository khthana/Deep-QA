# ตรวจรับ — #319 ข้อมูลภาควิชา: ฟอร์มเพิ่ม/แก้ไขเป็นหน้าต่างลอย

[#319](https://github.com/khthana/Deep-QA/issues/319) — `docs/ui-consistency.md` ข้อ 8 (คำตอบของเจ้าของงาน 27 พ.ย. 2569)
ฟอร์มของ `DepartmentForm` วาดใน `frontend/src/components/FormDialog.js` ซึ่งเป็นของใหม่ และเป็นเปลือกที่ #320–#334 จะใช้ทีละหน้า ·
หน้าตาลอกจาก `components/users/AddUserDialog.js` (#304) · `pages/Departments.js` วาดรายการตลอด และวาดหน้าต่างเมื่อ `editing`

## รูปนี้คือแม่แบบของอีกสิบห้าหน้า

สิ่งที่ตัดสินที่นี่จะถูกลอกไปทุกหน้าของ #320–#334 เว้นแต่เจ้าของงานจะค้าน:

- **ทำตาม `Users.js` หลัง #304 และ #307 ทีละบรรทัด** ไม่ได้ออกแบบใหม่ — ข้อ 8 กับตั๋วชี้ไปที่การเพิ่มผู้ใช้งานเป็นแบบ และ #307
  คือคำตอบของเจ้าของงานต่อรูปเดียวกันนี้พอดี (ฟอร์มในหน้าต่างเหนือรายการ แบนเนอร์ของหน้าอยู่หลังผ้าคลุม) · สิ่งที่ลอกมาคือ
  `refused` (คำปฏิเสธของการบันทึกของหน้าต่างเอง ล้างเมื่อหน้าต่างไป) · `refuse()` (ไปที่แบนเนอร์ของหน้าเมื่อหน้าต่างปิดไปแล้ว) ·
  `{!editing && <Notice/>}` · **ยกเลิกไม่ล้างแบนเนอร์** (สิ่งที่อยู่ในมันลงมาระหว่างหน้าต่างเปิดและยังไม่มีใครอ่าน)
- **`FormDialog` เป็นเปลือกร่วม** `AddUserDialog` ไม่ได้ถูกเขียนใหม่ผ่านมัน เพราะมัตแตนต์ของ #304 ยึดบรรทัดของมัน — สองไฟล์นี้
  เหมือนกันด้วยการเดินมือ ไม่ใช่ด้วยไฟล์เดียว และเป็นทางเลือกที่ย้อนได้
- **ฟอร์มไม่มีกล่องและหัวของตัวเองแล้ว** หัวเป็นของหน้าต่าง (`h2` ที่เป็นชื่อของ dialog) ด้วยคำเดิม *เพิ่มภาควิชา* / *แก้ไขภาควิชา*
  — `openEditor` ของ `e2e/support/departments-screen.js` และทุกแถวที่หาหัวนี้จึงหาเจอเหมือนเดิม

## สามอย่างที่ตั๋วขอ และ `AddUserDialog` ไม่มี

- **Escape ไม่ทำอะไรระหว่างการบันทึกค้าง** (`saving={writing}`) — คำของตั๋ว · ปุ่ม *ยกเลิก* ในฟอร์มยังกดได้ระหว่างนั้น เพราะเป็นของ
  #228 และ #249 ที่ตัดสินไว้แล้วสำหรับจอนี้ (19 แถวของ `142a` และ `146a` จัดสถานการณ์ด้วยการกดมัน) · ทางออกสองทางจึงต่างกัน
  ระหว่างการบันทึกค้าง และความต่างนั้นเป็นของตั๋ว · `writing` เป็นธงของหน้า จึงกันทั้งการลบที่ค้างอยู่ด้วย (ทางเข้าคือ Escape
  ที่กล่องยืนยันขณะ `busy` แล้วกด *เพิ่มภาควิชา*) ซึ่งกว้างกว่าที่ตั๋วเขียนเล็กน้อย และไม่มีแถวใดถือ
- **โฟกัสกลับไปที่สิ่งที่เปิดมัน** — ปุ่ม *เพิ่มภาควิชา* หรือ *แก้ไข* ของแถว · ทำใน `FormDialog` ไม่ใช่ใน `useModalFocus` เพราะ
  `ConfirmDialog` และหน้าต่างนำเข้าใช้ hook นั้นด้วยและไม่มีตั๋วขอ
- **`!m-0` บนผ้าคลุม** ซึ่ง `AddUserDialog` มี — ไม่อย่างนั้น `space-y-6` ของหน้าดันผ้าคลุมลง 24 px (#274)

## สิ่งที่รีวิวพบ (27 พ.ย. 2569)

- **โฟกัสคืนผิดใน StrictMode และพังใน production** ในร่างแรก — cleanup ที่คืนโฟกัสวิ่งก่อนตัวกักโฟกัสถูกถอด แก้แล้ว: อ่าน
  ผู้เปิดตอน render แรก และประกาศ effect คืนโฟกัสหลัง `useModalFocus`
- **ประโยคที่ลงมาระหว่างหน้าต่างเปิดถูกประโยคสำเร็จเขียนทับ** — รูปเดียวกับ `Users.js` ตั้งแต่ #304/#307 จึงเป็นคำถามถึงเจ้าของงาน
  ไม่ใช่งานของตั๋วนี้: [#337](https://github.com/khthana/Deep-QA/issues/337)
- **หลังบันทึกการแก้ไขสำเร็จ โฟกัสตกไปที่ `body`** — การโหลดใหม่วาด *กำลังโหลด…* แทนแถว ปุ่ม *แก้ไข* ที่เปิดหน้าต่างจึงหลุดจาก
  เอกสารก่อนที่หน้าต่างจะคืนโฟกัส · `319a` แถว 2 อ่านโฟกัสหลัง *ยกเลิก* ซึ่งไม่โหลดใหม่ จึงไม่เห็นข้อนี้ · ไม่ได้แก้: เป้าสำรอง
  ต้องเลือกว่าคืนไปที่ไหน (แถวที่วาดใหม่ · ตาราง · หัวหน้า) ซึ่งเป็นคำถามของหน้าตา ไม่มีแถวใดถือ

## census

- **`held-sentences.js` ไม่ต้องเปลี่ยนประชากร** — มันอ่าน `setNotice(<ref>.current.said)` และสามส่วนของการรอ ซึ่งบรรทัดของ
  `Departments.js` ไม่ได้เปลี่ยนเลย · ยังเขียวที่ held 8 · marked 2 · เมื่อหน้าอื่นของ #320–#334 ลง ข้อนี้ต้องถามใหม่ทีละหน้า
- **`save-window-fields.js` มองไม่เห็น Escape** — คำถามที่สามของมันหาปุ่มที่ส่งคืนฟอร์มด้วยกลไก (`<button>` ที่ `onClick` ส่งต่อให้ prop)
  และ Escape เป็นตัวฟังบน `window` ใน `useModalFocus` · จึงเป็นทางส่งคืนที่มันนับไม่ได้ · `319a` แถว 3 คือสิ่งที่ถือข้อนี้แทน

## spec ที่ต้องกลับไปดูเมื่อรันรอบรวม

นับจาก `e2e/` 27 พ.ย. 2569 — 28 แฟ้มเปิดหน้านี้ หาสามชนิดที่รูปใหม่เปลี่ยนความหมาย:

- **ตัวหาตำแหน่งแบบหลวมบนคำที่ตอนนี้วาดสองครั้ง** (หัวตารางกับป้ายของช่อง · *ใช้งานอยู่* / *ปิดใช้งาน* ของป้ายสถานะกับ
  ตัวเลือก · *เพิ่มภาควิชา* ของปุ่มกับหัวหน้าต่าง) — ไม่พบ `getByText` บนคำเหล่านี้ · `statusField` หาด้วยบทบาท `combobox`
  ซึ่งตารางไม่มี · หัว `เพิ่มภาควิชา` หาด้วยบทบาท `heading` ซึ่งปุ่มไม่ใช่ · `locator('table').first()` ของ `139a` `142a` `146a`
  เป็นตารางของรายการ เพราะหน้าต่างไม่มีตาราง
- **จุดนิ่งที่รอให้ตาราง แถว หรือปุ่มเพิ่ม *กลับมา* เป็นหลักฐานว่าฟอร์มปิด** — ตอนนี้ผ่านทันทีเพราะมันอยู่ตลอด · ที่พบคือแถว 1 ของ
  `14c` (`departmentRow(page, '05')` หลังยกเลิก) ซึ่งยังเป็นจริงแต่ไม่ได้พิสูจน์ว่าหน้าต่างไปแล้ว · แถว 2 ที่ต่อท้ายใช้หน้าต่างหาย
  เป็นจุดนิ่งแทน · แถวของ `146a` `202a` `228a` `249a` `298a` อ่าน *หัวของฟอร์มหายไป* ซึ่งยังถูก
- **แถวที่ assert ว่าตารางไม่อยู่ระหว่างฟอร์มเปิด** — ไม่พบในแฟ้มของหน้านี้ (`246a` เป็นของหน้า PLO)

สิ่งที่ grep ไม่เห็นและการรันจะบอก: แถวที่กดปุ่มของรายการ*ระหว่าง*หน้าต่างเปิด (ผ้าคลุมรับการคลิก) — รูปเดิมทำไม่ได้เพราะรายการไม่อยู่ จึงไม่น่ามี

## รายการที่ต้องเดิน

ช่องสุดท้ายมีสี่ค่า

- **☑** เดินด้วยมือจบแล้ว หรือพิสูจน์ที่ seam HTTP แล้ว — **สองอย่างนี้เป็น ☑ เท่ากัน** ⚙ สงวนไว้ให้ browser seam เท่านั้น และแถวบอกเองว่าอะไรพิสูจน์มัน (`CLAUDE.md` §Marks on the sheets · [#194](https://github.com/khthana/Deep-QA/issues/194))
- **◐** เดินไปได้ครึ่งเดียว อีกครึ่งยังไม่ได้เดิน — **แถวนั้นบอกไว้เองว่าครึ่งไหนยังขาด และครึ่งนั้นรออะไร** · ส่วนใหญ่ครึ่งที่เดินแล้วคือครึ่งของ server และครึ่งที่เหลือคือสิ่งที่หน้าจอวาด (แถบสี ตาราง dropdown) ซึ่งยังต้องมีคนดู — **แต่นั่นเป็นกรณีที่พบบ่อย ไม่ใช่นิยาม** ครึ่งที่เหลือรออยู่สามอย่าง คือ **คน** (เช่น attribute ที่ไปถึง DOM แล้ว แต่ยังไม่มีใครเปิดโปรแกรมอ่านหน้าจอฟัง) · **ตั๋ว** ซึ่งแถวจะอ้างเลขไว้ · หรือ **ไม่รออะไรเลย** เพราะไม่มีตัวควบคุมบนจอสร้างคำขอนั้นได้ ซึ่งเป็น ◐ ถาวรโดยโครงสร้าง — **สามอย่างนี้นับแยกกัน** (`CLAUDE.md` §Marks on the sheets · [#157](https://github.com/khthana/Deep-QA/issues/157))
- **☐** ยังไม่ได้เดิน
- **⚙** ครอบคลุมด้วย browser seam แล้ว (#65) ไม่ต้องเดินด้วยมือซ้ำ แถวบอกไฟล์ที่ครอบคลุมไว้ และมาร์กนี้ได้มาเมื่อมัตแตนต์ฆ่า assertion ของแถวนั้นเอง — **ถ้าแถวนั้นพูดถึงสิ่งที่วาดด้วย (เมนู ถ้อยคำ สี) ครึ่งนั้นยังเป็นงานของคนเดิน และแถวจะเขียนกำกับไว้** (`CLAUDE.md` §Two test seams · [#194](https://github.com/khthana/Deep-QA/issues/194))
