# ตรวจรับด้วยมือ — #12 Role grants

`docs/06-implementation-plan.md` §Acceptance กำหนดว่า ticket หนึ่งจะเสร็จเมื่อ automated test ผ่าน
**และ** checklist ที่ทำด้วยมือถูกเดินจนครบ เอกสารนี้คือครึ่งหลังของ #12

ครึ่งแรกอยู่ที่ `backend/test/grants.test.js` (36 subtests) เกณฑ์ข้อ 6 และข้อ 8 ถูกพิสูจน์ไว้ครบที่นั่น
โดยเจตนา — ทุกคำปฏิเสธในไฟล์นั้นเกิดจากการยิง request ตรงไปที่ API พร้อม cookie จริง ไม่ใช่การ
ตรวจว่า dropdown ไม่ได้แสดงตัวเลือกนั้น ซึ่งเป็นถ้อยคำของเกณฑ์ข้อ 8 ตรงตัว
ส่วนที่เหลือลงมาอยู่ในตารางข้างล่างเพราะ docs/06 §Testing Decisions ระบุว่า
**"Frontend components are not unit-tested"**

## ตั้งต้น

```
docker start deep-core-postgres
cd db      && npm run seed
cd backend && npm start          # http://localhost:3000
cd frontend && npm start         # http://localhost:5000
```

ทุกบัญชีใน seed ใช้รหัสผ่านเดียวกัน คือค่า `PASSWORD` ใน `db/seed.js`
เมนูที่ใช้ตลอดเอกสารนี้คือ *ผู้ใช้งานระบบ* (`/main/users`) → กด *แก้ไข* ที่แถวของใครสักคน
แผง *บทบาทที่ได้รับ* จะอยู่ใต้ฟอร์มข้อมูลส่วนตัว

หลายข้อข้างล่างเขียนข้อมูลจริงลงฐานข้อมูล — **`npm run seed` ใหม่หลังเดินจบ** ก่อนเริ่มตั๋วถัดไป

## สิ่งที่เปิดเผยไว้ว่าเบี่ยงจากตั๋ว

1. **ปฏิเสธการจับคู่บทบาทที่เข้าด้วยรหัสผ่านกับบทบาทที่เข้าด้วย Google** ตั๋วไม่ได้ขอ แต่ `backend/routes/me.js`
   ของ #10 เขียนโน้ตไว้ว่า "#11 is where granting is written, and that is where the pairing has to be refused"
   #11 สร้างสถานการณ์นี้ไม่ได้ (บัญชีละหนึ่งบทบาท) #12 เป็น route แรกที่สร้างได้ จึงปฏิเสธที่นี่ —
   บัญชีที่บทบาทสูงสุดคือ `FULL_ADMIN` หรือ `EXT_ASSESSOR` จะถือบทบาทที่ต้องเข้าผ่าน Google พร้อมกันไม่ได้
   (`REFUSALS.roleNotCombinable`) ถ้าอาจารย์เห็นว่ากฎนี้ควรอยู่ที่อื่น ให้ย้ายได้
2. **ยกเลิกบทบาทของตัวเองไม่ได้** ตั๋วไม่ได้ขอ แต่เป็นกฎเดียวกับที่ #11 ใช้กับการระงับบัญชีตัวเอง
   ผู้ดูแลที่ถอดบทบาทสุดท้ายของตัวเองจะถูกล็อกออกใน request ถัดไป และคนที่ใส่กลับให้ได้ต้องอาวุโสกว่าเสมอ
3. **ยกเลิกบทบาทที่มีขอบเขตนอกเขตรับผิดชอบไม่ได้** ถึงแม้เจ้าของบัญชีจะอยู่ในเขตก็ตาม —
   สมมาตรกับกฎตอนให้ ตอบ `403 scopeNotYours`

## ข้อค้างจาก #12

1. **ยกเลิกบทบาทสุดท้ายได้** ตั๋วข้อ 3 เขียนว่า "revoke a grant, and the grantee loses that access" ไม่มีข้อยกเว้น
   จึงไม่ได้ห้าม บัญชีที่ไม่เหลือบทบาทจะเข้าระบบไม่ได้ (`REFUSALS.noRole`) และผู้ดูแลต้องใส่กลับให้ —
   ถ้าอาจารย์เห็นว่าควรเตือนก่อน ให้เปิดตั๋วใหม่
2. **แผง *บทบาทที่ได้รับ* ยังไม่บอกชื่อคนที่กำหนด** แสดงเป็นรหัสผู้ใช้ (`deptadm05`) เพราะ route
   ตอบเฉพาะ `assigned_by` การ join ชื่อกลับมาต้องอ่านบัญชีคนอื่นเพิ่มอีกหนึ่งครั้ง
3. **`GET /api/users/grantable` อ่านชื่อคณะ/ภาควิชา/หลักสูตรตรงจากตาราง** ซึ่งเป็นงานของ #14/#15
   ที่นี่อ่านเฉพาะ id ที่อยู่ใน `coveredScopes` อยู่แล้วกับชื่อไทยสำหรับแสดงผล ไม่ได้เปิดรายการทั้งมหาวิทยาลัย
4. **ข้อค้างเดิมจาก #11 ที่ #12 ปิดไปหนึ่งข้อ** ข้อ 7 (รายชื่อบทบาทอยู่สามที่) ปิดแล้ว —
   `ROLES` ใน `UserForm.js` ถูกถอดออกและถามเซิร์ฟเวอร์แทน ส่วนข้อ 6 (`coveredScopes` คำนวณซ้ำ)
   ปิดด้วย memoisation ต่อ request ใน `auth/administration.js` ข้อ 1 (ผู้ดูแลรีเซ็ตรหัสผ่านไม่ได้) ยังค้าง
