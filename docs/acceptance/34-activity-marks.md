## สิ่งที่ต้องเข้าใจก่อนเดิน

**สวิตช์สองตัวไม่ใช่การเก็บสองแบบ** `activity_scores.clo_id` เป็น NOT NULL — migration 0003
อธิบายไว้ยาวว่าทำไม — จึงไม่มีสิ่งที่เรียกว่า *คะแนนของกิจกรรม* ในฐานข้อมูล มีแต่คะแนนต่อผลการเรียนรู้
สวิตช์ *ต่อกิจกรรม / ต่อผลการเรียนรู้* จึงเป็นเรื่องของ **การพิมพ์** ไม่ใช่การเก็บ: พิมพ์ทีเดียวแล้ว
เซิร์ฟเวอร์แบ่งตามน้ำหนักของแต่ละแถว และอ่านกลับด้วยการบวกกลับ

เพราะอ่านกลับด้วยการบวก **การแบ่งจึงต้องลงตัวพอดี ไม่ใช่ใกล้เคียง** เศษจากการปัดจึงถูกยกไปไว้ที่
แถวแรก ไม่ปล่อยให้หายไป คนที่พิมพ์ 61 แล้วเปิดมาเห็น 60.99 มีสิทธิ์ไม่เชื่อหน้าจอนี้ทั้งหน้า

**คะแนนของกลุ่มเป็นของนักศึกษา ไม่ใช่ของกลุ่ม** สวิตช์ *รายกลุ่ม* เขียนเลขเดียวกันให้สมาชิกทุกคน และ
ไม่มีอะไรจำไว้ว่ามันมาด้วยกัน ซึ่งถูกแล้ว — คนที่ถูกย้ายกลุ่มทีหลัง (#26) ยังถือคะแนนที่เคยได้ ไม่ใช่คะแนน
ของกลุ่มใหม่ ผลที่ตามมาบนจอคือ **ช่องของกลุ่มจะมีเลขก็ต่อเมื่อสมาชิกทุกคนถือเลขเดียวกัน** ถ้าไม่ตรงกัน
ช่องจะว่าง ไม่ใช่หยิบของคนแรกมาแสดงแทนทุกคน

**ช่องว่างไม่ใช่ศูนย์** ช่องที่เว้นไว้คือ *ยังไม่ได้ให้คะแนน* และถูกบันทึกเป็น null คนที่ตั้งใจให้ศูนย์
ต้องพิมพ์ศูนย์ หน้าจอที่แปลงช่องว่างเป็นศูนย์จะตัดคะแนนทั้งห้องตั้งแต่ครั้งแรกที่เปิดแล้วกดบันทึก

**ไฟล์นำเข้าเป็นรายคนเสมอ** เกณฑ์ข้อ 7 ให้ตรวจสี่อย่าง — จำนวนนักศึกษา รหัส ชื่อ และคอลัมน์ CLO —
ทั้งสี่เป็นเรื่องของนักศึกษา ไฟล์จึงเป็นบัญชีรายชื่อ และสวิตช์ต่อ-CLO เปลี่ยน *คอลัมน์* ของไฟล์
ไม่ใช่ *แถว* ส่วนสวิตช์กลุ่มเป็นวิธีพิมพ์บนจอเท่านั้น (การตัดสินใจของผู้ใช้ 2 ก.ย. 2569)

**สวิตช์กลุ่มตั้งต้นตามชนิดของกิจกรรม แล้วปล่อยให้เลือกเอง** งานกลุ่มเปิดมาที่ *รายกลุ่ม* งานเดี่ยว
เปิดมาที่ *รายคน* แต่เปลี่ยนได้ทั้งคู่ — ชนิดของงานเป็นข้อเท็จจริง ส่วนวิธีกรอกเป็นเรื่องของผู้สอน

**กิจกรรมที่ยังไม่ผูกผลการเรียนรู้บันทึกคะแนนไม่ได้** และหน้าจอบอกไว้ตรงนั้น ไม่ใช่ปล่อยให้กดบันทึก
แล้วค่อยปฏิเสธ กิจกรรม *ใบงานที่เพิ่งสร้าง…* ของ seed เป็นตัวนี้พอดี

## ตั้งต้น

```
docker start deep-core-postgres
cd db      && npm run reset && npm run migrate && npm run seed
cd backend && npm start          # http://localhost:3000
cd frontend && npm start         # http://localhost:5000
```

**ต้อง kill แล้ว start backend ใหม่ก่อนเดิน** — `node server.js` ไม่มี reload กระบวนการที่ค้างจาก
ตั๋วก่อนจะตอบ 404 ให้ทุก route ของ #34 ในขณะที่หน้าจอ hot-reload ตามปกติ **จอจึงดูใหม่ทั้งที่
server เป็นของเก่า**

ทุกบัญชีใน seed ใช้รหัสผ่าน `deep-core-local` — ค่าของตัวแปร `PASSWORD` ใน `db/seed.js`

ทางเข้าคือ เลือกตอนเรียนจากหน้า *รายวิชา* แล้วกดเมนู **คะแนนกิจกรรมการเรียนรู้** ทางซ้าย
ที่อยู่คือ `/teacher/teacherDashboard/<section_id>/activityScores`

seed หลังเดินคำสั่งข้างบนมีรูปร่างที่ใบนี้ต้องใช้พอดี

| กิจกรรม | ชนิด | คะแนนเต็ม | ผลการเรียนรู้ | แบ่งข้อละ |
|---|---|---|---|---|
| โครงงานย่อยที่ 1 — คลาสและอ็อบเจกต์ | กลุ่ม | 100 | CLO-1, CLO-2 | 50 / 50 |
| โครงงานย่อยที่ 2 — การสืบทอดและพอลิมอร์ฟิซึม | กลุ่ม | 100 | CLO-3, CLO-4 | 50 / 50 |
| โครงงานปลายภาค | กลุ่ม | 100 | CLO-5, CLO-8, CLO-9 | 34 / 33 / 33 |
| สอบกลางภาค | เดี่ยว | 100 | CLO-1, CLO-3, CLO-6 | 34 / 33 / 33 |
| สอบปลายภาค | เดี่ยว | 100 | CLO-5, CLO-6, CLO-7 | 34 / 33 / 33 |
| ใบงานที่เพิ่งสร้าง… | เดี่ยว | 20 | **ไม่มีเลย** | — |

**นักศึกษาทุกคนมีคะแนนครบทุกกิจกรรมอยู่แล้ว** seed เขียนไว้ให้ทั้ง 2249 แถว ใบนี้จึงเป็นการ *แก้*
คะแนน ไม่ใช่การกรอกจากศูนย์ ซึ่งตรงกับเกณฑ์ข้อ 4 พอดี — และแปลว่า **ต้องนับก่อนและหลัง**

ตอนเรียน 1 มี **6 กลุ่ม · 57 คน** และกิจกรรมละ `57 × จำนวน CLO` แถวคะแนน

## บันทึกการเดินด้วยมือ

**เดินจบแล้ว 2 ก.ย. 2569** โดย Claude ขับ Chrome ให้ผู้ใช้ดู (ผู้ใช้เป็นคนลงชื่อเข้าใช้เอง)
บนสแตกเดินมือ พอร์ต 3000/5000 สคีมา `deep_core`

**นับก่อน–หลัง** `SELECT count(*) FROM activity_scores` = **2249** ทั้งสองครั้ง และ
`WHERE score IS NULL` = **0** ตอนจบ คะแนนของ `66010001` ที่ถูกล้างเพื่อเดินแถว *ช่องว่างคือ
ยังไม่ให้คะแนน* ถูกเขียนกลับเป็น 31.48/26.49/25.41 ตามเดิม

สิ่งที่เห็นจริงบนจอ

- เข้าทางเมนู **คะแนนกิจกรรมการเรียนรู้** ของตอนเรียน 1 แล้วหน้าเปิดจริง ไม่ใช่ *ยังไม่ได้สร้าง*
- ล้างช่องของ `66010001` แล้วบันทึก — ทั้งสาม CLO เป็น **NULL ไม่ใช่ 0** และจำนวนแถวไม่ขยับ
  (upsert แก้ ไม่ใช่เพิ่ม) ส่วนถ้อยคำใต้หัวข้อเขียนไว้ว่า *ช่องที่เว้นว่างหมายถึง ยังไม่ให้คะแนน ไม่ใช่ศูนย์*
- งานกลุ่มเปิดมาที่ *รายกลุ่ม* งานเดี่ยวเปิดมาที่ *รายคน* และสลับเองได้ทั้งคู่
- แถบปฏิเสธห้าแบบ ไม่มีแบบไหนเป็น *เกิดข้อผิดพลาดในระบบ* สักครั้ง — สองแบบจากหน้าจอ
  (`bg-red-50` `text-red-800`) และสามแบบจากไฟล์ ทุกแบบเอ่ยสิ่งที่ผิดของตัวเอง:
  `99019999` · `66010005` พร้อมชื่อในทะเบียน *"วรเมธ พงษ์เจริญ"* · `CLO-1, CLO-3, CLO-6 ตามลำดับ`
- ปุ่มแบบฟอร์มอ่านสวิตช์ปัจจุบันจริง — ยิง `?mode=clo` แล้ว `?mode=activity` ตามที่กดไว้
  และหัวตารางของสองไฟล์ต่างกัน (`student_id,full_name_th,score` กับ
  `student_id,full_name_th,CLO-1,CLO-3,CLO-6`)
- *แบบฝึกหัดท้ายบท* ซึ่งยังไม่ผูก CLO ขึ้นแถบ `bg-amber-50` `text-amber-700` ว่ายังบันทึกไม่ได้
  และ**ไม่มีตารางกับไม่มีปุ่มบันทึก**
- ที่ 607px ตารางเลื่อนในกรอบ `overflow-x-auto` ของตัวเอง (576 > 510) และหน้าไม่เลื่อนข้าง
- ไฟล์ที่ถูกปฏิเสธทั้งสามไม่เขียนอะไรเลย — ไม่มีแถว `score = 10` อยู่ในตารางสักแถว

### สิ่งที่การเดินจับได้ และสาม seam ไม่จับ

**ช่องคะแนนรวมของ `66010003` อ่านได้ `88.66999999999999`**

ส่วนแบ่งที่เก็บไว้ตรงเป๊ะ — 32.08 · 31.27 · 25.32 — แต่หน้าจออ่านคะแนนรวมด้วยการ**บวกกลับ
ใน JavaScript** และผลบวกนั้นไม่ได้ปัดเศษ ฝั่งเซิร์ฟเวอร์ปัดทั้งตอนหารและตอนเก็บ ทางอ่านกลับไม่เคยปัด

มันโผล่เฉพาะกับคะแนนที่ส่วนแบ่งบวกกันไม่ลงตัวในฐานสอง ซึ่งเป็นเหตุผลว่าทำไม 25 subtests
14 แถวเบราว์เซอร์ และ 14 มัตแตนต์ถึงไม่เจอ — `61` กับ `12.5` ที่ชุดทดสอบพิมพ์นั้นหารแล้วบวกกลับ
ได้พอดีทุกครั้ง **ต้องใช้ข้อมูลจริงถึงจะเห็น** และนี่คือสิ่งที่ seam ที่สามมีไว้เพื่อ

## คำตอบที่ถูกแทนที่ — #133 (16 ก.ย. 2569)

**จอนี้ถือทั้งสองตระกูลของ #133 พร้อมกัน และเป็นจอเดียวที่ถือ** สามจุดของมันคือ `load`
(`ActivityScores.js:179`) ที่อ่านคะแนนของกิจกรรมที่เลือกอยู่ · **คำตอบของการบันทึก** (`:312`)
ซึ่งวาดเหมือนการอ่านทุกประการ · และ `loadList` (`:130`) ที่ดึงตัวเลือกให้ `<select>` เอง
สองจุดแรกแทนได้ด้วยตัวควบคุมบนจอนี้ จึงได้แถวและมัตแตนต์ของตัวเอง จุดที่สามแทนได้ด้วย
การเดินทางเท่านั้น จึงได้ธงกับย่อหน้าข้างล่าง

**ตั๋วจัดจอนี้ไว้ผิดครึ่งของตารางตัวเอง** #133 เขียนไว้ว่าจอนี้อยู่ในกลุ่ม `useParams` ซึ่งจริง
เฉพาะ `sectionId` (ADR-0004) ส่วน `activityId` เป็น state ที่ `<select>` บนจอเป็นคนตั้ง
การเลือกกิจกรรมที่สองระหว่างที่ตารางแรกยังไม่กลับ จึงเป็นสิ่งที่ผู้สอนทำได้จริงโดยไม่ต้องเปลี่ยน
หน้าจอเลย — *What is wrong ของตั๋วเป็นข้ออ้างจากวันที่มันถูกเขียน วัดก่อนแก้* (#133 เองเป็น
ตัวอย่างที่เจ็ดของกฎข้อนั้น)

**และคำตอบของการบันทึกถามคำถามคนละข้อกับการอ่าน** ธงของ effect ตอบว่า *คำขอนี้ยังเป็นของ
รอบที่ยังไม่ถูกถอดหรือเปล่า* ซึ่งใช้กับ handler ไม่ได้ เพราะไม่มีอะไรถอด `save` ทิ้ง คำถามที่ถูก
คือ *ตัวเลือกยังอยู่ที่เดิมกับตอนที่ถูกส่งไปหรือเปล่า* และคำตอบคือ `const onScreen = useRef(activityId)`
กับ `if (onScreen.current === asked) setData(answer)` ส่วนแถบแจ้งผลพูดทุกครั้งและเอ่ยชื่อ
กิจกรรมที่บันทึก เพราะมันรายงานสิ่งที่ผู้สอนทำ ไม่ใช่สิ่งที่อยู่บนจอ

**และผู้เรียกที่สองของ `load` คือแผงนำเข้า ซึ่งได้ธงเดียวกันแต่ยังไม่ได้ทดสอบ**
`<ImportPanel onImported={…} />` เรียก `load` ใหม่หลังอัปโหลดไฟล์เสร็จ และ `ImportPanel`
ส่งอาร์กิวเมนต์ให้ไม่เลย (`components/ImportPanel.js:85` เรียกว่า `onImported?.()`)
การส่งต่อ**ด้วยชื่อ**แบบนั้นทำให้ grep ที่มองหา `load(` หามันไม่เจอ
รอบแรกของตั๋วจึงปล่อยให้มันรับค่าตั้งต้นว่า *ยังเป็นปัจจุบัน* ซึ่งผิดด้วยเหตุผลเดียวกับการบันทึก
คือ `<select>` กิจกรรมอยู่บนจอตลอดเวลาที่ไฟล์กำลังอัปโหลด ตอนนี้มันถาม `onScreen` เหมือนกัน
**แต่ไม่มีแถวของตัวเอง** เพราะการสร้างสถานการณ์ต้องอัปโหลดไฟล์ที่เขียนคะแนนทั้งห้องจริง
ซึ่งเป็นสิ่งที่แถวการนำเข้าของใบนี้เป็นเจ้าของ และการหน่วงคำตอบของมันไว้จะทำให้แถวนั้น
วัดคนละเรื่องกับที่มันตั้งใจวัด — *ยังไม่ได้ทดสอบ* ไม่ใช่ *ไม่ต้องมี* วัดเมื่อ 16 ก.ย. 2569

**ส่วน `loadList` ยังไม่ได้ทดสอบ ไม่ใช่ไม่ต้องมี** มันถามด้วย `sectionId` ตัวเดียว ซึ่งมาจาก
`useParams` (ADR-0004) สิ่งเดียวที่แทนคำขอของมันได้คือการเดินจากตอนเรียนหนึ่งไปอีกตอนบน
เส้นทางเดิมโดยคอมโพเนนต์ไม่ถูกถอด ซึ่งทุกลิงก์บนจอนี้เดิน*ขึ้น*ไปหารายการที่ถอดหน้านี้ทิ้ง —
วัดเมื่อ 16 ก.ย. 2569 และเป็นคำกล่าว**ที่มีวันหมดอายุ** ตั๋วที่เพิ่มทางเดินระหว่างตอนเรียนบน
เส้นทางนี้ ทำให้มันเข้าถึงได้ทันที และต้องมีแถวของตัวเองในวันนั้น รายการทั้งยี่สิบสองจุด

## รายงานของแผงนำเข้าเป็นของกิจกรรมของตัวเอง — #179 (1 ต.ค. 2569)

`ImportPanel` เก็บรายงานไว้ในสเตตของตัวเอง และรายงานนั้นเป็นเรื่องของ *กิจกรรมที่ไฟล์ถูกส่งไปให้*

**สองกลไก วัดเป็นตาราง ไม่ใช่เถียงว่าเลือกอันไหน** (#148) ลำดับที่ตั๋วเขียนไว้เป็นการแข่ง —
คำตอบของการนำเข้า A กลับมาตอนตัวเลือกอยู่ที่ B วัดแล้วเจอทางที่สองที่ไม่ต้องแข่งเลย คือ
**รายงานที่ลงมาแล้วค้างอยู่** เมื่อตัวเลือกย้าย เพราะไม่มีอะไรเคลียร์มัน ทางนั้นไม่ใช่หน้าต่างแคบ ๆ
มันอยู่จนกว่าจะรีโหลด และเป็นทางที่คนเจอ ทั้งสองทางถูกทำให้แดงก่อนแก้ แถวละคำกล่าวอ้าง —
`Expected: 0 / Received: 1` ทั้งสี่แถว โดยแถวที่ 1 กับที่ 3 อ่านสีเขียวของตัวเองผ่านก่อน
จึงไม่ใช่ตัวอ่านที่อ่านว่างทั้งตอนจอพังและตอนจอดี (#171)

**การแก้คือ prop ที่ผู้เรียกทุกรายถูกบังคับให้ส่ง** ซึ่งเป็นรูปที่ตั๋วเดาไว้เอง — `target` เทียบได้กับ

**ในการเรนเดอร์ ไม่ใช่ใน effect** เพราะ effect ที่คีย์บนการเปลี่ยนนั้นจะวาดค่าเก่าไปรอบหนึ่งก่อน (#167)

ข้างบน เพราะคำตอบของฝั่งที่สำเร็จผูกอยู่ข้างใน และการถามข้างบนจะทำให้จุดนั้นหายไปจาก
สำมะโนที่พบ #179 ตั้งแต่แรก — มันคือคำถามเดียวที่ถูกอ่านสองครั้ง ไม่ใช่สองความเห็น (#97)
