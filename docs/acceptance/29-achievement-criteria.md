รวมถึงครึ่งหนึ่งของ *คำอธิบายเป็นทางเลือก* ที่จอทำให้ดูไม่ได้ คือช่องที่ถูกลบจนว่างเก็บเป็น NULL
ไม่ใช่ `''`

seam ที่สองคือเบราว์เซอร์ — `e2e/tests/29a-achievement-criteria.spec.js` (8 แถว) ดูหัวข้อ
*มัตแตนต์ที่พิสูจน์แถว ⚙* ท้ายเอกสาร ซึ่งเป็นเหตุผลว่าทำไมแถวเหล่านั้นถึงถือว่าครอบแล้วจริง

## สิ่งที่ต้องเข้าใจก่อนเดิน — เกณฑ์การบรรลุผลเป็นของ CLO และของอย่างอื่นไม่มีเลย

`subject_clo_achievement_criteria` มีแค่ `clo_id` — ไม่มีตอนเรียน ไม่มีปี ไม่มีหลักสูตร ไม่มีเจ้าของ
ทั้ง ADR-0003 จึงมาถึงหน้านี้โดยการสืบทอดแบบเดียวกับ #28 ทุกประการ: เข้าผ่านตอนเรียนไหนของ
การเปิดสอนก็เห็นชุดเดียวกัน และ CLO รหัสเดียวกันของคนละปีถือคนละชุด `achievementCriteria.js`
ไม่ได้ถามคำถามสิทธิ์เอง — มัน import `offeringOf` กับ `cloOf` จาก `clos.js` และทุกการอ่านแถวเป็น
`WHERE id = $1 AND clo_id = $2` เสมอ

**สี่ระดับเป็น CHECK ไม่ใช่ enum และค่าที่เก็บคือคำไทยเอง** ดีเยี่ยม · ดี · พอใช้ · ต้องปรับปรุง —
คำเดียวกับที่ rubric ใช้ (ดูโน้ตใน migration 0002 ว่าทำไมถึงเป็น CHECK ที่ขยายได้ในตารางเดียว)
จอจึง**ไม่มีตารางป้าย** แบบ `labels.js` ของ #28: ค่าบนสายกับคำบนจอคือตัวเดียวกัน route
ยังตรวจในโค้ดก่อนถึงฐานข้อมูลเพราะ 23514 ที่ไปถึง error handler จะกลายเป็น
*เกิดข้อผิดพลาดในระบบ* — ประโยคผิดสำหรับค่าที่คนเลือกจากรายการ

**ระดับไม่ unique ต่อ CLO** ตั๋วบอกว่า CLO *สามารถ*ถือเกณฑ์ครบทั้งสี่ระดับ — เป็นความสามารถ
ไม่ใช่ข้อบังคับ — และ CLO หนึ่งถือหลายเกณฑ์ระดับเดียวกันได้ (เทสต์จัดเลขใหม่เขียนสามข้อ
ระดับเดียวกันเพื่อพิสูจน์ว่าไม่มีอะไรห้าม) constraint ที่บอกว่า *ต้อง* จะเป็นของที่ประดิษฐ์ขึ้นเอง
ไม่ใช่ของที่หามาได้จากที่ไหน

**คำอธิบาย (`criteria_description`) เป็นช่องเดียวที่ไม่บังคับ** คอลัมน์ nullable ช่องเว้นว่าง
ขาวล้วน หรือไม่ส่งมา ล้วนเก็บเป็น NULL — การแก้ที่ลบข้อความออกจนหมดจึงล้างคอลัมน์จริง
ไม่ใช่เก็บ `''` และจอวาดย่อหน้าคำอธิบายเฉพาะเมื่อมี (ขีดกลางจะสื่อว่าเป็นช่องที่ลืมกรอก
ซึ่งไม่ใช่)

**เลขลำดับเป็นของเซิร์ฟเวอร์ ไม่ใช่ของฟอร์ม** เพิ่มแล้วได้เลขถัดไป (ล็อกแถว CLO ก่อนนับ)
ลบแล้วที่เหลือถูกจัดใหม่เป็น 1..N ไม่มีช่องว่าง — `UNIQUE (clo_id, criteria_no)` ยึดตาม
ความเข้าใจนี้ไว้แล้วใน migration 0002 เลขใน body ถูกเมินแบบเดียวกับปีที่ส่งมาหา #27

**ไม่มีใครถูกบันทึกว่าเป็นคนแก้ และการลบไม่มีด่านกั้น** — คำตอบของ schema ทั้งคู่ แบบเดียวกับ
#28: ไม่มี `updated_by` และไม่มีตารางไหนอ้างถึงเกณฑ์การบรรลุผล กล่องยืนยันของหน้าจอ
คือด่านเดียว และประโยคในกล่องต้องบอกว่ากำลังจะลบข้อไหน

## ตั้งต้น

```
docker start deep-core-postgres
cd db      && npm run reset && npm run migrate && npm run seed
cd backend && npm start          # http://localhost:3000
cd frontend && npm start         # http://localhost:5000
```

**ต้อง reset + seed ใหม่จริง ๆ ก่อนเดินใบนี้** — `db/term.js` ทำให้ seed เดินตามนาฬิกา

**ต้อง kill แล้ว start backend ใหม่ก่อนเดิน** — `node server.js` ไม่มี reload ตรวจด้วยการ login
แล้วยิง `GET /api/teaching/sections/1/clos/<clo_id>/criteria` หนึ่งครั้ง ต้องได้ 200 พร้อมรายการ

ทุกบัญชีใน seed ใช้รหัสผ่านเดียวกัน คือ `deep-core-local`

ทางเข้า: เลือกตอนเรียนจากหน้า *รายวิชา* → เมนู **ผลการเรียนรู้รายวิชา** → กดลิงก์
**เกณฑ์การบรรลุผล** บนการ์ดของ CLO ที่ต้องการ (อยู่ข้างลิงก์ *พฤติกรรมบ่งชี้* ของ #28)
ที่อยู่ที่ได้คือ `/teacher/teacherDashboard/<section_id>/courseOutcomes/<clo_id>/criteria`

seed ให้ **CLO ทุกตัวของทั้งสองปีมีเกณฑ์ครบสี่ข้อ ข้อละหนึ่งระดับ เรียงจากดีสุด**:
ข้อ 1 ดีเยี่ยม · ข้อ 2 ดี · ข้อ 3 พอใช้ · ข้อ 4 ต้องปรับปรุง — ทุกข้อมีทั้งเกณฑ์การประเมิน
และคำอธิบาย (`เกณฑ์ระดับ…ของ CLO-…`)

| `section_id` (ที่อยู่) | ปีการศึกษา | ผู้สอน | ใช้เดินอะไร |
|---|---|---|---|
| `1` | 2569 (ปัจจุบัน) | `teacher.one@` | เกือบทุกข้อ |
| `2` | 2569 (ปัจจุบัน) | `multi.role@` (สลับเป็น *อาจารย์ผู้สอน* ก่อน) | ข้อชุดเดียวกันข้ามตอนเรียน |
| `3` | **2568 (ปีก่อน)** | `teacher.one@` | ข้อปีอื่นมีชุดของตัวเอง |
