## สิ่งที่ต้องเข้าใจก่อนเดิน

**หน้านี้ไม่เก็บอะไรเลย** ทุกอย่างบนจอคือคะแนนที่ #34 บันทึกไว้ อ่านผ่านกฎของ
`backend/lib/attainment.js` การเดินใบนี้จึงไม่เขียนอะไร ยกเว้นแถวที่จงใจสร้างสถานการณ์แล้วคืนค่า

**เกณฑ์ในคอลัมน์คือกฎ ไม่ใช่รูบริก** และนี่คือการตัดสินใจเดียวของตั๋วนี้

`subject_clo_achievement_criteria` ที่ #29 เขียนไว้ เก็บ**สี่ประโยค**ต่อหนึ่งข้อ —
ดีเยี่ยม / ดี / พอใช้ / ต้องปรับปรุง — และไม่มีตัวเลขอยู่ในนั้นเลยสักตัว ไม่มีอะไรในตารางนั้น
ตัดสินได้ว่านักศึกษาคนหนึ่งบรรลุผลการเรียนรู้ข้อหนึ่งหรือไม่ และ `lib/attainment.js` เขียนไว้ตรง ๆ
ว่าเส้นแบ่งจริงคือ `PASS = 3` จากห้า ซึ่ง *ไม่ได้มาจากตารางเกณฑ์* — ตกลงกันไว้ก่อนสร้าง #38
เพราะตารางนั้นเก็บประโยค ส่วน BR-17 พูดถึงแต่สัดส่วน

คอลัมน์ *เกณฑ์การบรรลุ* จึงเขียนกฎที่ตัดสินจริง และรูบริกสี่ระดับอยู่ใต้แผ่นพับเป็นข้อมูลอ้างอิง
ถ้าเอาประโยครูบริกไปวางในคอลัมน์นั้นแทน ผู้อ่านทุกคนจะเข้าใจว่าตัวเลขข้าง ๆ เกิดจากประโยคนั้น —
ความผิดพลาดชนิดเดียวกับที่ #39 เกือบวาดเส้นจากคะแนนใต้หัวเรื่องที่เขียนว่าร้อยละ

**เส้นแบ่งมีสองเส้น ไม่ใช่เส้นเดียว** `PASS` ตัดสินนักศึกษาหนึ่งคนต่อผลการเรียนรู้หนึ่งข้อ
ส่วน 60% ของ BR-17 ตัดสินผลการเรียนรู้ข้อนั้นต่อทั้งชั้น และ BR-17 อ่านว่า **มากกว่า** อย่างเคร่งครัด
ข้อที่มีผู้ผ่านพอดี 60% จึง **ไม่ผ่าน**

**seed ผ่านทุกข้ออย่างสบาย ๆ** ทุกข้อในนั้นอยู่ห่างจากทั้งสองเส้นมาก หน้าจอที่พิมพ์ *ผ่าน*
ไปเรื่อย ๆ จะทำให้ทุกแถวที่เขียนบน seed อย่างเดียวเขียวหมด แถวที่เกี่ยวกับ *ไม่ผ่าน*
กับ *ยังไม่ประเมิน* จึงต้องสร้างสถานการณ์เองทั้งหมด

### สิ่งที่การเดินหาเจอ

**หนึ่ง — แผ่นพับรูบริกเปิดออกมาเป็นกล่องเปล่า** เมื่อรายวิชายังไม่ได้กำหนดผลการเรียนรู้เลย
แผ่นพับถูกวาดนอกโซ่สามสถานะ จึงขึ้นทั้งสามสถานะ และในสถานะ `no_outcomes` มันไม่มีอะไรให้เปิด
ผู้ใช้ตัดสินว่าเป็นข้อบกพร่องและให้แก้ในตั๋วนี้ **แก้แล้ว** — ไม่วาดเลยเมื่อ `no_outcomes`
(ยังวาดตอน `empty` เพราะผลการเรียนรู้มีอยู่จริงและรูบริกของมันคือข้อมูลอ้างอิงจริง
สิ่งที่ยังไม่มีคือคะแนน) พร้อมแถว 9 ใน `40a` และมัตแตนต์ `rubricofferedwithnorubric`

นี่คือแถวชนิดที่ไม่มี assertion ไหนจับได้เลย: ทุกแถวอัตโนมัติถามว่าแผ่นพับ*ทำงานไหม*
และมันทำงานสมบูรณ์แบบ — กับความว่างเปล่า รูปเดียวกับที่การเดินของ #43 เจอหนึ่งหน้าจอถัดไป
คือตัวควบคุมที่ตอบว่าไม่มีอะไร ยื่นให้คนที่ต้องกดก่อนถึงจะรู้

**สอง — PDF ขึ้นบรรทัดใหม่ตัดกลางคำไทย** `splitTextToSize` ของ jsPDF วัดทีละตัวอักษร
ภาษาไทยไม่มีช่องว่างระหว่างคำ ทั้งย่อหน้าจึงเป็นคำเดียวในสายตาของมัน CLO-4 ทิ้งสระ **เ**
ค้างท้ายบรรทัดแล้วขึ้น **ฟซ** บรรทัดถัดไป ซึ่งแยกสระนำออกจากพยัญชนะที่มันนำ
เปิดเป็น [#117](https://github.com/khthana/Deep-QA/issues/117) ไม่แก้ในตั๋วนี้ —
เป็นเรื่องของทุกที่ที่พิมพ์ไทยยาว ๆ ลง PDF ไม่ใช่ของ #40 ข้อเดียว และคนละเรื่องกับ #103
ซึ่งเป็นเรื่องขนาดตัวอักษร

**สาม — ไฟล์หน้าจอของตั๋วนี้ไม่ได้ผ่าน prettier** ส่วนหน้าอื่นในโปรเจกต์ผ่านหมด
รันแล้วในการเดินนี้ ซึ่งขยับย่อหน้าในตัวตารางและทำให้มัตแตนต์สองตัวหลุดสมอ
(`fractionsayseverybodypassed` กับ `verdictisonlyacolour`) ปักใหม่แล้วและกวาดซ้ำทั้งชุด

## สิ่งที่รีวิวสองแกนเจอ และแก้ไปแล้ว

รีวิวสองแกนเจอเก้าอย่าง แก้ไปทั้งหมด สองอย่างในนั้นทั้งสองแกนเจอตรงกัน

**แกน spec**

1. **`empty` เป็นจริงแบบว่างเปล่า** `lines.every(...)` บนอาร์เรย์ว่างคืน `true` การเปิดสอนที่ยัง
   ไม่มี CLO เลยจึงรายงานตัวเองว่า *ยังไม่มีคะแนน* ทั้งที่ปัญหาจริงคือยังไม่มีอะไรให้วัด
   ตอนนี้ `empty` มี `lines.length > 0` คุม และมี `no_outcomes` เป็นสถานะของตัวเอง
   พร้อมประโยคของตัวเองบนหน้าจอ และเทสต์ที่สร้างการเปิดสอนใหม่ที่ไม่มี CLO
2. **เกณฑ์ข้อ 8 พิสูจน์ขอบล่างไม่ครบ** เส้น 60% ถูกยืนยันที่ *พอดี 60* กับ *80* แต่ไม่เคยยืนยัน
   ที่ต่ำกว่า — แถวที่จัดคะแนนเป็น 0 อ่าน `passed_count` กับ `pass_rate` แต่ไม่เคยอ่าน `passed`
   เพิ่ม `assert.equal(bottom.passed, false)`
3. **สามเอกสารบอกสองอย่างเรื่องตารางตอนไม่มีคะแนน** JSDoc ของ route กับคอมเมนต์ในเทสต์
   เขียนว่า *หน้าจอเก็บตารางไว้แล้วบอกว่าทำไมทุกช่องว่าง* ส่วนหน้าจอจริง ใบตรวจรับ และ `40a`
   ล้วนบอกว่าไม่มีตาราง — แก้คอมเมนต์ทั้งสองให้พูดเฉพาะสิ่งที่ route ตัดสิน คือคำตอบยังพา
   ผลการเรียนรู้ไปด้วย ส่วนหน้าจอจะวาดอะไรไม่ใช่เรื่องของ route
4. **ประโยคเตือนอ้างถึงหน้าจอที่ยังไม่มี** *ต้องระบุแนวทางปรับปรุงในรายงานการปรับปรุงอย่างต่อเนื่อง*
   ชี้ไปที่ #41 ซึ่งยังเป็นหน้า *กำลังพัฒนา* — บอกให้ผู้สอนไปที่ที่ไปไม่ได้ ตัดออกเหลือ
   *ยังไม่ผ่านเกณฑ์ที่ระบุไว้ข้างต้น*
5. **แถวปฏิเสธอ้างการเทียบที่ไม่ได้ทดสอบ** คอมเมนต์เขียนว่าพิสูจน์ *บัญชีที่สอนตอนเรียนนั้นได้ผล*
   แต่ตัวแปรชื่อ `mine` กลับเป็นตอนเรียนของ U_MULTI ที่ขอด้วยคุกกี้ของ U_TEACH2 — 404 นั้นถูก
   แต่การเทียบที่อ้างไม่ได้ถูกยืนยันตรงไหน แก้ชื่อและคอมเมนต์ให้ตรงกับสิ่งที่ยืนยันจริง

**แกน standards**

6. **แถว ⚙ ข้อ 1 อ้างสองอย่าง แต่มีมัตแตนต์ค้ำอย่างเดียว** ครึ่ง *หนึ่งแถวต่อหนึ่งข้อ ครบทุกข้อ*
   ไม่มีอะไรฆ่า — รอบกวาดเองบันทึกไว้แล้วว่า `unmeasuredoutcomenotlisted` ฆ่ามันไม่ได้
   เพิ่ม `onerowmissingfromthetable` ที่ตัดแถวแรกทิ้งโดยไม่มีเงื่อนไข
7. **คำว่า *มากกว่า* ไม่เคยถูกยืนยัน** `40a` อ่านแค่ substring `ร้อยละ 60` ทั้งที่ `bands.js`
   เขียนไว้เองว่า *มากกว่า* กับ *ไม่น้อยกว่า* คนละกฎกัน แก้เป็นยืนยันทั้งประโยค
   แล้วเพิ่ม `criterionsaysnotlessthan`
8. **คำตัดสินสามสถานะเขียนไว้สองที่สองรูป** หน้าจอใช้ map ส่วน PDF ใช้ if-cascade
   และคำไทยสามคำถูกพิมพ์ซ้ำ — มีแต่ฝั่งหน้าจอที่มีมัตแตนต์ ทุบฝั่ง PDF แล้วไม่มีอะไรแดง
   ย้ายไปเป็น `verdictLabel` ใน `lib/bands.js` เหตุผลเดียวกับที่ตั๋วนี้ยกให้ `criterionLines`
   เอาไว้แล้ว สีของชิปยังอยู่กับหน้าจอ เพราะ PDF ไม่มีชิป
9. **คอมเมนต์ที่ export ระบุตัวหารผิด** เขียนว่า *60% ของชั้น* ทั้งที่ทั้งโค้ดและคอมเมนต์ของ
   `passed_count` ยืนยันว่าเป็น *ของผู้มีคะแนน* — และคอมเมนต์นั้นคือเหตุผลเดียวที่ export
   `OUTCOME_PASS_PERCENT` ออกมา

**และอีกสองอย่างที่รีวิวชี้ว่าไม่ใช่ข้อบกพร่อง** สำเนาที่สี่ของ query ของ #38 ซึ่ง JSDoc ประกาศไว้
พร้อมเหตุผลของ #39 และ #104 อยู่แล้ว · กับหัวไฟล์มัตแตนต์ที่ยังเขียนว่า *Eleven mutants*
ซึ่งเป็นตัวเลขค้าง แก้แล้ว

## หมายเหตุที่ไม่ใช่เกณฑ์

**route นี้เรียกด่านทีละตัว ไม่ใช่ `Promise.all` แบบ #39** และเหตุผลไม่ใช่ความเร็ว
มีแต่ `sectionOf` ที่ใช้ `integerId`; `offeringOf` ยังกันด้วย `/^\d+$/` เอง รหัสที่เป็นตัวเลขล้วน
แต่ใหญ่เกิน `integer` จึงวิ่งเข้า query ของมันแล้วกลับมาเป็น 22003 — ห้าร้อยสำหรับ URL ที่คนพิมพ์ผิด
นั่นคือ [#107](https://github.com/khthana/Deep-QA/issues/107) ซึ่งไล่ไว้สิบเอ็ดจุดและไม่ควรแก้ครึ่งเดียว
จากในตั๋วนี้ การถามด่านที่ตัดสินก่อนเป็นรูปที่ถูกกว่าอยู่แล้ว และ `backend/test/clo-assessment.test.js`
มีแถวปักไว้

**`columnOf` ได้ `passed_count` เพิ่มมาหนึ่งฟิลด์** เพราะรายงานพิมพ์ *55 / 57* ข้าง ๆ *96.5%*
ถ้า route นี้นับเอง มันจะเป็นที่ที่สองที่ `PASS` อยู่ เหตุผลเดียวกับที่ `summaryOf` พา
`scored_count` กับ `passed_count` ไปด้วยตั้งแต่ #38 เพียงแต่ลึกลงมาหนึ่งชั้น
#38 กับ #36 ได้ฟิลด์นี้ติดไปด้วยและไม่มีใครใช้ ซึ่งไม่เป็นไร — มันคือฟิลด์เพิ่ม ไม่ใช่ฟิลด์เปลี่ยน

**`SCALE` กับ `OUTCOME_PASS_PERCENT` ถูก export แล้ว** โดยคอมเมนต์ในไฟล์เขียนเส้นแบ่งไว้ว่า
export มาเพื่อ **พิมพ์** ไม่ใช่เพื่อ **ใช้คำนวณ** — เหมือนที่ `BAND_FLOORS` เดินทางไปหา legend ของ #38
อยู่แล้ว ไม่มีอะไรนอกไฟล์นั้นหารด้วยห้าหรือเทียบกับหกสิบ

**`outcomesOf` เป็นสำเนาตรงตัวที่สี่ของ query ของ #38** ต่อจาก `sectionResults.js` และ
`outcomeActivityMap.js` กฎของ `lib/fields.js` คือแยกที่ครั้งที่สาม และ #39 ไม่แยกไปแล้วครั้งหนึ่ง
ด้วยเหตุผลของ `enrolment.js` — อีกสองสำเนาอยู่ในไฟล์ที่อยู่ในชุดมัตแตนต์ของตั๋วอื่น
[#104](https://github.com/khthana/Deep-QA/issues/104) ตอนนี้มีผู้เรียกสี่รายแล้ว

**PDF ตั้งตัวอักษรไว้ไม่ต่ำกว่า 14pt ทุกจุด** ซึ่งเป็นบทเรียนจาก
[#103](https://github.com/khthana/Deep-QA/issues/103) ที่พบว่า PDF ของ #20 ตั้งไว้ 10pt
ฟอนต์ไทยมี x-height เตี้ยกว่าละตินที่ point size เดียวกันและมีสระบนล่างที่ต้องมีที่ว่าง
PDF ของ #20 ยังเป็น 10pt และมีตั๋วของมันเอง — ใบนี้เขียนโดยรู้เรื่องนั้น ไม่ใช่ทำซ้ำแล้วได้ตั๋วใบที่สอง

**ตารางรูบริกใน PDF เรียงตามข้อ ไม่ได้พิมพ์ครั้งเดียว** ถึงแม้ seed จะให้ทุกข้อมีสี่ประโยคเหมือนกัน
