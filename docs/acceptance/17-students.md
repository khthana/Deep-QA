# ตรวจรับด้วยมือ — #17 ข้อมูลนักศึกษากลาง

`docs/06-implementation-plan.md` §Acceptance กำหนดว่า ticket หนึ่งจะเสร็จเมื่อ automated test ผ่าน
**และ** checklist ที่ทำด้วยมือถูกเดินจนครบ เอกสารนี้คือครึ่งหลังของ #17

ครึ่งแรกอยู่ที่ `backend/test/students.test.js` (14 subtests) — ทุกเกณฑ์ที่พิสูจน์ได้ที่ seam เดียว
ของเราคือ HTTP surface ของ backend ถูกพิสูจน์ที่นั่นแล้ว รวมทั้งข้อที่ต้องเดินสองทางจึงจะมีความหมาย

- **ข้อ 1 (ตัวกรอง)** — นักศึกษาทั้ง 173 คนใน seed อยู่หลักสูตร `0501` ทั้งหมด `?program_id=0501`
  จึงคืนครบทุกคนไม่ว่า route จะอ่านพารามิเตอร์หรือไม่ test จึงสร้างนักศึกษาใน `0503` ก่อน
  แล้วยืนยันว่าหน้าของ `0501` **ไม่มี** คนนั้น ส่วนตัวกรองภาควิชายืนยันว่า `?department_id=01`
  คืน `total: 0` ทั้งที่ผู้เรียกเพิ่งเพิ่มนักศึกษาของตัวเองไป — หน้าว่างจึงแปลว่าตัวกรองปฏิเสธ
  ไม่ใช่ตารางว่าง
- **ข้อ 7 (ปีที่เข้าศึกษา)** — พิสูจน์ด้วยการ *ส่ง* `admission_year: '2599'` ทั้งทาง POST และทาง
  คอลัมน์พิเศษในไฟล์ CSV แล้วยืนยันว่าค่าที่เก็บคือค่าที่คำนวณเอง ถ้าไม่ส่ง เกณฑ์นี้จะผ่านแม้ route
  จะอ่านจาก body
- **ข้อ 8 (ขอบเขต)** — เดินสองทาง คือ `dept.admin.01@` ไม่เห็นและเขียนไม่ได้ **และ**
  รหัสนักศึกษาของภาควิชาอื่นถูกปฏิเสธเมื่อ `dept.admin.05@` พยายาม import ทับ (ถ้าเช็คแต่หลักสูตร
  ที่ส่งมา การ import จะกลายเป็นช่องทางย้ายนักศึกษาของภาควิชาอื่นเข้ามาเงียบ ๆ)

เกณฑ์สองข้อพิสูจน์ที่อื่น และควรรู้ว่าที่ไหน

- **ข้อ 3 (ปุ่มดาวน์โหลดแบบฟอร์ม)** ครึ่งหนึ่งเป็นการคลิกปุ่มและได้ไฟล์ลงเครื่อง ซึ่ง docs/06
  ระบุว่าไม่ทำ unit test ฝั่ง frontend ตัวไฟล์ที่ server ส่งถูกยืนยันใน test แล้ว (หัวคอลัมน์สี่ช่อง
  และไฟล์นั้น import กลับเข้าไปได้จริง) เหลือแต่การคลิก ซึ่งอยู่ในตารางข้างล่าง
- **ข้อ 9 (นักศึกษาที่เพิ่มที่นี่พร้อมให้ลงทะเบียนใน Section)** ยังไม่มี endpoint ให้เดิน —
  การลงทะเบียนคือ #25 ซึ่งถูก block ด้วยตั๋วนี้ — test จึงพิสูจน์ที่จุดที่ข้ออ้างนี้อยู่จริง คือ
  foreign key `student_course.student_id` โดยสร้างนักศึกษาผ่าน API อ่านกลับผ่าน API แล้วจึง
  ลงทะเบียน และยืนยันว่ารหัสที่ register ไม่รู้จักลงทะเบียนไม่ได้เลย (23503)

## ตั้งต้น

```
docker start deep-core-postgres
cd db      && npm run reset && npm run migrate && npm run seed
cd backend && npm start          # http://localhost:3000
cd frontend && npm start         # http://localhost:5000
```

ทุกบัญชีใน seed ใช้รหัสผ่านเดียวกัน คือค่า `PASSWORD` ใน `db/seed.js`
เมนูที่ใช้ตลอดเอกสารนี้คือ *หลักสูตร → ข้อมูลนักศึกษากลาง* (`/main/student-data`)

**ต้อง restart backend ก่อนเดิน** — process ที่ค้างจากตั๋วก่อนจะตอบ 404 ให้ทุก route ของ #17

seed มีนักศึกษาอยู่แล้ว **173 คน** (รุ่น `66…` 113 คน และรุ่น `65…` 60 คน) อยู่ภาควิชา `05`
หลักสูตร `0501` ทั้งหมด — จำนวนนี้เกินสิบอยู่แล้ว การแบ่งหน้าจึงเห็นได้ทันทีโดยไม่ต้องเตรียมอะไร
และเป็นเหตุผลที่ตัวกรอง *หลักสูตร* ต้องเดินด้วยนักศึกษาที่เพิ่มเข้า `0503` เอง

**รายการเรียงจากคนที่ถูกเพิ่มล่าสุดก่อน** (`created_at` มากไปน้อย และใช้รหัสตัดสินเมื่อเวลาเท่ากัน)
ข้อมูลใน seed ถูกเขียนในธุรกรรมเดียว `created_at` จึงเท่ากันทั้ง 173 แถว แถวบนสุดของหน้าแรกตอนตั้งต้น
จึงเป็นรหัสมากที่สุดคือรุ่น `66…` แต่คนที่ *เพิ่งเพิ่ม* จะอยู่บนสุดเสมอ **ไม่ว่ารหัสจะเป็นรุ่นใด** —
ข้อ 5 จึงใช้รหัสที่เก่ากว่าทุกคนใน seed โดยตั้งใจ ถ้าเรียงด้วยรหัสอย่างเดียว แถวนั้นจะไปอยู่หน้าสุดท้าย

**แบบฟอร์มไม่มีแถวตัวอย่างแล้ว — #67 (8 ก.ย. 2569)** เดิมแถวตัวอย่างใช้รหัส `66010001` ซึ่งเป็นรหัสของนักศึกษาใน seed จริง และการนำเข้าของหน้านี้ *ทับ* รหัสที่มีอยู่ — เป็นการนำเข้าเดียวในระบบที่ทับ **คน** ที่อยู่ในทะเบียนแล้ว การอัปโหลดแบบฟอร์มที่ยังไม่ได้แก้จึงเปลี่ยนชื่อนักศึกษาจริงเป็น สมชาย ใจดี แล้วรายงานว่า *นำเข้าสำเร็จ 1 รายการ* โดยไม่มีอะไรเตือน

การนำเข้าที่ *ทับ* ของเดิมมีสามที่ — `weights.js` ทับหมวดของเกณฑ์น้ำหนัก และ `activityScores.js` ทับคะแนน ข้อความเดิมของย่อหน้านี้เขียนว่า *เป็นการนำเข้าเดียวในระบบที่ทับ* ซึ่งผิด `/code-review` จับได้ สิ่งที่ทำให้ข้อบกพร่องนี้ต่างออกไปไม่ใช่การทับ แต่เป็นสิ่งที่ถูกทับ — อีกสองหน้าทับตัวเลขที่หน้าจอนั้นเป็นเจ้าของ และการนำเข้าของทั้งสองหน้า **ปฏิเสธ** นักศึกษาที่ไม่รู้จัก ของหน้านี้ทับชื่อคน และทะเบียนนี้ไม่มี route ลบ

**สิ่งที่การแก้นี้เสียไป** ตั๋วเขียนค้านไว้ว่าแถวตัวอย่างสอนรูปแบบของข้อมูล และชื่อไทยในแถวนั้น คือสิ่งที่ทำให้ BOM ของ #62 มีความหมาย ข้อนี้รับไว้ว่าเสียจริง ไม่ใช่การแลกที่เสมอตัว — แบบฟอร์มของหน้านี้ตอนนี้เป็น ASCII ล้วน ข้อ 12 จึงยังยืนยันว่า BOM รอดผ่านการดาวน์โหลด แต่ไม่ได้แสดงอีกต่อไปว่ามันกันตัวยึกยือได้จริง ครึ่งนั้นเคยย้ายไปอยู่ที่แบบฟอร์มของ #11 ซึ่งตอนนั้นยังมีแถวตัวอย่างเป็นภาษาไทย — **ประโยคนั้นหมดอายุเมื่อ 9 ก.ย. 2569** ตอนที่ [#124](https://github.com/khthana/Deep-QA/issues/124) เอาแถวตัวอย่างของแบบฟอร์มนั้นออกด้วยเหตุผลคนละข้อ (แถวนั้นสร้างบัญชีที่ลบไม่ได้) หัวคอลัมน์ของมันเป็น ASCII ล้วนเหมือนกัน ที่ค้ำข้ออ้างเรื่อง BOM อยู่ตอนนี้คือแบบฟอร์มอีกหกใบที่ยังมีภาษาไทยในแถวตัวอย่าง — คะแนนกิจกรรม ภาควิชา หลักสูตร รายวิชา สัดส่วนคะแนน และกลุ่มงาน — โดยเดินด้วยมือไว้แล้วสองใบที่ `docs/acceptance/14-departments.md` แถว 5 และ `docs/acceptance/15-programs.md` แถว 7 แลกมากับการที่แบบฟอร์มของหน้านี้ไม่ทับใครอีกต่อไป

ย่อหน้านี้เคยเป็นคำเตือนให้คนเดินหลบเอาเอง (*อย่า upload แบบฟอร์มโดยไม่แก้*) ซึ่ง #50 บันทึกไว้แล้วว่าการอธิบายช่องโหว่ไม่ใช่การปิดมัน ตอนนี้แบบฟอร์มมีแต่หัวคอลัมน์ อัปโหลดกลับไปโดยไม่แก้จะถูกปฏิเสธว่า *ไม่พบข้อมูลในไฟล์ที่นำเข้า* และไม่เขียนอะไรเลย — ข้อ 23

หลายข้อข้างล่างเขียนข้อมูลจริงลงฐานข้อมูล — **`npm run seed` ใหม่หลังเดินจบ** ก่อนเริ่มตั๋วถัดไป

## รายการที่ต้องเดิน

ช่องสุดท้ายมีสี่ค่า

- **☑** เดินด้วยมือจบแล้ว หรือพิสูจน์ที่ seam HTTP แล้ว — **สองอย่างนี้เป็น ☑ เท่ากัน** ⚙ สงวนไว้ให้ browser seam เท่านั้น และแถวบอกเองว่าอะไรพิสูจน์มัน (`CLAUDE.md` §Marks on the sheets · [#194](https://github.com/khthana/Deep-QA/issues/194))
- **◐** เดินไปได้ครึ่งเดียว อีกครึ่งยังไม่ได้เดิน — **แถวนั้นบอกไว้เองว่าครึ่งไหนยังขาด และครึ่งนั้นรออะไร** · ส่วนใหญ่ครึ่งที่เดินแล้วคือครึ่งของ server และครึ่งที่เหลือคือสิ่งที่หน้าจอวาด (แถบสี ตาราง dropdown) ซึ่งยังต้องมีคนดู — **แต่นั่นเป็นกรณีที่พบบ่อย ไม่ใช่นิยาม** ครึ่งที่เหลือรออยู่สามอย่าง คือ **คน** (เช่น attribute ที่ไปถึง DOM แล้ว แต่ยังไม่มีใครเปิดโปรแกรมอ่านหน้าจอฟัง) · **ตั๋ว** ซึ่งแถวจะอ้างเลขไว้ · หรือ **ไม่รออะไรเลย** เพราะไม่มีตัวควบคุมบนจอสร้างคำขอนั้นได้ ซึ่งเป็น ◐ ถาวรโดยโครงสร้าง — **สามอย่างนี้นับแยกกัน** (`CLAUDE.md` §Marks on the sheets · [#157](https://github.com/khthana/Deep-QA/issues/157))
- **☐** ยังไม่ได้เดิน
- **⚙** ครอบคลุมด้วย browser seam แล้ว (#65) ไม่ต้องเดินด้วยมือซ้ำ แถวบอกไฟล์ที่ครอบคลุมไว้ และมาร์กนี้ได้มาเมื่อมัตแตนต์ฆ่า assertion ของแถวนั้นเอง — **ถ้าแถวนั้นพูดถึงสิ่งที่วาดด้วย (เมนู ถ้อยคำ สี) ครึ่งนั้นยังเป็นงานของคนเดิน และแถวจะเขียนกำกับไว้** (`CLAUDE.md` §Two test seams · [#194](https://github.com/khthana/Deep-QA/issues/194))

**สิบแถวที่คนต้องเดิน เดินครบแล้วเมื่อ 22 ส.ค. 2569** — ข้อ 1–9, ข้อ 18 และครึ่งที่เป็นเมนูของข้อ 19–22 ทั้งหมดพูดถึงสิ่งที่หน้าจอ *วาด* (กล่องเทาที่พิมพ์ไม่ได้ ปุ่มที่ถูกปิด ถ้อยคำ สี ตัวเลือกใน dropdown) ซึ่ง #65 กันไว้ให้คนดูด้วยตาโดยตั้งใจ ส่วนข้อที่เป็นจำนวน การหายไป และการปฏิเสธ ย้ายไป browser seam แล้ว

หมายเหตุข้อ 5: ครึ่งที่ว่า *แถวใหม่อยู่บนสุดแม้รหัสจะเก่ากว่าทุกคนใน seed* ถูกยึดไว้แล้วใน `e2e/tests/17c-students-register.spec.js` (ส่วนตั้งต้นของ row 10) สิ่งที่ยังต้องดูด้วยตาคือแถบเขียวและการกลับมาหน้ารายการ

## คำตอบที่ถูกแทนที่ — #68 (12 ก.ย. 2569)

ทะเบียนนี้เป็นหนึ่งในสิบห้าแผงที่อ่านคำตอบจากเซิร์ฟเวอร์แบบที่คำขอถูกแทนที่ได้
และทั้งสิบห้าอ่านคำตอบด้วยรูปแบบเดียวกัน
คือ `setData(await listSomething(…))` โดยไม่มีอะไรผูกคำตอบเข้ากับคำขอที่ทำให้มันเกิด
ถ้ามีสองใบวิ่งพร้อมกัน **ใบที่มาถึงทีหลังชนะ ไม่ใช่ใบที่ขอทีหลัง** ตารางจึงวาดหน้าที่ pager
ไม่ได้อยู่แล้วได้ และ `setLoading(false)` ของใบเก่าก็ปิดสถานะกำลังโหลดของใบที่ยังไม่กลับ

ตั๋วให้รายชื่อไว้เจ็ดไฟล์และบอกว่ามาจาก `grep` ให้ยืนยันทีละไฟล์ก่อนแก้ ทั้งเจ็ดตรงจริง
แต่คำถามที่ยังไม่มีใครถามคือ grep นั้น**พลาดใครไปบ้าง** — คำตอบคืออีกห้าที่อ่านรายการ
เหมือนกัน (`Rubrics` · `Offerings` · `SubjectStudents` · `UserHistory` ·
`groups/GroupHistory`) และอีกสามที่**ความเห็นในตั๋วเองวัดไว้แล้ว** (`ProgramLevelByIntake` ·
`ProgramLevelIndividual` · `ProgramLevelAllStudents`) รวมเป็นสิบห้า นับจากตัวโค้ดและจาก
ตั๋วทั้งใบ ไม่ใช่จากรายชื่อในตัวตั๋วอย่างเดียว

**ทะเบียนคือจอที่พิสูจน์ ในสิบห้าจอนั้น** เพราะเป็นไฟล์เดียวที่ไม่มีใบมัตแตนต์ไหนถืออยู่
มัตแตนต์ของ #68 จึงกวาดได้โดยไม่ชนใบไหน และเพราะ seed ใส่นักศึกษาไว้ 173 คน หน้าที่สอง
จึงมีอยู่โดยไฟล์ทดสอบไม่ต้องเขียนขึ้นเอง อีกสิบสี่จอเปลี่ยนด้วยกฎเดียวกัน
แต่**พิสูจน์ด้วยรูปแบบ ไม่ใช่ด้วยแถวของตัวเอง** ซึ่งเขียนไว้บน `docs/acceptance/57-pager.md`
ตรง ๆ แทนที่จะปล่อยให้เข้าใจเอาเอง

ทั้งสามแถวสร้างสถานการณ์ของตัวเองด้วย `page.route` แทนที่จะรอให้เน็ตช้าพอดี ผลจึงเป็น
ข้อเท็จจริงเรื่องโค้ด ไม่ใช่เรื่องเครื่อง และนี่เป็นเหตุผลที่ทั้งสามเป็นแถวที่เดินด้วยมือไม่ได้เลย
ไม่ใช่แค่แถวที่เครื่องเดินแทน

**หนึ่งแถวต่อหนึ่งอนุประโยคของผู้คุ้มกัน** — สิ่งที่มันวาด (ข้อ 24) ธงที่มันปิด (ข้อ 25)
และคำปฏิเสธที่มันรายงาน (ข้อ 26) กฎของที่นี่คือทุกอนุประโยคต้องบอกได้ว่าเป็นอย่างไหนในสาม:
พิสูจน์แล้ว เข้าไม่ถึงโดยโครงสร้าง หรือยังไม่ได้ทดสอบ รอบแรกข้อที่สามไม่มีแถวและไม่มีมัตแตนต์
ซึ่งแปลว่า *ยังไม่ได้ทดสอบ* โดยไม่ได้เขียนไว้ว่าอย่างนั้น

**คำถามที่ตั๋วฝากไว้ ถูกตอบแล้ว (20 ก.ย. 2569)** ร่างแรกให้ *ยกเลิก* เขียน `null` ลง `showing`
การบันทึกที่ถูก *ยกเลิก* แซงโดยไม่มีฟอร์มที่สองมาแทน จึงเงียบทั้งประโยคสำเร็จและคำปฏิเสธ —
คนที่กด *บันทึก* ไม่ได้ยินอะไรเลยเกี่ยวกับการเขียนที่ตัวเองสั่ง ตั๋วฝากเรื่องนี้ไว้เองว่าเป็น
*คำถามเรื่องสิ่งที่คนเห็น แบบเดียวกับ #143* ซึ่ง `docs/06` §Out of Scope บอกว่าเป็นคำถาม
ไม่ใช่การแก้ คำตอบของอาจารย์คือ **ให้ขึ้นเหมือนเดิมเมื่อไม่มีใครมาแทน**

`showing` จึงไม่ได้แปลว่า *ฟอร์มไหนเปิดอยู่* อีกต่อไป แต่แปลว่า **สิ่งล่าสุดที่เปิดขึ้นบนจอนี้**
— *ยกเลิก* ไม่เขียนมัน และการบันทึกที่ปิดฟอร์มของตัวเองก็ไม่เขียน `null` จึงเหลือความหมายเดียว
คือ *ยังไม่มีอะไรเปิดขึ้นเลย* บรรทัดที่เทียบ (`showing.current === sent`) ไม่ถูกแตะเลย
สิ่งที่เปลี่ยนคือใครเขียน ref บ้าง

### มัตแตนต์

`146:studentsclosewins` และ `146:studentsrefusalwins` ใน `mutation/146-save-closes-a-later-form.py`
เปลี่ยนการเทียบ `showing.current === sent` เป็น `showing.current !== null` — guard ที่จำว่า *มีฟอร์มเปิดอยู่ไหม*
แทนที่จะจำว่า *ฟอร์มไหน* ซึ่งเป็นความผิดที่คนเขียนจริง ๆ จะเขียน ไม่ใช่การถอดเงื่อนไขทิ้ง (#102)

กวาดเมื่อ 20 ก.ย. 2569 ด้วย `146a` ทั้งไฟล์ — baseline **31 ผ่านทั้ง 31** แต่ละตัว **ล้ม 1 ผ่าน 30**
คือแถวของตัวเองแถวเดียว ไม่ใช่สองแถวอย่างจอรายการอื่น เพราะทะเบียนมีทางเข้าทางเดียว
อีกยี่สิบห้าตัวของ #146 กวาดก่อนหน้านั้นบนฐาน 28 ซึ่งเป็นจำนวนแถวของไฟล์ก่อนสองแถวนี้

### วัดซ้ำทั้งใบ หลังคำตอบของอาจารย์ที่ปรึกษา (20 ก.ย. 2569)

คำตอบเปลี่ยน*ความหมาย*ของ `showing` ไม่ใช่รูปของการเทียบ มัตแตนต์เดิมยี่สิบหกตัวจึงเกาะที่เดิม
ทั้งหมด แต่ *สมอที่ยังอยู่ไม่ได้แปลว่ายังพิสูจน์อะไรได้ มีแต่การกวาดที่บอกได้* (#107) และไฟล์
`146a` โตจาก 31 เป็น 49 แถว ตัวเลขทุกตัวข้างบนจึงหมดอายุพร้อมกัน กวาดใหม่ทั้งใบ 42 ตัว
ทีละตัว — baseline **49 ผ่านทั้ง 49** ทุกรันใช้เวลา 2.6–3.0 นาทีเท่า baseline และทุกรัน
ล้ม + ผ่าน = 49 พอดี ไม่มีตัวไหนหยุดแอปพลิเคชัน และไม่มีแถวไหนหายไปจากการรัน

- `146:studentsclosewins` **ล้ม 1 ผ่าน 48** ที่แถว *a save that lands after the form was opened
  again leaves what was typed where it was* — จอนี้มีฟอร์มเดียว
  ทางเข้าที่สองคือปุ่มเดิมที่ถูกกดอีกครั้ง
- `146:studentsrefusalwins` **ล้ม 1 ผ่าน 48** ที่แถว *a save refused after the screen moved on
  says nothing over the new form*
- `146:studentscancelclears` **ล้ม 1 ผ่าน 48** ที่แถว *a save that nothing took the place of says
  what it did* ที่คำตอบเพิ่มเข้ามา

ทุกตัวล้มที่ assertion ของแถว ไม่ใช่ที่ timeout และตัวที่ล้มคือแถวที่ชื่อของมันบอก อ่านจากชื่อเทสต์
ที่ตาย ไม่ใช่จากจำนวน

### สมอของ `146:studentsclosewins` ที่ #202 ยกไป — การกวาดซ้ำ (11 ต.ค. 2569)

#202 แก้ `confirmRemoval` ของอีกสี่จอ และสมอของสี่ตัวนั้นเจอสองที่เพราะคำถามเดียวกันอยู่ที่ย่อหน้า
เท่ากัน การซ่อมทำด้วยการเติม `setEditing(null)` เข้าไปใน**ค่าคงที่ที่ใช้ร่วมกัน** ของ

## #203 — คำปฏิเสธชนะ และประโยคที่ฝากไว้กับการย้ายหน้า (12 ต.ค. 2569)

เจ้าของตัดสินเมื่อ 10 ต.ค. 2569 ว่า **คำปฏิเสธชนะ**: การเขียนที่สำเร็จแล้วเรียกรายการใหม่ไม่ได้ ต้องพูด
คำปฏิเสธ ไม่ใช่คำว่าบันทึกแล้ว #152 ทำสิบแปดจุดของฝ่ายผู้สอน และ #203 ทำยี่สิบจุดที่เหลือในสิบไฟล์ของ
ฝ่ายบริหาร **เหตุผลยาว รูปร่างของ `load` ที่คืนคำตอบว่ามันวาดหรือไม่ และราคาของการวัด อยู่ใน §#203 ของ
`docs/acceptance/14-departments.md`** ใบนี้เก็บแถวของจอนี้ — และ **ครึ่งที่ census มองไม่เห็น** ซึ่งถูก
พิสูจน์ที่นี่เพราะทะเบียนเป็นที่ที่มันถูกที่สุดที่จะไปถึง (173 คนที่ seed ไว้ 18 หน้า)

`save` ของทะเบียนเรียกรายการใหม่ด้วยมือ **เฉพาะเมื่อ** จอยังอยู่หน้าหนึ่ง จากหน้าอื่นคนที่ถูกเพิ่มไม่ได้อยู่
บนหน้าที่คนมองอยู่ มันจึงขอหน้าหนึ่งแทน และการอ่านนั้นเป็นของ **effect** ไม่ใช่ของ handler handler
ไม่มีคำตอบของตัวเองจะรอ ประโยคจึงถูกฝากไว้ที่ ref ชื่อ `waiting` ให้ `load` เป็นคนพูดเมื่อมันวาดแล้ว ซึ่งเป็น
รูปของ #152 บน `SubjectStudents.js` census มองไม่เห็นอะไรในนั้นเลย เพราะกิ่งนี้ไม่ `await` loader ตัวไหน
จึงไม่มีคำตอบให้อ่าน

การลบที่ถอยหน้ากลับหกจุด และการคัดลอกภาคการศึกษาของ `Offerings` ขอหน้าหนึ่งแบบเดียวกันนี้ ที่วัดที่นี่คือ
**รูปร่าง** ซึ่งเป็นโค้ดเดียวกันทั้งแปดจุด (#191 ว่าแต่ละทางเข้าจะเพิ่มข้ออะไร) อีกเจ็ดจุดยังไม่มีแถวของตัวเอง
— ดูหัวข้อ *ครึ่งที่ยังไม่ได้พิสูจน์* ใน §#203 ของใบ `14`

*การลบที่ถอยหน้ากลับหกจุด* ข้างบนเป็นชื่อของกลไกก่อน 19 ต.ค. 2569 คำตอบข้อ ก ของเจ้าของงานใน #209
ย้ายการตัดสินเรื่องหน้าไปที่เซิร์ฟเวอร์ หกจุดนั้นวันนี้คือ *การลบที่อ่านหน้าที่คนยืนอยู่ใหม่* และ `load`
เป็นคนส่งหน้าต่อ รูปร่างที่วัดไว้ที่นี่ — ประโยคฝากไว้ที่ ref ให้การอ่านที่วาดเป็นคนพูด — ไม่เปลี่ยน
(ลงวันที่กำกับ 20 ต.ค. 2569)

**สองแถวของการย้ายหน้าเป็นคู่โดยเจตนา** แถวแรกบอกว่าการฝากเกิดขึ้นจริง แถวที่สองบอกว่าคำปฏิเสธยังชนะ
ข้ามการฝากนั้น ถ้าไม่มีแถวแรก การลบบรรทัดใน `load` ที่พูดประโยคที่ฝากไว้จะไม่ทำให้อะไรแดงเลยบนจอนี้

แถวข้างล่าง **เดินด้วยมือไม่ได้** `e2e/support/gate.js` กักการเขียนไว้แล้วตอบ 200 ที่แต่งขึ้น และกักการอ่าน
รายการไว้ 300 ms แล้วตอบ 409 จึงไม่มีแถวไหนแตะฐานข้อมูล — การเขียนที่แต่งขึ้นหมายความว่าไม่มีใครถูกเพิ่ม

การอ่านทะเบียนครั้งหนึ่งเป็นของ **หน้า** และของ **ตัวกรอง** เพราะหน้าเดียวกันของอีกหลักสูตรคือ

`try` ของตัวเอง) ตัวกรองจึงกลับมาอยู่ใต้มือขณะที่การอ่านนั้นยังค้างอยู่ ซึ่งเป็นทางเข้าที่แถวทะเบียนของ

**ล้างประโยคโดยไม่พูด** พบโดย code review ทั้งสองแกนในรอบเดียวกัน ไม่ใช่โดยเครื่องมือ

## #252 — ประโยคของแฟ้มที่ตกนอกตัวกรองของตาราง (30 ต.ค. 2569)

รีวิวของ #247 เปิด [#252](https://github.com/khthana/Deep-QA/issues/252) ไว้จากข้อจำกัดที่
สำมะโนของตั๋วนั้นเขียนไว้ใน docblock ของมันเอง — **ประโยคที่อยู่ในมอดูลอื่น** `ImportPanel`
พูด *นำเข้าสำเร็จ N รายการ* ด้วยตัวเอง และถูกเมานต์บนสี่จอในเจ็ดจอของ #247
(`ProgramSubjects`, `Students`, `Subjects`, `Users`) เหนือแถวที่ CSV วางไว้นอกตัวกรองของ
จอแม่ได้ โดยจอแม่ไม่ได้ส่งตัวกรองลงไปให้เทียบเลย

### สิ่งที่วัดก่อนเขียนคำถามให้เจ้าของงาน

ใบเขียนสามข้อไว้ และข้อแรกคือ *ไม่อยู่ในสปีชีส์นี้ ปิดใบ* ซึ่งเป็นข้อที่ถูกกับเงื่อนไขรับรองของ
ใบเองก่อน (#114) · เหตุผลที่ใบให้ไว้คือ *คนอ่านกล่องรายงานใต้มันอยู่แล้ว* และ **การวัดบอกว่า
เหตุผลนั้นเป็นเท็จ**: `ImportPanel` วาดตารางรายงานทีละแถว **เฉพาะตอนปฏิเสธ** ตอนสำเร็จ
มันวาดเส้นเขียวบรรทัดเดียวและไม่มีรายการแถวใด ๆ (#66 — เกณฑ์ที่ครบตามตัวอักษรแต่ไม่ครบ
ในสาระ วัดถูกกว่าเถียง)

และการวัดเดียวกันหา **ข้อที่สี่** ที่ใบไม่ได้เขียนไว้: แผงเรียก `onImported?.()` อยู่แล้ว และทั้งสี่จอ
ส่งมันลงไปแล้ว ฉะนั้นจอแม่พูดได้โดยไม่ต้องมี prop ใหม่บนแผงที่มีสิบจุดเมานต์ — ซึ่งเป็นราคาที่
ข้อ ข กับ ค ของใบจ่าย (#182 `REQUIRED_PROPS`) และกฎยังถูกคัดลอกต่อจอ ไม่ใช่แชร์กัน
ฉะนั้นข้ออ้างสี่จอยังแยกมัตแตนต์ได้ (#68, #104)

อีกข้อที่วัด: ประโยคของแผงเป็นของการสร้างใหม่ ไม่ใช่สิ่งที่โค้ดนักศึกษาเลือก — `DEEP-QA-FRONTEND`
พูดแค่ *นำเข้าไฟล์ผู้ใช้งาน สำเร็จ* ผ่าน `setAlert` ฉะนั้นการต่อประโยคที่สองไม่ใช่การขยับเลขที่
คนส่งมอบเลือก (`docs/06` §Out of Scope)

### คำตอบของเจ้าของงาน (30 ต.ค. 2569)

**ข้อ ง — จอแม่พูด ผ่าน `onImported` ที่มีอยู่** และถ้อยคำคือ
*บางแถวที่นำเข้าอยู่นอกรายการที่กรองอยู่* · เป็นประโยคที่สองของตระกูล ไม่ใช่ประโยคของ #247
เพราะประโยคนั้นพูดว่า *แถวนี้* ซึ่งแฟ้ม N แถวถือไม่ได้ · ทั้งสองอยู่ที่
`frontend/src/lib/outsideTheFilter.js` และสำเนาของ seam อยู่ที่ `e2e/support/outside-the-filter.js`

### สองกลไก และแถวของมัน

### สิ่งที่ไม่มี seam ไหนถือ

**คีย์ที่ `ProgramSubjects` กับ `Subjects` เลือก** — `program_id` และ `department_id` ที่
`onImported` ของสองจอนั้นส่งเข้า `someImportedOutside` · ทั้งสองไม่มีแถวและไม่มีมัตแตนต์ของตัวเอง
`252:importquiet` แก้กฎร่วมที่ทั้งสองใช้ แต่ไม่มีแถวของทั้งสองให้มันฆ่า และคำถามที่สี่ของสำมะโนบอก
เองว่ามันไม่ถามว่าคำถามที่ handler ถามถูกไหม ฉะนั้นคีย์ที่สะกดผิดเป็นคอลัมน์อื่นที่คำตอบถือมาจะไม่มี
อะไรแดง (รีวิวของ 30 ต.ค. 2569 · #123) · ราคานี้คือสิ่งที่ #68 ซื้อ: สำมะโนถือจอที่ใช้กลไกร่วม
และสิ่งที่มันถือคือ *กฎถูกเรียก* ไม่ใช่ *เรียกด้วยคีย์อะไร*
