`docs/06-implementation-plan.md` §Acceptance กำหนดว่า ticket หนึ่งจะเสร็จเมื่อ automated test ผ่าน
**และ** checklist ที่ทำด้วยมือถูกเดินจนครบ เอกสารนี้คือครึ่งหลังของ #18

ครึ่งแรกอยู่ที่ `backend/test/program-subjects.test.js` (12 subtests) — ทุกเกณฑ์ที่พิสูจน์ได้ที่ seam
เดียวของเราคือ HTTP surface ของ backend ถูกพิสูจน์ที่นั่นแล้ว รวมทั้งเกณฑ์ข้อ 8 ที่เดินสองทาง คือ
`prog.manager.0503@` ถูกปฏิเสธบนหลักสูตร `0501` **และ** ผู้ดูแลภาควิชากับคณะเข้าถึง `0501` ได้จริง
(reach ที่ปฏิเสธทุกคนก็ผ่านครึ่งแรกได้ จึงต้องเดินทั้งสองทาง)

เกณฑ์สองข้อพิสูจน์ที่อื่น และควรรู้ว่าที่ไหน

- **ข้อ 6 (ถามยืนยันก่อนลบ)** เป็น dialog ล้วน ๆ ไม่มีอะไรให้ server ยืนยัน — request ที่มาถึงคือ
  request ที่ตั้งใจส่ง จึงอยู่ในตารางข้างล่างอย่างเดียว
- **ข้อ 7 (import ผ่านโมดูลกลาง)** เป็นข้อความเกี่ยวกับ *ผู้เรียกห้าราย* และสี่รายคือหน้าผู้ใช้งาน
  หน้าภาควิชา หน้าหลักสูตร และหน้ารายวิชา พิสูจน์โดย suite ของตัวเอง ซึ่ง **ไม่ถูกแก้เลย**ในตั๋วนี้ —
  นั่นคือความหมายของคำว่าใช้ซ้ำ

## ตั้งต้น

```
docker start deep-core-postgres
cd db      && npm run reset && npm run migrate && npm run seed
cd backend && npm start          # http://localhost:3000
cd frontend && npm start         # http://localhost:5000
```

ทุกบัญชีใน seed ใช้รหัสผ่านเดียวกัน คือค่า `PASSWORD` ใน `db/seed.js`
เมนูที่ใช้ตลอดเอกสารนี้คือ *ข้อมูลหลัก → รายวิชาในหลักสูตร* (`/main/course-in-program`)

**ต้อง restart backend ก่อนเดิน** — process ที่ค้างจากตั๋วก่อนจะตอบ 404 ให้ทุก route ของ #18

seed มีหลักสูตรสองหลักสูตรอยู่ในภาควิชา `05` เดียวกัน คือ `0501` (ของ `prog.manager@`) และ `0503`
(ของ `prog.manager.0503@`) — สองหลักสูตรนี้คือคู่ที่ใช้เดินข้อ 8 และเป็นคู่ที่ reach แบบหยาบ ๆ
จะปล่อยผ่าน เพราะอยู่ภาควิชาเดียวกันและคณะเดียวกัน

seed มีรายวิชาเดียวคือ `01076105` และ **คู่ (`0501`, `01076105`) มีข้อมูลอ้างอิงอยู่แล้ว**
(การเปิดสอน → CLO → คะแนน) จึงเป็นแถวที่ใช้เดินข้อ 5 ครึ่งที่ *ปิดการใช้งานแทนการลบ*
ส่วนครึ่งที่ *ลบได้จริง* ต้องเพิ่มคู่ใหม่เองในข้อ 1

**คลังรายวิชามีวิชาเดียวตอนเริ่ม** ข้อ 1 ถึงข้อ 4 จึงต้องไปเพิ่มรายวิชาที่หน้า *ข้อมูลรายวิชา* ก่อน
อย่างน้อยสามวิชา ใช้บัญชี `faculty.admin@` เพิ่มได้เร็วที่สุด แนะนำ `01076106`, `01076107`
และวิชาของภาควิชา `01` อีกหนึ่งวิชา (เช่น `01016101`) — วิชาสุดท้ายคือตัวที่ใช้เดินข้อ 10

หลายข้อข้างล่างเขียนข้อมูลจริงลงฐานข้อมูล — **`npm run seed` ใหม่หลังเดินจบ** ก่อนเริ่มตั๋วถัดไป

## หมายเหตุ — ขอบเขตของ catalogue

ตั๋วเขียนเกณฑ์ข้อ 3 ว่า *"รหัสวิชาที่ไม่มีในคลังถูกปฏิเสธ"* เท่านั้น ไม่ได้บอกว่าคลังที่เลือกได้ควร
แคบแค่ไหน การตัดสินใจของตั๋วนี้คือ **เลือกได้ทุกภาควิชา** ด้วยเหตุผลสามข้อ

1. หลักสูตรวิศวกรรมคอมพิวเตอร์จริง ๆ มีวิชาคณิตศาสตร์ ฟิสิกส์ และวิชาศึกษาทั่วไปของภาควิชาอื่น
   ถ้าจำกัดไว้ที่ภาควิชาของหลักสูตร หน้าจอนี้จะแสดงหลักสูตรจริงไม่ได้เลย
2. ของเดิมที่นักศึกษาส่งมอบไม่ได้จำกัดอะไรเลย (`getAllProgramSubjects` คืนทุกแถว)
3. การ*อ่าน* คลังรายวิชาไม่ใช่การ*เขียน* — ทุกการเขียนยังถูกตรวจกับ reach ของหลักสูตรตามเดิม

ถ้าเจ้าของโดเมนเห็นว่าควรแคบกว่านี้ จุดที่แก้คือ `catalogueRefusal` และ route
`/api/program-subjects/catalogue` ใน `backend/routes/programSubjects.js` ที่เดียว
