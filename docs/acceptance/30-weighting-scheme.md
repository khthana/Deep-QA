## สิ่งที่ต้องเข้าใจก่อนเดิน — บันทึกทั้งชุดหรือไม่บันทึกเลย

**สัดส่วนคะแนนถูกบันทึกทั้งชุดเสมอ ไม่มีการบันทึกรายแถว** BR-05 (รวมร้อย) เป็นกติกาของทั้งชุด
ไม่ใช่ของแถวไหน — เพิ่มหมวดเข้าไปในชุดที่รวมร้อยอยู่แล้วต้องผ่านสถานะ 110 เสมอ — โค้ดเดิมมี
endpoint ลบรายแถวที่ทำให้ผลรวมไหลต่ำกว่าร้อยแบบเงียบ ๆ rebuild จึงเหลือการเขียนทางเดียวคือ
PUT ทั้งลิสต์: ไม่รวมร้อยถูกปฏิเสธพร้อม**ผลรวมปัจจุบันในประโยค** (เกณฑ์ข้อสอง) และลิสต์ว่าง
คือผลรวมศูนย์ ไม่ใช่ทางลัดอ้อมกติกา

**แถวมีตัวตนข้ามการบันทึก** `activities.score_ratio_id` กับ `activity_clo_mapping.score_ratio_id`
ชี้มาที่แถวพวกนี้ การบันทึกจึง reconcile: แถวที่ถูกอ้าง (ด้วย id หรือด้วยชื่อ — import อ้างด้วยชื่อ)
ถูก UPDATE ที่เดิม แถวที่ไม่ถูกอ้างถูกลบหลังด่านตรวจ และแถวใหม่จริง ๆ เท่านั้นที่ INSERT

**หมวดที่มีกิจกรรมอ้างอยู่ลบไม่ได้ และประโยคระบุชื่อหมวด** ตรวจในโค้ดก่อนถึง RESTRICT
ของฐานข้อมูล เพราะ 23503 ที่ไปถึง error handler คือ *เกิดข้อผิดพลาดในระบบ* สำหรับสิ่งที่คนแก้เองได้
seed ผูกกิจกรรมไว้กับ**ทุกหมวดของทั้งสองปี** การจะลองลบจึงต้องเพิ่มหมวดใหม่ก่อนแล้วลบหมวดนั้น
(แถว 5 ของ 30a ทำแบบนั้น)

**สองประโยคปฏิเสธเป็นฟังก์ชัน — ครั้งแรกของ refusals.js** `weightsNotHundred(total)` กับ
`weightInUse(category)` ถ้อยคำยังอยู่ที่เดียวในไฟล์เดิม แค่มีช่องให้ค่าที่คำนวณ เหตุผลอยู่ใน
คอมเมนต์ของ block นั้น

**import คือชุดทั้งไฟล์ ผ่านโมดูลร่วม** `lib/importer` ได้ hook ใหม่สองตัวจากตั๋วนี้: `whole`
(กติการะดับไฟล์ — รวมร้อย ปฏิเสธพร้อมผลรวม) และ `onCommit` ที่ปฏิเสธได้ (ลบหมวดที่ไฟล์
ไม่เอ่ยถึง หลังด่านตรวจเดียวกัน) แถวในไฟล์จับคู่กับหมวดเดิมด้วยชื่อและ upsert — re-import
จึงอัปเดตแถวเดิม ไม่ทำให้ Activities หลุด

**หน้าจอไม่ blank ระหว่าง reload — ต่างจากหน้าพี่น้องโดยตั้งใจ** ImportPanel เก็บรายงาน
(นำเข้าสำเร็จ N รายการ / ตารางรายแถว) ไว้ใน state ของตัวเอง ถ้า reload หลัง import ถอด
panel ออกจากจอ รายงานจะหายไปตอนที่มันกำลังบอกว่าเกิดอะไรขึ้นพอดี — เจอจริงตอนเขียน 30a แถว 8
