## สิ่งที่ต้องเข้าใจก่อนเดิน — grain กลับด้านจากเพื่อนทั้งเมนู

**แผนการสอนเป็นของตอนเรียน ไม่ใช่ของการเปิดสอน** #27–#30 ทุกใบพูดประโยคเดียวกันว่า
*ทุกตอนเรียนใช้ชุดเดียวกัน* — ใบนี้คือหน้าเดียวที่พูดตรงข้าม: `course_syllabus.section_id`
ถือ grain ไว้ตรง ๆ สองตอนเรียนของการเปิดสอนเดียวถือแผนคนละชุด และ route จึง import
`sectionOf` จาก `enrolment.js` (คำถาม "ตอนเรียนนี้ของฉันไหม" หยุดที่ตอนเรียน — #104)
ไม่ใช่ `offeringOf` ซึ่งจะทำให้ทุกตอนเรียนอ่านแผนร่วมกันเงียบ ๆ seed ทำให้ grain อ่านได้
จากแถวเอง: ทุกหัวข้อลงท้ายด้วย `(ตอนเรียนที่ N ปีการศึกษา Y)`

**เลขสัปดาห์เป็นของคน ไม่ใช่ของเซิร์ฟเวอร์** ลูก ๆ ของ CLO (#28/#29) ให้เซิร์ฟเวอร์แจกเลข
เพราะเลขของพวกมันคือตำแหน่ง — เลขของใบนี้คือสัปดาห์ตามปฏิทิน: พิมพ์เอง แก้ได้ ซ้ำได้
(หนึ่งสัปดาห์สองหัวข้อ — migration 0002 จงใจไม่ตั้ง unique บน `(section_id, week_no)`)
และลบสัปดาห์ 2 ไม่ทำให้สัปดาห์ 3 กลายเป็น 2 ฟอร์มจึงมีช่องเลขที่ฟอร์มพี่น้องจงใจไม่มี
สิ่งที่เซิร์ฟเวอร์ยังถือคือ**ทรง**: จำนวนเต็มบวกที่ลง smallint ได้ ตรวจในโค้ดเพราะ 22003
ที่ไปถึง error handler คือ *เกิดข้อผิดพลาดในระบบ* สำหรับนิ้วพลาด

**ด่านลบเข้มกว่า schema และนั่นคือประเด็น** `activities.course_syllabus_id` เป็น SET NULL
(0003: เขียนแผนใหม่ไม่ควรพากิจกรรมไปด้วย) — DELETE ที่ไม่มีด่านจะตอบ 204 แล้วปลด
กิจกรรมจากสัปดาห์เงียบ ๆ route จึงปฏิเสธพร้อม**เลขสัปดาห์ในประโยค** (`weekInUse`)
แบบเดียวกับที่ #30 เอ่ยชื่อหมวด seed ผูก **สอบกลางภาค** ไว้กับสัปดาห์ 1 ของทุกตอนเรียน
เพื่อให้ด่านนี้มีของจริงให้ปฏิเสธ

**ด่านอยู่ใน DELETE เอง ไม่ใช่ SELECT ก่อนหน้า** — ของ #30 ถามด้วยคำสั่งแยกได้เพราะมี
RESTRICT รองอยู่ข้างล่าง ของใบนี้ไม่มีอะไรรองเลย ช่องว่างระหว่าง "ถาม" กับ "ลบ" จึงเป็นช่อง
ที่กิจกรรมซึ่งถูกผูกเข้ามาพอดีจะถูกปลดทิ้งเงียบ ๆ — คือความเสียหายที่ด่านมีไว้กัน `NOT EXISTS`
ในคำสั่งเดียวปิดช่องนั้น (code review รอบ #31 เป็นคนเจอ) ถ้าไม่มีอะไรถูกลบ route จึงถามอีกครั้ง
เพื่อแยกสองเหตุ: กิจกรรมยังอ้างอยู่ → ปฏิเสธพร้อมเลขสัปดาห์ · แถวหายไปแล้วใต้มือ → `ไม่พบ`

**ไม่มีใครถูกบันทึกว่าแก้อะไร** — `created_by` มีและถูกเขียนตอน insert แต่ไม่มี `updated_by`
คำถาม "ใครย้ายสัปดาห์ 5" จึงไม่มีคำตอบ และหน้าจอไม่วาดบรรทัดผู้แก้

## ตั้งต้น

```
docker start deep-core-postgres
cd db      && npm run reset && npm run migrate && npm run seed
cd backend && npm start          # http://localhost:3000
cd frontend && npm start         # http://localhost:5000
```

**ต้อง reset + seed ใหม่จริง ๆ ก่อนเดินใบนี้ และต้อง kill แล้ว start backend ใหม่** —
`node server.js` ไม่มี reload ตรวจด้วยการ login แล้วยิง `GET /api/teaching/sections/1/plan`
หนึ่งครั้ง ต้องได้ 200 พร้อมสามสัปดาห์

ทุกบัญชีใน seed ใช้รหัสผ่านเดียวกัน คือ `deep-core-local`

ทางเข้า: เลือกตอนเรียนจากหน้า *รายวิชา* → เมนู **แผนการสอน** ที่อยู่ที่ได้คือ
`/teacher/teacherDashboard/<section_id>/teachingPlan`

seed ให้ทุกตอนเรียนทุกปี: สัปดาห์ **1 · 2 · 3** โดยสัปดาห์ 1 มีทั้งรายละเอียดและหมายเหตุ
สัปดาห์ 2 มีแต่รายละเอียด สัปดาห์ 3 ไม่มีทั้งคู่ — และ**สอบกลางภาค**อ้างสัปดาห์ 1 อยู่

## คำตอบของการบันทึก ปิดฟอร์มที่ส่งมันไป ไม่ใช่ฟอร์มที่มันเจอ — #146 (20 ก.ย. 2569)

โดยไม่ถามอะไรเลย
การเขียนไม่มีอะไรมารื้อทิ้ง คำตอบของมันจึงมาถึงหน้าจอที่ขยับไปแล้วได้ —

*ยกเลิก* ด้วยซ้ำ
ฟอร์มที่สองจึงถูกปิดไปพร้อมสิ่งที่พิมพ์ค้างไว้

เป็นเรื่องของรายการที่คนกำลังมองอยู่ ตอนนี้ `showing` จำ **สิ่งล่าสุดที่เปิดขึ้นบนจอนี้**
ทุกตัวควบคุมที่เปิดอะไรขึ้นมาเขียนมัน และคำตอบที่เจอการเปิดอื่นไม่ปิดอะไรและไม่พูดอะไร ทั้งประโยคสำเร็จ
และคำปฏิเสธ — คำถามเดียวกับที่ #139 ให้การอ่านถาม ที่ปลายของการเขียน (#133) เหตุผลทั้งหมดอยู่บน
`frontend/src/pages/Departments.js`

สิ่งที่ไม่ได้เปลี่ยนคือสิ่งที่หน้าจอปิดการใช้งาน ทั้งรายการและดินสอทุกตัวยังกดได้ระหว่างการบันทึก

**ฟอร์มอยู่ต่อ แต่สิ่งที่พิมพ์ในนั้นไม่อยู่**
([#149](https://github.com/khthana/Deep-QA/issues/149)) จอนี้วาดทั้งรายการและฟอร์มไว้ใน
`{!loading && data && (` อันเดียวกัน และการโหลดทุกครั้งขึ้นต้นด้วย `setLoading(true)`
การโหลดที่ตามหลังการบันทึกจึง **ถอดฟอร์มทิ้ง** ตลอดช่วงที่คำขอยังไม่กลับ แล้วสร้างใหม่โดยอ่านค่า
จากระเบียน #146 กันไม่ให้คำตอบที่มาช้า *ปิด* ฟอร์มที่คนย้ายไปแล้ว แต่ไม่ได้กันสิ่งที่พิมพ์ค้างไว้
ในฟอร์มนั้น แถวข้างล่างไม่ได้อ้างถึงเนื้อในฟอร์ม (มันอ่านว่าฟอร์มไหนเปิดอยู่ กับการมีหรือไม่มีประโยค)
จึงไม่มีการอ้างเกิน แต่ก็ยังไม่มีแถวไหนถือเรื่องนี้ไว้ หกจอที่เป็นรายการไม่มีรูปนี้ — `!loading`
ของมันครอบแค่แถวในตาราง ฟอร์มอยู่นอกนั้นและรอดการโหลด ซึ่งเป็นเหตุผลที่แถวของจอเหล่านั้น
อ่านค่าที่พิมพ์ไว้ในช่องได้หลังการโหลด (`inputValue()`) และแถวของจอนี้อ่านไม่ได้

## การโหลดใหม่ไม่ถอดฟอร์มที่คนกำลังพิมพ์ — #149 และ #148 (21 ก.ย. 2569)

คำตอบของเจ้าของ (21 ก.ย. 2569 บันทึกไว้บน [#148](https://github.com/khthana/Deep-QA/issues/148)
และ [#149](https://github.com/khthana/Deep-QA/issues/149)) คือ **จอเก็บสิ่งที่วาดครั้งล่าสุดไว้ระหว่างการโหลด**
— `{data && (` แทน `{!loading && data && (` และบรรทัด *กำลังโหลดข้อมูล…* ขึ้นเฉพาะตอนที่ยังไม่มีอะไร
ให้วาด (`{loading && !data && …}`) ฟอร์มจึงรอดการโหลด และสิ่งที่พิมพ์ค้างไว้อยู่ต่อ

การแก้นั้นเปิดประตูที่ #146 นับไว้ว่าปิด: ระหว่างการโหลดมีดินสอให้กดแล้ว และทั้ง `save` กับ `remove`
ตั้งประโยคของตัวเอง*หลัง*การโหลด ประโยคของการบันทึกจึงถาม `showing.current === sent` ตอนที่มันตัดสิน
แทนที่จะถือคำตอบเก่าไว้ใน `mine` และ `remove` จับ `sent` ไว้ตอนถูกกด แล้วถามคำถามเดียวกันก่อน
ประโยค *ลบหัวข้อออกจากแผนการสอนแล้ว*

ทุกแถวข้างล่าง **เดินด้วยมือไม่ได้** มันต้องการคำขอที่ถูกกักไว้ที่ route จนกว่าแถวจะปล่อย
(`e2e/support/gate.js`) การเขียนที่ถูกกักถูกตอบด้วย 200 ที่แต่งขึ้น จึงไม่มีแถวไหนเขียนฐานข้อมูล

### สิ่งที่การตรวจเจอ และการกวาดที่มันขอ (21 ก.ย. 2569)

การตรวจโค้ดอ่านสามข้อที่การกวาดครั้งแรกไม่เห็น

- **ไม่มีแถวไหนถามว่าประโยคของการลบยังขึ้น** ทุกแถวถามแค่ให้มันเงียบ ตัวที่ทำให้มันไม่พูดอีกเลยจะรอด ทุกไฟล์ แถว *a removal nothing took the place of says what it did* กับ `planremovalbannerunsaid` (`false &&` หน้าเงื่อนไข) เพิ่มเข้ามา — *สองตัวที่แปรคุณสมบัติเดียวกันไม่เห็นอันที่สาม* (#96)
- **`removalsentatthelanding` คือการถอดเงื่อนไขทิ้งในผล** `sent` ที่จับข้างการเปรียบเทียบเท่ากับ ref ตัวเอง ใบมัตแตนต์เคยเขียนว่าไม่ใช่ แก้คำบรรยายแล้ว การฆ่ายังเป็นการฆ่า
- **คำตอบนี้แยกประโยคของการบันทึกออกจาก `mine`** ก่อนหน้านั้น `146:planclosewins` ฆ่าทั้งการปิดและประโยคด้วยตัวเดียว ตอนนี้มันเห็นแค่การปิด ครึ่ง *ไม่มีประโยคสำเร็จ* ของแถว [#146](https://github.com/khthana/Deep-QA/issues/146) จึงได้ `plansavebannerunguarded` (`true ||` หน้าเงื่อนไข) — การกวาดซ้ำของ `146` เป็นที่ที่เห็นมัน *สมอที่ยังอยู่ไม่ได้แปลว่ายังพิสูจน์อะไรได้* (#107)

## การโหลดใหม่ที่ล้มเหลวเก็บสิ่งที่วาดไว้ — #151 (22 ก.ย. 2569)

ตั้งแต่ #149 จอเก็บรายการและฟอร์มไว้ระหว่างการโหลดใหม่ แต่การโหลดที่**ล้มเหลว**ยังล้างทั้งคู่: `catch` ของ `load` ตั้ง `data` เป็น `null` ฟอร์มจึงถูกถอดพร้อมสิ่งที่พิมพ์ไว้ คำตอบ (22 ก.ย. 2569) คือคำตอบของ #149 ต่อไปอีกขั้น — **การโหลดที่ล้มเหลวเก็บสิ่งที่จอวาดไว้ล่าสุด** และคำปฏิเสธขึ้นเหนือมัน การโหลดครั้งแรกที่ล้มไม่มีอะไรให้เก็บ `loading && !data` วาดเหมือนเดิม ซึ่งตั๋วนี้ไม่เปลี่ยน

ทุกแถว **เดินด้วยมือไม่ได้** การเขียนถูกตอบด้วย 200 ที่แต่งขึ้น และการโหลดที่ตามมาด้วย 409 ที่แต่งขึ้น (`e2e/support/gate.js`) จึงไม่มีแถวไหนเขียนฐานข้อมูลผ่านการบันทึก เข้าด้วย `teacher.one@kmitl.ac.th` ครอบคลุมโดย describe *แผนการสอน (TeachingPlan.js)* ใน `151a-failed-reload-keeps-the-list.spec.js` จุดอ่านคือหลังคำปฏิเสธถึงหน้า แล้ว 250 ms อ่านครั้งเดียว (#52) สิ่งที่ค้ำมันคือการกวาดข้างล่าง
