`docs/06-implementation-plan.md` §Acceptance กำหนดว่า ticket หนึ่งจะเสร็จเมื่อ automated test ผ่าน
**และ** checklist ที่ทำด้วยมือถูกเดินจนครบ เอกสารนี้คือครึ่งหลังของ #16

ครึ่งแรกอยู่ที่ `backend/test/subjects.test.js` (19 subtests) — ทุกเกณฑ์ที่พิสูจน์ได้ที่ seam เดียว

คือ *รหัสวิชาซ้ำถูกปฏิเสธ* กับ *การปฏิเสธข้ามภาควิชา* ที่เหลือลงมาอยู่ในตารางข้างล่างเพราะ
docs/06 §Testing Decisions ระบุว่า **"Frontend components are not unit-tested"**

- **ข้อ 6 (import ผ่านโมดูลกลาง)** เป็นข้อความเกี่ยวกับ *ผู้เรียกสี่ราย* และสามรายคือหน้าผู้ใช้งาน
  หน้าภาควิชา และหน้าหลักสูตร พิสูจน์โดย `users.test.js`, `departments.test.js` และ
  `programs.test.js` ซึ่ง **ไม่ถูกแก้เลย**ในตั๋วนี้ — นั่นคือความหมายของคำว่าใช้ซ้ำ

## ตั้งต้น

```
docker start deep-core-postgres
cd db      && npm run reset && npm run migrate && npm run seed
cd backend && npm start          # http://localhost:3000
cd frontend && npm start         # http://localhost:5000
```

ทุกบัญชีใน seed ใช้รหัสผ่านเดียวกัน คือค่า `PASSWORD` ใน `db/seed.js`
เมนูที่ใช้ตลอดเอกสารนี้คือ *ข้อมูลหลัก → ข้อมูลรายวิชา* (`/main/subjects`)

seed มีรายวิชาเดียวคือ `01076105` *การเขียนโปรแกรมเชิงวัตถุ* 3 หน่วยกิต อยู่ในภาควิชา `05`
และ **มีข้อมูลอ้างอิงอยู่** (รายวิชาในหลักสูตร → การเปิดสอน → CLO → คะแนน) รายวิชาที่จะลบได้จริง
จึงต้องสร้างเองในข้อ 1 ส่วนภาควิชา `01` ยังไม่มีรายวิชาเลย และ `dept.admin.01@` เป็นผู้ดูแลของ
ภาควิชานั้น — สองอย่างนี้คือคู่ที่ใช้เดินข้อ 3

**บัญชีหลักของเอกสารนี้คือ `dept.admin.05@`** ผู้ดูแลภาควิชา `05` ซึ่งเป็นภาควิชาของรายวิชาใน seed
เดิมเป็น `faculty.admin@` จนกระทั่ง #61 ตัดสินว่าแคตตาล็อกรายวิชาเป็นของภาควิชาที่สอนวิชานั้น
ตำแหน่งผู้ดูแลระดับคณะจึงเข้าหน้านี้ไม่ได้เลย ไม่ว่าจะอ่านหรือแก้ — และเหลือหนึ่งแถวในตารางข้างล่าง
คือแถวที่พิสูจน์ว่าเข้าไม่ได้จริง

`subjects-good.csv` ที่เตรียมไว้มีแถวของภาควิชา `01` อยู่หนึ่งแถว **ต้องแก้เป็น `05` ก่อนเดินข้อ 6**
เพราะบัญชีที่อัปโหลดตอนนี้ดูแลภาควิชาเดียว

**รหัสวิชายาวได้ไม่เกิน 8 ตัวอักษร** เพราะคอลัมน์เป็น `varchar(8)` และรหัสวิชาจริงของ KMITL
มีแปดหลักพอดี ตัวอย่างที่ใช้ข้างล่างจึงเป็นแปดหลักทั้งหมด

ไฟล์ CSV ที่ข้อ 6 และข้อ 7 ใช้ ถูกเตรียมไว้ให้แล้วในโฟลเดอร์ Downloads ทั้งสี่ไฟล์ —
`subjects-good.csv`, `subjects-broken.csv`, `subjects-no-description.csv`, `subjects-many.csv`
บันทึกเป็น UTF-8 พร้อม BOM แบบเดียวกับที่ Excel เขียน จึงไม่ต้องแก้ไฟล์ด้วยมือเรื่อง encoding ซึ่งเป็นที่มา
ของปัญหาตอนเดิน #15 — การแก้ภาควิชาหนึ่งแถวใน `subjects-good.csv` ที่บอกไว้ข้างบนเป็นข้อยกเว้นเดียว
และไฟล์ทั้งสี่อยู่นอก repo จึงแก้ล่วงหน้าให้ไม่ได้

หลายข้อข้างล่างเขียนข้อมูลจริงลงฐานข้อมูล — **`npm run seed` ใหม่หลังเดินจบ** ก่อนเริ่มตั๋วถัดไป

## รายการที่ต้องเดิน

ช่องสุดท้ายมีสี่ค่า

- **☑** เดินจบแล้ว
- **◐** ครึ่งของ server เดินแล้วและผ่าน ส่วนที่เหลือคือสิ่งที่หน้าจอวาด (แถบสี ตาราง dropdown) ยังต้องมีคนดู
- **☐** ยังไม่ได้เดิน
- **⚙** ครอบคลุมด้วย browser seam แล้ว (#65) ไม่ต้องเดินด้วยมือซ้ำ แถวบอกไฟล์ที่ครอบคลุมไว้ ถ้าแถวนั้นพูดถึงสิ่งที่วาดด้วย (เมนู ถ้อยคำ สี) ครึ่งนั้นยังเป็นงานของคนเดิน และแถวจะเขียนกำกับไว้

## แถวที่ browser seam รับไป และแถวที่ยังเป็นของคนเดิน (#65, 2026-08-20)

เจ็ดในสิบแถวที่ #61 ถอนติ๊กคืน ถูกรับไปด้วย `e2e/tests/16a-subjects.spec.js` แปดข้อทดสอบ
ผ่านทั้งหมด และชุด e2e ทั้งชุดผ่าน 49 ข้อ **ตอนนี้จึงเป็น 24 ☑, 7 ⚙ และ 3 ☐**

สามแถวที่ยังเป็น ☐ เป็นโดยตั้งใจ ไม่ใช่เพราะเขียนไม่ถึง

- **ผู้ดูแลระดับคณะเข้าหน้านี้ไม่ได้เลย** (เกณฑ์ข้อ 3) — ครึ่งที่เป็นกฎถูก assert แล้ว
  ที่เหลือคือรายการในเมนูซ้าย ซึ่งเป็นสิ่งที่วาด #65 ให้ครึ่งนี้เป็นงานของคนเดิน
- **ตัวกรองเป็นชื่อภาควิชา ไม่ใช่ dropdown** (เกณฑ์ข้อ 7) — ครึ่งที่ว่าบรรทัดนั้นบอกภาควิชาถูก assert แล้ว
  ส่วน "เป็นข้อความ ไม่ใช่ตัวเลือก" เป็นคำกล่าวถึงสิ่งที่วาด การ assert ว่า "ไม่มี combobox"
  เป็นตัวแทนของข้ออ้างนั้น ไม่ใช่ตัวข้ออ้าง จึงไม่ติด ⚙ ให้
- **ตัวกรองที่ server ยังกันข้ามภาควิชาอยู่** (เกณฑ์ข้อ 7) — พิสูจน์ครบที่ seam ของ backend แล้ว
  และหน้าจอสร้างคำขอนี้ไม่ได้เลยตั้งแต่ #61 (ดูหมายเหตุในแถว) การเขียน spec ที่ยิง API ตรง ๆ
  จาก Playwright จะเป็นสำเนาของการทดสอบที่มีอยู่ ไม่ใช่การพิสูจน์สิ่งใหม่

ทุกข้ออ้างใหม่ในไฟล์ spec ถูกพิสูจน์ด้วย mutation test ก่อนติด ⚙ สิบสี่ตัวกลายพันธุ์
สิบสี่ตัวถูกฆ่าตรงจุดที่ตั้งใจ — รายการภาควิชาที่ไม่ถูกจำกัดขอบเขต, ไม่เลือกภาควิชาเดียวที่มีให้อัตโนมัติ,
คอลัมน์สถานะที่อ่านกลับด้าน, การปิดใช้งานที่รายงานว่าลบ, เปิดหน้ารายวิชาให้ผู้ดูแลระดับคณะอีกครั้ง,
รายการรายวิชาที่ไม่ถูกจำกัดขอบเขต, ตัดภาควิชาที่ปิดแล้วออกจาก dropdown ทั้งที่รายวิชาอยู่ในนั้น,
นับภาควิชาที่ปิดแล้วเป็นที่ที่สร้างของใหม่ได้, ตารางที่ไม่โหลดใหม่หลังนำเข้าสำเร็จ,
บรรทัดตัวกรองที่ไม่บอกรหัสภาควิชา, ชื่ออังกฤษที่ไม่ถูกวาด, และหน่วยกิตที่หายไประหว่างทางลงฐานข้อมูล
อีกสองตัว ตัวหนึ่งคืนคำว่า *ปิดใช้งาน* ท้ายตัวเลือก
อีกตัวถอด attribute `disabled` ออกโดยที่ตัวเลือกยังอยู่และยังถูกเลือกอยู่ สองข้ออ้างนี้จึงมีตัวฆ่าเป็นของตัวเอง

   ที่นี่ ยังไม่ได้ทำที่นั่น

7. **บัญชีที่ดูแลภาควิชาเดียวเห็นชื่อภาควิชาแทน dropdown** — แถวของตัวกรองถูกวาดเสมอ

   ที่เหลืออยู่ในโค้ดถูกเก็บไว้เพราะเป็นตัวควบคุมตัวเดียวกับที่ *รายวิชาในหลักสูตร* ใช้จริง และ
