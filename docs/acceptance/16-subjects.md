## ตั้งต้น

```
docker start deep-core-postgres
cd db      && npm run reset && npm run migrate && npm run seed
cd backend && npm start          # http://localhost:3000
cd frontend && npm start         # http://localhost:5000
```

ทุกบัญชีใน seed ใช้รหัสผ่านเดียวกัน คือค่า `PASSWORD` ใน `db/seed.js`
เมนูที่ใช้ตลอดเอกสารนี้คือ *ข้อมูลหลัก → ข้อมูลรายวิชา* (`/main/subjects`)

seed มีรายวิชาเดียวคือ `01076105` *การเขียนโปรแกรมเชิงวัตถุ* 3 หน่วยกิต อยู่ในภาควิชา `05`
และ **มีข้อมูลอ้างอิงอยู่** (รายวิชาในหลักสูตร → การเปิดสอน → CLO → คะแนน) รายวิชาที่จะลบได้จริง
จึงต้องสร้างเองในข้อ 1 ส่วนภาควิชา `01` ยังไม่มีรายวิชาเลย และ `dept.admin.01@` เป็นผู้ดูแลของ
ภาควิชานั้น — สองอย่างนี้คือคู่ที่ใช้เดินข้อ 3

**บัญชีหลักของเอกสารนี้คือ `dept.admin.05@`** ผู้ดูแลภาควิชา `05` ซึ่งเป็นภาควิชาของรายวิชาใน seed
เดิมเป็น `faculty.admin@` จนกระทั่ง #61 ตัดสินว่าแคตตาล็อกรายวิชาเป็นของภาควิชาที่สอนวิชานั้น
ตำแหน่งผู้ดูแลระดับคณะจึงเข้าหน้านี้ไม่ได้เลย ไม่ว่าจะอ่านหรือแก้ — และเหลือหนึ่งแถวในตารางข้างล่าง
คือแถวที่พิสูจน์ว่าเข้าไม่ได้จริง

`subjects-good.csv` ที่เตรียมไว้มีแถวของภาควิชา `01` อยู่หนึ่งแถว **ต้องแก้เป็น `05` ก่อนเดินข้อ 6**
เพราะบัญชีที่อัปโหลดตอนนี้ดูแลภาควิชาเดียว

**รหัสวิชายาวได้ไม่เกิน 8 ตัวอักษร** เพราะคอลัมน์เป็น `varchar(8)` และรหัสวิชาจริงของ KMITL
มีแปดหลักพอดี ตัวอย่างที่ใช้ข้างล่างจึงเป็นแปดหลักทั้งหมด

ไฟล์ CSV ที่ข้อ 6 และข้อ 7 ใช้ ถูกเตรียมไว้ให้แล้วในโฟลเดอร์ Downloads ทั้งสี่ไฟล์ —
`subjects-good.csv`, `subjects-broken.csv`, `subjects-no-description.csv`, `subjects-many.csv`
บันทึกเป็น UTF-8 พร้อม BOM แบบเดียวกับที่ Excel เขียน จึงไม่ต้องแก้ไฟล์ด้วยมือเรื่อง encoding ซึ่งเป็นที่มา
ของปัญหาตอนเดิน #15 — การแก้ภาควิชาหนึ่งแถวใน `subjects-good.csv` ที่บอกไว้ข้างบนเป็นข้อยกเว้นเดียว
และไฟล์ทั้งสี่อยู่นอก repo จึงแก้ล่วงหน้าให้ไม่ได้

หลายข้อข้างล่างเขียนข้อมูลจริงลงฐานข้อมูล — **`npm run seed` ใหม่หลังเดินจบ** ก่อนเริ่มตั๋วถัดไป

## รายการที่ต้องเดิน

ช่องสุดท้ายมีสี่ค่า

- **☑** เดินด้วยมือจบแล้ว หรือพิสูจน์ที่ seam HTTP แล้ว — **สองอย่างนี้เป็น ☑ เท่ากัน** ⚙ สงวนไว้ให้ browser seam เท่านั้น และแถวบอกเองว่าอะไรพิสูจน์มัน (`CLAUDE.md` §Marks on the sheets · [#194](https://github.com/khthana/Deep-QA/issues/194))
- **◐** เดินไปได้ครึ่งเดียว อีกครึ่งยังไม่ได้เดิน — **แถวนั้นบอกไว้เองว่าครึ่งไหนยังขาด และครึ่งนั้นรออะไร** · ส่วนใหญ่ครึ่งที่เดินแล้วคือครึ่งของ server และครึ่งที่เหลือคือสิ่งที่หน้าจอวาด (แถบสี ตาราง dropdown) ซึ่งยังต้องมีคนดู — **แต่นั่นเป็นกรณีที่พบบ่อย ไม่ใช่นิยาม** ครึ่งที่เหลือรออยู่สามอย่าง คือ **คน** (เช่น attribute ที่ไปถึง DOM แล้ว แต่ยังไม่มีใครเปิดโปรแกรมอ่านหน้าจอฟัง) · **ตั๋ว** ซึ่งแถวจะอ้างเลขไว้ · หรือ **ไม่รออะไรเลย** เพราะไม่มีตัวควบคุมบนจอสร้างคำขอนั้นได้ ซึ่งเป็น ◐ ถาวรโดยโครงสร้าง — **สามอย่างนี้นับแยกกัน** (`CLAUDE.md` §Marks on the sheets · [#157](https://github.com/khthana/Deep-QA/issues/157))
- **☐** ยังไม่ได้เดิน
- **⚙** ครอบคลุมด้วย browser seam แล้ว (#65) ไม่ต้องเดินด้วยมือซ้ำ แถวบอกไฟล์ที่ครอบคลุมไว้ และมาร์กนี้ได้มาเมื่อมัตแตนต์ฆ่า assertion ของแถวนั้นเอง — **ถ้าแถวนั้นพูดถึงสิ่งที่วาดด้วย (เมนู ถ้อยคำ สี) ครึ่งนั้นยังเป็นงานของคนเดิน และแถวจะเขียนกำกับไว้** (`CLAUDE.md` §Two test seams · [#194](https://github.com/khthana/Deep-QA/issues/194))

  และหน้าจอสร้างคำขอนี้ไม่ได้เลยตั้งแต่ #61 (ดูหมายเหตุในแถว) การเขียน spec ที่ยิง API ตรง ๆ

ทุกข้ออ้างใหม่ในไฟล์ spec ถูกพิสูจน์ด้วย mutation test ก่อนติด ⚙ สิบสี่ตัวกลายพันธุ์
สิบสี่ตัวถูกฆ่าตรงจุดที่ตั้งใจ — รายการภาควิชาที่ไม่ถูกจำกัดขอบเขต, ไม่เลือกภาควิชาเดียวที่มีให้อัตโนมัติ,
คอลัมน์สถานะที่อ่านกลับด้าน, การปิดใช้งานที่รายงานว่าลบ, เปิดหน้ารายวิชาให้ผู้ดูแลระดับคณะอีกครั้ง,

อีกสองตัว ตัวหนึ่งคืนคำว่า *ปิดใช้งาน* ท้ายตัวเลือก
อีกตัวถอด attribute `disabled` ออกโดยที่ตัวเลือกยังอยู่และยังถูกเลือกอยู่ สองข้ออ้างนี้จึงมีตัวฆ่าเป็นของตัวเอง

## คำตอบของการบันทึก ปิดฟอร์มที่ส่งมันไป ไม่ใช่ฟอร์มที่มันเจอ — #146 (20 ก.ย. 2569)

`save` ของ `frontend/src/pages/Subjects.js` เคยจบด้วย `setEditing(null)` กับประโยคสำเร็จ
โดยไม่ถามอะไรเลย
การเขียนไม่มีอะไรมารื้อทิ้ง คำตอบของมันจึงมาถึงหน้าจอที่ขยับไปแล้วได้ — *ยกเลิก*
กดได้ระหว่างที่การเขียนยังไม่กลับ ตารางที่มันกลับไปไม่ปิดปุ่มไหนเลย และ *แก้ไข* หรือ *เพิ่ม…*
เปิดฟอร์มที่สอง
ฟอร์มที่สองจึงถูกปิดไปพร้อมสิ่งที่พิมพ์ค้างไว้
และประโยคของการบันทึกครั้งก่อนมาขึ้นในที่ที่อ่านได้ว่า
เป็นเรื่องของรายการที่คนกำลังมองอยู่ ตอนนี้ `showing` จำ **สิ่งล่าสุดที่เปิดขึ้นบนจอนี้**
ทุกตัวควบคุมที่เปิดอะไรขึ้นมาเขียนมัน และคำตอบที่เจอการเปิดอื่นไม่ปิดอะไรและไม่พูดอะไร ทั้งประโยคสำเร็จ
และคำปฏิเสธ — คำถามเดียวกับที่ #139 ให้การอ่านถาม ที่ปลายของการเขียน (#133) เหตุผลทั้งหมดอยู่บน
`frontend/src/pages/Departments.js`

สิ่งที่ไม่ได้เปลี่ยนคือสิ่งที่หน้าจอปิดการใช้งาน *ยกเลิก* ยังกดได้ระหว่างการบันทึก
เพราะนั่นเป็นการเปลี่ยน UI ซึ่งเป็นคำถาม
ไม่ใช่การแก้ (`docs/06` §Out of Scope) และการโหลดรายการใหม่ทำเสมอ ไม่ว่าการเทียบจะออกทางไหน (#131)

ทุกแถวข้างล่าง **เดินด้วยมือไม่ได้** มันต้องการคำขอที่ถูกกักไว้จนกว่าแถวจะปล่อย ซึ่ง
`e2e/support/gate.js` ทำให้
การเขียนที่ถูกกักถูกตอบด้วย 200 หรือ 409 ที่แต่งขึ้น จึงไม่มีแถวไหนเขียนฐานข้อมูล เข้าด้วย
`dept.admin.05@kmitl.ac.th`
ครอบคลุมโดย describe *ข้อมูลรายวิชา (Subjects.js)* ใน `146a-save-closes-a-later-form.spec.js`
จุดรอของแถวที่การบันทึกสำเร็จคือการโหลดรายการ
ที่ตามมา — การปิดฟอร์มที่ข้อบกพร่องจะวาด commit ไปก่อนคำขอนั้นถูกส่ง — แล้วอ่านครั้งเดียวหลังจากนั้น
250 ms ส่วนแถวคำปฏิเสธไม่มีจุดแบบนั้น (คำปฏิเสธไม่โหลดอะไรใหม่
และประโยคที่ถูกต้องคือประโยคที่ไม่ถูกวาด)
จึงนับจากตอนที่คำตอบถึงหน้า ตัวเลขนั้นตัดสินผลได้ (#52) สิ่งที่ค้ำมันคือการกวาดข้างล่าง

**คำถามที่ตั๋วฝากไว้ ถูกตอบแล้ว (20 ก.ย. 2569)** ร่างแรกให้ *ยกเลิก* เขียน `null` ลง `showing`
การบันทึกที่ถูก *ยกเลิก* แซงโดยไม่มีฟอร์มที่สองมาแทน จึงเงียบทั้งประโยคสำเร็จและคำปฏิเสธ —
คนที่กด *บันทึก* ไม่ได้ยินอะไรเลยเกี่ยวกับการเขียนที่ตัวเองสั่ง ตั๋วฝากเรื่องนี้ไว้เองว่าเป็น
*คำถามเรื่องสิ่งที่คนเห็น แบบเดียวกับ #143* ซึ่ง `docs/06` §Out of Scope บอกว่าเป็นคำถาม
ไม่ใช่การแก้ คำตอบของอาจารย์คือ **ให้ขึ้นเหมือนเดิมเมื่อไม่มีใครมาแทน**

`showing` จึงไม่ได้แปลว่า *ฟอร์มไหนเปิดอยู่* อีกต่อไป แต่แปลว่า **สิ่งล่าสุดที่เปิดขึ้นบนจอนี้**
— *ยกเลิก* ไม่เขียนมัน และการบันทึกที่ปิดฟอร์มของตัวเองก็ไม่เขียน `null` จึงเหลือความหมายเดียว
คือ *ยังไม่มีอะไรเปิดขึ้นเลย* บรรทัดที่เทียบ (`showing.current === sent`) ไม่ถูกแตะเลย
สิ่งที่เปลี่ยนคือใครเขียน ref บ้าง

และเพราะ *ยกเลิก* ไม่เขียน ref แล้ว หน้าต่างที่ผู้ตรวจโค้ดเคยชี้ก็เป็นจริงขึ้นมา — *แก้ไข*
ของจอนี้เปิดฟอร์มจากการอ่าน ระหว่างที่การอ่านยังไม่กลับจึงไม่มีฟอร์มใดบนจอเลย และการบันทึก
ที่ถูกกักข้ามช่วงนั้นจะเจอการเปิดของตัวเอง แล้ววางประโยคไว้เหนือฟอร์มที่กำลังจะถูกวาด ref
จึงถูกเขียน *ตอนกด* ไม่ใช่ตอนการอ่านกลับ — *ถามด้วยการกด ไม่ใช่ด้วยแถว* (#139)
ตอนที่ผู้ตรวจขอแถวนี้ ยังไม่มีทางเข้าไปในหน้าต่างนั้นได้ (#102) คำตอบของคำถามข้างบน
คือสิ่งที่เปิดมัน

### การกวาดซ้ำของมัตแตนต์ที่ตั๋วนี้ขยับ (12 ต.ค. 2569)

การแก้เติมบรรทัดเข้าไปในก้อนที่ handler เคยเป็น สมอของมัตแตนต์ที่อ้างก้อนนั้นทั้งก้อนจึงเลื่อน — ตั๋วนี้
ขยับ **ยี่สิบแปดตัว** ของ #140 #146 #202 #133 #21 #23 และ #68 รวมกัน เหตุผลและกฎที่ใช้เล็งใหม่
อยู่ใน §#203 ของ `docs/acceptance/14-departments.md` ของใบนี้มี สาม ตัว การตรวจสมอบอกได้แค่ว่า
มัตแตนต์ยังเกาะ มีแต่การกวาดที่บอกว่ามันยังพิสูจน์อะไร (#107 #68) จึงกวาดซ้ำทีละตัวกับไฟล์ของมันเอง

ตัวเลขข้างล่างวัดด้วย **ไฟล์ของมันเองทั้งไฟล์** และชื่อไฟล์เขียนเต็ม เพราะอาร์กิวเมนต์ของไฟล์ทดสอบถูก
จับแบบ substring (#154 #158) มันจึงเทียบกับตัวเลขเก่าในใบนี้ตรง ๆ ไม่ได้ ถ้าตัวเลขเก่าวัดด้วยชุดอื่น —
เป็นค่าของวันนี้ กับชุดของวันนี้

- `140:subjectssavestalewins` **ล้ม 1 ผ่าน 31** (baseline `140a` **32 ผ่านทั้ง 32**)
- `140:subjectsremovestalewins` **ล้ม 1 ผ่าน 31** (baseline `140a` **32 ผ่านทั้ง 32**)
- `146:subjectsclosewins` **ล้ม 2 ผ่าน 47** (baseline `146a` **49 ผ่านทั้ง 49**)

### มัตแตนต์ตัวใหม่ของแถวที่เสียที่ค้ำไป (12 ต.ค. 2569)

`146:subjectsclosewins` เคยล้ม **สามแถว** เพราะบรรทัดที่มันลบ อยู่ในก้อนเดียวกับประโยคของการบันทึก
#203 ให้ประโยคมี `if` ของตัวเอง มันจึงเหลือล้มสองแถว และแถวที่สาม *a save that lands while the next
row is being read says nothing* (`146a` บรรทัด 333) ไม่มีมัตแตนต์ค้ำอีก — การตรวจสมอบอกไม่ได้ มีแต่
การกวาดซ้ำที่บอก (#107 #68) เหตุผลเต็มอยู่ใน §#203 ของ `docs/acceptance/14-departments.md`

`146:subjectssavesaysanyway` ใน `mutation/146-save-closes-a-later-form.py` เล็งไปที่บรรทัดที่ถือ
ข้ออ้างนั้นอยู่ตอนนี้ — `if (reloaded && showing.current === sent) setNotice(said)` ของ `save` เป็น
`if (reloaded) setNotice(said)` คือลืม clause ที่สองของ guard ไม่ใช่ถอดเงื่อนไขทิ้งทั้งอัน (#102)
สมอของมันกินบรรทัด `const reloaded = await load(...)` ข้างบนด้วย เพราะย่อหน้าหกช่องเป็น substring
ของแปดช่อง บรรทัดเดียวจึงไปตรงกับครึ่งของการลบด้วย

กวาดเมื่อ 12 ต.ค. 2569 ด้วย `146a-save-closes-a-later-form.spec.js` ทั้งไฟล์ — baseline
**49 ผ่านทั้ง 49**

- `146:subjectssavesaysanyway` **ล้ม 3 ผ่าน 46**
  - *ข้อมูลรายวิชา (Subjects.js) › a save that lands after แก้ไข leaves the form it found open*
  - *ข้อมูลรายวิชา (Subjects.js) › a save that lands after เพิ่ม leaves what was typed where it was*
  - *ข้อมูลรายวิชา (Subjects.js) › a save that lands while the next row is being read says nothing*

มันล้ม **สามแถว** ไม่ใช่แถวเดียว เพราะสองแถวของฟอร์มยืนยันด้วยว่าแบนเนอร์ของการบันทึกครั้งก่อนนับเป็น
ศูนย์ — อ่านว่ามันล้มที่ **assertion ไหน** ไม่ใช่อ่านที่จำนวน (#201) `*closewins` ฆ่าสองแถวนั้นที่
assertion ของฟอร์ม ตัวนี้ฆ่าที่ assertion ของแบนเนอร์ และแถวที่สามล้มที่ข้ออ้างของมันเอง ซึ่งเป็นข้อที่
ไม่มีอะไรค้ำอยู่ก่อนตัวนี้

## ช่องสถานะเป็น `select` — #180 (22 ต.ค. 2569)

เจ้าของงานตอบ [#180](https://github.com/khthana/Deep-QA/issues/180) เมื่อ 22 ต.ค. 2569 ว่าให้ใช้ `select` สองตัวเลือกทั้งห้าจอ ด้วยคำของ
ป้ายในตาราง (*ใช้งานอยู่ / ปิดใช้งาน*) เรื่องเต็มอยู่ใน §#180 ของ
`docs/acceptance/14-departments.md` ฟอร์มของจอนี้เป็นหนึ่งในสามจอที่เคยเป็น checkbox ที่อ่านว่า
*เปิดใช้งาน* คือเขียนสถานะเดียวด้วยสองชุดคำบนหน้าจอเดียว

**บนใบนี้มาร์กถอยหลังสองแถว และนั่นถูกต้อง** — ข้อ 4 *ข้อมูลเดิมยังอ่านได้* เป็น ◐ เพราะครึ่งที่ว่า
ชื่อ หน่วยกิต ภาควิชา คำอธิบาย ยังครบนั้นเดินแล้วและยังจริง ส่วนครึ่งที่อ่านช่องสถานะเดินผ่าน
checkbox ที่ไม่มีอยู่แล้ว · ข้อ 4 *เปิดกลับมาได้* กลับเป็น ☐ เพราะทั้งแถวเดินผ่านตัวควบคุมนั้น
ตัวเดียว · ข้อ 4 *ฟอร์ม เพิ่ม ไม่มีช่องสถานะ* ยังเป็น ☑ เพราะคำกล่าวอ้างของมันคือการ **ไม่มี**
ซึ่งไม่เปลี่ยน มีแต่คำว่า checkbox ในข้อความที่หมดอายุ (#54 — เปลี่ยนเกณฑ์ ลงวันที่บันทึก)

**และแถวเหล่านี้ไม่ได้ ⚙ จากการที่ `16a` กดช่องนั้น** `16a` row 97 กับ `18a` row 10 กดช่องสถานะ
ของฟอร์มนี้ในฐานะ **เครื่องมือ** เพื่อจัดสถานการณ์ให้จออื่น และเครื่องมือไม่ใช่คำกล่าวอ้าง (#171)
มัตแตนต์ที่สลับคำกับค่าของฟอร์มนี้จึงไม่มีใน `mutation/180-the-status-field-shape.py` — มันจะฆ่า
แถวที่ไม่เคยพูดถึงคำบนช่องเลย
