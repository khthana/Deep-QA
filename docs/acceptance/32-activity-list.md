## สิ่งที่ต้องเข้าใจก่อนเดิน — สอง grain อยู่บนจอเดียวกัน

**กิจกรรมเป็นของตอนเรียน หมวดคะแนนเป็นของรายวิชาที่เปิดสอน** `activities.section_id` ถือ grain
แบบเดียวกับแผนการสอน (#31) — สองตอนเรียนของการเปิดสอนเดียวมีกิจกรรมคนละชุด — ส่วนหมวดคะแนน
ที่ใช้จัดกลุ่มเป็นของ (หลักสูตร, รายวิชา, ปีการศึกษา) ตาม ADR-0003 (#30) ใช้ร่วมกันทุกตอนเรียน
บรรทัดใต้หัวเรื่องพูดทั้งสองครึ่งด้วยเหตุผลเดิม: ข้อมูลถูกอยู่แล้วไม่ว่าจะเข้าใจอย่างไร
ที่เดียวที่แก้ความคาดหวังได้คือก่อนที่มันจะก่อตัว

**กลุ่มมาจากสัดส่วนคะแนน ไม่ได้มาจากรายการ** หมวดที่ยังไม่มีงานถูกวาดเป็นกลุ่มว่าง ไม่ใช่หายไป —
เพราะหมวดว่างคือหมวดที่ผู้สอนยังต้องออกงาน ถ้าหน้าจอสร้างกลุ่มจากสิ่งที่มีอยู่ หมวดนั้นจะเงียบหายไป
พอดีตอนที่มันสำคัญที่สุด (มัตแตนต์ `schemefromrows` คือข้อนี้) กิจกรรมที่ยังไม่ระบุหมวด — คอลัมน์
เป็น nullable — ตกไปอยู่กลุ่มท้ายสุดของตัวเอง ไม่ใช่หายไปจากจอ

**ด่านลบมีสองด่าน และ schema พังคนละทาง** `activity_scores.activity_id` เป็น **CASCADE**:
ลบกิจกรรมแล้วคะแนนทั้งรุ่นหายตามไปเงียบ ๆ ฐานข้อมูลไม่ทักอะไรเลย — นี่คือเหตุที่ด่านต้องอยู่
**ใน** คำสั่ง DELETE (บทเรียนจาก code review ของ #31) ส่วน `activity_evidence.activity_id`
เป็น **RESTRICT** และแถวถูก soft-delete: ฐานข้อมูลทักเอง แต่ทักเป็น 23503 → 500 →
*เกิดข้อผิดพลาดในระบบ* สำหรับสิ่งที่คนแก้เองได้ และมันทักแม้กับหลักฐานที่กดลบไปแล้วบนจอ
เพราะ foreign key ไม่อ่าน `is_deleted`

**ทั้ง seed มีกิจกรรมที่ลบได้ตอนเรียนละหนึ่งรายการเท่านั้น** ทุกกิจกรรมที่ seed ปลูกมีคะแนนของ
นักศึกษาทั้งรุ่นผูกอยู่ จึงลบไม่ได้ทั้งหมด #32 จึงเพิ่ม `แบบฝึกหัดท้ายบท (ตอนเรียนที่ N ปีการศึกษา Y)`
เข้าไปหนึ่งแถวต่อตอนเรียน — ไม่มีการผูก CLO ไม่มีคะแนน — เพราะไม่อย่างนั้นทั้งระบบจะไม่มีอะไร
ให้ลบเลย และเบราว์เซอร์สร้างกิจกรรมเองไม่ได้จนกว่า #33 จะสร้างหน้าแก้ไข ชื่อของมัน bake
ตอนเรียนกับปีไว้ด้วยเหตุผลเดียวกับแผนการสอน `db/test/seed.test.js` ยกเว้นแถวนี้ออกจาก
invariant สองข้อโดยระบุชื่อ แล้วปักหมุดไว้ว่ามันคืออะไร

**สร้างและแก้ไขไม่ได้อยู่ในใบนี้** #33 เป็นเจ้าของหน้าแก้ไข รวมถึงการผูกกิจกรรมกับ CLO
ใบนี้แสดงรายการกับลบ ซึ่งคือสิ่งที่ #32 ขอ และเป็นทั้งหมดที่มันขอ

## ตั้งต้น

```
docker start deep-core-postgres
cd db      && npm run reset && npm run migrate && npm run seed
cd backend && npm start          # http://localhost:3000
cd frontend && npm start         # http://localhost:5000
```

**ต้อง reset + seed ใหม่จริง ๆ ก่อนเดินใบนี้ และต้อง kill แล้ว start backend ใหม่** —
`node server.js` ไม่มี reload ตรวจด้วยการ login แล้วยิง `GET /api/teaching/sections/1/activities`
หนึ่งครั้ง ต้องได้ 200 พร้อมหกกิจกรรมและสามหมวด

ทุกบัญชีใน seed ใช้รหัสผ่านเดียวกัน คือ `deep-core-local`

ทางเข้า: เลือกตอนเรียนจากหน้า *รายวิชา* → เมนู **กิจกรรมการเรียนรู้ในรายวิชา** ที่อยู่ที่ได้คือ
`/teacher/teacherDashboard/<section_id>/learningActivities`

seed ให้ทุกตอนเรียน: **โครงงาน** (โครงงานย่อย 1, โครงงานย่อย 2, โครงงานปลายภาค, แบบฝึกหัดท้ายบท) ·
**สอบกลางภาค** (สอบกลางภาค) · **สอบปลายภาค** (สอบปลายภาค) — ห้ารายการแรกมีคะแนนผูกอยู่
มีแต่ *แบบฝึกหัดท้ายบท* ที่ลบได้

## สิ่งที่ตัดสินใจไว้และควรรู้ก่อนแก้

**ทำไมสัดส่วนคะแนนถูกอ่านผ่านตอนเรียน ไม่ใช่ผ่าน `offeringOf`** — อ่านหัวไฟล์
`backend/routes/activities.js` ช่วง *reached through the Section*: `sectionOf` ตอบคำถามสิทธิ์
ไปแล้ว และตอนเรียนหนึ่งอยู่ในการเปิดสอนเดียวเท่านั้น การ import `offeringOf` มาด้วยคือการถาม
ทะเบียนผู้สอนสองครั้งต่อหนึ่งคำขอ เพื่อรู้สิ่งที่คำตอบแรกบอกอยู่แล้ว — และจะเป็น caller ที่สี่
ให้ [#104](https://github.com/khthana/Deep-QA/issues/104) ต้องมาแกะ

**ด่านสองด่านอยู่ในคำสั่งเดียว** `NOT EXISTS` สองอันใน DELETE เดียว แล้วค่อยถามว่าทำไมไม่มีอะไร
ถูกลบ ถ้าถามก่อนลบจะมีช่องว่างระหว่าง "ถาม" กับ "ลบ" ซึ่งสำหรับ CASCADE ช่องนั้นวัดเป็นคะแนน
ของนักศึกษาทั้งรุ่น (บทเรียนจาก code review ของ #31 ที่มีด่านเดียว)

**`NOT EXISTS` ของหลักฐานไม่อ่าน `is_deleted` โดยตั้งใจ** — foreign key ไม่อ่าน ถ้าด่านอ่าน
การลบจะทะลุไปชน RESTRICT แล้วคนจะได้ *เกิดข้อผิดพลาดในระบบ* แทนประโยคที่บอกว่าเกิดอะไรขึ้น

**`integerId` เกิดที่ใบนี้** — `/^\d+$/` อย่างเดียวปล่อยให้ `99999999999999999999` ผ่านไปถึง
ฐานข้อมูลแล้วกลายเป็น 22003 → 500 เทสต์ของใบนี้จับได้ จึงย้ายทั้งรูปทรงและขอบเขตไปไว้ที่
`backend/lib/fields.js` และใช้กับสามที่บนเส้นทางของ #32 ส่วนที่เหลือเป็น
[#107](https://github.com/khthana/Deep-QA/issues/107)
