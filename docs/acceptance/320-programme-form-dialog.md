# ตรวจรับ — #320 ข้อมูลหลักสูตร: ฟอร์มเพิ่ม/แก้ไขเป็นหน้าต่างลอย

[#320](https://github.com/khthana/Deep-QA/issues/320) — `docs/ui-consistency.md` ข้อ 8 (คำตอบของเจ้าของงาน 27 พ.ย. 2569)
ฟอร์มของ `ProgramForm` วาดใน `components/FormDialog.js` ของ #319 · `pages/Programs.js` วาดรายการตลอด และวาดหน้าต่างเมื่อ `editing`

## รูปเดียวกับ #319 ทีละบรรทัด

ไม่ได้ตัดสินอะไรใหม่ — ทุกข้อของ `docs/acceptance/319-department-form-dialog.md` §*รูปนี้คือแม่แบบ* และ §*สามอย่างที่ตั๋วขอ*
ใช้ที่นี่เหมือนกัน: `refused` · `refuse()` · `{!editing && <Notice/>}` · ยกเลิกไม่ล้างแบนเนอร์ · `saving={writing}` · ฟอร์มไม่มีกล่อง
และหัวของตัวเอง หัวของหน้าต่างคือคำเดิม *เพิ่มหลักสูตร* / *แก้ไขหลักสูตร* — `openEditor` ของ `e2e/support/programs-screen.js`
และแถวของ `177a` ที่หาหัวนี้ด้วยบทบาท `heading` จึงหาเจอเหมือนเดิม

สองข้อที่รีวิวของ #319 พบและไม่ได้แก้เป็นจริงที่นี่ด้วย ด้วยกลไกเดียวกัน: ประโยคที่ลงมาระหว่างหน้าต่างเปิดถูกประโยคสำเร็จเขียนทับ
([#337](https://github.com/khthana/Deep-QA/issues/337) คำถามถึงเจ้าของงาน) · โฟกัสตกที่ `body` หลังบันทึกการแก้ไขสำเร็จ (ไม่มีแถวใดถือ)

## สิ่งที่รีวิวพบ (27 พ.ย. 2569)

**แก้แล้ว: แถวที่อ่านแบนเนอร์ของหน้าขณะฟอร์มเปิดผ่านได้เสมอ** แบนเนอร์อยู่หลังผ้าคลุมและไม่ถูกวาด ข้อนี้เป็นของ #319 ด้วย
และรีวิวของ #319 ไม่เห็น:
- `142a` แถว *a read that lands while a removal is out leaves บันทึก disabled* จะ**ล้ม**บนสองหน้าที่มีหน้าต่างแล้ว เพราะคำปฏิเสธการลบไปที่แบนเนอร์ของหน้า
  ตอนนี้อ่านหลังกดยกเลิก
- `146a` สามแถวของจอรายการ และ `139a` แถว *a refusal of the first แก้ไข does not land on the second form* ผ่าน**ทุกกรณี**ไม่ว่าโค้ดจะเป็นอย่างไร
  ตอนนี้มีธง `dialog: true` บนรายการของหน้าภาควิชาและหน้าหลักสูตร และแถวเหล่านี้อ่านอีกครั้งหลังปิดฟอร์ม
  · บันทึกการฆ่าของ `146:programssavesaysanyway` (*ล้ม 3*) และตัวคู่ของหน้าภาควิชาต้องกวาดซ้ำใน #336
  · `Users.js` อยู่ในรูปนี้มาตั้งแต่ #304 แต่**ไม่ได้**ใส่ธงให้ เพราะยังไม่ได้วัดว่าแถวของมันกดยกเลิกด้วยคำเดียวกันได้ จึงฝากไว้กับ #336
- `320a` แถว 3 ปิดหน้าต่างหลังคำปฏิเสธ แล้วอ่านว่าแบนเนอร์ของหน้าไม่มีสำเนา ก่อนหน้านี้คำว่า *ครั้งเดียว* ไม่มีอะไรวัด
- ตารางทำนายของ `s320refusalonpage` เพิ่ม `142a` และ `55a` ก่อนการรัน

**ไม่ได้แก้ จดไว้:**
- **Escape ใช้ธงของทั้งหน้า (`saving={writing}`)** การบันทึกที่ค้างจากฟอร์มที่ยกเลิกไปแล้วจึงทำให้ Escape ในฟอร์มถัดไปไม่ทำงาน จนกว่าจะได้คำตอบ
  ตรงกับคำของตั๋ว (*ปิดเมื่อไม่มีการบันทึกค้าง*) และตรงกับ `busy` ที่ปุ่มบันทึกของฟอร์มใช้อยู่แล้ว แต่ #249 ให้ธงบอกว่า*ของใคร*
  ข้อนี้เป็นของ `Departments.js` ด้วย จึงถามพร้อมกันทั้งสองหน้าใน #336
- **คำปฏิเสธเดิมยังอยู่ในหน้าต่างระหว่างที่กดบันทึกครั้งใหม่** เพราะ `refused` ล้างเมื่อหน้าต่างปิดเท่านั้น เป็นรูปเดียวกับ `Users.js` (#307)
- **`ProgramForm` ยังห่อตัวเองด้วย `ContentMotionDIV`** ซ้อนอยู่ใน `ContentMotionDIV` ของหน้าต่าง ภาพเคลื่อนไหวตอนเปิดจึงซ้อนกัน `DepartmentForm` ก็เหมือนกัน
  เป็นเรื่องที่ต้องดูด้วยตา ไม่มีแถวใดถือ เป็นส่วนหนึ่งของแถว 6
- **`55a` แถบแดงสองแถว** อ่าน `.bg-red-50` และตำแหน่งในจอ ตอนนี้แถบอยู่ในหน้าต่าง การรันจะบอกว่าการพาแถบกลับเข้ามาในจอยังทำงานในกล่องที่เลื่อนได้หรือไม่

## รายการที่ต้องเดิน

ช่องสุดท้ายมีสี่ค่า

- **☑** เดินด้วยมือจบแล้ว หรือพิสูจน์ที่ seam HTTP แล้ว — **สองอย่างนี้เป็น ☑ เท่ากัน** ⚙ สงวนไว้ให้ browser seam เท่านั้น และแถวบอกเองว่าอะไรพิสูจน์มัน (`CLAUDE.md` §Marks on the sheets · [#194](https://github.com/khthana/Deep-QA/issues/194))
- **◐** เดินไปได้ครึ่งเดียว อีกครึ่งยังไม่ได้เดิน — **แถวนั้นบอกไว้เองว่าครึ่งไหนยังขาด และครึ่งนั้นรออะไร** · ส่วนใหญ่ครึ่งที่เดินแล้วคือครึ่งของ server และครึ่งที่เหลือคือสิ่งที่หน้าจอวาด (แถบสี ตาราง dropdown) ซึ่งยังต้องมีคนดู — **แต่นั่นเป็นกรณีที่พบบ่อย ไม่ใช่นิยาม** ครึ่งที่เหลือรออยู่สามอย่าง คือ **คน** (เช่น attribute ที่ไปถึง DOM แล้ว แต่ยังไม่มีใครเปิดโปรแกรมอ่านหน้าจอฟัง) · **ตั๋ว** ซึ่งแถวจะอ้างเลขไว้ · หรือ **ไม่รออะไรเลย** เพราะไม่มีตัวควบคุมบนจอสร้างคำขอนั้นได้ ซึ่งเป็น ◐ ถาวรโดยโครงสร้าง — **สามอย่างนี้นับแยกกัน** (`CLAUDE.md` §Marks on the sheets · [#157](https://github.com/khthana/Deep-QA/issues/157))
- **☐** ยังไม่ได้เดิน
- **⚙** ครอบคลุมด้วย browser seam แล้ว (#65) ไม่ต้องเดินด้วยมือซ้ำ แถวบอกไฟล์ที่ครอบคลุมไว้ และมาร์กนี้ได้มาเมื่อมัตแตนต์ฆ่า assertion ของแถวนั้นเอง — **ถ้าแถวนั้นพูดถึงสิ่งที่วาดด้วย (เมนู ถ้อยคำ สี) ครึ่งนั้นยังเป็นงานของคนเดิน และแถวจะเขียนกำกับไว้** (`CLAUDE.md` §Two test seams · [#194](https://github.com/khthana/Deep-QA/issues/194))
