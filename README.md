# DEEP-Core

Curriculum and learning-outcomes management for the Faculty of Engineering, KMITL. Records what a programme intends
its graduates to learn, how each subject teaches and assesses that, and how far each student actually got — as
evidence for TABEE accreditation.

**Status: the rebuild has not started.** What is in this repository today is the student implementation exactly as
delivered, plus the design work planning its replacement. There is no database and the application cannot be run yet.
Ticket [#2](https://github.com/khthana/Deep-QA/issues/2) is the first piece of work.

## Layout

```
Deep-QA/
├── DEEP-QA-BACKEND/     student implementation — read-only reference
├── DEEP-QA-FRONTEND/    student implementation — read-only reference
├── docs/                specs, ADRs, plan and ticket breakdown
├── scripts/             tooling (issue publishing)
├── CONTEXT.md           domain glossary
└── CLAUDE.md            orientation for AI agents
```

The rebuild lands in new `backend/`, `frontend/` and `db/` trees, one screen at a time. The two `DEEP-QA-*`
directories are never edited — they are copied from, and deleted once the rebuild completes.

## Setting up on a new machine

Requires Docker, Node 20 or later, and the [`gh`](https://cli.github.com/) CLI authenticated against this repository.

```bash
git clone https://github.com/khthana/Deep-QA.git
cd Deep-QA
```

**Then copy the environment files across by hand.** They hold live credentials, are deliberately excluded from version
control, and will not arrive with the clone:

- `DEEP-QA-BACKEND/.env`
- `DEEP-QA-FRONTEND/.env`

[`.env.example`](./.env.example) documents every variable. Move the real files over a channel that is not this
repository — a password manager or a USB stick, not email or chat.

Two further directories are excluded and are **not** needed to work on the rebuild:

- `DEEP-QA-BACKEND/uploads/` — roughly 200 assessment evidence files uploaded through the running system. These are
  student work. If they must be moved, treat them as personal data and never commit them.
- `DEEP-QA-FRONTEND/build/` — a compiled bundle, regenerated by `npm run build`.

`node_modules/` is likewise excluded; run `npm install` in each application directory.

Once ticket [#2](https://github.com/khthana/Deep-QA/issues/2) lands, this section gains the commands that bring the
database up and seed it.
